# Git 手册 · 只记四个命令

> 你不用专门学 Git，但**必须搞懂这四件事**，因为往后 147 天每节课都要用。
>
> 不用背命令，理解"它在干什么"就够了。卡住了翻这张。

---

## 一、Git 在干什么（一句话）

**给你的代码文件夹"拍快照"。每拍一张，就多一个可以退回去的时间点。**

类比：打游戏存档。写代码是打怪，`commit` 是存档，`push` 是上传到云。

**为什么必须会**：以后代码被改坏了，你能退回任何一个存档。**没存档，改坏了就真没了。**

---

## 二、四个区，理解这个就全懂了

```
你的文件夹          暂存区            本地仓库            GitHub
（改代码的地方）  →（准备提交的）  →（快照存档）    →（云端备份）
              add              commit            push
```

| 区 | 在哪 | 里面是什么 |
|---|---|---|
| 工作区 | 你看到的文件夹 | 你现在写的东西 |
| 暂存区 | 看不见，Git 内部 | "这次要存哪几个文件"的清单 |
| 本地仓库 | `.git` 文件夹 | 所有历史快照 |
| 远程仓库 | GitHub 网站 | 云端备份 |

**`add` = 放进清单，`commit` = 按清单拍快照，`push` = 传云端。**

**在 VS Code 里：**

- 点文件右边的 `+` = `add`
- 输入信息点 `✓` = `commit`
- 点同步按钮 = `push`

**图形界面已经帮你做好了。你只需要知道它对应哪一步。**

## 四、出事时用的命令

打开终端（`` Ctrl + ` ``）。

### 看现在什么状态

```
git status
```

**什么时候用**：不确定自己改了什么、有没有提交成功。

**怎么读**：

- `nothing to commit, working tree clean` = 全提交了，干净
- `Your branch is ahead of 'origin/main' by 2 commits` = **有 2 个提交没推上去**
- 红色字 = 改了但没加进清单
- 绿色字 = 已加进清单但还没提交

> **`ahead` 这个词最容易骗人。** 它听着像"领先"，实际上是**"没备份"**。
>
> 看到 `ahead` 就去点同步。

### 看历史（我提交过什么）

```
git log --oneline
```

输出长这样：

```
635111a init: 全新结构
```

**前面那串字母数字是快照编号**，后面是你写的提交信息。想退回某次，就用这个编号。

### 撤销还没提交的改动

```
git restore .
```

**什么时候用**：你把文件改乱了，想恢复成上次提交的样子。

> **⚠️ 危险**：这会**永久丢弃**所有未提交的修改，**没有反悔机会**。
>
> 用之前先 `git status` 确认丢的是什么。

**只撤销某一个文件**：

```
git restore index.html
```

### 推上去被拒绝

```
git pull --rebase
```
```
git push
```

**什么时候用**：在 GitHub 网页上改过文件，本地推不上去，报 `Updates were rejected`。

**它在干什么**：先把 GitHub 上的新东西拉下来接到本地后面，再推。

## 五、最容易搞混的一件事：提交 ≠ 备份

**这是新手最可能理解错的地方。**

| 动作 | 做了什么 | 安全吗 |
|---|---|---|
| `Ctrl+S` 保存 | 写到硬盘上的文件 | ❌ 不算 |
| `commit` 提交 | 在**本地** `.git` 里拍快照 | ❌ 硬盘坏了还是没了 |
| `push` 推送 | 传到 **GitHub 云端** | ✅ **这才叫备份** |

**所以每节课必须点那个"同步"按钮。**

**只 commit 不 push，等于只在本地存了档。电脑一摔全没。**

## 六、常见报错

| 报错 | 它在说什么 | 怎么办 |
|---|---|---|
| `not a git repository` | 你不在仓库文件夹里 | `cd` 到 `B:\OPC-Distance_study` |
| `nothing to commit` | 没有新改动 | 正常，说明已提交过了 |
| `Please tell me who you are` | 没配名字邮箱 | 跑下面那两行 |
| `Authentication failed` | GitHub 登录失效 | 重推一次，弹窗重新授权 |
| `Updates were rejected` | 云端有你本地没有的改动 | `git pull --rebase` 再 push |
| `CONFLICT` | 同一个文件两边都改了 | **别自己乱改**，把报错原文发给 AI |
| `error: src refspec main does not match any` | 当前分支不叫 `main` | `git branch -M main` |

**配名字邮箱**（只需一次）：

```
git config --global user.name "keal-24"
```
```
git config --global user.email "276084243+keal-24@users.noreply.github.com"
```

## 七、`.env` 绝对不能提交

`.gitignore` 里已经有 `.env`，但**每次提交前还是要确认一下**：

```
git status
```

**`.env` 不应该出现在列表里。**

> **为什么这条单独说**：`.env` 里是 API key。**提交上去之后，就算马上删掉，Git 历史里还有。**
>
> 要彻底清除得重写历史，很麻烦。而 GitHub 上有爬虫专门扫这类 key，扫到就直接用。
>
> **养成习惯：每次提交前 `git status` 看一眼。** 这是你唯一一次能发现"key 要泄露"的机会。

## 八、一句话总结

> **Git 不是要你背命令，是要你养成一个习惯：每节课收工，写一句话，点两下，推上云。**
>
> 记不住命令无所谓 —— VS Code 的图形界面能干 90% 的事。你只需要记住那条铁律：
>
> **只在本地 commit 不算备份，必须 push 到 GitHub。**
