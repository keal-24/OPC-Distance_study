# 环境搭建 · 从空电脑到能写代码

> 这份文档的唯一标准：**拿到一台全新的电脑，只靠这一份，能恢复到「可以开始写代码」的状态。**
>
> 每一步都给验证方法。验证不过，别往下走。

---

## 一、只需要三个软件

不要装别的。装多了只会拖慢机器、增加出问题的可能。

| 软件 | 干什么 | 装哪 |
|---|---|---|
| **VS Code** | 写代码的编辑器 | `code.visualstudio.com` |
| **Node.js** | 让 JS 能在浏览器外面跑（后端要用） | `nodejs.org`，选 **LTS** |
| **Git** | 版本管理，每节课提交用 | `git-scm.com/download/win` |

> **为什么只这三个**：VS Code 写代码，Node 跑代码，Git 存代码。**这三件覆盖了 252 节课里 95% 的操作。** 其他的（比如 Docker、数据库工具）等真需要了再装。

---

## 二、装（Windows）

打开 PowerShell（`Win + R` → 输入 `powershell` → 回车），**逐行**粘贴执行：

```powershell
winget install --id Microsoft.VisualStudioCode -e --accept-package-agreements --accept-source-agreements
```

```powershell
winget install --id OpenJS.NodeJS.LTS -e --accept-package-agreements --accept-source-agreements
```

> **⚠️ Node 必须落在 22 这条线上。**
>
> `OpenJS.NodeJS.LTS` 装的是"当前 LTS"，而 LTS 每年会往上滚一格（现在可能已经给你 24）。
> **本课程全部按 Node 22 写**，第 5 周起要用 22 才有的 `node:sqlite`。
>
> 所以第 32 行跑完，**先敲 `node -v` 看一眼**：
>
> - 出 `v22.x.x` → 对了，继续；
> - 出 `v24.x.x` 或更高 → 去 `nodejs.org` 下 **22.x 的 LTS 安装包**覆盖安装一次（约 30MB，两分钟）。
>
> 为什么不干脆用 24：24 上 `node:sqlite` 已经转正，不再打 `ExperimentalWarning`，第 5 周"屏幕上应该看到什么"那段输出会对不上。**版本统一到 22，全课程 252 节的输出才和你屏幕一致。**

```powershell
winget install --id Git.Git -e --accept-package-agreements --accept-source-agreements
```

> **`winget` 是什么**：Windows 自带的软件包管理器。相当于一个命令行版的应用商店，一条命令装完，不用点安装向导。
>
> **为什么不手动下载**：手动下载要点五六次"下一步"，还得留意别装了捆绑软件。**命令行一条就完了，而且以后换电脑能直接复制这三行。**
>
> **如果 `winget` 报"不是内部或外部命令"**：你的 Windows 版本太旧。去微软商店搜 "App Installer" 装上，或者手动去官网下载。

**三条跑完，关掉 PowerShell，重新开一个。** 这一步不能省——不重开，环境变量不生效，下面验证会全部失败。

## 三、验证（四条都要出版本号）

新开 PowerShell，逐行执行：

```
node -v
```
```
npm -v
```
```
git --version
```
```
code --version
```

**期望看到类似：**

```
v22.22.2
10.9.7
git version 2.55.0.windows.3
1.9x.x
```

**四条都出版本号才算过。**

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 报"不是内部或外部命令" | PowerShell 没重开 | 关掉重开，再试 |
| `node -v` 不是 v22 | 装成了老版本，或 LTS 已经滚到 24 | 去 `nodejs.org` 下 22.x 的 LTS 包覆盖安装；或用 nvm-windows 切到 22 |
| `code` 报错 | VS Code 没加进 PATH | 打开 VS Code → `Ctrl+Shift+P` → 输入 `Shell Command` → 选 `Install 'code' command in PATH` |
| `git --version` 报错 | Git 装失败 | 重跑第二条 winget |

## 四、配 Git 身份（一次配置，终身有效）

Git 靠两行配置认你是谁。不配的话，提交记录里作者是空的，GitHub 不会把提交算成你的贡献，**绿点不会亮**。

```
git config --global user.name "keal-24"
```
```
git config --global user.email "276084243+keal-24@users.noreply.github.com"
```

验证：

```
git config --global --list
```

看到 `user.name=keal-24` 和 `user.email=...` 就对了。

> **邮箱必须和 GitHub 账号的邮箱一致。** 不一致的话提交能成功，但 GitHub 不认，你的贡献图一片空白。

## 五、拿回仓库（换电脑的核心动作）

### 情况 A：新电脑，第一次拉

```
cd B:\
```
```
git clone https://github.com/keal-24/OPC-Distance_study.git
```
```
cd OPC-Distance_study
```

**第一次会弹登录窗**，选 `Sign in with your browser` → 浏览器里点 `Authorize git-credential-manager`。

看到 `Clone succeeded` 就成了。

> **仓库名和本地文件夹名故意保持一致**：都叫 `OPC-Distance_study`。两边不一致的话，你以后在文档、路径、命令里会反复搞混。

### 情况 B：本地已有目录，只想接上 GitHub

就是把现有目录推上去：

```
cd "B:\OPC-Distance_study"
```
```
git remote add origin https://github.com/keal-24/OPC-Distance_study.git
```
```
git branch -M main
```
```
git push -u origin main
```

推完去 `https://github.com/keal-24/OPC-Distance_study` 刷新能看到文件就成功了。

**这一步没做，所有提交都只存在本地硬盘上，等于没备份。**

## 六、装三个 VS Code 插件

打开 VS Code → 左侧竖排第五个图标（四个小方块，「扩展」）→ 搜索 → 点 `安装`。

| 插件 | 作者 | 干什么 | 必须吗 |
|---|---|---|---|
| **Chinese (Simplified)** | Microsoft | 界面变中文 | **强烈建议**（零基础看英文菜单会卡） |
| **Live Server** | Ritwick Dey | 改完代码浏览器自动刷新 | **必须**（没有它每改一个字都要手动刷） |
| **Prettier** | Prettier | 一键把乱代码排整齐，`Shift+Alt+F` | 建议 |

> **装 `Chinese` 时认准作者是 Microsoft。** 搜索会出来几十个第三方汉化包，有的一装界面就乱码。

装完中文包会弹窗问要不要切换语言，点 `Change Language and Restart`。**不点它，装了也还是英文。**

## 八、八个必须知道的终端命令

252 节课里你会反复用这八个。**现在不用背，遇到翻回来查。**

| 命令 | 干什么 | 例子 |
|---|---|---|
| `pwd` | 我在哪个文件夹 | `pwd` |
| `ls` | 这个文件夹里有什么 | `ls` |
| `cd` | 进某个文件夹 | `cd "B:\OPC-Distance_study"` |
| `cd ..` | 回上一级 | `cd ..` |
| `mkdir` | 建文件夹 | `mkdir 第01节课` |
| `cat` | 看文件内容 | `cat README.md` |
| `node 文件名` | 运行一个 js 文件 | `node server.js` |
| `Ctrl + C` | **停止正在运行的程序** | — |

> **`pwd` 是这里最重要的一条。**
>
> 你已经在这上面栽过两次：一次在仓库根目录跑 `npm init` 报"名字不合法"，一次在上层目录跑 `node server.js` 报"找不到模块"。
>
> **养成习惯：运行任何命令前，先 `pwd` 看一眼。** 这一个动作能省掉一半"莫名其妙"的报错。

**本课程所有命令都按 PowerShell 写。** 和 cmd（老式黑窗口）的唯一差别是跨盘切换：

```text
PowerShell   cd "B:\OPC-Distance_study"        ← 课程里全是这个写法
cmd          cd /d "B:\OPC-Distance_study"     ← 少那个 /d 就切不过去
```

**别混着用。** 在 PowerShell 里敲 `cd /d` 会报 `A positional parameter cannot be found`，这是新手最常撞的一个"看起来像 bug 其实不是"的错。
