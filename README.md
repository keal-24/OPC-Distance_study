## 为什么这么排

**一天一个文件夹，任务、代码、笔记全在里面。**

你不需要在三个地方之间跳。进 `w01-地基/d01/`，看 `TASK.md` 做，代码写在同一个文件夹，收工写 `NOTES.md`。

**以前把任务、代码、笔记分三个顶层目录，是错的** —— 你每天都在三个地方跳来跳去，还不知道哪个文件属于哪天。现在一天一处，进了就出不了错。

**`docs` 是资料，只读。** 那不是你要改的东西，是给你查的。翻了就关掉，别在里面写东西。

---

## 每天的四步

**1. 读 `TASK.md`**

从第一句开始读，不要跳。里面有：今天交付什么、每一步怎么做、每步的目的是什么、你会看到什么、出错了怎么办。

**2. 在同一个文件夹里写代码**

不需要另建目录。`d01/index.html` 就在 `TASK.md` 旁边。

**3. 收工写 `NOTES.md`**

```markdown
今天做了什么：
卡在哪：
怎么解决的：
```

**"卡在哪"这一栏别空着。** 代码 AI 三秒能重写，你踩过的坑只有你自己知道。

**4. 提交**

VS Code 左侧第三个图标 → 写一句 → 点 `✓` → **点同步**

---

## 三条铁律

**一、每天 commit + push**

`commit` 只是本地快照，`push` 才是云端备份。**只 commit 不 push 等于没备份。**

收工打一句 `git status`，看到 `ahead` 就是没推。

**二、`docs` 不要改**

它是刻度。改了就没法对照自己有没有偏离。

**三、`NOTES.md` 比代码重要**

代码能重写，坑不能。
