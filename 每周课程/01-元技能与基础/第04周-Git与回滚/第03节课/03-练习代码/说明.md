## 为什么必须自己造历史

**因为"查历史"这个能力，只在自己造过历史之后才长得出来。**

- 你要知道"每次提交改了什么"，才能看懂 `--stat`；
- 你要知道"哪次故意写错、哪次改回来"，才能用 `-S` 找到 bug 的生命周期；
- 你要知道"某一行是谁改的"，才能理解 `blame` 只显示最后修改者。

**照着课件做六次提交，包括故意留的 `multiply` bug。**

## 六个提交的顺序

```text
1. 初始化项目：添加 README
2. 添加 add 函数
3. 添加 subtract 函数
4. 添加 multiply 函数     ← 故意写成 a + b（bug）
5. 更新 README：补充用法说明
6. 修复 multiply 用成了加法的问题
```

**第 4 次故意写错，第 6 次改回来。**
**这条"bug 的生命周期"是后面所有调查练习的素材。**
