# 第 0 步：全用 div 会怎样（5 分钟）

## 0.1 先看一段真实的乱代码

```html
<div class="a">
  <div class="b">
    <div class="c">我的网站</div>
    <div class="d">
      <div class="e">首页</div>
      <div class="e">关于</div>
    </div>
  </div>
  <div class="f">
    <div class="g">文章标题</div>
    <div class="h">文章内容...</div>
  </div>
  <div class="i">版权所有</div>
</div>
```

**问题：**

- 哪个是页头？
- 哪个是导航？
- 哪个是主内容？
- 哪个是页脚？

**光看标签，一个都看不出来。** 只能靠猜 `class` 名字。

## 0.2 换成有意义的标签

```html
<header>
  <h1>我的网站</h1>
  <nav>
    <a href="/">首页</a>
    <a href="/about">关于</a>
  </nav>
</header>
<main>
  <article>
    <h2>文章标题</h2>
    <p>文章内容...</p>
  </article>
</main>
<footer>版权所有</footer>
```

**现在一眼就能看出来：**

- `<header>` 是页头；
- `<nav>` 是导航；
- `<main>` 是主体；
- `<article>` 是一篇文章；
- `<footer>` 是页脚。

**这就是"语义化"。**

## 0.3 `语义化` 是什么意思

```text
语义 = 含义
语义化 = 用标签名字把"这块是什么"说清楚
```

**对比：**

| 不语义 | 语义化 | 差别 |
|---|---|---|
| `<div class="header">` | `<header>` | 后者标签名本身就说明了 |
| `<div class="nav">` | `<nav>` | 后者一看就懂 |
| `<div class="footer">` | `<footer>` | 后者不需要 class 也能懂 |

## 0.4 语义化有三个好处

**好处一：你自己看得懂**
三个月后回来看，不用回忆 `class="f"` 是什么。

**好处二：屏幕阅读器能用**
视障用户用的读屏软件会根据标签跳转。它知道 `<nav>` 是导航区，可以直接跳过；知道 `<main>` 是主内容，可以直接定位。

**好处三：搜索引擎能理解**
搜索引擎知道哪块是正文、哪块是广告、哪块是页脚，给的权重不一样。

# 第 2 步：认识 8 个语义化标签（25 分钟）

## 2.1 `<header>` 页头

```html
<header>
  <h1>网站名</h1>
  <nav>...</nav>
</header>
```

**放什么：** 网站 logo、网站名、主导航、搜索框。

**放几个：** 一个页面一般一个。**但一篇文章内部也可以有自己的 `<header>`**（放标题和作者信息）。

**和 `<head>` 别搞混：**

| 标签 | 位置 | 显示吗 |
|---|---|---|
| `<head>` | `<html>` 的直接子元素 | **不显示** |
| `<header>` | `<body>` 里面 | **显示** |

**这两个词长得像，但完全不是一回事。** 这是新手最常混淆的一对。

## 2.2 `<nav>` 导航

```html
<nav>
  <a href="/">首页</a>
  <a href="/articles">文章</a>
  <a href="/about">关于</a>
</nav>
```

**`nav` = navigation（导航）。**

**放什么：** 一组"跳转到别处"的链接。

**什么时候不该用：**
如果只是一两个零散链接（比如文章里的"点击这里"），不用 `<nav>`。**`<nav>` 是给"主要导航区域"用的。**

**一个页面可以有多个 `<nav>`：** 顶部主导航一个，页脚"友情链接"一个。但别滥用。

## 2.3 `<main>` 主体

```html
<main>
  <!-- 这页最主要的内容 -->
</main>
```

**放什么：** 这个页面**独有**的核心内容。

**不能放什么：**

- 网站名和导航（那是每个页面都有的）；
- 页脚版权（也是每页都有的）；
- 侧边栏（通常也是共用的）。

**规则：一个页面只能有一个 `<main>`。**

**为什么：**
读屏软件有"跳到主内容"的快捷键，它需要知道唯一的主内容在哪。多个 `<main>` 会让它不知道跳哪。

## 2.4 `<article>` 文章

```html
<article>
  <h2>文章标题</h2>
  <p>正文...</p>
</article>
```

**放什么：** **能独立拿出来、单独发布也有意义**的内容。

**判断标准：**

```text
把这块内容单独贴到别的地方，还看得懂吗？
能 → 用 <article>
不能 → 用 <section> 或 <div>
```

**例子：**

- 一篇博客文章 → `<article>` ✓
- 一条微博 → `<article>` ✓
- 一个商品卡片 → `<article>` ✓（可以单独分享）
- "网站简介"这一块 → 不是 `<article>`，因为它脱离网站就没意义了

## 2.5 `<section>` 区块

```html
<section>
  <h2>本章内容</h2>
  <p>...</p>
</section>
```

**放什么：** 一个有主题的内容块，但**不能独立存在**。

**和 `<article>` 的区别：**

| `<article>` | `<section>` |
|---|---|
| 能独立发布 | 不能独立发布 |
| 一篇完整文章 | 文章里的一章 |
| 一条评论 | 评论区 |

**注意：`<section>` 通常应该有标题。** 没有标题的 `<section>` 一般应该用 `<div>`。

## 2.6 `<aside>` 侧边栏

```html
<aside>
  <h2>相关文章</h2>
  <ul>...</ul>
</aside>
```

**`aside` = 在旁边（旁白、附注）。**

**放什么：** 和主内容相关、但**不是主内容**的东西。

- 侧边栏推荐；
- 广告；
- 作者简介；
- 相关链接；
- 名词解释框。

**判断标准：** 去掉它，主内容还完整吗？完整 → 可以用 `<aside>`。

## 2.7 `<footer>` 页脚

```html
<footer>
  <p>版权所有 2026</p>
  <nav>...</nav>
</footer>
```

**放什么：** 版权、联系方式、备案号、友情链接、隐私政策。

**位置：** 一个页面的页脚在最后；**一篇文章也可以有自己的 `<footer>`**（放标签、分享按钮）。

## 2.8 `<figure>` 和 `<figcaption>` 图文块

```html
<figure>
  <img src="chart.png" alt="销售趋势图">
  <figcaption>图 1：2026 年销售趋势</figcaption>
</figure>
```

- `figure` = 图形、插图；
- `figcaption` = 图注（caption = 说明文字）。

**为什么需要：**
因为图片和它的说明文字是一体的。用 `<figure>` 包起来，语义上就"绑定"了。

**`<figcaption>` 必须放在 `<figure>` 里面**，而且一般放在最后。

## 2.9 八个标签对照表

| 标签 | 中文 | 放什么 | 数量限制 |
|---|---|---|---|
| `<header>` | 页头 | logo、站名、导航 | 一般 1 个 |
| `<nav>` | 导航 | 主要跳转链接组 | 可以多个 |
| `<main>` | 主体 | 本页独有内容 | **只能 1 个** |
| `<article>` | 文章 | 可独立发布的内容 | 可以多个 |
| `<section>` | 区块 | 有主题的段落 | 可以多个 |
| `<aside>` | 侧栏 | 相关内容、广告 | 可以多个 |
| `<footer>` | 页脚 | 版权、联系方式 | 一般 1 个 |
| `<figure>` | 图文块 | 图片 + 图注 | 可以多个 |

## 2.10 马上自测

不看上面，回答：

1. `<head>` 和 `<header>` 有什么区别？
2. 一个页面能有几个 `<main>`？
3. `<article>` 和 `<section>` 怎么区分？
4. 侧边栏该用什么标签？

## 3.5 新出现的两个东西

### `<time datetime="2026-11-16">`

```html
<time datetime="2026-11-16">2026-11-16</time>
```

**这个标签干什么：** 告诉浏览器和搜索引擎"这是一个时间"。

**两个部分的区别：**

| 部分 | 作用 |
|---|---|
| `datetime="2026-11-16"` | 给机器读的标准格式 |
| `2026-11-16` | 给人看的显示文字 |

**为什么需要分开：**
因为人可以看"2026年11月16日"、"11月16日"、"昨天"，但机器需要统一格式。`datetime` 属性写标准格式，标签内写显示文字。

**比如：**

```html
<time datetime="2026-11-16">昨天</time>
```

**显示"昨天"，但机器知道是 2026-11-16。**

### 文章内部也有 `<header>`

```html
<article>
  <header>
    <h2>第一篇文章</h2>
    <p><time>...</time></p>
  </header>
  ...
</article>
```

**为什么这里能再用 `<header>`：**
因为 `<header>` 不限于"整个页面的头"。**任何一块内容都可以有自己的头部。**

**这种 `header` 里不再放 `<nav>`，而是放标题和元信息（日期、作者）。**

# 第 4 步：`<div>` 还有用吗（10 分钟）

## 4.1 一个常见误解

很多人学完语义化标签后说：“那 `<div>` 是不是不用了？”

**不是。`<div>` 依然大量使用。**

## 4.2 `<div>` 的正确用途

```text
当你要"把几个东西装在一起"，但这个"组合"本身没有语义时，用 <div>。
```

**例子一：布局容器**

```html
<div class="layout">
  <main>...</main>
  <aside>...</aside>
</div>
```

**为什么这里用 `<div>`：**
"主内容 + 侧边栏"这个组合本身没有语义名称。它就是一个布局容器。

**例子二：装饰性包裹**

```html
<div class="card-shadow">
  <p>内容</p>
</div>
```

**为什么用 `<div>`：**
这个 `div` 只是为了加阴影效果，本身不代表任何内容。

## 4.3 什么时候不该用 `<div>`

**反例：**

```html
<div class="article">
  <div class="title">标题</div>
  <div class="content">内容</div>
</div>
```

**问题：** 这明明是一篇文章，为什么用 `div`？

**应该改成：**

```html
<article>
  <h2>标题</h2>
  <p>内容</p>
</article>
```

## 4.4 选择标签的决策顺序

```text
第一步：这块内容有专门的语义标签吗？
        有 → 用它（header/nav/main/article/section/aside/footer/figure）
第二步：这块是一个标题吗？
        是 → h1-h6
第三步：是一段文字吗？
        是 → p
第四步：是一个列表吗？
        是 → ul/ol + li
第五步：都不是，只是要把东西装一起？
        → div
```

**`<div>` 是最后的选择，不是第一选择。**

## 4.5 一个重要提醒

**不要为了语义化而滥用语义标签。**

**反例：**

```html
<section>
  <section>
    <section>
      <p>一句话</p>
    </section>
  </section>
</section>
```

**问题：** 三层 `section` 包一句话，什么意义都没有。

**规则：**

```text
<section> 应该有标题。
没有标题的"分区"，用 <div>。
```

## 4.6 自己判断四个场景

**场景一：** 一个商品列表，每个商品有图、名称、价格。

**你的答案：** 每个商品用 `<article>`（能独立分享），整个列表用 `<section>` 或 `<ul>`。

**场景二：** 网站的"关于我们"页面。

**你的答案：** 整页内容放 `<main>`，里面用 `<section>` 分"公司简介""团队""联系方式"。

**场景三：** 一个登录表单，右侧有个"忘记密码"的提示框。

**你的答案：** 表单用 `<section>` 或直接 `<form>`，提示框用 `<aside>`。

**场景四：** 页面顶部一条"双 11 大促"的公告横幅。

**你的答案：** 用 `<aside>`（它不是主内容）或者 `<div>`（如果只是装饰）。

**操作：**

1. 在 `index.html` 里，把 `<aside>` 改成 `<main>`：

**为什么：** 浏览器不会因为这个报错，它照样显示。

**但问题在哪：**

- 读屏软件的"跳到主内容"会不知道跳哪一个；
- 搜索引擎会搞不清哪个是主内容；
- 这不符合规范。

**这就是"语义化"的一个特点：错了不会报错，但会损害可用性和 SEO。**

## 错误 2：`<nav>` 里塞满非链接

**操作：**

1. 把一段普通文字放进 `<nav>`：

   ```html
   <nav>
     <a href="#">首页</a>
     <p>这是一段说明文字</p>
   </nav>
   ```

2. 保存，打开。

**你会看到什么：** 显示正常。

**问题在哪：** `<nav>` 应该只放导航链接。混进普通段落，语义就乱了。

## 错误 3：`<h1>` 用了三个

**操作：**

1. 把三个 `<h2>` 都改成 `<h1>`。
2. 保存，打开。

**你会看到什么：** 三个一样大的标题。

**问题在哪：**

- 一个页面应该只有一个 `<h1>`（页面主标题）；
- 多个 `<h1>` 会让结构层级混乱；
- 搜索引擎不知道这页到底讲什么。

**正确做法：** 一个 `<h1>`（网站名或页面主题），下面用 `<h2>`，再下面 `<h3>`。

## 三个错误的共同点

```text
它们都不会报错，页面照样显示。
但会让代码难维护、让读屏软件困惑、让搜索引擎误判。
```

**所以语义化是一个"靠自觉"的东西。** 你必须自己知道规则。

# 第 6 步：标题层级怎么排（10 分钟）

## 6.1 六级标题

```html
<h1>一级标题（最大）</h1>
<h2>二级标题</h2>
<h3>三级标题</h3>
<h4>四级标题</h4>
<h5>五级标题</h5>
<h6>六级标题（最小）</h6>
```

## 6.2 三条规则

### 规则一：一个页面只有一个 `<h1>`

**它代表这个页面最核心的主题。**

## 规则二：不要跳级

**错误：**

```html
<h1>标题</h1>
<h3>小标题</h3>   ← 跳过了 h2
```

**正确：**

```html
<h1>标题</h1>
<h2>小标题</h2>
<h3>更小的标题</h3>
```

**为什么不能跳：**
因为标题层级表达的是"包含关系"。跳级等于说"这个三级标题属于一个不存在的二级标题"。

### 规则三：不要为了字号用标题

**错误：**

```html
<h3>这段字我想大一点</h3>
```

**为什么错：** 标题是结构，不是样式。**要改字号用 CSS。**

**正确：**

```html
<p class="big-text">这段字我想大一点</p>
```

## 6.3 一个完整的标题结构

```html
<h1>小栈笔记</h1>

  <h2>最新文章</h2>
    <h3>第一篇文章</h3>
    <h3>第二篇文章</h3>

  <h2>分类</h2>
    <h3>技术</h3>
    <h3>生活</h3>
```

**看出来了吗：** 它像一本书的目录。

## 6.4 检查你现在的结构

**打开 `index.html`，回答：**

1. `<h1>` 有几个？
2. 有没有跳级？
3. 每个 `<h2>` 下面有没有内容？

**如果没有问题，说明结构合格。**

# 第 7 步：用读屏视角检查你的页面（5 分钟）

## 7.1 一个思维实验

**假设你看不见屏幕，只能用耳朵听。**

读屏软件读你的页面，大概是这样：

```text
"横幅"
"一级标题：小栈笔记"
"导航"
"链接：首页"
"链接：文章"
"链接：关于"
"导航结束"
"横幅结束"
"主内容"
"文章"
"二级标题：第一篇文章"
"2026-11-16"
"这是第一段内容。"
"这是第二段内容。"
"文章结束"
...
```

**如果你用的是全 `div` 版本，它只会读：**

```text
"小栈笔记"
"首页"
"文章"
"关于"
...
```

**没有任何"这是导航""这是主内容"的提示。**

**这就是语义化的实际价值。**

## 7.2 怎么实际测试

**Chrome 浏览器：**

1. 打开你的 `index.html`；
2. 按 `F12` 打开开发者工具；
3. 点左上角的"元素"（Elements）标签；
4. 从上往下看你的 HTML 结构；
5. 观察：能一眼分清层次吗？

**更直观的方法：**

1. 在 Chrome 里装一个"HTML5 Outliner"扩展；
2. 打开页面，它会给你列出标题大纲。

**不过不用装也行。** 你只要自己看一遍代码，问：“如果我不认识这些字，只看标签，能知道这是什么吗？”

## 7.3 把你的页面和 bad.html 并排对比

**操作：**

1. 把两个文件的代码并排打开（Visual Studio Code 里右键 → 拆分编辑器）；
2. 从上往下对比。

**你会明显感觉到：** 右边的 `index.html` 结构清晰得多。

**把这个感受记下来。** 以后你写任何页面，都要追求这种"一眼看懂"。

# 附：常见问题速查

| 情况 | 原因 | 怎么做 |
|---|---|---|
| 加了语义标签但看不出变化 | 还没写 CSS | 正常，语义化影响的是结构不是外观 |
| `<header>` 没显示 | 写在了 `<head>` 里 | 移到 `<body>` 里 |
| 页面结构看起来还是乱 | 只换了标签没整理缩进 | `Shift + Alt + F` 格式化 |
| 不知道某块该用 article 还是 section | 没想清能不能独立存在 | 问："单独拿出去还有意义吗" |
| 用了多个 `<main>` | 习惯性当容器用 | 只留一个，其余换 `<div>` 或 `<section>` |
| 标题跳级了 | 只按字号选 | 按层级选，字号用 CSS 改 |
| 读屏测试听不出层次 | 语义标签用错或没用 | 对照第 7 步的读屏输出检查 |
| `<figure>` 里图片和图注分开了 | `figcaption` 放错位置 | 必须在 `<figure>` 内部 |
| `<time>` 显示的不是想要的 | `datetime` 和显示文字搞混 | 属性写标准格式，标签内写显示文字 |
