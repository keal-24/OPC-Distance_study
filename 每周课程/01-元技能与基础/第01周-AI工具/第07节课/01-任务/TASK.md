# 第 7 节课：给项目写一份说明——CONTEXT.md

> **这份文件是你（学员）一步一步照着做的操作手册。**
> 前六节课你写代码、读代码、修报错、改文件、存档。这节课做一件收尾的事：**把你这一周的经验写成一份文件，让以后每次和 AI 对话都不用重复解释。**
> 这节课基本不写代码，写文档。但这份文档的价值比一半代码都大。

**建议用时**：90 分钟
**你需要先完成**：第 1—6 节课

# 第 0 步：为什么需要这份文件（5 分钟）

## 0.1 你这一周踩过的坑

回想一下这六节课，你有没有遇到过：

- 工具给你的代码用 `...` 省略了；
- 工具改了你没让它改的文件；
- 工具把函数名改了，导致调用处全错；
- 你说了“不要安装库”，它还是给你 `npm install`；
- 它说“已完成”，实际没做完；
- 它一遍遍问你“你用什么语言”“你的文件结构是什么”。

**这些问题的共同原因：每次对话都要从头解释。**

## 0.2 一个解决方法的思路

假设你有这样一份文件：

```text
我的项目用 Node.js 22，不用任何第三方库。
目录结构是 xxx。
命名规则是 xxx。
有这十条硬规则。
不要做这五件事。
```

**每次开新对话，先把这份文件给它看。**

它就不会再犯那些错了。

## 0.3 这份文件叫什么

```text
CONTEXT.md
```

**`Context` 是什么：**
英文意思是“上下文、背景”。这份文件就是给 AI 的“项目背景说明书”。

**注意：** 不同工具可能用不同文件名（`AGENTS.md`、`CLAUDE.md`、`.cursorrules`）。**内容结构是通用的**，文件名按你用的工具调整。

## 0.4 今天的交付物

| 文件 | 位置 | 内容 |
|---|---|---|
| `TASK.md` | `01-任务` | 你正在读的这份 |
| `NOTES.md` | `02-笔记` | 你的学习记录 |
| `CONTEXT.md` | `03-练习代码` | **今天唯一的产出** |
| `demo.js` | `03-练习代码` | 验证 CONTEXT.md 有效性的测试文件 |

# 第 1 步：先看看没有 CONTEXT.md 会怎样（10 分钟）

## 1.1 做一次对照实验

**操作：**

1. 打开 WorkBuddy。
2. 只说这一句：

   ```text
   帮我写一个函数，计算商品折扣后的价格。
   ```

3. 发送，观察它的回答。

## 1.2 记录它自己“发明”了什么

拿纸记录，看它做了下面哪些决定：

- [ ] 用了什么语言？（可能是 JavaScript，也可能是 Python）
- [ ] 金额用什么单位？（元？分？）
- [ ] 参数是一个对象还是两个数字？
- [ ] 有没有处理小数精度？
- [ ] 有没有考虑折扣是 0.2 还是 20？
- [ ] 有没有处理负数？
- [ ] 有没有用第三方库？
- [ ] 有没有写注释？中文还是英文？

**你会发现：它替你做了至少 5 个决定。**

**这 5 个决定，可能全都和你的项目不一致。**

## 1.3 现在再试一次，这次给背景

```text
项目背景：
- 语言：JavaScript，运行环境 Node.js 22
- 不使用任何第三方库
- 所有金额一律用整数分存储，不用小数元
- 函数命名用 camelCase
- 注释用中文
- 每个函数必须处理 null 和 undefined 输入

请按以上规则写一个函数，计算商品折扣后的价格。
折扣率用小数表示（0.2 表示打 8 折）。
输入是一个对象 { priceCents, qty } 和折扣率。
```

**发送，对比两次结果。**

## 1.4 差在哪

**第二次的回答会：**

- 直接用 `priceCents`（分），不会给你小数；
- 不会问你要不要装库；
- 会加中文注释；
- 会处理空输入。

**因为它有了上下文。**

**这就是 CONTEXT.md 的全部意义：把你最常重复的那 20 句话，写成一份文件。**

# 第 2 步：CONTEXT.md 应该包含什么（15 分钟）

## 2.1 六个部分

```text
① 项目是什么
② 技术栈（用什么语言、什么工具、什么版本）
③ 目录结构
④ 命名规则
⑤ 硬规则（必须遵守的）
⑥ 禁令（绝对不能做的）
```

**为什么是这六个：**
因为它们正好对应 AI 最容易犯错的六类事。

## 2.2 逐个看

### ① 项目是什么

**一句话说清这个项目是干什么的。**

```markdown
## 项目

一个订单金额计算练习项目，用于学习 JavaScript 基础。
不涉及真实交易、不连接数据库、不部署上线。
```

**为什么需要“不涉及什么”：**
不然它可能给你加数据库、加登录、加支付。

### ② 技术栈

**写清版本，不要只写名字。**

```markdown
## 技术栈

- 语言：JavaScript（ES2022）
- 运行环境：Node.js 22
- 第三方库：无，一律不使用
- 编辑器：Visual Studio Code
```

**为什么必须写版本：**
`Node.js 18` 和 `22` 有些内置方法不一样。不写版本，它可能给你一个跑不了的写法。

**为什么写“无，一律不使用”：**
不写这句，它会默认可以装库。**AI 很喜欢“帮你引入一个更好的库”。**

### ③ 目录结构

**把你实际的文件夹结构列出来。**

```markdown
## 目录结构

```text
项目根/
├── 03-练习代码/
│   ├── config.js      配置
│   ├── format.js      格式化
│   ├── cart.js        购物车计算
│   └── index.js       入口
└── 02-笔记/
    └── NOTES.md       学习记录
```
```

**为什么要写：**
这样它给代码时会知道“该放哪个文件”，不会凭空造一个新文件。

### ④ 命名规则

**这是最容易出问题的地方。**

```markdown
## 命名规则

| 类型 | 规则 | 例子 |
|---|---|---|
| 变量、函数 | camelCase | `totalPrice`、`calcCart` |
| 常量 | UPPER_SNAKE_CASE | `MAX_RETRY`、`TAX_RATE` |
| 类、组件 | PascalCase | `OrderService` |
| 文件名 | kebab-case | `order-utils.js` |
| 数据库字段 | snake_case | `created_at` |
| 布尔变量 | is/has/can 开头 | `isMember`、`hasPaid` |
```

**为什么必须显式写：**
不然它一会儿 `total_price`，一会儿 `totalPrice`，一会儿 `TotalPrice`。**同一个项目三种风格，三个月后你自己都看不懂。**

### ⑤ 硬规则

**必须遵守的技术规则。**

```markdown
## 硬规则

1. 所有金额用整数分（cents）存储和计算，只在显示时转成元。
2. 判断相等一律用 `===`，不用 `==`。
3. 外部请求必须设置超时。
4. 不允许空 `catch`，至少记录错误信息。
5. 时间统一用 UTC 存储，显示时再转本地时区。
6. 每个函数必须处理 null、undefined、空字符串输入。
7. 函数不要同时“返回结果”和“修改传入的参数”。
8. 不写 `var`，只用 `const`，需要重新赋值时用 `let`。
```

**这八条不是随便写的。** 每一条都对应一个真实的坑：

| 规则 | 对应的坑 |
|---|---|
| 金额用分 | `0.1 + 0.2 !== 0.3`（第 3 节课实测过） |
| 用 `===` | `"1" == 1` 是 `true`，类型混乱 |
| 请求超时 | 请求不返回，程序永久卡住 |
| 不空 catch | 错误被吞掉，数据错了你不知道 |
| 时间用 UTC | 换时区后时间全错 |
| 处理空输入 | 第 1 节课的 `formatTime("")` 就是这个问题 |
| 不同时做两件事 | 第 6 节课的 `cartSummary` 副作用 |
| 不用 `var` | `var` 有变量提升，容易出诡异 bug |

### ⑥ 禁令

**绝对不能做的事。**

```markdown
## 禁令

1. 不要修改 `01-任务/` 和 `02-笔记/` 下的任何文件。
2. 不要安装任何第三方依赖。
3. 不要新建配置文件（如 `.babelrc`、`tsconfig.json`）。
4. 不要删除已有的 `console.log` 测试代码。
5. 不要用 `...` 或“其余不变”省略代码。
6. 不要在代码里写真实密码、密钥、手机号。
7. 不要一次改超过 2 个文件。
```

**为什么禁令比规则更重要：**
规则是“你要做什么”，禁令是“你不能做什么”。**AI 闯祸基本都闯在禁令这条线上。**

**第 7 条特别关键：**
一次改超过 2 个文件，你就很难用 diff 看清它动了什么。

一个订单金额计算练习项目，用来练习日期处理、金额计算和代码规范。

**版本号怎么查：**

**建议（本课程统一）：**

```text

常量：UPPER_SNAKE_CASE
文件名：kebab-case
布尔：is/has/can 开头
```

**为什么定这一套：**
不是因为它是唯一正确，是因为**它必须统一**。统一比“最优”重要。

**从第 2 步的八条里，挑你这一周真正踩过的坑。**

**比如：**

- 你在第 1 节课遇到过空输入崩溃 → 写“必须处理空输入”；
- 你在第 3 节课看到 `0.1 + 0.2` 的误差 → 写“金额用整数分”；

**没踩过的不用硬凑。** 写了但不懂，反而会让 AI 给出你看不懂的代码。

### 第六部分：禁令

**这一部分要写得非常具体。**

**反例：**

```text

```

**正例：**

```text

```

**为什么正例更好：** “乱改”是主观的，“不要改 01-任务”是可以检查的。

### 第七部分：当前已知问题

**把你这一周发现但还没修的问题记下来。** 比如：

```text
- 2 月 30 日会被 JavaScript 自动顺延成 3 月 2 日，还没加校验。

```

**为什么写这个：**
这样 AI 不会把“已知问题”当成新 bug 再“修”一遍，也不会在你没让它修的时候擅自改。

## 4.4 把测试代码自己敲出来

**操作：**

1. 在 `03-练习代码` 新建 `demo.js`。
2. **自己敲**下面代码（按你的 CONTEXT.md 规则整理过的版本）：

```javascript
// 第07节课：验证 CONTEXT.md 的效果

const ORDERS = [
  { id: "A001", amountCents: 12800 },
  { id: "A002", amountCents: 9650 },
  { id: "A003", amountCents: 7420 },
];

function summarizeOrders(orders) {
  if (!Array.isArray(orders) || orders.length === 0) {
    return { totalCents: 0, averageCents: 0, count: 0 };
  }

  const totalCents = orders.reduce((sum, order) => sum + order.amountCents, 0);
  const averageCents = Math.round(totalCents / orders.length);

  return {
    totalCents,
    averageCents,
    count: orders.length,
  };
}

function formatYuan(cents) {
  return "¥" + (cents / 100).toFixed(2);
}

const result = summarizeOrders(ORDERS);

console.log("订单数：", result.count);
console.log("总金额：", formatYuan(result.totalCents));
console.log("平均金额：", formatYuan(result.averageCents));

console.log("--- 空输入测试 ---");
console.log(summarizeOrders([]));
console.log(summarizeOrders(null));
console.log(summarizeOrders(undefined));
```

3. 保存，运行 `node demo.js`。

**应该看到：**

```text
订单数： 3
总金额： ¥298.70
平均金额： ¥99.57
--- 空输入测试 ---
{ totalCents: 0, averageCents: 0, count: 0 }
{ totalCents: 0, averageCents: 0, count: 0 }
{ totalCents: 0, averageCents: 0, count: 0 }
```

**验算：**

- 12800 + 9650 + 7420 = 29870 分 = ¥298.70
- 29870 / 3 = 9956.67 → `Math.round` → 9957 分 = ¥99.57

**这里有一个细节要注意：**
平均金额四舍五入到 9957，三个加起来是 299 元？不是，9957 × 3 = 29871，比总额多 1 分。

**这是“平均值舍入误差”。** 它不可避免，但你必须知道它存在。真实报表里通常会在最后一行注明“因四舍五入，合计可能略有差异”。

## 4.5 这段代码里用了哪些 CONTEXT.md 规则

对照你自己写的规则，找出这段代码遵守了哪几条：

```text
✅ 金额用整数分（amountCents、totalCents）
✅ 处理 null / undefined / 空数组
✅ 命名用 camelCase（summarizeOrders、averageCents）
✅ 常量用 UPPER_SNAKE_CASE（ORDERS）
✅ 用 === 判断
✅ 函数只返回结果，不修改传入的数组
✅ 注释用中文
```

**这个练习是让你看到：规则不是写在纸上好看的，它真的会改变代码的样子。**

**先看看它是什么。**

有些工具（比如 Codex）会读根目录的 `AGENTS.md`。如果你用的是这种工具，可以：

- 把 `CONTEXT.md` 的内容合并进 `AGENTS.md`；
- 或者让 `AGENTS.md` 里写一句“本项目规则见 CONTEXT.md”。

**两种做法都行。关键是：AI 每次都能读到这份规则。**

## 5.3 以后每节课怎么用

**开新对话时的固定动作：**

```text
1. 打开 CONTEXT.md
2. 全选复制
3. 粘贴到对话开头
4. 让它先读，回“已了解”
5. 再说这次的具体任务
```

**为什么要单独一步让它“先读”？**
因为你把上下文和任务混在一条消息里，它可能只关注任务，跳过规则。

**分开两步，它就必须先处理规则。**

## 5.4 定期更新

**CONTEXT.md 不是写一次就完。**

**什么时候要更新：**

- 加了新的目录；
- 定了新的命名规则；
- 踩到新的坑，要加进硬规则；
- 修好了已知问题，要删掉。

**建议节奏：每周末花 5 分钟更新一次。** 第 7 节课这节课的作业就是第一次更新。

# 第 7 步：课后练习

## 练习一：找出你 CONTEXT.md 的三个漏洞

把 `CONTEXT.md` 给 WorkBuddy 看，然后问：

```text
请阅读我的项目上下文文件，然后回答三个问题：

1. 如果我要你写一个新函数，你最可能在哪里违反我的规则？
2. 我的规则里有没有互相冲突的地方？
3. 有没有哪条规则写得太模糊，可以被多种理解？

只指出问题，不要修改我的文件。
```

**把它的回答记下来，然后自己判断哪些问题是真的。**

**注意：不要盲信它的判断。** 它可能指出一些不存在的问题。**你自己判断，觉得有理才改。**

## 练习二：做一次真实使用

1. 开一个新对话；
2. 先发 CONTEXT.md，让它回“已了解”；
3. 再发一个真实任务（比如“给 demo.js 加一个功能：找出金额最大的订单”）；
4. 检查它给的代码是否遵守了你的规则；
5. 如果违反了，指出哪一条，让它改。

**记录：它第一次就遵守了几条规则？违反了几条？**

## 练习三：给 CONTEXT.md 加一节

加一个新章节：

```markdown
## 八、代码风格偏好
```

写清：

- 缩进用几个空格；
- 字符串用单引号还是双引号；
- 每行最长多少个字符；
- 函数之间空几行；
- 要不要写分号。

**为什么要写这些：**
这些细节不定，它每次给你的风格都不一样，diff 会变得很乱。

# 附：常见问题速查

| 情况 | 原因 | 怎么做 |
|---|---|---|
| `CONTEXT.md` 存成了 `.txt` | 没开扩展名显示 | 打开显示后重命名 |
| AI 读了 CONTEXT.md 还是违规 | 规则写得太模糊 | 把“不要乱改文件”改成“不要修改 01-任务 下的文件” |
| AI 说“已了解”但没遵守 | 上下文和任务混在一条消息 | 分两条消息发 |
| 每次都要重新粘贴很麻烦 | 工具有项目级配置文件 | 查你的工具文档，看是否支持 `AGENTS.md` 之类的项目文件 |
| 版本号不知道写什么 | 没查 | 终端运行 `node -v` |
| 目录结构画不出来 | 不会用 `tree` | 打开文件夹照着写，只写两层就够 |
| 硬规则写不出来 | 没踩过坑 | 只写你这一周真踩过的，别硬凑 |
| `demo.js` 平均金额差 1 分 | 舍入误差 | 正常现象，报表里注明“因四舍五入略有差异” |
| `git push` 要求输入密码 | 没配 SSH 或 token | 按 GitHub 提示配一次，或在 VS Code 里登录 |
| 推送被拒绝（rejected） | 远程有本地没有的提交 | 先 `git pull`，解决冲突后再 push |
