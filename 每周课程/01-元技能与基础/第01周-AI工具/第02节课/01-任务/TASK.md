# 第 1 步：认识到“五个格子”缺一不可（15 分钟）

## 1.1 先做一个实验：只说一句话

**操作：**

1. 打开 WorkBuddy。
2. 在输入框里只输入这五个字：

```text
优化这段代码
```

3. 发送。

**屏幕上会出现什么：**
它会问你“哪段代码？”或者直接开始编一段它自己想的代码。

**这说明什么：**
你没有给它代码，也没有说“优化”是指变快、变短、变好读，还是加功能。它只能猜。

## 1.2 再加一句，看变化

这次输入：

```text
优化这段代码：function f(a){return a*2}
```

**屏幕上会出现什么：**
它会给出一两个版本，但依然不知道你要什么。可能改成箭头函数，可能加类型检查，可能加注释。

**关键结论：**

> 你给的每一分信息，都在缩小它的猜测范围。

## 1.3 五个格子各自负责什么

```text
① 背景   → 我在什么环境、什么水平、已有什么
② 任务   → 这次到底做什么（一句话，动词开头）
③ 要求   → 必须有哪些具体行为（一条一条列）
④ 限制   → 不许做什么（防止它顺手扩大范围）
⑤ 验收   → 怎么判断做对了（给测试样例）
```

**记住一个比喻：**

你请一个装修师傅来家里干活：

| 格子 | 装修场景 |
|---|---|
| 背景 | 这是老房子，墙是砖墙，不能打承重墙 |
| 任务 | 把这间卧室刷白 |
| 要求 | 用环保漆，刷两遍，边角要齐 |
| 限制 | 不许动地板，不许换门，预算 2000 以内 |
| 验收 | 我用手摸不掉粉，闻不到刺鼻味，边角没有漏刷 |

少了任何一格，师傅都可能做出一间你不想要的房间。

# 第 2 步：逐格拆开，每格配真实例子（25 分钟）

## 2.1 背景：写清“我在哪”

**它回答的问题：** 我现在用什么语言？什么水平？已经有什么文件？不想引入什么？

**反例（太模糊）：**

```text
我在学编程。
```

**正例：**

```text
我在学 JavaScript，用的是 Node.js 22，目前只有一个文件 try.js，
里面已经有一个能跑的 formatTime 函数。
我不想安装任何第三方库。
```

**为什么要写版本：**
因为不同版本的语法和功能不一样。`Node.js 18` 和 `22` 有些内置函数不同。不写版本，它可能给你一个你电脑上跑不了的写法。

**为什么要写“不想引入什么”：**
不然它可能给你装一个库。装库意味着多一个依赖，多一个以后可能坏掉的地方。

## 2.2 任务：一句话，动词开头

**它回答的问题：** 这次具体做什么？

**反例（一句话塞了五件事）：**

```text
帮我优化代码，加上错误处理，改成中文注释，顺便写个文档，再看看有没有安全问题。
```

**正例：**

```text
给 try.js 里的 formatTime 函数增加“一周内显示星期几”的能力。
```

**规则：**

- 一次只做一件事；
- 用动词开头：增加、修改、删除、重命名、拆分、解释；
- 不写“优化”“改进”“完善”这种没有标准的词。

**为什么不能写“优化”：**
因为“优化”没有终点。它可能优化了速度，同时让代码变难读。你要说清优化什么、优化到什么程度。

## 2.3 要求：一条一条，可以打勾

**它回答的问题：** 做完以后，程序必须有哪些行为？

**反例：**

```text
日期显示要合理一些。
```

**正例：**

```text
1. 如果日期在 7 天以内（不含今天、昨天），显示“星期X 12:30”，例如“星期三 12:30”。
2. 星期用中文：星期一、星期二、星期三、星期四、星期五、星期六、星期日。
3. 今天仍然显示“今天 12:30”。
4. 昨天仍然显示“昨天 12:30”。
5. 超过 7 天且是今年，仍然显示“11月16日 12:30”。
6. 不是今年，仍然显示“2025年11月16日”。
```

**为什么要求要带例子：**
因为“合理”是主观的，`星期三 12:30` 是客观的。带例子，它可以自查；不带例子，它只能猜。

## 2.4 限制：明确“不许做什么”

**它回答的问题：** 哪些行为你不能做？

**反例：**

```text
尽量少改。
```

**正例：**

```text
1. 只修改 try.js 这一个文件，不要新建文件。
2. 不要安装任何第三方库。
3. 不要改动已有的“今天”“昨天”“今年”“往年”四条逻辑。
4. 不要删除现有的测试调用行。
5. 不要用省略号省略代码。
```

**限制为什么重要：**
工具很“热心”。你说加功能，它可能顺手把整个文件重构一遍。你第二天打开文件，看不懂了。

**第 5 条特别重要：**
`...` 是它偷懒最常用的方式。复制到你电脑上，语法直接报错。

## 2.5 验收：给它测试用例

**它回答的问题：** 怎么算做对？

**正例：**

```text
请给出这些测试，并写出每条的预期输出：
1. 今天          → 今天 12:30
2. 昨天          → 昨天 12:30
3. 3 天前        → 星期三 12:30（按实际星期）
4. 8 天前（今年）→ 11月8日 12:30
5. 去年          → 2025年11月16日
6. 空字符串      → 未知时间
7. 乱写的文字    → 未知时间
```

**验收为什么必须提前写：**
因为做完再看，你会被它的输出说服。**先定标准，再看结果**，这是唯一能防止“它说对了其实错了”的办法。

## 2.6 五格写完之后，自己过一遍

写完后用眼睛扫，逐项问自己：

- [ ] 背景里写了语言和版本吗？
- [ ] 任务是一句话、一个动作吗？
- [ ] 要求能一条条打勾吗？带例子吗？
- [ ] 限制写了“不许新建文件、不许装库、不许省略”吗？
- [ ] 验收有具体测试用例和预期结果吗？

五项全过，再发送。

## 3.8 你写的算不算合格：参考答案与自查

**这一节是给你对照用的。** 上面五个版本我故意只给提示、不给范文，因为你先自己写才有意义。**写完了，现在来对答案。**

### 先自查：五个版本各扣一分的地方

**版本 1 应该是“一句话”，如果你的写了三句以上，说明你没敢真的写烂。**

这一版故意写烂是有原因的：你得先看到“一句话”会产生什么后果，才知道后面四格各有什么用。**如果版本 1 就写得很完整，整个实验就废了。**

自查：你版本 1 是不是真的只有一句话？

**版本 2 必须包含四件事，缺一件就说明你还没理解“背景”的作用：**

| 要素 | 不合格的写法 | 合格的写法 |
|---|---|---|
| 学什么语言 | “我在写代码” | “我在学 JavaScript” |
| 运行环境 | 不提 | “用 Node.js 跑，不是浏览器” |
| 现在有什么 | “有个函数” | “只有一个文件 `try.js`，里面已有 `formatTime`” |
| 约束 | 不提 | “不想装任何第三方库” |

**为什么“运行环境”必须写：** 因为 Node.js 和浏览器能用的 API 不一样。你不说，AI 可能给你一个 `window` 或者 `document`，在 Node 里直接报错。

**版本 3 的“要求”必须能打勾。** 判断标准很简单：

```text
❌ “界面好看一点”        → 没法打勾
✅ “7 天以内显示「星期三 12:30」” → 能打勾
```

**如果你的要求里有任何一条**不能**用“是/否”判断，它就不合格。** 这一条是整节课最实用的检验方法。

**版本 4 的“限制”必须至少有一条是“不许做什么”。**

很多人写要求很会写，写限制就卡住。**因为人天生只想“我要什么”，不想“我不要什么”。**

而限制往往比要求更管用：

| 只写要求 | 加了限制 |
|---|---|
| 它可能给你装个库 | “不装任何第三方库” → 只能手写 |
| 它可能把测试删了 | “不删现有 5 行 console.log” → 测试还在 |
| 它可能用 `...` 省略 | “代码不许用省略号” → 必须给完整代码 |

**记住：要求决定“做成什么样”，限制决定“不许偷哪些懒”。**

**版本 5 的“验收”必须给具体输入和具体预期输出。**

不合格的写法：

```text
❌ 请给测试用例
```

合格的写法：

```text
✅ 请给出这些输入对应的输出：
   今天 → 今天 12:30
   昨天 → 昨天 12:30
   3 天前 → 星期三 12:30
```

**区别在哪：** 前者它随便给两个测试就交差；后者它必须按你列的七种情况逐个回答，**少一个你一眼就能看出来**。

### 一个真实对比：同一句话，两种结果

**输入 A（不合格）：**

```text
给日期加个星期。
```

**它可能回你：**

```javascript
function getWeekday(dateStr) {
  const days = ["日", "一", "二", "三", "四", "五", "六"];
```

## 4.5 逐块看新代码，找这三处

不要急着粘贴。先对照新旧代码，找这三处：

**第一处：它怎么算“星期几”**

可能看到：

```javascript
const weekdays = ["星期日", "星期一", "星期二", "星期三", "星期四", "星期五", "星期六"];
const weekday = weekdays[date.getDay()];
```

**`getDay()` 返回什么：**
返回 `0` 到 `6`。`0` 是星期日，`1` 是星期一……**注意：是从星期日开始的，不是星期一。** 这是第二个新手常踩的坑。

**第二处：它怎么算“7 天以内”**

可能看到：

```javascript
const diffDays = Math.floor((now - date) / (1000 * 60 * 60 * 24));
if (diffDays > 0 && diffDays < 7) {
```

**这块在干什么：**
两个日期相减得到毫秒数，除以 `1000*60*60*24` 换算成天。

**这里有个坑：**
这样算出来的是“24 小时的整数倍”，不是“日历天”。如果是昨天 23:00 和今天 01:00，只差 2 小时，`diffDays` 是 0，可能被误判成今天。**先记住这个坑，第 5 节课会专门讲。**

**第三处：它有没有动你原来的逻辑**

用眼睛找 `今天`、`昨天`、`getFullYear` 这几个词，看原来的判断还在不在。

**注意：这一步不是“把新代码贴进去覆盖旧代码”。**

1. 你整段覆盖一次，就永远不知道自己改了什么；

3. 覆盖会把你原来正确的部分也一起换掉，出问题你查不出来。

**操作：**

4. 手动把“多出来的那几行”敲进你的文件里。
5. 如果它改了原有的某一判断，你自己决定要不要接受（对照你的要求）。
6. `Ctrl + S` 保存。
7. 运行 `node try.js`。

**一个判断标准：**

```text
如果它给你的新代码和你原来的代码有 80% 是一样的，

```


# 第 5 步：学会判断回答里的三个危险信号（10 分钟）

## 5.1 信号一：出现省略号

**看起来像这样：**

```javascript
function formatTime(value) {
  // ... 前面的代码不变 ...
  const weekday = weekdays[date.getDay()];
  // ... 后面的代码不变 ...
}
```

**为什么危险：**
这不是能跑的代码。你粘过去，语法直接报错。它这么做是因为“省字数”。

**怎么处理：**
直接回一句：

```text
请不要用省略号或“代码不变”代替代码。我需要完整可以复制运行的文件内容。
```

## 5.2 信号二：它自作主张加了新东西

**看起来像这样：**
你说加星期，结果它顺手加了“相对时间（3小时前）”，还引入了一个日期库。

**为什么危险：**
你没要的功能，将来出问题你要多查一处。装库还多一个依赖。

**怎么处理：**

```text
我只要求增加星期显示。你额外加入了相对时间显示和第三方库，这超出了我的限制。
请去掉这两项，只保留星期显示。
```

## 5.3 信号三：它说“已完成”，但没给证据

**看起来像这样：**

```text
我已经为你加上了星期显示功能，现在可以正确工作了。
```

**为什么危险：**
“正确工作”是它的判断，不是事实。

**怎么处理：**

```text
请不要只说“已完成”。请逐条对照我给的 7 条验收，写成表格：
每条写“通过/不通过”，并写出实际输出。
```

## 5.4 三个信号总结

```text
出现省略号   → 要完整代码
自作主张加东西 → 要它去掉
只说完成不给证据 → 要逐条对照验收
```

**这三句话背下来。** 后面每节课都会用到。

# 附：常见问题速查

| 情况 | 原因 | 怎么做 |
|---|---|---|
| 它给的代码有 `...` | 它在省字数 | 明确要求“给完整可运行文件内容” |
| 它把今天/昨天逻辑改了 | 你没写“不许改动” | 在限制里写“不改变现有 4 条规则” |
| 星期显示成 `Wed` | 你没要求中文 | 在要求里写“用中文星期三” |
| 星期显示差一天 | `getDay()` 从星期日开始 | 记住 0=星期日，数组要从星期日排起 |
| 8 天前显示成星期 | 天数判断边界写错 | 用“预期 / 实际 / 只改这一处”的格式反馈 |
| 加完功能坏输入崩了 | 回归错误 | 每次加功能后重跑全部坏输入测试 |
| `prompts.md` 打不开正常显示 | 存成了 `.txt` | 开扩展名显示后重命名 |
| 找不到 `try.backup.js` | 复制到了别的目录 | 回到第 01 节课 `03-练习代码` 找 |
| 终端 `cd` 不进去 | 路径有中文和空格 | 把文件夹拖进终端自动填路径 |
| `node try.js` 报“找不到文件” | 终端不在该目录 | 先 `cd` 再运行 |
