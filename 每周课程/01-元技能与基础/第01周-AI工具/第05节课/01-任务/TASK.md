# 第 4 步：逐行读懂这段新代码（15 分钟）

## 4.1 为什么要逐行读

因为**你要为这段代码负责**。它跑错了，是你没检查，不是它的错。

## 4.2 逐行拆

### 第 1 行

```javascript
const isNegative = yuan < 0;
```

**在干什么：** 先记下是不是负数。

**为什么要先记：**
因为后面要对金额取绝对值来做千分位。取了绝对值，符号就丢了，所以要先存起来。

### 第 2 行

```javascript
const abs = Math.abs(yuan).toFixed(2);
```

**在干什么：**

- `Math.abs(-1234.5)` → `1234.5`（取绝对值）；
- `.toFixed(2)` → `"1234.50"`（固定两位小数，变成字符串）。

**注意：** `toFixed` 返回的是**字符串**，不是数字。后面都是字符串操作。

### 第 3 行

```javascript
const parts = abs.split(".");
```

**在干什么：** 用 `.` 切开字符串。

- `"1234.50"` → `["1234", "50"]`

**为什么要切：**
因为千分位只加在整数部分，小数点后面不加。

### 第 4 行（最关键的一行）

```javascript
const integerPart = parts[0].replace(/\B(?=(\d{3})+(?!\d))/g, ",");
```

**这一行是三个东西拼起来的：**

1. `parts[0]` —— 整数部分，比如 `"1234"`；
2. `.replace(正则, ",")` —— 把匹配到的位置换成逗号；
3. 正则 `/\B(?=(\d{3})+(?!\d))/g` —— 决定“在哪里插逗号”。

**拆正则：**

| 部分 | 含义 |
|---|---|
| `\B` | 不在单词边界的位置（也就是数字中间，不是开头也不是结尾） |
| `(?=...)` | 向后看，要求后面满足括号里的条件，但**不消耗字符** |
| `(\d{3})+` | 后面是 3 的倍数的数字 |
| `(?!\d)` | 再往后不能还是数字 |
| `g` | 全部替换，不只第一个 |

**合起来读：**

> 在“后面刚好是 3 个、6 个、9 个数字”的位置，插入一个逗号。

**为什么这样写能对：**

- `"1234"`：从右往左数，`4` 前面是 `234`（3 个数字）→ 插逗号 → `"1,234"`；
- `"128000"`：`000` 前插一个，`128` 前再插一个 → `"128,000"`。

**如果你觉得正则太难：**
先记住它的作用，不必现在就会写。**但你必须知道“它在这里干什么”**，不然出问题你不知道往哪查。

### 第 5 行

```javascript
const decimalPart = parts[1];
```

**在干什么：** 取小数部分 `"50"`。

### 第 6 行

```javascript
return (isNegative ? "-" : "") + "¥" + integerPart + "." + decimalPart;
```

**在干什么：** 拼起来。

- 负数 → `-¥1,234.50`
- 正数 → `¥1,234.50`

**注意符号位置：** 是 `-¥` 不是 `¥-`。这是财务规范。

# 第 7 步：学会看 diff（15 分钟）

## 7.1 为什么要看 diff

因为**你以为你只改了三行，实际上可能不是**。

编辑器可能顺手做了什么，工具可能多插了空行，你粘贴时可能少了一行。

## 7.2 用编辑器的对比功能

**操作（Visual Studio Code）：**

1. 在左侧文件列表里，右键点 `report.before.js`。
2. 选“选择以进行比较”。
3. 再右键点 `report.js`。
4. 选“与已选项目进行比较”。

**屏幕上会出现左右两栏：**

- 左边是改前；
- 右边是改后；
- 绿色表示新增的行；
- 红色表示删除的行。

## 7.3 你要检查的四件事

### 检查一：改动行数对不对

**这次应该只有 1 处改动区域**（就是 `formatAmount` 那三行变成六行）。

如果看到别的地方也有绿色或红色，**说明你改多了**。

### 检查二：改动内容对不对

左边的：

```javascript
return yuan.toFixed(2) + " 元";
```

右边的：

```javascript
const isNegative = yuan < 0;
const abs = Math.abs(yuan).toFixed(2);
const parts = abs.split(".");
const integerPart = parts[0].replace(/\B(?=(\d{3})+(?!\d))/g, ",");
const decimalPart = parts[1];
return (isNegative ? "-" : "") + "¥" + integerPart + "." + decimalPart;
```

**这就是预期的一处替换。**

### 检查三：有没有意外的空白变化

有时候你粘贴时会带入多余空格或空行。虽然不影响运行，但会让以后看 diff 时很乱。

### 检查四：文件末尾有没有多空行

很多编辑器会自动加一个空行。不是大问题，但要知道。

## 7.4 用命令看 diff（可选，但很有用）

如果电脑装了 Git，在 `03-练习代码` 里运行：

```text
git diff --no-index report.before.js report.js
```

**屏幕上会出现类似：**

```text
@@ -11,7 +11,12 @@ function buildReport(sales) {
...
-  return yuan.toFixed(2) + " 元";
+  const isNegative = yuan < 0;
+  const abs = Math.abs(yuan).toFixed(2);
...
```

**读法：**

- `-` 开头的行：被删掉的；
- `+` 开头的行：新加的；
- 空格开头的行：没变的；
- `@@ -11,7 +11,12 @@`：改前从第 11 行开始 7 行，改后从第 11 行开始 12 行。

**`git diff` 是程序员每天用的东西。今天先认识一下，第 4 周会专门讲 Git。**

# 第 8 步：改坏了怎么办（10 分钟）

## 8.1 先故意改坏一次

**操作：**

1. 在 `report.js` 的 `formatAmount` 里，把 `parts[1]` 改成 `parts[2]`。
2. 保存，运行。

**你会看到：**

```text
华东：¥128,000.undefined
```

**为什么：**
`"128000.00".split(".")` 只有两个元素 `["128000", "00"]`，`parts[2]` 不存在，是 `undefined`。

**注意：程序没报错，但输出是错的。** 这种错最危险——它不崩，只是默默地错。

## 8.2 三种回退方式

### 方式一：撤销（最简单）

按 `Ctrl + Z`。

**适用：** 刚刚改的，还在编辑器里。

**缺点：** 关了文件就没了。

### 方式二：从备份恢复

**操作：**

1. 打开 `report.before.js`，全选复制；
2. 打开 `report.js`，全选，粘贴；
3. 保存。

**适用：** 改了一大堆，撤销不回去了。

**缺点：** 你备份之后做的所有正确改动也一起丢了。

### 方式三：只回退那一处

**操作：**

1. 打开 diff 对比；
2. 找到那一处改动；
3. 手动改回来。

**适用：** 只坏了一处，其他地方是好的。

**这是最精确的方式。**

## 8.3 三种方式怎么选

```text
只改了一行，马上就发现 → 用撤销
改了很多，整体都坏了   → 用备份
只有一处不对，其他都好 → 手动改回那一处
```

## 8.4 最后一个办法：问工具

```text
我把 parts[1] 改成了 parts[2]，现在输出变成 ¥128,000.undefined。
请只告诉我应该改回什么，不要给我整个文件。
```

**注意：** 这个办法是最后手段。前三个办法你自己就能做，更快。

## 8.5 把这次改坏记下来

在 `NOTES.md` 里：

```text
我故意把 parts[1] 改成 parts[2]，结果输出变成 undefined。
程序没有报错，但结果是错的。
这告诉我：不报错不等于对，必须每次改完都跑一遍看输出。
```

# 附：常见问题速查

| 情况 | 原因 | 怎么做 |
|---|---|---|
| 改完输出多了 `undefined` | 访问了不存在的数组元素 | 检查 `parts[1]` 这类索引 |
| 千分位没生效 | 正则写错或没加 `/g` | 先单独测 `"1234".replace(...)` |
| 函数名被改了 | 要求里没写“不要改名” | 明确写进限制 |
| 调用处也被改了 | 要求里没写“不改调用处” | 明确写进限制 |
| diff 里一堆意外改动 | 粘贴时带入了整段代码 | 只替换那几行，别整段覆盖 |
| `toFixed` 结果不对 | 它做四舍五入 | 金额应在“分”级别算好，显示不再舍入 |
| 备份文件打不开 | 存成了 `.bak` | 用 `.js` 扩展名 |
| 改完跑不起来 | 括号/引号没配平 | 按第 4 节课方法读报错 |
| 撤销不回去了 | 已关闭文件 | 从 `.before.js` 恢复 |
| 负数显示成 `¥-1,234` | 符号位置拼错 | 财务规范是 `-¥1,234` |
| 大额数字显示异常 | 超过 `Number` 安全整数范围 | 大金额要用字符串或 BigInt 处理 |
