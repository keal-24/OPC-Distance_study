## 1.2 自己敲这段代码

**规矩：一个字一个字敲，不许复制粘贴。**

**为什么这节课特别要求手敲：**

这节课练的是“读代码”。**读不懂的代码，你敲一遍就会懂一半。** 因为敲的时候你必须看清每个符号、每个括号、每个引用，而复制粘贴你可以完全没有意识。

**分段敲，每段敲完保存一次：**

### 第 1 段：规则表和折扣函数

```javascript
// 订单折扣计算（练习用，不涉及真实支付）

const RULES = [
  { minYuan: 500, rate: 0.2 },
  { minYuan: 200, rate: 0.1 },
  { minYuan: 100, rate: 0.05 },
];

function discountRate(totalCents) {
  for (const rule of RULES) {
    if (totalCents >= rule.minYuan * 100) {
      return rule.rate;
    }
  }
  return 0;
}
```

**敲的时候注意三件事：**

- `minYuan` 和 `rate` 后面是冒号，不是等号；
- `minYuan * 100` 这里的 `100` 是“元换分”；
- `return 0` 是在 `for` 循环**外面**，缩进要和 `for` 对齐。

### 第 2 段：算总价的主函数

```javascript
function finalPrice(items, isMember) {
  const totalCents = items.reduce((sum, item) => sum + item.priceCents * item.qty, 0);
  const rate = discountRate(totalCents);
  const discounted = Math.round(totalCents * (1 - rate));
  const shipping = discounted >= 9900 ? 0 : 600;
  const memberCut = isMember ? Math.round(discounted * 0.02) : 0;

  return {
    totalCents,
    rate,
    discounted,
    shipping,
    memberCut,
    payable: discounted + shipping - memberCut,
  };
}
```

**敲的时候注意：**

- `reduce((sum, item) => ..., 0)` 最后那个 `, 0` 是初始值，别漏；
- 两个 `? :` 三元运算符，问号和冒号都要有；
- `return { ... }` 里面每项后面是逗号。

### 第 3 段：格式化函数和测试数据

```javascript
function yuan(cents) {
  return `¥${(cents / 100).toFixed(2)}`;
}

const orderA = [
  { name: "笔记本", priceCents: 2990, qty: 2 },
  { name: "中性笔", priceCents: 350, qty: 3 },
];

const orderB = [{ name: "台灯", priceCents: 12900, qty: 1 }];
```

**注意 `yuan` 里那个反引号 `` ` ``，还有 `${}`。** 这是模板字符串，只能用反引号，用单引号或双引号都不生效。

### 第 4 段：四行输出

```javascript
console.log("订单 A：", finalPrice(orderA, false));
console.log("订单 B：", finalPrice(orderB, true));
console.log("A 的应付：", yuan(finalPrice(orderA, false).payable));
console.log("B 的应付：", yuan(finalPrice(orderB, true).payable));
```

**注意第三、四行的 `.payable`：** 它是从返回的对象里取一个字段。

# 第 3 步：四步法第二招——看数据长什么样（15 分钟）

## 3.1 数据是这段代码的“原料”

先别看逻辑，先看数据。因为逻辑都是围着数据转的。

## 3.2 逐个看清楚

### 数据一：`RULES`

```javascript
const RULES = [
  { minYuan: 500, rate: 0.2 },
  { minYuan: 200, rate: 0.1 },
  { minYuan: 100, rate: 0.05 },
];
```

**用话读出来：**

> 这是一个列表，里面有三条折扣规则。
> 第一条：满 500 元，打 8 折（减 20%）。
> 第二条：满 200 元，减 10%。
> 第三条：满 100 元，减 5%。

**关键观察：顺序是从大到小排的。** 这个顺序很重要，第 4 步会讲为什么。

### 数据二：`orderA`

```javascript
const orderA = [
  { name: "笔记本", priceCents: 2990, qty: 2 },
  { name: "中性笔", priceCents: 350, qty: 3 },
];
```

**用话读出来：**

> 订单 A 有两件商品。
> 笔记本：单价 2990 分（29.9 元），买 2 本。
> 中性笔：单价 350 分（3.5 元），买 3 支。

**注意 `priceCents` 这个名字：**

### 数据三：`orderB`

```javascript
const orderB = [{ name: "台灯", priceCents: 12900, qty: 1 }];
```

**用话读出来：**

> 订单 B 只有一件：台灯，单价 12900 分（129 元），买 1 件。

# 第 4 步：四步法第三招——找岔路口（25 分钟）

## 4.1 什么叫“岔路口”

代码里让程序“根据条件走不同路”的地方：

- `if`、`else`；
- 三元运算符 `? :`；
- `for`、`while` 循环里的判断；
- `return` 提前结束。

**岔路口是 bug 最爱藏的地方。**

## 4.2 逐个读四个岔路口

### 岔路口 1：`discountRate` 里的 `for` + `if`

```javascript
function discountRate(totalCents) {
  for (const rule of RULES) {
    if (totalCents >= rule.minYuan * 100) {
      return rule.rate;
    }
  }
  return 0;
}
```

**逐行读：**

| 行 | 在读什么 |
|---|---|
| `for (const rule of RULES)` | 从第一条规则开始，一条一条试 |
| `if (totalCents >= rule.minYuan * 100)` | 如果金额 ≥ 这条规则的门槛（元×100 换成分） |
| `return rule.rate` | 立刻返回这条规则的折扣率，**不再继续试后面的** |
| `return 0` | 三条都没满足，返回 0（不打折） |

**这里有个必须看懂的点：`return` 会立刻跳出整个函数。**

因为规则是从大到小排的，第一条先试“满 500”。如果满足，直接给 20%，不会再去看“满 200”。**这个顺序如果反过来排，所有人都会只拿到 5%。**

**现在就验算：**

- 订单 A 合计 7030 分 = 70.3 元 → 不到 100 → 三条都不满足 → 返回 `0`，**不打折**。
- 订单 B 合计 12900 分 = 129 元 → 满 100 但不满 200 → 命中第三条 → 返回 `0.05`。

### 岔路口 2：运费判断

```javascript
const shipping = discounted >= 9900 ? 0 : 600;
```

**这是三元运算符，读法是：**

```text
条件 ? 条件成立时的值 : 条件不成立时的值
```

**用话读出来：**

> 如果折后金额 ≥ 9900 分（99 元），运费 0；否则运费 600 分（6 元）。

**验算：**

- 订单 A 折后 7030 分 → 不到 9900 → 运费 600 分（6 元）。
- 订单 B 折后 12900 × 0.95 = 12255 分 → ≥ 9900 → 运费 0。

### 岔路口 3：会员优惠

```javascript
const memberCut = isMember ? Math.round(discounted * 0.02) : 0;
```

**用话读出来：**

> 如果是会员，再减折后金额的 2%；不是会员就是 0。

**验算：**

- 订单 A：`isMember = false` → `memberCut = 0`。
- 订单 B：`isMember = true` → `Math.round(12255 × 0.02) = Math.round(245.1) = 245` 分。

### 岔路口 4：`yuan` 函数里的小数处理

```javascript
function yuan(cents) {
  return `¥${(cents / 100).toFixed(2)}`;
}
```

**逐行读：**

- `cents / 100`：分转成元；
- `.toFixed(2)`：保留两位小数，不足补 0；
- 外层反引号：拼成一个字符串。

**为什么需要 `toFixed(2)`：**
因为 `7030 / 100` 得到 `70.3`，显示成 `¥70.3` 不规范，要显示 `¥70.30`。

## 4.3 填一张“分支表”

在 `predict.md` 里写：

```markdown
## 分支表

| 岔路口 | 条件 | 条件成立做什么 | 不成立做什么 |
|---|---|---|---|
| discountRate 循环 | 金额 ≥ 门槛 | 返回该档折扣率并结束 | 试下一档；都不满足返回 0 |
| 运费 | 折后 ≥ 9900 分 | 运费 0 | 运费 600 分 |
| 会员优惠 | isMember 为真 | 减折后 2% | 0 |
| yuan | 总是 | 除以 100 并保留两位小数 | 无 |
```

**这张表填不出来，说明你还没读懂。** 回去重读 4.2。

# 第 7 步：读懂之后，改一处，看后果（15 分钟）

## 7.1 现在你已经敢改了

因为你知道每一行在干什么。接下来做一个实验，验证你的理解。

## 7.2 实验一：把规则顺序反过来

**操作：**

1. 找到 `RULES`，把三条顺序倒过来，变成：

   ```javascript
   const RULES = [
     { minYuan: 100, rate: 0.05 },
     { minYuan: 200, rate: 0.1 },
     { minYuan: 500, rate: 0.2 },
   ];
   ```

2. 保存，运行。
3. 看订单 B 的 `rate` 变成了多少。

**你会看到：** 订单 B 的 `rate` 还是 `0.05`，似乎没变。

**为什么没变？** 因为订单 B 是 129 元，正常该拿 5%；顺序反了以后先命中“满 100”那一档，也是 5%。**碰巧一样。**

**要做更明显的验证：** 在文件最后临时加一笔 600 元的订单：

```javascript
const orderC = [{ name: "显示器", priceCents: 60000, qty: 1 }];
console.log("订单 C（顺序反转后）：", finalPrice(orderC, false).rate);
```

运行，你会看到 `rate: 0.05`。

**但正确答案应该是 0.2（20%）。** 因为 600 元满 500 了。

**这就证明了：`return` 会立刻结束整个函数，所以规则必须从大到小排。** 顺序反了，大额订单会按最低档打折，公司每笔都少收钱。

**在 `predict.md` 里加一行：**

```markdown
## 实验一：顺序反过来

结论：____（写你观察到的）
为什么：因为 `return` 会立刻结束函数，规则从大到小排才能让人拿到最高档。
```

**改完记得改回来**（`Ctrl + Z` 撤销，或重新粘贴原始顺序）。

## 7.3 实验二：把 `Math.round` 改成 `Math.floor`

**操作：**

1. 找到：

   ```javascript
   const memberCut = isMember ? Math.round(discounted * 0.02) : 0;
   ```

2. 把 `Math.round` 改成 `Math.floor`。
3. 保存，运行。
4. 看订单 B 的 `memberCut`。

**你会看到：** `245` 变成 `245`（因为 245.1 向下取整还是 245）。

**再试一个能看出差别的：** 把 `0.02` 改成 `0.03`：

- `Math.round(12255 × 0.03) = Math.round(367.65) = 368`
- `Math.floor(12255 × 0.03) = Math.floor(367.65) = 367`

**差 1 分。** 一分钱在电商里是大问题——对不上账。

**在 `predict.md` 里加：**

```markdown
## 实验二：round 和 floor

round 是四舍五入，floor 是直接砍掉小数。
在金额计算里，差 1 分就会导致对账对不上。
所以我以后写金额，必须明确说清用哪种取整方式。
```

**改完改回 `0.02` 和 `Math.round`。**

function gradeOf(score) {
  if (score >= 90) return "A";
  if (score >= 80) return "B";
  if (score >= 60) return "C";
  return "D";
}

function averageOf(scores) {
  if (scores.length === 0) return 0;
  const sum = scores.reduce((acc, n) => acc + n, 0);
  return sum / scores.length;
}

const classA = [95, 82, 58, 74];
const avg = averageOf(classA);
console.log("平均分：", avg);
console.log("等级：", gradeOf(avg));

# 附：常见问题速查

| 情况 | 原因 | 怎么做 |
|---|---|---|
| 输出里金额是小数 | 用了元做单位 | 金额统一用整数分，显示时再除 100 |
| 所有人都只拿到最低折扣 | `RULES` 顺序从小排到大 | 从大到小排，靠 `return` 提前结束 |
| 折后金额出现 `.999999` | 浮点误差 | 用整数分计算，最后再转元 |
| `memberCut` 差 1 分 | `round` 和 `floor` 不同 | 明确业务规则要哪种取整 |
| `toFixed` 返回字符串 | 它是字符串方法 | 只用于显示，不要拿去再参与运算 |
| 空订单收了运费 | 业务规则如此 | 记下来问业务方，不要自己改 |
| `reduce` 报错 “of undefined” | 没给初始值且数组为空 | 加初始值 `, 0` |
| 预测和实际不一致 | 漏看某一行分支 | 回到岔路口表逐行核对 |
| 中文输出乱码 | 终端编码 | 用 VS Code 内置终端 |
