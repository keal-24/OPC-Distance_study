# 第 0 步：先准备好桌面（5 分钟）

## 0.1 你需要一台什么样的电脑

- Windows 电脑（本课以 Windows 10 / Windows 11 为例）；
- 能上网；
- 键盘上有 `Ctrl` 键、`Shift` 键、`Enter` 键（回车键）。

本课截图和路径都按 Windows 写。如果你用的是苹果电脑，路径写法不同，但步骤逻辑一样。

## 0.2 你需要打开的三个东西

本课会用到三个窗口，先把它们的位置记住：

| 名称 | 它是什么 | 本课用它做什么 |
|---|---|---|
| 文件资源管理器 | Windows 自带的管理文件夹的工具，图标像一个黄色文件夹 | 找到课程文件夹、新建文件 |
| WorkBuddy | 人工智能对话工具 | 问概念、检查回答 |
| 代码编辑器（Visual Studio Code） | 专门用来看和写代码的软件 | 打开 `try.js`、保存代码 |

> **名词解释：代码编辑器**
> 普通的记事本也能存文字，但它不会给代码上色、不会提示行号。代码编辑器会把不同的代码部分染成不同颜色，并且左边显示行号，出错时方便我们对行号。

## 0.3 打开文件资源管理器

**操作：**

1. 把鼠标移到屏幕最下方的任务栏。
2. 找到一个**黄色文件夹图标**，它通常叫“文件资源管理器”。
3. 用鼠标**左键单击一次**（左键就是平时点东西的那个键）。

**屏幕上应该看到：**
一个窗口弹出来，左边有一列“此电脑”“桌面”“下载”等文字，右边是一片空白或一些文件夹。

**如果找不到黄色文件夹图标：**

1. 按键盘上的 `Win` 键（在 `Ctrl` 和 `Alt` 中间，图标是四个方块）。
2. 直接打字输入：`资源管理器`
3. 按 `Enter` 键。
4. 如果弹出搜索结果，用鼠标左键点第一项。

## 0.4 学会看“地址栏”在哪里

**操作：**

1. 看文件资源管理器窗口的**最上面一条**。
2. 你会看到一条长长的白框，里面可能写着“此电脑”或一个路径。
3. 这一条叫**地址栏**。

**为什么要认识它：**
后面我会让你“把路径粘贴到地址栏”。路径就是文件夹的位置，例如 `B:\OPC-Distance_study`。把它粘到地址栏再按回车，就能直接跳到那个文件夹，不用一层一层点。

**自己练一次：**

1. 用鼠标左键**单击**地址栏里的文字区域。
2. 里面的文字会变成蓝色（表示被选中）。
3. 按键盘上的 `Esc` 键取消选择。

能做到“点一下变蓝”就说明你找对位置了。

# 第 2 步：先弄懂四个词（20 分钟）

## 2.1 为什么要先学词

后面每一节课都会出现这几个词。如果现在跳过，你会一直似懂非懂。

**学习方式：** 每个词我都按“它是什么 → 生活里像什么 → 它不能做什么”三步讲。你不需要背英文，只需要能用中文说清楚。

## 2.2 第一个词：人工智能

**它是什么：**
人工智能是一个总称。意思是让电脑去完成一些本来需要人来理解、判断、或者创造内容的工作。

**生活里像什么：**
像一个读了很多书、反应很快，但**不了解你具体情况**的实习生。

**它能做的例子：**

- 你给一段文字，它帮你改写得更通顺；
- 你描述一个需求，它写出一段代码；
- 你把报错贴给它，它解释大概哪里错了。

**它不能做的事：**

- 它不知道你公司真实的账目；
- 它不知道你的密码能不能用；
- 它做错了不会替你赔钱。

**所以本节课的第一条规则：**

> 人工智能负责“生成”，你负责“判断能不能用”。

## 2.3 第二个词：LLM（大语言模型）

**先看英文，不要怕：**
`LLM` 是三个英文单词的缩写，中文叫**大语言模型**。本节课你只要记中文名，英文看到能认出来就行。

**它是什么：**
它是人工智能里面**专门处理文字**的那部分能力。你给它文字，它给你文字。

**生活里像什么：**
像一个极其擅长写字的人。你口述要求，他写出来。但他写的东西你要读一遍，因为他可能写得很通顺，内容却是错的。

**举个例子：**

你输入：

```text
请把“程序运行失败”改成对普通用户更友好的一句话。
```

它可能返回：

```text
暂时没能完成，请稍后再试。
```

这里：

- 你输入的那句话叫**输入**；
- 它返回的那句话叫**输出**。

**为什么必须检查：**
因为它写得很像真的。通顺 ≠ 正确。代码也是，看起来完整，但可能少一个条件、算错一个数。

## 2.4 第三个词：Agent（智能体）

**中文名：** 智能体。

**它是什么：**
普通聊天是“你问一句，它答一句”。智能体是：**你给它一个目标，它自己拆成好几步，还可能去调用工具，最后把结果交给你。**

**生活里像什么：**

- 普通聊天 = 你问路，对方告诉你往哪走；
- 智能体 = 你叫一个跑腿的人，他自己规划路线、坐车、取东西、回来交给你。

**举个例子：**
你说：

```text
把这个文件夹里所有表格的金额加起来，生成一份汇总。
```

智能体可能这样干：

```text
第 1 步：打开文件夹
第 2 步：逐个读取表格
第 3 步：提取金额
第 4 步：计算总数
第 5 步：写出汇总文件
```

**为什么更要小心：**
因为它能干的事多，所以出事也大。它可能一次改掉十几个文件。

**本节课的安全规则：**

> 只要涉及**删除文件、改数据库、发消息、花钱、发布上线**，必须停下来人工确认。

## 2.5 第四个词：MCP

**先看英文：**
`MCP` 是 `Model Context Protocol` 的缩写，中文可以先理解成**模型连接工具的协议**。“协议”就是大家约定好的一套对接规则。

**它是什么：**
它是让人工智能**用统一的方式连接外部工具**的一种方法。

**生活里像什么：**

```text
大语言模型 = 会思考的助手
MCP = 统一的插座和插头
文件、浏览器、数据库 = 不同的电器
```

助手的脑子再好，没有插座也开不了电器。接上插座，助手才能真的去读你的文件、查你的数据库。

**为什么它是重点，又为什么危险：**

- 重点：没有它，人工智能只能“说”，不能“做”；
- 危险：能做了以后，它就可能真的删掉你的东西。

**所以记住这句话：**

```text
能连接工具 ≠ 可以随便操作工具
```

## 2.6 四个词连起来看

```text
人工智能       → 总称，让电脑参与理解和生成
LLM 大语言模型 → 里面专门处理文字的那部分能力
Agent 智能体   → 围绕目标分多步做事的方式
MCP           → 让它能连上外部工具的统一接口
```

## 2.7 马上自测（不要看上面）

拿一张纸或打开记事本，用你自己的话写三句：

1. LLM 是干什么的？
2. 智能体和普通聊天差在哪？
3. MCP 明明能连工具，为什么还要人工确认？

写不出来就回到 2.3、2.4、2.5 重读一遍。**这一步不能跳。**

# 第 3 步：认识你要用的两个工具（15 分钟）

## 3.1 为什么要分两个工具

因为它们管的事不一样。混着用会让你不知道自己在干什么。

```text
WorkBuddy：帮你想清楚、讲清楚、解释清楚
Codex    ：进入代码文件夹，把代码写出来、跑起来
你       ：说清楚要求、允许或拒绝操作、检查结果
```

## 3.2 WorkBuddy 怎么打开、怎么发第一句话

**操作：**

1. 找到 WorkBuddy 的图标（桌面或任务栏），左键单击打开。
2. 等它加载完，你会看到一个对话窗口。
3. 看窗口**最下方**，有一个长条形的输入框，里面通常有浅色提示文字，例如“输入你的问题”。
4. 用左键**单击这个输入框**，光标会在里面闪。
5. 输入下面这句话（可以直接复制粘贴）：

```text
请用完全不懂编程的人能听懂的话解释“代码”是什么，不要使用新的专业词。
```

6. 发送方式二选一：
   - 按 `Enter` 键；
   - 或用左键点输入框右侧的发送按钮（通常是圆形或箭头图标）。
7. **等它回答完再操作**，不要在它还在输出时反复按发送。

**屏幕上应该看到：**
你的问题出现在对话上方，下面逐字出现它的回答。

**如果按 `Enter` 只是换行没有发送：**
说明这个工具的 `Enter` 是换行键。改用 `Ctrl + Enter`，或者直接点发送按钮。

**如果提示需要登录：**
先完成登录再继续。登录时不要把密码发到任何对话框里。

## 3.3 WorkBuddy 用完之后要记住的一件事

它的回答是**参考**，不是结论。尤其涉及数字、权限、删除、钱，一定自己核对。

## 3.4 Codex 怎么打开一个项目

> **名词解释：项目**
> 在这门课里，“项目”就是一个装着代码文件的文件夹。打开项目 = 告诉工具“我现在只在这个文件夹里干活”。

**操作：**

1. 打开 Codex。
2. 找到“打开项目 / Open Project / 选择文件夹”之类的入口并点击。
3. 在弹出的选择框里，把下面路径粘到文件名位置，或在左侧一层层找到它：

   ```text
   B:\OPC-Distance_study
   ```

4. 确认选择这个文件夹（不是它里面的某一个文件）。
5. 等左侧出现文件列表。

**屏幕上应该看到：**
左侧一列文件和文件夹名字，例如 `参考手册`、`每周课程`、`README.md`。

**然后发一句只读的指令：**

```text
请告诉我当前打开的项目文件夹完整路径，只回答路径，不要修改任何文件。
```

**发送后如果有权限询问：**
先读它写了什么。只要它只是想“读取”，可以允许。**今天不允许它修改、删除任何文件。** 不确定就点取消。

## 3.5 如果还没有 Codex

不影响本节课。今天真正要交付的是 `try.js`，你可以用 WorkBuddy + 代码编辑器完成。Codex 的安装和使用会在后面的课单独讲。

# 第 4 步：学会把要求说清楚（20 分钟）

## 4.1 为什么同一句话结果差别很大

你只写“写一个日期程序”，它只能猜：猜你要什么格式、猜错了怎么办、猜用不用装东西。

要求写得越清楚，你要检查的地方就越少。这不是技巧，是省时间。

## 4.2 五个格子

以后每次让人工智能写东西，按这五格写：

```text
① 背景  ② 任务  ③ 要求  ④ 限制  ⑤ 验收
```

### ① 背景：现在是什么情况

写清你的水平、已有条件、不想用什么。

```text
我正在学习 JavaScript，这是第一次做日期练习，暂时不安装额外代码库。
```

> **名词解释：JavaScript**
> 一种编程语言，网页和很多工具都用它。本课用它写这段小程序。你不需要现在学整门语言。

### ② 任务：这次到底做什么

一句话说清核心工作。

```text
请写一个名为 formatTime 的函数，把日期文字转换成中文显示文字。
```

> **名词解释：函数**
> 一段可以反复使用的小程序。你给它一个东西（输入），它处理完还你一个结果（返回）。

### ③ 要求：必须具备什么行为

写成一条一条，像清单，越具体越好。

```text
如果是今天，显示“今天 12:30”
如果是昨天，显示“昨天 12:30”
如果是今年其他日期，显示“11月16日 12:30”
如果不是今年，显示“2025年11月16日”
如果输入为空或不是日期，显示“未知时间”
```

### ④ 限制：不允许做什么

```text
只用 JavaScript 自带功能，不安装任何东西
只改我指定的这一个文件
不要动我的其他文件
```

### ⑤ 验收：怎么算做对

```text
请给出 6 组测试：今天、昨天、今年其他日期、去年日期、空文字、乱写的文字
每组都写出预期结果
```

## 4.3 用买水再理解一遍

```text
背景：我在办公室，手边没水
任务：帮我买一瓶水
要求：常温、无气泡
限制：不超过 3 元，不要玻璃瓶
验收：拿回来我看温度、气泡、价格、瓶子
```

只说“买水”，对方可能买冰的、带气的、玻璃瓶的、8 块的。写代码一模一样。

## 4.4 现在动手写一遍（不要抄上面的）

打开 `02-笔记` 文件夹，新建 `NOTES.md`（具体怎么新建见第 9 步，这里先写在纸上或记事本里也行）。

用你自己的话写这五行：

```text
背景：
任务：
要求：
限制：
验收：
```

写不出来没关系，第 5 步会给你完整范例对照。

# 第 5 步：先看一次“说得太模糊”会怎样（10 分钟）

## 5.1 在 WorkBuddy 输入这句

```text
写一个日期格式化程序。
```

看着它的回答，逐个打勾：

- [ ] 它说了日期从哪里来吗？
- [ ] 它说了显示成什么样子吗？

# 第 6 步：发送完整要求（15 分钟）

## 6.1 完整复制下面这一整段

```text
背景：
我正在学习 JavaScript，这是我第一次练习让人工智能帮助我写小程序。我希望先使用 JavaScript 自带功能，不安装额外代码库。

任务：
请写一个名为 formatTime 的函数。它接收一段日期文字，返回一段容易阅读的中文时间文字。

要求：
1. 输入示例是 2026-11-16T12:30:00+08:00 这样的日期文字。
2. 如果日期是今天，返回类似“今天 12:30”。
3. 如果日期是昨天，返回类似“昨天 12:30”。
4. 如果日期属于今年但不是今天或昨天，返回类似“11月16日 12:30”。
5. 如果日期不属于今年，返回类似“2025年11月16日”。
6. 如果输入为空、不是日期或无法识别，返回“未知时间”。
7. 必须给出完整代码，不能用省略号代替代码。
8. 代码后用中文解释主要部分的作用。

限制：
1. 只使用 JavaScript 自带功能。
2. 不安装其他软件或代码库。
3. 只提供本节练习需要的代码，不修改其他文件。
4. 先解释思路，再给出完整代码。

验收：
请提供并说明至少六组测试：今天、昨天、今年的其他日期、去年的日期、空文字、完全不是日期的文字。每组测试都写出预期结果。
```

## 6.2 发送前逐个数

用眼睛从上往下扫，确认能看到这六个字：

```text
背景  任务  要求  限制  验收
```

少一个就补上，再发送。

## 6.3 发送

# 第 8 步：把完整代码写进去（15 分钟）

## 8.1 逐段理解，不要直接闭眼粘贴

下面这段代码我会分成 5 块讲，每块讲完你再往下看。**看不懂细节没关系，但要能说出每一块在干什么。**

### 第 1 块：函数开头和错误拦截

```javascript
function formatTime(value) {
  if (value === null || value === undefined || value === "") {
    return "未知时间";
  }
```

**这块在干什么：**

- `function formatTime(value)`：定义一个叫 `formatTime` 的函数，它接收一个东西，这个名字叫 `value`；
- `if (...)`：如果括号里的条件成立；
- `value === null || value === undefined || value === ""`：如果这个值是“空的”“没给的”“空字符串”；
- `return "未知时间"`：直接交回“未知时间”，不再往下算。

**为什么要这块：**
如果先不拦住空值，后面把空值当日期处理，程序就会出错。这是“先挡住明显的坏输入”。

### 第 2 块：把文字变成日期，并再拦一次坏输入

```javascript
  const date = new Date(value);
  if (Number.isNaN(date.getTime())) {
    return "未知时间";
  }
```

**这块在干什么：**

- `new Date(value)`：把传进来的文字尝试变成日期；
- 如果这段文字根本不是日期，得到的是一个“无效日期”；
- `Number.isNaN(date.getTime())`：检查它是不是无效；
- 无效就返回“未知时间”。

**为什么要两次拦截：**
第一次拦“根本没给东西”，第二次拦“给了但不是日期”。两种坏情况都要挡住。

### 第 3 块：准备“现在”的时间和补零工具

```javascript
  const now = new Date();
  const pad = (number) => String(number).padStart(2, "0");
  const time = `${pad(date.getHours())}:${pad(date.getMinutes())}`;
```

**这块在干什么：**

- `const now = new Date()`：取到此刻的时间，用来比较“今天”“昨天”；
- `pad`：把数字补成两位。`9` 变成 `09`，不然会显示 `9:5` 而不是 `09:05`；
- `time`：拼出 `时:分`，例如 `12:30`。

**为什么要补零：**
这是显示习惯。`12:5` 看起来像错的，`12:05` 才对。

### 第 4 块：判断今天、昨天

```javascript
  const sameDay = (left, right) =>
    left.getFullYear() === right.getFullYear() &&
    left.getMonth() === right.getMonth() &&
    left.getDate() === right.getDate();

  const yesterday = new Date(now);
  yesterday.setDate(now.getDate() - 1);

  if (sameDay(date, now)) {
    return `今天 ${time}`;
  }

  if (sameDay(date, yesterday)) {
    return `昨天 ${time}`;
  }
```

**这块在干什么：**

- `sameDay`：判断两个日期是不是同一天（年、月、日都相同）；
- `yesterday`：拿“现在”减一天，得到昨天；
- 如果输入是今天 → 返回“今天 12:30”；
- 如果输入是昨天 → 返回“昨天 12:30”。

**为什么不能直接比字符串：**
因为同一天可能写成不同格式。分别比年、月、日最稳。

### 第 5 块：今年其他日期、往年日期

```javascript
  if (date.getFullYear() === now.getFullYear()) {
    return `${date.getMonth() + 1}月${date.getDate()}日 ${time}`;
  }

  return `${date.getFullYear()}年${date.getMonth() + 1}月${date.getDate()}日`;
}
```

**这块在干什么：**

- 如果是今年但不是今天/昨天 → 显示“11月16日 12:30”；
- 否则（往年）→ 显示“2025年11月16日”，不带时分。

**为什么 `getMonth() + 1`：**
JavaScript 的月份从 0 开始算，0 代表 1 月。所以要加 1 才是人看的月份。**这是新手最常踩的坑之一。**

### 加上测试调用

# 第 10 步：专门测坏输入（10 分钟）

程序只处理正确输入不算合格。真实使用中，用户会乱填、会漏填。

## 10.1 已经有的三个坏输入

代码里已经有：

```javascript
console.log(formatTime(""));
console.log(formatTime("这不是日期"));
console.log(formatTime(null));
```

含义：

- `""`：什么都没输入；
- `"这不是日期"`：填了，但不是日期；
- `null`：表示没有这个值。

**期望结果：**都返回 `未知时间`，程序不崩。

## 10.2 你自己再加两个

在代码**最后面**加两行：

```javascript
console.log(formatTime("  "));
console.log(formatTime("2026-02-30"));
```

保存，重新运行。

**观察并记录：**

- `"  "`（两个空格）返回了什么？
- `"2026-02-30"` 返回了什么？2 月 30 日其实不存在，程序有没有发现？

把这两个真实结果写进 `NOTES.md`。**不要写“应该”，要写你屏幕上真实出现的。**

**先告诉你答案，别以为自己搞坏了：**

- `"  "` → 返回 `未知时间`（正确，空格被当成无效输入）；
- `"2026-02-30"` → 很可能会返回 `3月2日 08:00` 这样的结果。

**为什么 2 月 30 日会变成 3 月 2 日？**
这是 JavaScript 自带的日期规则：它不报错，而是自动“往后多出来的天数顺延”。2 月只有 28 或 29 天，多出来的 2 天就滚到 3 月了。

**这不是你写错了，是这个工具本身的脾气。** 知道这一点很重要：以后做订单日期、账单日期、报名截止时间，如果直接信它，用户填 2 月 30 日就会变成 3 月 2 日，账目就错了。

## 10.3 想一想

如果这两个坏输入的结果你不满意，说明程序还有改进空间。**这就是真实开发的常态：先能跑，再发现边界问题，再修。** 本课不要求你现在改到完美，但要求你能看出问题在哪。

**如果你想把 2 月 30 日也拦住，思路是这样的（本节不要求你改）：**
先检查这段文字是不是“年-月-日”格式，再把年、月、日拆出来，用月历规则核对这一天到底存不存在。存在才交给 `new Date` 处理。这个技巧会在后面的日期与表单校验课程里正式讲。

# 附：常见问题速查

| 你遇到的情况 | 原因 | 怎么做 |
|---|---|---|
| 地址栏粘路径后提示找不到 | 盘符或路径不存在 | 确认是 `B:\OPC-Distance_study`，别自己新建 |
| 新建的文件变成 `try.js.txt` | 没打开“文件扩展名”显示 | 第 7.2 步打开，再重命名 |
| 右键没有“新建文本文档” | 系统策略或精简版 | 用 Visual Studio Code `Ctrl + N` 再 `Ctrl + S` |
| 运行报 `'node' 不是内部或外部命令` | 没装 Node.js 或终端没重开 | 装好后**关掉终端重开** |
| 运行报“找不到模块 / 找不到文件” | 终端目录不对 | 用 `cd` 进到 `03-练习代码` 再跑 |
| 出现 `SyntaxError` | 括号、引号、分号写错 | 复制完整错误，按第 9.5 处理 |
| 出现 `ReferenceError` | 用了没定义的名字 | 检查拼写是否和函数名一致 |
| 前两行不是“今天” | 运行日期不是示例日期 | 正常现象，符合规则即可 |
| 后三行出现红色报错 | 空值处理没生效 | 检查第 1、2 块拦截代码在不在 |
| `2026-02-30` 显示成 3 月 2 日 | JavaScript 自动顺延不存在的日期 | 正常现象，见 10.2 说明，不是你的错 |
| 中文显示成乱码 | 终端编码问题 | 改用 Visual Studio Code 内置终端运行 |
| 保存后结果没变 | 没保存或跑错文件 | 确认标题栏无圆点，确认跑的是 `try.js` |
