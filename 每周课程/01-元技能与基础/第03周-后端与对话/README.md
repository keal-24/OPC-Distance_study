## 这一周有一个"假模型"

**第 20 节课提供了一个本地假模型（`src/mock-llm.js`），不需要密钥、不花钱。**

**为什么要这样设计：**

```text
① 你可能还没有密钥
② 你不想在调试错误处理时把额度烧光
③ 假模型能可控地制造"超时""500""HTML 错误页""空内容"四种异常
```

**这四种异常用真模型很难复现。** 而它们恰恰是上线后最容易出问题的地方。

**假模型有四个触发词：**

| 输入包含 | 行为 |
|---|---|
| `慢` | 8 秒后才回复（测超时） |
| `出错` | 返回 500 |
| `网页错误` | 返回 HTML 错误页（测 `.json()` 的坑） |
| `空` | 返回空内容（测内容校验） |

**用假模型把整条链路练熟，再改 `.env` 换成真模型。代码一行不改。**

## 这一周最容易卡住的六个地方

### 第一处：`EADDRINUSE`

**端口被占用。** 关掉旧进程（`Ctrl + C`），或者改 `config.js` 里的 port。

### 第二处：`ERR_MODULE_NOT_FOUND`

**import 路径少了 `./` 或 `.js`。** 报错说的是 "package 找不到"，很容易误判成"没装依赖"。

**ES Module 必须写完整：`import { CONFIG } from "./config.js"`。**

### 第三处：`require is not defined in ES module scope`

**`"type": "module"` 的项目里用了 `require`。** 改成 `import`。

### 第四处：中间件忘了 `next()`

**现象：浏览器一直转圈，终端有日志但没响应。**

**"有日志没响应" = 查 `next()`。**

### 第五处：`req.body` 是 `undefined`

**`express.json()` 放错位置。** 必须在所有路由**之前**。

### 第六处：模型请求永不返回

**没设超时。** 加 `signal: AbortSignal.timeout(ms)`。**这一行是第 20 节课最重要的代码。**

## 这一周必须建立的三个认知

### 认知一：服务器是"一直等着的程序"

不是一台特殊的机器。**它的特殊性在于"不退出"。**

### 认知二：密钥永远不进浏览器

**F12 一按就暴露。** 所有模型调用必须经过你自己的服务器。

### 认知三：模型没有记忆

**这是全周最重要的一句话：**

> **模型从来不记得你，是你在每次请求时替它记住了全部。**

**"记忆"存在你的数据库里，不在模型里。** 每次请求都要把历史重新发一遍。

**想明白这一点，所有"AI 记忆"类功能都不再神秘——它们本质都是"操作数据库里的消息列表"。**

## 这一周的最终产出

**第 21 节课的对话应用。**

它要满足：

- 能开新对话、能切换、能删除；
- 同一对话里记得上下文；
- 刷新页面消息还在；
- 模型超时或报错时，用户看到人话，且自己的消息不丢；
- 密钥只在服务器端。

**做完记进根目录 `CONTEXT.md` 的"我的作品"，并注明它的局限：**

```markdown
注意：数据存在 JSON 文件里，只适合单用户。并发写入会丢数据。
```

**主动写出局限，比假装完美更专业。**
