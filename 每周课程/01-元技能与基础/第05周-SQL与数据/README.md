## 从 JSON 文件到真正的数据库

---

## 这一周的目标

第 19 节课你用 JSON 文件存数据，我实测过：**同时发 23 条消息，最后只剩 2 条。**

这一周解决这个问题，并且把能力补齐：

1. **知道数据库和文件到底差在哪** —— 不是"更高级"，是"能保证数据正确"；
2. **会设计表** —— 给你一段需求，你能推出要几张表、每张表哪些列；
3. **会增删改查** —— 包括 NULL 的三个坑、分页、动态筛选；
4. **会 JOIN** —— 一对多、多对多、反连接；
5. **会写安全** —— 事务的原子性、索引的原理、软删除；
6. **会保护数据** —— 备份、验证、恢复演练。

## 为什么排在这一周

**因为前四周你做的东西，数据都是假的。**

`chat-app` 存在 JSON 文件里，它有三个致命问题：

| 问题 | 后果 |
|---|---|
| 并发写丢数据 | 两个人同时发消息，丢一半 |
| 查数据要读全文件 | 会话多了很慢 |
| 没有约束 | `role` 可以写任何值 |

**这一周把 `chat-app` 真正迁到数据库，它才成为一个"能给多人用"的应用。**

## 这一周实测到的六个"反直觉"结论

**这些不是理论，是我在这台机器上跑出来的。你会在课件里看到原始输出。**

| 结论 | 实测数据 |
|---|---|
| **事务让批量插入快 1243 倍** | 无事务 2000 条 = 4972ms，有事务 = 4ms |
| **索引只快 3.6 倍（2 万行）** | 无索引 25ms，有索引 7ms —— 大数据时差距会放大 |
| **WAL 模式下直接复制 `.db` 会得到空库** | 报错 `no such table: t`，因为数据在 `-wal` 里 |
| **`INSERT OR REPLACE` 会改 id** | 它实际是"删了再插"，从 8 变成 10 |
| **`NOT IN (1,2,NULL)` 返回空** | 加一个 null，结果从 36 条变成 0 条 |
| **SQLite 排不了中文拼音** | 只有 `BINARY`/`NOCASE`/`RTRIM` 三种 collation |

**每一条我在课件里都附了原始输出。你可以自己复现。**

## 这一周最危险的两条命令

**第一：`UPDATE` / `DELETE` 不带 `WHERE`**

```sql
UPDATE accounts SET balance = 0      ← 忘了 WHERE
changes: 2000                        ← 2000 行全被改了
```

**它不报错。`changes` 还会如实告诉你"影响了 2000 行"，但不认为这是错的。**

**第二：软删除后忘记过滤**

```sql
SELECT * FROM accounts               ← 忘了 WHERE is_deleted = 0
```

**已注销的用户会出现在列表里。** 这个 bug 能活很久。
