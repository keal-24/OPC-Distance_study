# 03-练习代码

**这个文件夹故意留空。**

这节课你在 `saas-lab` 里新增：

```text
saas-lab/
├── scripts/
│   ├── seed.js              造两个租户和它们的数据（幂等）
│   └── attack.js            手工攻击脚本（打印结果，不做判断）
└── tests/
    └── isolation.test.js    九条自动化测试（这节课的主角）
```

## 测试要跑起来，需要三样东西同时在

```text
1. 数据库在跑（第 162 节验过）
2. 服务在跑（另一个窗口 npm run dev）
3. 种子数据在（node scripts/seed.js）
```

**少一样，报错信息会指向完全不同的方向：**

```text
没数据库  → ECONNREFUSED 5432
没服务    → fetch failed
没种子    → 登录失败：seed-alpha@test.local
```

**这三种报错要能一眼分清。** 第 162 节故意让你踩过前两种，这一节补上第三种。

## 为什么先写 attack.js 再写测试

**因为攻击脚本没有"通过 / 失败"的概念，你会真的去看每一条返回了什么。**

**直接写测试的话，你的注意力全在"怎么让它变绿"，而不是"这段响应说明什么"。**

**顺序反过来，你会漏掉一个关键认知：返回 200 不代表有漏洞，返回 404 也不代表没漏洞。**

## 这节课必须做的一件事

**改坏一个方法，看测试变红。**

不改坏，你不知道这九条测试到底在测什么——它可能什么都没测，只是恰好全绿。
