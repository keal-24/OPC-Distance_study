# 03-练习代码

**这个文件夹故意留空。**

这节课你在 `saas-lab` 里新增：

```text
saas-lab/
├── src/
│   ├── db/
│   │   └── tenant-db.js       withTenant + 三个仓储（这节课的主角）
│   └── routes/
│       ├── conversations.js   全部改用 withTenant
│       └── messages.js        先 find 再写
├── scripts/
│   ├── check-tenant.js        路由层检查
│   ├── rls-test.js            RLS 验证
│   └── bad-update.js          故意漏租户（做完删掉）
└── migrations/
    └── 005_rls.sql            行级安全策略
```

## 这节课的难点不在写，在设计

**写代码只要半小时，想清楚"为什么这样设计"要一小时。**

三个问题先想明白再动手：

```text
1. 为什么 tenantId 从闭包来，而不是当参数传？
2. 为什么每个请求要包一个事务，而不是直接用 pool.query？
3. RLS 已经能兜底了，为什么仓储层还要显式写 tenant_id？
```

**答不上来就先别写。** 抄下来的代码下个月你会看不懂，然后被 AI 改一处就破了。

## 顺序别乱

```text
1. 先写 tenant-db.js（仓储层）
2. 再改路由（只用 withTenant）
3. 再写 check-tenant.js（检查脚本）
4. 最后做 RLS（005 迁移）
5. 最后跑 rls-test.js 验证
```

**为什么 RLS 放最后：** 它要依赖 `withTenant` 里的 `set_config`。先做 RLS，你的接口会全部返回空——因为没人设上下文，你会以为代码写错了。

## 一个必须做的实验

**把 005 里的四个 `force row level security` 删掉，重跑 `rls-test.js`。**

你会看到"不设上下文能读到几条消息"从 0 变成 2。

**这个实验只需两分钟，能省掉你以后两小时的排查。** 因为 RLS 失效的时候不报错，它只是安静地什么也不做。
