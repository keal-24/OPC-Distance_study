## 这一节的重点不在代码量

**代码比前几节少，但每一条都对应一个"会丢客户"的场景：**

```text
试用到期没提示   → 客户某天直接用不了了，很生气
加人没限配额     → 你为一个 199 元的客户付 2000 元成本
导出没有入口     → 客户想走，到处说你扣数据
注销直接删       → 误点一下，数据没了
```

**技术都对，但商业上会输。** 这一节补的就是这个缝。

## 必须先改仓储层

**路由里不许出现 `db.client.query`。**

```text
加人   → 用 db.users.count() / db.users.create()
导出   → 用 db.exportAll()
```

**如果你偷懒直接写 `db.client.query`，`npm run check` 会报错。** 这不是刁难，是因为那个检查脚本在第 165 节就是为这个写的。

## 走通一遍完整流程

```text
1. node scripts/seed.js
2. npm run dev
3. 用 seed-alpha 登录，拿 cookie
4. GET  /api/usage              → 看到 members: 1
5. POST /api/tenant/members    → 402（免费版只有 1 个名额）
6. GET  /api/tenant/export     → 下载 json，检查没有 seed-beta 的数据
7. POST /api/tenant/delete-request（公司名输错）→ 400
8. POST /api/tenant/delete-request（输对）      → 200
9. GET  /api/conversations     → 403，带 restore 提示
10. POST /api/tenant/restore   → 200
11. GET  /api/conversations    → 200
12. node scripts/purge.js      → "没有需要清理的租户"
```

**第 9 步和第 10 步之间是最容易卡住的地方：** 注销后所有接口 403，但恢复接口必须能进——所以它不能挂 `tenant` 中间件。**这个坑想不明白，你会在那里卡半小时。**
