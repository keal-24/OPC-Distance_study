## 顺序

```text
1. plans.js（先定数字，后面全依赖它）
2. 006 迁移（两张表 + RLS）
3. quota.js（扣减逻辑）
4. quota-test.js（单线程验证）
5. 改路由 + usage.js
6. race.js（并发验证）
7. reconcile.js（对账）
```

## 这节课最重要的一次实验

**`race.js` 必须跑两次：一次用先查后写，一次用原子扣减。**

```text
第一次：上限 5，并发 20，成功放行可能是 8，used 也是 8
第二次：上限 5，并发 20，成功放行 5，used 也是 5
```

**跑第一次的时候你会觉得"这不就是个测试脚本吗"。**

**跑第二次看到 5 就是 5，你才会真的相信"判断和写入必须在同一条 SQL 里"。**

这个认知以后能救你：所有涉及"有限资源 + 并发"的功能（库存、名额、次数、积分），都是同一个形状。

## 一个容易忽略的地方

**`usage_events` 要记 `meta`。**

```js
await recordEvent(db.client, req.tenant.id, 'message_sent', 1, {
  conversation_id: conversationId,
});
```

**为什么记这个：** 客户投诉"我这条消息没发出去，为什么扣了额度"时，你能查到是哪条对话、什么时间。**没有 `meta`，你只有一行数字，什么也解释不了。**

**日志是给未来的自己看的，不是给现在用的。**
