## 在微信里能用

## 这一周的目标

把"网页版"这件事推进到微信里：

```text
第 27 周结束时你手上有什么：
  一个在手机上能用的网页系统
  五个页面，四态齐全，表单不折磨人
  埋点能看到漏斗

客户会说：
  "能不能做个小程序？"
  "能不能在微信里点开就用？"
```

**这一周要做的第一件事不是写小程序，是回答一个问题：**

> **你这个需求，真的需要小程序吗？**

## 为什么这件事必须放在第一位

**因为小程序和网页的成本差 5—10 倍：**

| | 网页（PWA） | 小程序 |
|---|---|---|
| 开发时间 | 已有，改一改 | 重写一遍（不同技术栈） |
| 要备案吗 | 要（域名 + ICP） | 要（小程序备案） |
| 要审核吗 | 不用 | **每次发版都要审核（1—7 天）** |
| 能扫码打开吗 | 能 | 能 |
| 能加桌面图标吗 | 能（PWA） | 不能（在微信里） |
| 能用微信支付 | 可以（H5 支付/JSAPI） | 可以（更顺） |
| 能发消息触达 | 不能 | 订阅消息 |
| 分享到聊天 | 发链接 | **卡片，点击率高一截** |
| 依赖 | 浏览器 | 微信 |

**看最后三行：**

```text
能用微信支付    → 网页也能，只是体验差一点
能发消息触达    → 小程序/公众号能，网页不能
分享到聊天      → 小程序的卡片明显更好
```

**所以判断标准是：**

```text
如果客户的核心场景是"分享到群里给同事看"  → 小程序
如果客户的核心场景是"定期收到提醒"        → 小程序（订阅消息）
如果客户只是想"手机上能用"                → PWA，成本低十倍
```

**这一周先花一节课做这个判断，剩下的时间只做"真的需要小程序"的那部分。**

## 一个必须先说清的取舍

**这一周不做完整的电商小程序。做一个小程序原型 + 打通登录。**

```text
做：
  三个页面（列表 / 详情 / 我的）
  调你的后端接口
  微信登录（code2session）
  订阅消息（模板 + 发送）
  支付流程"看懂"（不真接入，但要能画出时序图）

不做：
  完整商城（购物车、优惠券、多规格）
  小程序分包（包体积 2MB 够用）
  自定义组件库（用官方的够了）
  小程序音视频
```

**理由：**

```text
① 微信支付要企业主体 + 商户号 + 审核，你学习阶段拿不到
② 小程序的技术栈（WXML/WXSS）你两天就能上手，不需要练一周
③ 真正难的是"判断该不该做"和"登录/支付怎么通"，那才是这周的重点
```

**如果你有商户号，第 195 节给了真接入的步骤，直接换。**

## 这一周的四条铁律

```text
一、先算成本再决定做不做。
   小程序不是"更高级"，是"另一个渠道"，有它自己的税。

二、小程序的网络请求必须走 HTTPS，且域名要在后台白名单里。
   少了这一步，你的接口在小程序里全部失败，而且报错不明确。

三、登录不存 openid 当用户 id。
   openid 是"这个人 + 这个应用"的组合，不同应用不同。
   你的 users 表要有一个自己的 id，openid 只是一个映射。

四、所有"发消息"都要走订阅（用户主动授权）。
   公众号的模板消息已经被订阅消息取代，群发有严格限制。
```

## 这一周最容易出事的三个地方

**第一：request 域名没配**

```text
小程序里调 https://yoursite.com/api/orders
报错：request:fail url not in domain list
```

**这个报错不会告诉你"要配白名单"，只会让你去查代码。**

**必须在微信公众平台 → 开发 → 开发设置 → 服务器域名 里加。**

**而且：**

```text
① 必须是 HTTPS
② 不能带端口（只能是 443）
③ 一个月只能改 5 次
```

**第三条最坑：改错了要等下个月。**

**第二：openid 到处传**

```text
前端拿到 openid，放在 localStorage
每次请求带上
```

**openid 不是凭证。** **拿到 openid 不等于登录——** **openid 是可以被猜测和伪造的（尤其在某些历史漏洞下）。**

**正确做法：** **openid 只在服务端出现，前端只拿你的 token。**

**第三：订阅消息一次授权只能用一次**

```text
客户点了"允许"，你只能发一条
再发要再问一次
```

**很多人以为"授权一次就能一直发"，** **结果第二天发不出去，客户也收不到。**

**这是微信的设计：一次性订阅。**

**"长期订阅"只有少数类目能申请（政务、医疗、交通等），你的客户大概率申请不到。**
