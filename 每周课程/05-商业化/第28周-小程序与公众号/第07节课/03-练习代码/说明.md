## 这节课最重要的东西不是代码

**是 `miniprogram-handoff.md` 里那三样：**

```text
① 现在能做什么（具体到能点）
② 真机还需要什么（带责任方和时间）
③ 已知限制（"邀请码要手工发" + "systemPool 用的是超级用户"）
```

**第 ③ 条最要紧，而且必须是两条。**

**第一条不写：** 客户以为"员工打开就能用"，实际要手工发码。上线第一天他就会打电话问"为什么我员工是白屏"。

**第二条不写：** 这是给自己埋雷。`systemPool` 用的是 `postgres` 超级用户，意味着应用进程里有一条能看到所有客户数据的通道。**这不是"以后优化"，这是上线前的硬门槛。**

**写出来，既保护他也保护你。**

## 一个能省两小时的东西

**自检页。**

```text
没有它：白屏 → 改代码 → 还是白屏 → 换域名 → 还是白屏 → 怀疑 AppID……
有它：  "网络 ✓ 登录 ✕ 没有拿到 token" → 问题在登录层
```

**"把白屏变成第几步失败"，是排查效率的 10 倍差别。**

**你以后每交付一个客户端，都该有一个这样的页面。**

## 阶段收尾

**把五个阶段的代码完整提交一次，然后数一下提交次数。**

```text
git log --oneline | wc -l
```

**少于 30 次说明攒太多了。**

**后果不是"不好看"，是"出问题时没法用 `git bisect` 定位"。**

**下一个阶段开始，坚持每节课一提交。**
