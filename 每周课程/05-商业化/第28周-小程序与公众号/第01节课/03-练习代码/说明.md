## 这一节最重要的产出不是代码

**是那份 `wechat-decision.md`。**

**因为"该不该做小程序"这个问题，你以后每接一个客户都会被问一次。**

**有一份判断表，你能在 30 秒内给出答案，而且能讲清为什么。**

## 五个技术差异，两天能适应

| | 网页 | 小程序 |
|---|---|---|
| 标签 | `div` `span` `img` | `view` `text` `image` |
| 单位 | `px` | `rpx`（750 = 屏宽） |
| 事件 | `onclick` | `bindtap` + `dataset` |
| 更新 | 改 DOM | `setData` |
| 循环 | 手写 | `wx:for` + `wx:key` |

**都不难。难的是"先用错，再发现"。**

**所以三个墙必须自己撞一次。**

## 三个墙

**一、`url not in domain list`**

关掉"不校验合法域名"就会看到。

**这个报错不会告诉你"要配白名单"。**

**二、`data-order-id` → `dataset.orderId`**

中划线转驼峰。取 `dataset.id` 会得到 `undefined`。

**三、删 `wx:key`**

数据顺序变化时，列表会错位——**第 3 行的状态显示在第 5 行。**

**这个 bug 只在你排序/筛选时才出现，不是每次都出现。**

## `rpx` 换算

```text
750rpx   = 屏幕宽度
375px 宽 的手机上，1rpx = 0.5px
32rpx    = 16px（最常见的值）
```

**设计稿 750 宽：直接用 rpx。**
**设计稿 375 宽：px × 2。**

**记错了，你的界面要么挤要么空。**
