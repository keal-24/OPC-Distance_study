## 一句话原则

> **一次授权 = 一条消息。**

**所以授权必须绑在"会产生通知的业务动作"上，不能做成一个设置开关。**

```html
<!-- ❌ 设置页的开关：客户点一次，你以为永久开启，实际只能发一条 -->
<switch bindchange="toggleNotify" />

<!-- ✅ 绑在业务动作上 -->
<button bindtap="onSubmit">提交订单</button>
<!-- onSubmit 里：先 requestSubscribeMessage，再提交 -->
```

**这个认知会改变你的整个产品流程。**

## 三个必须记住的长度限制

```text
thing              20 字
phrase             5 字
character_string   32 位（字母数字）
```

**超了报 `47003`，而且不告诉你哪个字段超了。**

**所有字段都截断。**

## 三个错误码

| errcode | 含义 | 能重试吗 |
|---|---|---|
| 43101 | 用户未订阅 | 不能（要重新授权） |
| 47003 | 参数不符合规则 | 不能（改了才发） |
| 40001 | token 失效 | 能（清缓存重试） |

**前两个是永久失败，重试只会浪费配额并触发风控。**

## 一个容易被忽略的设计

**`consumeGrant` 只在成功时调。**

```js
if (data.errcode === 0) {
  await consumeGrant(...);      // 只有这里
}
```

**失败不扣。**

**为什么：** **客户没收到，这一条授权应该还给他。**

**如果失败也扣：** **客户授权 3 次，收 1 条，还有 2 条"凭空消失了"。** **他会来找你，你查不出来。**
