## 一句话原则

> **小程序不带 cookie，所以登录必须换成 Bearer token。**

**这不是"优化"，是"必须"。**

**`wx.request` 默认不带 cookie，** **而第 164 节的 `HttpOnly Cookie` 方案在小程序里完全不能用。**

**两套并存：**

```text
网页     → Cookie（HttpOnly，XSS 偷不走）
小程序   → Bearer token（存 storage）
```

## 五个墙

| 墙 | 现象 | 你会在哪撞 |
|---|---|---|
| 删 `Authorization` | 401 无限循环 | 部署到真机时 |
| 删 `loadingMore` | 同一页拉三次，列表重复 | 滚动带惯性时 |
| 删 `setData` 回调 | 总金额慢一步 | 每次算依赖前面的值 |
| `type="number"` | 单价输不了小数点 | 客户第一天 |
| 不 `JSON.parse` | `undefined`，无报错 | 上传图片时 |

**五个都撞过，你的代码在真机上才不会出问题。**

## 一个最隐蔽的坑

```js
this.setData({ 'form.quantity': '4' });
this.updateTotal();        // 读到的还是 '3'
```

**`setData` 是跨线程通信，不是同步赋值。**

**所有"改完立刻用新值算"的地方都要用回调：**

```js
this.setData({ 'form.quantity': '4' }, () => {
  this.updateTotal();
});
```

**这个坑的表现是"总金额总是慢一步"——** **你不会觉得是 bug，你会觉得"可能有点延迟吧"。**

**然后客户会说"这个算错了"。**
