## 一个判断方法

**跳转前只问一句：客户按"返回"应该回到哪？**

```text
回到刚才那页        → navigateTo
回到更上一层        → redirectTo
回到 tab 首页       → switchTab
回到小程序开始      → reLaunch
就是想退回去        → navigateBack
```

**答对了方法就定了。答不对会出现两个后果：**

```text
① navigateTo 用多了 → 卡在第 10 层，报 webview count limit exceed
② redirectTo 用多了 → 客户按返回回不到刚才那页，觉得"怎么跳回去了"
```

## 三个必须做的实验

**一、撞页面栈**

详情页加一个 `navigateTo` 跳回列表的按钮，来回点 10 次。

```text
期望：navigateTo:fail webview count limit exceed
```

**二、幂等键的位置**

把 `this._refundKey` 从 `onLoad` 挪到 `doRefund` 里，每次都 `Date.now()`。

**然后快速点两次"退款"。**

```text
期望：两个不同的 key → 服务端认为两次不同的请求 → 退两次
```

**这就是为什么幂等键要在页面加载时生成一次。**

**三、切 tab 五次**

在 Network 面板数 `/api/me` 的请求次数。

```text
没节流：5 次
有节流：1 次
```

## 一个容易忽略的细节

`<block>` 不渲染任何元素。

```xml
<!-- ❌ 多一层 view，影响布局 -->
<view wx:if="{{order}}">
  <view class="card">…</view>
  <view class="card">…</view>
</view>

<!-- ✅ 什么都不留 -->
<block wx:if="{{order}}">
  <view class="card">…</view>
  <view class="card">…</view>
</block>
```

**多层 `<view>` 嵌套时，`margin` 会叠加、`flex` 会错乱。**

**用 `<block>` 包条件，用 `<view>` 包样式。**
