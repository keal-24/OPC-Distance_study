# 第25周 · Excel与支付 · 第169—175节课

## 客户的数据能进，你的钱能收

## 这一周的目标

两个看起来不相干、其实一模一样的技能：

```text
Excel 导入    →  把不可信的外部数据收进你的库
支付回调      →  把不可信的外部事件变成你的钱
```

**两件事的共同点：**

```text
① 数据从外面来，不能信
② 必须校验，而且校验失败要能说清哪一行错了
③ 必须幂等，同一份数据到两次不能算两次
④ 必须能对账，事后能证明"我这儿是对的"
```

**这就是为什么它们排在同一周。**

这一周结束，你要能做到这五件事：

1. **读得进别人的 Excel** —— 包括合并单元格、数字存成文本、日期是 `45000` 这种；
2. **导入时错一半也能用** —— 好的入库，坏的给一份带回错误原因的文件；
3. **导出不把服务器搞死** —— 十万行不 OOM，中文文件名不乱码；
4. **金额一分不差** —— 全用整数分，不碰浮点；
5. **回调来两次只算一次** —— 验签、幂等、主动查单三层。

## 为什么排在这一周

第 24 周你做出了能服务多个客户的系统。**但客户的第一句话通常是：**

```text
"我们以前的客户资料都在 Excel 里，能导进去吗？"
"我们能按月导出报表给老板看吗？"
```

**不能导入，客户就用不起来**——他不可能让员工手工录 3000 条。

**而第二个问题更要命：客户愿意付钱了，你收得到吗？**

```text
收不到 → 前面 24 周全白干
收错   → 客户付了钱但系统没开，你还要人工核对
收重   → 客户投诉，或者你多退一笔
```

**第 24 周结束时你有了 `usage_events` 和 `tenant_quotas`，能算清楚"该收多少"。这一周解决"怎么收进来"。**


**这和第三周的假模型是同一个思路：先把整条链路和所有异常路径练熟，接真网关时只换一个文件。**

**而且有个额外好处：真实网关的"重复回调""延迟回调""签名错误"你很难主动制造，mock 网关可以随便造。**

## 这一周的四条铁律

```text
一、金额一律用整数分，代码里不出现小数。
   需要除法的地方（分摊、打折），用整数运算 + 明确的舍入规则。

二、任何"收外部数据"的接口都要幂等。
   同一个订单号、同一个回调 id，处理两次的结果必须和处理一次一样。

三、导入允许部分成功，不允许静默丢弃。
   每一行失败必须能说出原因，而且要能让客户下载一份看。

四、下单金额只从服务端算，永远不信前端传的金额。
   前端传 price 的接口，等于让客户自己定价。
```

## 这一周最容易出事的三个地方

**第一：用 `parseFloat` 算钱**

```js
0.1 + 0.2                    // 0.30000000000000004
19.9 * 3                     // 59.699999999999996
Math.round(1.005 * 100)      // 100  ← 应该是 101
```

**第三条最阴。** `1.005` 在浮点里其实是 `1.00499999999999989...`，乘 100 是 `100.4999...`，`round` 变 100。

**你的系统会少收一分钱。** 一天一万笔，就是 100 块。

**第二：回调没做幂等**

**支付平台的行为是"重试直到你返回成功"。** 你的接口挂了 500，它会重试；你的接口响应慢，它会重试；它自己网络抖动，也会重试。

```text
同一个回调来 3 次 → 你的代码给客户加了 3 个月会员
```

**而且第 3 次来的时候，"改订单状态"可能是幂等的，但"给用户加额度"不是。**

**第三：导出把内存吃光**

```js
const workbook = new ExcelJS.Workbook();
// 逐条 addRow，10 万行
// → 内存里攒了 10 万个对象 → Node 进程被 OOM Killer 干掉
```

**表现是"导出大文件时网站整个挂了"**——不是这个接口慢，是整个进程死了，所有用户都受影响。

不要急着进下一周。先确认这五条：

- [ ] 我能导入一份带合并单元格、带 `45000` 这种日期的 Excel

- [ ] 我的代码里搜不到 `parseFloat` 处理金额，也搜不到 `toFixed` 存库
- [ ] 同一个支付回调重放三次，客户只被加了 1 次

- [ ] 每节课的 `NOTES.md` 都填了

```text

第三行才是表头，且有合并单元格
日期列是 45000 这种数字
金额列有的是 "1,299.00"，有的是 1299

```

**这不是故意刁难。这就是客户真实发给你的文件。**

**你做的读取器，就是要能把这种东西读对。**
