## 这一节的核心是两句话

**第一句：**

```text
"检查状态"和"更新状态"必须在同一条 SQL 的 where 里。
```

**第二句：**

```text
幂等键不是"额外加的安全措施"，是"客户点两次"这件事的唯一解法。
```

**其余所有代码都是这两句话的展开。**

## 必须做的三个实验

**一、5 个并发同 key**

```text
期望：只有 1 个订单 id，1 个 201，1 个 200（重放），3 个 409（处理中）
```

**二、5 个并发不同 key**

```text
期望：5 个 201，5 个订单（这是对的，客户真的点了 5 次）
```

**三、去掉幂等中间件，再跑第一个实验**

```text
期望：建出 5 个订单
```

**第三个实验是给自己看的。** 你会亲眼看到"没有幂等"的世界长什么样——**那个世界里，客户点两次就有两个订单。**

## 一个容易漏的细节

**`res.json` 被覆盖的那一层。**

```js
const originalJson = res.json.bind(res);
res.json = function (payload) { ... return originalJson(payload); };
```

**如果某个路由用 `res.send()` 或者 `res.end()` 返回，这一层就失效了——响应不会被存下来，下次重复请求永远是 409。**

**所以规矩是：所有挂幂等的路由必须用 `res.json` 返回。**
