## 这一节必须先做脏文件，不能先写代码

**顺序反了会怎样：**

```text
先写代码 → 你心里想的"文件长这样" → 代码只处理你想到的情况
        → 客户发来真文件 → 读出来一堆 null → 开始怀疑库有问题
        → 换库 → 换完还是不行
```

**先做脏文件，你才知道要处理什么。** 而且这份文件后面六节课都要用，第 170 节的校验、第 171 节的导出，都拿它当样例。

## 三个不能跳的验证

**一、`45000 → 2023-03-15`**

不管你怎么写 `serialToDate`，先跑这两个数。错了就是基准日或闰年 bug 处理错了。

**二、`2026-02-30` → `null`**

如果你的代码返回 `2026-03-02`，说明 `safeDate` 的回读校验没写。这个错误不会报错，只会悄悄改客户的数据。

**三、`20261105` 这个 8 位数字**

它既是"纯数字"，也是"YYYYMMDD"。**顺序写反了会被当序列号，转出一个 5 万多年后的日期。**

## 一个容易忽略的细节

**`eachRow` 默认跳过空行。**

```js
ws.eachRow((row, n) => { ... })              // 会跳过空行，rowNumber 不连续
ws.eachRow({ includeEmpty: true }, (row, n) => { ... })   // 不跳过
```

**你要的是后者。** 因为"第 5 行是空的"这个信息，在报错时要告诉客户"你文件里的第 6 行有问题"——**行号必须和客户在 Excel 里看到的行号一致。**
