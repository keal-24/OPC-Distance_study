## 这一节最重要的一个判断

**"四件套"必须在一个地方实现一次。**

**对比两种写法：**

```text
❌ 每个适配器自己验签、自己落库、自己判重复
   → 三家代码 90% 重复
   → 改一处要改三处
   → 某天你会漏掉某一家

✅ 适配器只写 verify 和 normalize
   → 核心逻辑只有一份
   → 加第四家只写两个函数
```

**判断标准：如果要加第四家平台，我需要改几个文件？**

**答案应该是"一个"（新增一个适配器文件）+ "一行"（加进数组）。**

**如果你要改三个文件，说明抽象没做对。**

## 三个必须做的实验

**一、加密推送**

```text
curl -X POST http://localhost:5000/mock/push-event-encrypted -d '{"text":"加密测试"}'
期望：正常收件，日志里 eventId 和明文推送一样能用
```

**二、`always.fail` 跑满 5 次**

```text
期望：10/20/40/80/160 秒的间隔，最后 failed_permanently，告警只来一次
```

**三、修好之后重放**

```text
node scripts/replay-failed.js         先看
node scripts/replay-failed.js --run   再放
期望：变成 done
```

**第二个实验会让你真的看到退避曲线。** 大部分人写重试都是"每 30 秒重试一次"，**指数退避只有在真的盯着日志看的时候，才能感觉到它的必要性。**

## 一个容易搞错的地方

**`express.raw` 之后，`req.body` 是 Buffer 不是对象。**

```js
// ❌
const eventType = req.body.event_type;

// ✅
const rawBody = req.body.toString('utf8');
const parsed = JSON.parse(rawBody);
const eventType = parsed.event_type;
```

**这个差异只在 webhook 路由里存在。** 其他路由还是正常解析的对象。

**混着写会不小心拿到 `undefined`，然后一路传下去，最后报一个完全无关的错。**
