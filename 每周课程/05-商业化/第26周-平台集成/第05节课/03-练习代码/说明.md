## 这节课最容易忘的一个字段

```sql
card_message_id text
```

**没有它，客户点了按钮，你改完数据库状态——** **但卡片上还是两个按钮。**

**客户会再点一次。第二次你返回"已处理"，卡片还是没变。**

**他会给你打电话。**

## 三个必须做的实验

**一、正常点击**

```text
建审批 → 点通过 → 状态变 approved → 卡片变绿 + 按钮消失
```

**二、重复点击**

```text
再点一次通过 → 状态还是 approved（不变）→ 卡片又被更新一次（内容一样）
```

**三、白名单外的人点**

```text
ou_stranger 点通过 → 日志"不在审批人白名单里" → 状态不变
```

**第三个实验最能说明问题。** 不做它，你的系统在客户群里就是一个"谁都能批 4.8 万"的漏洞。

## 一个必须现在想清楚的分层

```text
fastPath 能做的：
  ✅ 改一行数据库状态
  ✅ 生成卡片 JSON
  ❌ 发消息（要网络请求）
  ❌ 调大模型（要几秒）
```

**判断标准：这个操作会不会超过 500 毫秒？**

**会 → 走 worker。不会 → 可以在回调里直接做，这样能返回 toast 给客户即时反馈。**

**这个分层以后每加一个卡片按钮都要过一遍。**
