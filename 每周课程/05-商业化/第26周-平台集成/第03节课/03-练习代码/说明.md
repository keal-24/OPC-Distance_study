## 这一节的核心对比，必须亲眼看到

**推一条 `text: "slow"` 的事件（handler 里等 10 秒）。**

**你会看到：**

```text
假平台：  [mock-platform] 回调返回 200，耗时 8ms
你的服务： [handler] 收到消息： slow ...（然后等 10 秒）
```

**同一个请求，平台 8ms 就拿到了 200，而你的业务跑了 10 秒。**

**这就是 `acknowledge-then-process` 的全部含义。**

**如果你没看到这个对比，这一节就没学到。**

## 三个必须做的实验

**一、`slow` 事件**

```text
期望：回调 < 50ms，业务 10 秒
```

**二、重放 5 次**

```text
node scripts/replay-event.js 5
期望：5 个 200，但 handler 只执行 1 次，数据库里只有 1 行
```

**三、50 并发压测**

```text
node scripts/webhook-latency.js
期望：p95 < 100ms，超过 3000ms 的是 0 个
```

**第三个实验是你以后的"守门员"。** 每次改回调都要跑一遍——**回调变慢的征兆，永远是"某次改动顺手加了一个 await"。**

## 一个容易忽略的地方

**`req.rawBody`。**

```js
app.use(express.json({
  verify: (req, res, buf) => { req.rawBody = buf.toString('utf8'); },
}));
```

**没有这一行，验签永远失败。**

**而且报错是"签名不匹配"，不会告诉你"你的 body 被重新序列化了"。**

**因为 `JSON.stringify(req.body)` 和原始 body 的字节可能不同：**

```text
原始：{"a":1,"b":2}
重新序列化：{"a":1,"b":2}       ← 看起来一样
```

**但如果原始 body 里有空格、有换行、有 `1.0` 这种数字、有中文转义，重新序列化就变了。**

**所以必须用原始字节。**
