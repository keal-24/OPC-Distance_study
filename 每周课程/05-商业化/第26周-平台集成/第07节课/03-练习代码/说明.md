# 03-练习代码

**这个文件夹故意留空。**

这节课你在 `saas-lab` 里新增：

```text
saas-lab/
├── docs/
│   ├── integration-guide.md    给客户的对接说明（这节课最重要）
│   └── ops-runbook.md          给自己的运维手册
├── src/
│   ├── integrations/
│   │   └── approvals-pull.js   一致性检查
│   └── routes/
│       ├── integrations.js     仪表盘 + 事件日志 + 重放
│       └── contacts.js         加 30% 安全阀
└── scripts/
    └── full-scenario.js        十二步端到端剧本
```

## 这一节的两个产出比代码值钱

```text
docs/integration-guide.md   客户照着做就能配好
docs/ops-runbook.md         你出问题时知道查哪里
```

**代码只服务这一个项目。这两份文档服务你以后的每一个客户。**

**写它们的时间是 1—2 小时。省下的时间是"每个客户配一次问你十次" × 客户数。**

## `full-scenario.js` 的三个用途

```text
① 证明系统能工作（交付前跑一遍）
② 回归测试（改完代码跑一遍）
③ 交接文档（新人跑一遍就懂）
```

**第 ② 条最实用。** **你两个月后回来，改了一行代码，不确定有没有影响——跑一遍，全绿就放心。**

**这东西比单元测试更接近"用户实际会不会用"。**

## 30% 安全阀

```js
if (plan.localCount > 0 && plan.toDeactivate.length > plan.localCount * 0.3) {
  return res.status(409).json({ error: '本次同步将标记删除超过 30% 的成员，已中止' });
}
```

**这五行代码，防止的是一次"平台 API 返回空列表 → 你把全公司的人标记为离职 → 所有审批记录断链"的事故。**

**这种事故你在测试环境永远遇不到。** **它只在"平台那天抽风 + 你恰好点了同步"的时候发生。**

**把所有"批量改状态"的操作都加一个这样的比例检查。** **这个习惯会救你一次。**
