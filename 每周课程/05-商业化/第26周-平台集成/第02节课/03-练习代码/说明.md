## 这一节的两个"反常识"

**一、缓存并不是关键，"同时只换一次"才是关键。**

```text
只缓存       → 10 个并发各换各的，平台被调 10 次
缓存 + 单飞  → 10 个并发只调 1 次
```

**平台限流通常按应用计。被限流之后，你连 token 都拿不到，所有功能瘫痪。**

**二、"提前量"不能是固定值。**

```text
❌ expiresAt = now + (7200 - 300) * 1000     // 平台给 30 秒有效期时，你缓存 60 秒
✅ ttl = max(30, expire - min(300, expire * 0.1))
```

**平台给的有效期不是你能控制的。有的平台给 2 小时，有的给 30 分钟。**

**按比例算提前量，才能适配所有平台。**

## 三个必须做的实验

**一、10 并发压测**

```text
node scripts/token-stress.js
期望：平台被调用 1 次，10 个请求拿到同一个 token
```

**二、自动重试**

```text
node scripts/token-expire-test.js
期望：日志里有"token 失效，清缓存后重试一次"，最后调用成功
```

**三、提前过期循环**

```text
把假平台的 expire 改成 30
node scripts/token-loop.js
期望：看到 token 失效被自动救回
```

**第三个实验最有价值。** 因为 token 过期的 bug **只在你上线 2 小时后出现**，测试时永远遇不到——**除非你自己把它加速。**
