# 03-练习代码

**这个文件夹故意留空。**

这节课你在 `saas-lab` 里新增两个文件，**都不写业务代码**：

```text
saas-lab/
├── docs/
│   └── notify-list.md          消息清单（这节课的主要产出）
└── scripts/
    └── mock-platform.js        假平台（独立进程，端口 5000）
```

## 这一节为什么先写文档再写代码

**因为"接哪家平台"和"发什么通知"是产品决策，不是技术决策。**

**决策错了，代码写得再好也白费：**

```text
接错平台 → 客户 200 人都在企微，你接了飞书 → 没人用
通知太多 → 客户静音 → 系统等于不存在
第一行没信息量 → 客户不点开 → 白做
```

**先写清楚要发什么、发给谁、多紧急，再动手写代码。**

## `notify-list.md` 的写法

**至少 5 条，而且要能回答这三个问题：**

```text
如果我不发这条，客户会损失什么？
客户看到它的第一秒，能判断"要不要现在处理"吗？
它有没有一个能让客户少做一步操作的按钮？
```

**答不上来的条目，删掉。**

## 假平台的四个用途

```text
1. 换 token（含错密钥的分支）
2. 推事件（带 3 秒超时，会真的超时）
3. 一次推 N 次同一个 event_id（测幂等）
4. 清空所有 token（测自动续期）
```

**第 3、4 项在真实平台上你造不出来。** 这就是假平台的价值——**它让你能主动测试那些"一年才遇到一次"的场景。**

## 一个提醒

**别三家都接。**

```text
一家做深      2—3 天
三家都做      7—10 天，而且你记不住每家的差异
```

**先接客户正在用的那家。第二家等真有客户了再说。**
