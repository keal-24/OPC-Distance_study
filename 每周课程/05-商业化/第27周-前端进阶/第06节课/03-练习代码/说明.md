## 一句话原则

> **只记"决策点"，不记"所有动作"。**

```text
✅ 提交了、放弃了、被拦住了
❌ 滚动、停留、鼠标移动、点了导航
```

**判断方法：这个事件能回答"客户为什么留下/离开"吗？**

## 三个隐私红线

```text
一、记"哪个字段出错"，不记"填了什么"
   ✅ field: 'email'
   ❌ email: 'a@b.com'

二、不上报 IP
   你不需要它也能回答那五个问题

三、不上报精确时间戳 + 用户 id 的组合
   服务端接收时间就够，精确到分钟
```

**这三条现在做，比以后整改便宜一百倍。**

## 洞察 vs 数据

```text
数据：漏斗图，四根条，数字递减
洞察：流失最多的是「导入 → 建单」，掉了 12 人（只剩 40%）
```

**客户（和你）看数据会想"哦少了些人"，看洞察会想"去查导入为什么失败"。**

**你的报表要往洞察多走一步。哪怕只是一句模板拼出来的话。**

## 一个必须做的测试

```text
curl -X POST .../api/track/batch -d '{"events":[{"name":"test","props":{"email":"a@b.com","amount_cents":100}}]}'
```

**然后查：**

```sql
select props from ui_events where event_name = 'test' order by id desc limit 1;
```

**期望：`{"amount_cents": 100}`，`email` 被拦。**

**如果 `email` 进来了，你的白名单有问题——** **而这类 bug 一旦上线，客户的个人信息就进了你的日志表。**
