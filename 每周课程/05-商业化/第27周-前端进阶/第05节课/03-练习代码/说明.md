## 一句话原则

> **图表的目的是让人做出判断，不是把数据显示出来。**

**所以先问"客户要判断什么"，再决定画什么。**

```text
"这个月比上个月好吗"  → 数字 + ↑12% + 12 个月折线
"哪个客户贡献最大"    → 横向柱状图前 10
"钱花在哪"            → 堆叠柱 / 饼图（≤5 类）
"什么时候最忙"        → 按小时柱状图
"金额分布"            → 直方图
```

## 三个必须记住的规则

**一、Y 轴从 0 开始。**

**不从 0，3% 的波动看起来像翻倍。这是"误导性图表"，商业报告里常用来骗人。**

**二、饼图分类不超过 5 个。**

**超过就看不出差异了。改成"前 4 + 其他"，或者用横向柱状图。**

**三、涨红跌绿。**

```css
.kpi__delta--up { color: #c1121f; }    /* 红 = 涨 */
.kpi__delta--down { color: #0a7b34; }  /* 绿 = 跌 */
```

**这是中国市场的约定。搞反了客户第一眼会觉得别扭。**

## 一个必须处理的边界

**数据全 0 的时候。**

```js
// ❌ 崩
range: (u, min, max) => [0, max * 1.1]     // max = 0 时是 [0, 0]

// ✅ 不崩
range: (u, min, max) => [0, max > 0 ? max * 1.1 : 1]
```

**所有图表库都有这个"全零"的边界问题。**

**而"新客户还没数据"是最常见的场景——** **你的第一个客户打开仪表盘，看到的就是全 0。**

## `generate_series` 补空月

```sql
with months as (
  select generate_series(
    date_trunc('month', now()) - interval '11 months',
    date_trunc('month', now()),
    '1 month'
  )::date as month
)
select ... from months left join orders ...
```

**不用它，3 月没订单就没有 3 月这一行，前端的 `labels` 和 `values` 长度对不上，图表错位。**

**所有"按时间聚合"的报表都用这个写法。**
