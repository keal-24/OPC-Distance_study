# 第27周 · 前端进阶 · 第183—189节课

## 手机上能用、有图表、知道用户在干什么

---

## 这一周的目标

把前 26 周做出来的"功能都对的系统"，改成"客户敢用、用得下去的系统"。

```text
第 26 周结束时你手上有什么：
  一个在飞书里能对话、能审批、能收通知的系统
  数据库干净，隔离严密，金额精确，回调幂等

但它有一个致命问题：
  客户打开网页版，排版是乱的
  客户在手机上打开，按钮点不到
  点了按钮没反应，不知道是在加载还是坏了
  填了十项，提交时告诉你"第一项格式不对"
```

**这一周结束，你要能做到这五件事：**

1. **手机上真的能用** —— 不是"能看"，是"能点对"；
2. **知道"现在是什么状态"** —— 加载中、空、出错、没权限，四种状态都有界面；
3. **表单不折磨人** —— 错了立刻说，而且说清怎么改；
4. **数据能看懂** —— 一个图表胜过一张表；
5. **知道客户在哪一步放弃的** —— 埋点，不靠猜。

## 为什么排在这一周

**这里有一个很现实的事实：客户第一次用你的系统，是在手机上。**

```text
他在开会，收到你发的一条消息
点开链接
你在电脑上设计得很好看的界面，在 6 寸屏幕上排版全乱
表格要横向滚动，按钮藏在右边看不见
他退出了
```

**然后你在后台看到他"注册了但没使用"。**

**你以为他不需要，实际上是你的界面把他劝退了。**

**这一周的价值不在"更好看"，在"不漏掉本可以成交的客户"。**

## 一个必须先说清的取舍

**这一周不引入任何前端框架。**

```text
不装 React / Vue / Svelte
不装 Tailwind
不装 Vite / webpack
不装组件库（Ant Design / Element）
```

**为什么：**

```text
① 你现在的系统是"服务端渲染 + 少量 JS"，加框架等于重写
② 组件库的默认样式长得都一样，客户一眼看出"这是套模板"
③ 一个 6MB 的 bundle，客户在 4G 上等 8 秒
④ 你一个人维护，框架升级是纯负债
```

**这一周只用原生的 HTML / CSS / JS，加上一个 12KB 的图表库。**

**这不是"没钱买工具"，是"用不到那么多工具"。**

**判断标准：**

```text
如果你的界面有 5 个以上"高度交互的页面"（拖拽、实时协作、复杂状态）
→ 你该用框架，那时候再学

如果你有 5—15 个"表单 + 列表 + 详情"的页面
→ 原生足够，而且更快、更小、更好排查
```

**你现在在第二种。**

## 这一周的四条铁律

```text
一、所有页面先在 375px 宽下做完，再考虑桌面。
   反过来做的话，你会做出一个"缩小了就没法用"的东西。

二、任何异步操作都必须有四个状态：
   加载中 / 有数据 / 空 / 出错。
   少一个，客户就会在那一刻以为系统坏了。

三、错误提示必须说"怎么改"，不说"格式错误"。
   "请填写 11 位手机号" 而不是 "手机号格式不正确"。

四、埋点只记"决策点"，不记"所有点击"。
   记多了你永远不会看。
```

## 这一周最容易出事的三个地方

**第一：用 `px` 写死宽度**

```css
.container { width: 1200px; }      /* 手机上横向滚动，右侧内容永远看不到 */
```

**这是移动端最经典的错误，也是最容易改的。**

**第二：表单只在提交时校验**

```text
客户填了 12 个字段
点提交
"第 3 项格式不对"
改完再提交
"第 7 项也不对"
```

**两轮之后他会关掉页面。**

**第三：空状态只写"暂无数据"**

**客户看到"暂无数据"会想：**

```text
是我没权限？
是我筛错了？
是系统坏了？
本来就该是空的？
```

**四种可能，他不知道是哪一种。**

**"还没有数据，点右上角新建第一个" —— 这一句话能省掉一个电话。**

## 周末的验收

不要急着进下一周。先确认这五条：

- [ ] 我把浏览器窗口缩到 375px，所有页面都能正常用（不是"能看"）
- [ ] 每个异步操作的四种状态我都亲眼看过
- [ ] 表单的错误提示里，没有一句是"格式不正确"
- [ ] 我有一个图表，而且它比表格更能说明问题
- [ ] 我的埋点能看到"从注册到第一次付款"的漏斗

**另外：**

- [ ] `npm test` 九条隔离测试还是全绿
- [ ] 没有引入任何前端框架依赖（`package.json` 里搜不到 react/vue）
- [ ] 首屏加载在 3G 模拟下不超过 3 秒

> **第一条才是真标准。** "能看"和"能用"的差别是：**按钮是不是在拇指够得到的地方，表格要不要横向滚动，输入框点了会不会被键盘挡住。**
>
> **一周七节课，落一节课没关系，但第 183、185 节不能落。** 移动端和四态是客户流失的两个最大原因。

## 下一步

第 28 周：**小程序与公众号。**

这一周把"网页版能用"做通。下一周做"另一个入口"——微信里的小程序。

**这两个入口的区别要提前知道：**

```text
网页 / 平台集成   客户主动打开你的系统，或者你推到他的工作台
小程序           客户在微信里点开，用完就走
```

**小程序不是"网页缩小版"。它有自己的一套规则（包体积、审核、授权、支付）。** **但它也有一个网页没有的好处：微信里的分享传播。**

**先把网页做好，因为小程序里 80% 的业务逻辑和接口是一样的。**
