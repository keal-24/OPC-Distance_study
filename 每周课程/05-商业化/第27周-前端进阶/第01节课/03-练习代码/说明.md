## 三个数记下来

```text
44px    可点击区域的最小高度
16px    输入框的最小字号（低于它 iOS 会放大页面）
375px   最小要支持的屏幕宽度
```

**这三条是移动端的地基。记错任何一个，你的界面在真机上就是"不能用"。**

## 三个必须亲手撞的错误

**一、写死 `width: 1200px`**

```css
.app-main { width: 1200px; }
```
→ 375px 下出现横向滚动条，右侧永远看不到

**二、固定 `height: 56px`**

```css
.list__item { height: 56px; }
```
→ 系统字体调大时文字溢出，压在下一行上

**三、删掉 `min-width: 0`**

```css
.list__main { flex: 1; }   /* 少了 min-width: 0 */
```
→ 长客户名把金额挤出容器

**这三个错误覆盖了移动端布局 80% 的问题。** 撞过一次，以后看到类似的 CSS 你会本能地警觉。

## 一个容易被忽略但影响很大的细节

**`font-variant-numeric: tabular-nums`。**

```text
不加：
¥1,299.00
¥899.00        ← 小数点对不齐
¥12,000.00

加了：
¥1,299.00
¥  899.00      ← 对齐，能扫一眼比大小
¥12,000.00
```

**一个 CSS 属性，让金额列表从"看着乱"变成"能比较"。**

**所有"一列数字"的地方都该加，包括表格、图表坐标轴。**

## 真机测试不能省

**模拟器测不出三件事：**

```text
① 拇指的实际触摸精度
② 手机系统字体调大后的布局
③ 键盘弹起时的遮挡
```

**第 ② 条最容易被忽略。** 中老年客户很多把字体调到最大——**你的 `height: 52px` 顶部栏会在那一刻装不下标题。**
