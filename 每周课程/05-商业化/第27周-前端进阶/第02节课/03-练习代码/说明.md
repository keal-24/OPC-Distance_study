## 两个必须记住的分界线

**一、"渲染"和"请求"分开。**

```text
ui.js      只做字符串拼接，永远不出现 fetch
pages/*.js 只做数据编排，调用 UI 的函数
```

**为什么：** 渲染函数里一旦有 `fetch`，你就没法在控制台里单独试它了。

**`UI.Badge({kind:'paid'})` 能直接试，是排查 UI 问题最快的路径。**

**二、"用户数据"和"我生成的 HTML"分开。**

```js
ListItem({
  right: money(o.amount_cents),          // 用户数据 → 会 escape
  rightSub: Badge({...}),                // 我生成的 HTML → 不 escape
})
```

**混了会怎样：**

```text
全 escape → 你的 Badge 显示成字面量 "<span class=...>"
全不 escape → 用户的客户名里带 <script> 就执行了
```

## 三个破坏实验

**一、删 `escapeHtml`**

```js
title: '<img src=x onerror="alert(1)">恶意客户名'
```

**期望：`alert(1)` 弹出来。这就是 XSS。**

**二、删事件委托**

改成给每个 `.list__item` 单独 `addEventListener`，然后点"刷新"。

**期望：新渲染出来的列表点不动了。**

**三、清空数据**

```js
state.orders = [];
```

**期望：空状态 + "去导入"按钮。如果一片空白，说明空分支写漏了。**

**客户第一次登录看到的就是这个界面——空白页等于"系统坏了"。**
