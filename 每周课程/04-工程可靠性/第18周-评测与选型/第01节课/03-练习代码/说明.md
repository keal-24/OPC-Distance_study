# 03-练习代码

**这个文件夹故意留空。**

今天不写程序。你要建的是两份文档：

```text
03-练习代码/
└── eval/
    └── eval-spec.md        ← 今天唯一的交付物
```

**就一个文件。** 后面六节课都会往 `eval/` 里加东西，所以先把这个目录建出来。

```bash
mkdir -p eval
touch eval/eval-spec.md
```

## eval-spec.md 必须有的五块

```text
① 第一段：给定【输入】，系统必须输出【形态】，包含【字段】，供【谁】做【什么决定】
② 逐字段三档表（每档：可观测条件 + 逐字例子）
③ 一票否决清单（V1–V5 起）
④ 三个边界样例（A 应付型 / B 踩线型 / C 两可型）
⑤ 汇总公式（主指标 + 辅指标 + 致命错误判定）
```

**少一块就不算完成。** 特别是第 ④ 块，它看起来最没用，实际上是唯一能让"你和别人判得一样"的东西。

## 必须自己确认的六件事

**① 你的判定条件里还有没有形容词**

拿红笔通读一遍，把「准确」「简洁」「自然」「合理」「流畅」「符合预期」全圈出来。**圈出任何一个，就说明那个字段还不能用。**

替换方法：问自己"我是靠什么看出来它不准确的"，答案就是可观测条件。

**② 每个 FAIL 档有没有逐字例子**

不是"类似这样的"，是能直接复制的一整段文本。**没有例子 = 这个档位没定义。**

**③ `category` 的多类别优先级写了没有**

这条如果不写，你和任何人（包括三天后的你自己）都会在不同输入上判出不同结论。**这条歧义会污染后面全部六节课的数据。**

**④ 一票否决里有没有"编造事实"**

如果只写一条，就写这条。**编造是 LLM 最本质的失败模式，而且它编得像真的。**

**⑤ 一致性测试是不是"你先判完才看对方"**

顺序错了，你测的就不是判定卡，是你的说服力。

**⑥ 一致率低于 75% 时你有没有停下来改**

低于 75% 还往下走，等于拿一把会伸缩的尺子去量东西。后面所有数字都得重做。
