## 五个级别，一句话判断

```text
"这件事发生后需要我做什么吗？"
  不需要（系统自己处理了） → warn
  需要（我得看/得改）      → error
  立刻需要（半夜也得来）    → fatal
  排查时才需要            → debug
  业务上的一件事发生了     → info
```

## 必须自己观察的七件事

**① 一天 30 MB → 一年 11 GB**

**盘满了，服务写不进去，然后在最不该崩的时候崩。**

**② 删正在写的文件不释放空间**

```bash
lsof -p <pid> | grep deleted
# node ... 1w REG ... /tmp/test.log (deleted)   ← 这条
```

**`df` 显示满，`du` 找不到大文件。** 这个坑能查两小时。

**③ 只按大小切，你无法"打开上周三的日志"**

```text
size 100M rotate 3 → 最多 300M → 生产环境可能只覆盖 3 天
而且那 3 天是被切碎的片段
```

**④ 按天切之后，"跨天"这件事要处理**

```text
进程一直在跑 → 到 00:00 时它不换文件 → 今天的日志还写在昨天的文件里
```

**所以 `maybeRotate()` 必须在每次 write 时检查日期，不能只靠定时器。**

**⑤ 日志写失败会导致进程崩溃**

```javascript
stream.write(...)   // 磁盘满 → 抛 'error' 事件 → 没 handler → 进程退出
```

**"日志写失败导致服务崩溃"是最讽刺的一种事故。**

**⑥ 死循环里 `log.error` 会秒满磁盘，而且淹没真日志**

**限流是必须的。** 但在调试时会烦你 —— 所以只在 error 级以上启用。

**⑦ `grep` 多天日志要加 `-h`**

```bash
grep -h 'tr_xxx' logs/app-*.jsonl
#    ↑ 不加会看到一堆 logs/app-2026-11-15.jsonl:... 前缀
```
