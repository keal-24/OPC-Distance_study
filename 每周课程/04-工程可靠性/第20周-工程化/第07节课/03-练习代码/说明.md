# 03-练习代码

**这个文件夹故意留空。**

今天要建：

```text
你的项目/
├── CONVENTIONS.md            八条约定，每条有检查编号
├── README.md                 五问 + "我要改 X" 导航表
├── scripts/
│   ├── lint.js               C1–C8 检查
│   ├── lint-baseline.json    （可选）历史违规快照
│   └── install-hooks.js      （可选）安装 pre-commit
└── .git/hooks/pre-commit     提交前跑 lint
```

## 八条约定（每条都能 grep）

| 编号 | 约定 | 检查 |
|---|---|---|
| C1 | 禁止 utils/helpers/common/misc | 文件名黑名单 + 300 行上限 |
| C2 | 目录不超过 4 层 | 路径深度 |
| C3 | 禁止硬编码 key/端口/路径/URL | 正则（config 例外） |
| C4 | `process.env` 只在 config 里 | 正则（config 例外） |
| C5 | 禁止 `console.log` | 正则（scripts 例外） |
| C6 | 禁止裸 `throw new Error` | 正则（lib 例外） |
| C7 | SQL 只在 `app/repos/` | 正则（repos/db.js 例外） |
| C8 | 源码不许有真实 PII | 手机号/身份证正则 |

## 必须自己观察的七件事

**① 第一次跑一定是 30–100 处**

**不要试图一天修完。** 那 100% 会失败。

**用 baseline：把当前的都记成"历史遗留"，规则变成"新增零容忍"。**

**② lint 脚本会报自己**

```text
scripts/lint.js 里有 console.log
scripts/dangerous.js 里有 SQL 拼接
```

**所以白名单 `scripts/` 必须有。** 这是所有 lint 工具的第一个问题，**大部分人在这里就放弃了。**

**③ `app/config` 必须放过 C3/C4**

**config 的职责就是读 `process.env` 和写具体值。** 不放过就是自相矛盾。

**④ 每类只显示 10 条**

```text
输出 200 行 → 你不想看 → 关掉 → 永远不修
输出 10 行  → 修完这 10 条 → 再跑 → 又有 10 条 → 有进度感
```

**"可被修复"是好工具的核心特征。**

**⑤ pre-commit 最常见的失败是"设了但没生效"**

```text
① 文件没有可执行权限 → chmod +x
② .git/hooks 不进版本库 → 换电脑就没了
③ Windows 上 hooks 需要 bash → Git Bash 提供
```

**必须实测：造一个违规，看提交是否被拒。**

**⑥ `console.log` 在应用代码里必须清零**

因为它：不走日志文件、没结构、没 trace_id、没脱敏。

**四件事全丢。**

**⑦ "我要改 X"表比目录说明值钱十倍**

```text
目录说明："app/services/ 是业务规则"
→ 你知道该去那，但不知道去哪个函数

"我要改 X"表："分类规则 → decideCategory"
→ 5 秒定位
```
