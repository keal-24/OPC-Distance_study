今天要建（或改造）你的整个项目目录：

```text
你的项目/
├── app/
│   ├── index.js              程序入口（起服务、挂中间件、挂路由）
│   ├── config/index.js       所有会因环境而变的值
│   ├── routes/tickets.js     只解析参数 + 调 service + 拼响应
│   ├── services/
│   │   ├── ticket.js         业务规则（纯函数 + 少量编排）
│   │   └── prompt.js         读提示词（带缓存）
│   ├── repos/ticket.js       只碰数据库
│   ├── lib/
│   │   ├── db.js             连接 + 建表
│   │   ├── logger.js         结构化日志（第132节）
│   │   ├── model.js          模型调用（第128/129节）
│   │   └── redact.js         脱敏
│   ├── middleware/
│   │   ├── trace.js          trace_id
│   │   └── error.js          统一错误 + wrap
│   └── errors/index.js       错误码表 + AppError
├── .env                      不提交
├── .env.example              提交（只有名字）
├── prompt.txt
└── package.json
```

## 搬的顺序不能换

```text
config → lib（logger/db/model）→ repos → services → routes → index.js
```

**因为后面的依赖前面的。** 反过来搬，你会到处写临时空实现，然后再改一遍。

## 必须自己观察的七件事

**① 先打 tag 再动手**

```bash
git tag before-refactor
```

**没有这个，你会在第 60 分钟陷入"改也不好、退也不好"的地狱。**

**② 重构最容易犯的错是"顺手改了逻辑"**

今天只做搬家，**行为一点都不能变**。

```text
搬家 + 改逻辑一起做 → 出 bug 你分不清是哪一步
搬家单独做         → 出 bug 一定是搬家搬错了
```

**这也是为什么第 7 步要故意搞坏三次 —— 你要验证"错误的边界是清晰的"。**

**③ `Number("") === 0`**

`PORT=` 会得到 0（随机端口），然后你访问 3000 打不开，查半小时。

**所以 `num()` 必须检查 `isFinite`，而不是 `!== undefined`。**

**④ 忘了 `wrap` 会让请求挂住，不是报错**

Express 4 不捕获 async 函数的 rejection。**症状是"用户一直转圈"，不是"看到错误"。**

**这个症状极难排查** —— 因为日志里什么都没有（异常根本没被记录）。

**⑤ `services` 里不能出现 SQL**

```bash
grep -n "SELECT\|INSERT\|UPDATE" app/services/*.js
```

**有输出就说明分层没做到。** 因为换数据库时你要改业务代码。

**⑥ `services` 的核心函数不能接收 `req`**

```javascript
decideCategory(req)              // ❌ 第21周无法单测
decideCategory(text, modelSaid)  // ✅ 十行就能测
```

**传 `req` 意味着你测一个分类函数要构造一个 HTTP 请求对象。**

**⑦ `prompt` 缓存的代价是"改提示词要重启"**

**不写进 NOTES，你会在某次改完提示词测试没变化时，怀疑自己半小时。**
