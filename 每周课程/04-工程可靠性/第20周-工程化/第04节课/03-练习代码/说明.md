## 统一结构

```json
{
  "ok": false,
  "code": "TOO_LONG",
  "message": "消息太长了，请用几句话简述问题",
  "hint": "上限 4000 字",
  "trace_id": "tr_20261116_8f3a2b1c"

```

**四个字段的分工：**

```text
code      给程序看（if / switch）
message   给人看（一句话，能进 toast）
hint      告诉人怎么办（可以长）
trace_id  给你看（定位用）
```

**`detail` 不在里面** —— 它只进日志。

## 必须自己观察的七件事

**① `errorMiddleware(err, req, res)` 只有三个参数会静默失效**

Express 靠 `fn.length === 4` 识别错误中间件。**少一个参数它就是个普通中间件，永远不会被错误触发。**

**没有报错，你只会发现"我的错误处理好像没生效"。这个 bug 能查一下午。**

**② `res.ok` 不能判断成功**

```javascript
202 → res.ok === true   ← 但业务上"还在处理"
```

**所以每个响应都有 `body.ok` 字段，前端用 `body.ok` 判断。**

**③ `rev.body` 不能记进日志**

```text
req.body 里可能有：客户原话（含手机号）、密码、token
→ 记了就等于把第 132 节的脱敏全部作废
```

**只记 `body_bytes`** —— 足够你知道"30 字节"还是"200KB 粘贴"。

**④ 4xx 记 warn，5xx 记 error**

**全部记 error 的后果：错误日志里 90% 是"用户输错了" → 真正的 bug 被淹没 → 你开始不看 error 日志。**

**⑤ `headersSent` 必须单独处理**

```text
你已经 res.write 了一部分流式响应 → 出错
→ 再 res.status(500).json() → 抛 "Cannot set headers after they are sent"
→ 又进中间件 → 无限循环
```

**⑥ `res.json()` 本身会抛错**

```javascript
const a = { name: "a" }; a.self = a;    // 循环引用
res.json(a);                             // TypeError: Converting circular structure
```

**这个错误进中间件 → 中间件里又 res.json → 又抛。必须自己兜一层。**

**⑦ 流式接口不能用全局错误中间件**

**因为响应头已经发出去了。** 必须自己 try/catch，出错时写一条 `data: {"error":...}` 再 `res.end()`。
