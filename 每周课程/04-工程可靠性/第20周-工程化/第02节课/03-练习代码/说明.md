```bash
grep -rn "3000\|8080" app/ --include="*.js" | grep -v "config/"
grep -rniE "sk-|api[_-]?key|password|secret" app/ --include="*.js" | grep -v "config/"
```

## 必须自己观察的七件事

**① `Number("") === 0`**

`.env` 里写 `PORT=`（等号后为空），你的端口会变成 0，服务"启动成功"但监听在随机端口。

**现象：日志说 listening，浏览器打不开，查半小时。**

**② `Boolean("false") === true`**

```javascript
Boolean("false")  → true
Boolean("0")      → true
```

**如果你的代码是 `isProd: Boolean(process.env.PROD)`，那 `PROD=false` 会开启生产模式。**

**③ `"" ?? "默认值"` 得到 `""`**

`??` 只对 `null`/`undefined` 生效，对空字符串不生效。

**所以 `.env` 里写 `KEY_PRIMARY=` 会拿到空字符串，而不是默认值。**

**④ 有一类配置错了不报错，只是静默做错事**

```text
DB_FILE 指错  → 建了一个空库 → "数据不见了"  ← 最危险
LOG_DIR 指错  → 建了一个新目录 → 旧日志"消失"
KEY 错        → 调用失败 → 会报错（相对安全）
PORT 错       → 换个端口 → 可见
```

**DB_FILE 这一类必须用 `required()`，不能用默认值。**

**⑤ 半配置化比完全硬编码更危险**

```javascript
export const config = {
  dbUrl: "postgres://user:pass@localhost/app",   // 硬编码
  isProd: process.env.NODE_ENV === "production", // 读了环境
};
```

**这给了你"我已经配置化了"的错觉，实际上最危险的那个（数据库密码）还在代码里。**

**⑥ `dotenv` 默认只读 `.env`**

```bash
NODE_ENV=staging npm start
# 你以为读了 .env.staging，实际还是读 .env
```

**要用别的文件必须 `dotenv.config({ path: ... })`。**

**⑦ 密钥泄露的地方不止 git**

```text
[ ] .env.bak / .env.old
[ ] 部署脚本里的 cp .env
[ ] Docker 的 COPY . .（会把 .env 打进镜像）
[ ] 你发给别人看的截图
[ ] 崩溃日志里打印的 process.env
```
