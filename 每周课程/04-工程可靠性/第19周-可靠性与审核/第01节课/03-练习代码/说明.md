## `call.js` 必须先写对

```javascript
// reliable/call.js
// 所有模型调用都从这里走，方便统一超时/重试/计量

export function makeCaller(cfg) {
  let calls = 0;
  let tokens = { in: 0, out: 0 };

  return {
    async call(input, { temperature = 0, max_tokens = 400 } = {}) {
      calls++;
      const t0 = Date.now();
      const res = await fetch(`${cfg.baseURL}/chat/completions`, {
        method: "POST",
        headers: { "Content-Type": "application/json", Authorization: `Bearer ${cfg.apiKey}` },
        body: JSON.stringify({
          model: cfg.model,
          temperature, max_tokens,
          messages: [
            { role: "system", content: cfg.prompt },
            { role: "user", content: input },
          ],
        }),
        signal: AbortSignal.timeout(60_000),
      });
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
      const j = await res.json();
      tokens.in += j.usage?.prompt_tokens ?? 0;
      tokens.out += j.usage?.completion_tokens ?? 0;
      return { text: j.choices?.[0]?.message?.content ?? "", ms: Date.now() - t0 };
    },
    stats: () => ({ calls, tokens }),
  };
}
```

**为什么必须统一出入口：**

```text
① 采样要 3 倍调用，你得知道花了多少
② 第 129 节要加超时，改一处就够
③ 第 128 节要换模型，改一处就够
④ 第 132 节要记 trace，改一处就够
```

**如果你在三个地方各写一遍 fetch，后面四节你会改二十处。**

## 必须自己观察的七件事

**① 自报置信度是一条水平线**

加 `confidence` 字段，跑 10 条，看数字。**大概率有 8 条是 0.85 或 0.9。**

这不是置信度，是格式。

**② `temperature: 0` 的采样毫无意义**

三次必然一样。**你测出"100% 一致"然后以为自己做了个好东西 —— 实际什么都没测。**

必须改 0.7。

**③ `hard` 层的转人工率必须明显高于 `typical`**

```text
typical 20-30% / hard 60-80%   ← 对
所有层都 30%                    ← 闸门在瞎判
```

**这个梯度是闸门"在工作"的唯一证据。**

**④ 信号三的精度会让你失望**

大概率 20–40%。**真实工单里也有"已核实""相关部门"。**

**所以它只能当"触发采样"的弱提示，不能单独判死。**

**⑤ 中文数字是信号二最大的误报源**

输入"一千三百八"，输出"1380 元" → 你的归一化会判它"未落地"。

**误杀的最高频原因就是这个。** 做一次 `cnToNum` 能砍掉 2/3 的误杀。

**⑥ 转人工时不返回模型输出**

这条极容易违反，因为你觉得"给个草稿比较好"。**不是。**

用户看到"正在核实"会等；看到"客户反馈商品破损（核实中）"会直接用。

**⑦ 编造漏过率必须用判分器算，不能凭感觉**

你第 18 周已经有了 V1（编造）判定。**跑一遍，得出"基线 7 条 → 加闸门 2 条"。**

**没有这个前后对比，你今天做的东西没法证明有用。**
