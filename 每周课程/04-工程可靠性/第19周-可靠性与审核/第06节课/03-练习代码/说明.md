# 03-练习代码

**这个文件夹故意留空。**

今天要建：

```text
03-练习代码/
└── reliable/
    ├── redact.js        脱敏 + 摘要 + 指纹
    ├── log.js           结构化 logger（全局脱敏）
    ├── trace.js         trace_id 生成（短，能念出来）
    ├── vault.js         原文保险箱（加密 + 30 天过期）
    ├── stats.js         聚合统计（漏斗/失败/耗时/降级率）
    └── alert.js         三个阈值告警
```

**六个文件。今天最大的难点是"能查"和"不泄露"的平衡 —— 它决定你在 `vault.js` 上花多少功夫。**

## 核心矛盾

```text
要能查（出事时能复现）  ←→  不能记原文（日志变 PII 库）
```

**三条路都要用：**

```text
① 记指纹（hash）   → 能判断"是不是同一条"
② 记摘要（脱敏+截断）→ 能看出"大概在说什么"
③ 原文另存（加密+限期+审计）→ 真要复现时才解
```

## 必须自己观察的七件事

**① 你的日志现在查不出问题**

不是因为没记，是因为**没有 trace_id 关联**。

```text
[INFO] 收到请求
[INFO] 调用模型
[ERROR] 请求失败
```

**三行日志之间没有任何关系。30 条/分钟的并发下，你无法判断哪条属于哪个请求。**

**② `event` 必须可枚举**

```text
❌ "调用模型失败了，原因是超时"     → 无法 GROUP BY
✅ event:"call_fail" + kind:"first_byte_timeout"
```

**九个好过三十个。** 事件多了你就不看了。

**③ 脱敏必须在 logger 里统一做**

因为**你一定会忘**：

```text
第 127 节记了 input
第 129 节记了 error.message
第 131 节记了 row.input
→ 三处都要记得脱敏，忘一处就漏
```

**放进 logger 的 `emit` 里，一个循环兜住所有字符串字段。**

**④ 姓名脱敏的误伤率极高**

```text
"张三" → 容易识别
"东西" → 不是姓名但会被误判
"质量" → 同上
```

**所以姓名不强制脱敏，但要写清这是已知取舍。** 姓名本身不是《个人信息保护法》明确列举的敏感信息，电话/身份证/银行卡才是。

**⑤ trace_id 要被用户看见**

```text
没有：客户说"我昨天发的一条没回复" → 翻 24 小时日志
有：  客户把 tr_20261116_8f3a2b1c 发给你 → 5 秒定位
```

**而且有编号的系统看起来就"有人管"。**

**⑥ 8 位 trace_id 不加日期前缀会有 1.5% 年碰撞率**

```text
32 位空间 = 42 亿
一年 36.5 万条
碰撞概率 ≈ 1.5%/年
```

**加 `tr_20261116_` 前缀后降为 0（同日不超 42 亿条）。**

**⑦ 告警必须"比率 + 最小样本数"双条件**

```javascript
if (deg.n > 10 && deg.d / deg.n > 0.2)
```

**没有 `n > 10`：凌晨进来 1 个请求失败了 → 降级率 100% → 半夜被叫醒。**

**这个细节能救你一晚上的睡眠。**
