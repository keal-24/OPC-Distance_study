## 必须自己观察的七件事

**① `guardInput` 返回 `{ ok, blocking }`，两个含义不同**

```javascript
if (!gi.ok) return ...       // ❌ 误拦"只有弱信号"的条目
if (gi.blocking) return ...  // ✅ 只拦致命的
```

**这个错误会让你的 F4 通过，但误杀一批正常输入。**

**② F4 的验收标准不是"返回 400"，是"模型调用 0 次"**

```javascript
expect: { modelNotCalled: true }
```

**因为在入口拦掉 = 零成本零风险。如果模型还被调用了，你只是"事后拒绝了结果"，中间该花的花了，该泄的泄了。**

**③ F1 的事件序列里必须有 `call_fail`**

```text
req_in → guard_in → call_start → call_fail → call_start → call_end → guard_out → gate → req_out
                                   ↑ 最多人漏这个
```

**漏掉是因为在 `catch` 里只 `console.error`，没走 logger。**

**④ 单点最优，接起来会打架**

```text
F7（低置信）单独跑：11.2 秒（3 次采样）
F2（主超时）单独跑：11 秒
F2 + F7 叠加：8 + 3×3.6 = 18.8 秒   ← 用户不可接受
```

**这就是本节的核心发现。** 你必须自己碰到它。

**⑤ 并发采样把 3T 变成 T**

```javascript
// 串行 10.8 秒
for (...) await call();

// 并发 3.6 秒
await Promise.all([call(), call(), call()]);
```

**成本一样，耗时 1/3。** 这是解决 ④ 的最直接办法。

**⑥ `output` 可能是 null**

```text
超时的条目 → r.text 不存在
→ enqueue 时 output: r?.text ?? null
→ 不处理会存成字符串 "null"，复核界面显示 "null"
```

**⑦ 队列满的时候会发生什么，你测了吗**

```text
这是"未覆盖"清单里最该写的一条。
1000 条待处理 → 界面查询变慢 → 你 25 天才能清空 → 彻底失控
```

**正确做法是"队列过载时降级"** —— 只让 redo 类进队列，其余放行。**和主备切换同一个思路。**
