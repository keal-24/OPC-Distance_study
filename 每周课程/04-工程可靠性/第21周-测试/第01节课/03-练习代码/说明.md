# 03-练习代码

**这个文件夹故意留空。**

今天不写测试代码。只写一个文件：

```text
你的项目/
└── TEST-PLAN.md      测试计划（八个待测点 + 用例表 + 五条禁令）
```

## `TEST-PLAN.md` 的五块

```text
① 排序表：八个待测点，按"代价 × 频率"排
② 每个待测点的用例表（至少一个写完整）
③ 五条禁令 + 反例
④ 明确不测清单
⑤ 测试数据方案（内存库）
```

## 必须自己观察的七件事

**① 单次代价最大的，不是最该优先测的**

```text
judgePII     单次 2000 元，日频 0.003 → 月 20 元
decideUrgency 单次 5 元，日频 10     → 月 1500 元
```

**差 75 倍。** 只看"单次最贵"，你会把一周花在 PII 上，而每天在流血的分类规则没人管。

**② "会变"这一条本身就该提高优先级**

```bash
git log --oneline --follow -- app/services/ticket.js | wc -l
# 20 次 → 会不停改 → 必须测
```

**改得越多，越值得测。** 因为测试的价值是"让你敢改"。

**③ 从 11 个砍到 8 个，这一步比加法重要**

```text
不砍 → 你想"都测一点" → 每个都测两条 → 每个都不够
砍掉 → 八个里四个写透 → 真正抓到 bug
```

**"该测什么"的真实过程是减法。**

**④ 边界三连（499/500/501）能抓住 `>=` 写成 `>`**

```javascript
if (Number(amount) >= 500) return "high";   // 499→medium, 500→high
if (Number(amount) > 500)  return "high";   // 500→medium  ← 这个错
```

**用 600 和 100 永远测不出来。**

**⑤ 类型异常里藏着两个静默错误**

```javascript
Number(null)  === 0        ← 不报错，得到 0
Number("abc") === NaN      ← 不报错，NaN >= 500 是 false
```

**两个都不抛异常，静默给出错误的业务判断。**

**⑥ 优先级冲突用例是最值钱的**

```javascript
it("投诉关键词优先于金额门槛", () => {
  assert.equal(decideUrgency("我要投诉，才 20 块", 20), "high");
});
```

**它保护的不是 bug，是一个决策。** 三个月后你把条件顺序调了，这条会失败，你会停下来想"当初为什么这么定"。

**⑦ 覆盖率不衡量"情况被验证"**

```javascript
function decideUrgency(text, amount) {
  if (amount >= 500) return "high";
  return "low";
}
// 一条测试：decideUrgency("", 600) === "high"
// 覆盖率：50%（两个分支走了一个）
// 但如果再跑 decideUrgency("", 0) === "low"
// 覆盖率：100%（但 499/500 的边界从没验证过）
```

**100% 覆盖率 + 边界没测 = 有 bug 且你不知道。**
