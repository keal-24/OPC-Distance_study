## 断言的分寸（这是今天的核心）

```text
✅ 断言什么：
  · HTTP 状态码
  · body.ok / code
  · 字段存在性和类型
  · 枚举值在允许范围内
  · trace_id 格式和一致性
  · 库里的 input 和发出去的一字不差

❌ 不断言什么：
  · category === "quality"（那是 helper 里硬编码的）
  · summary 的具体文字（那是模型的输出）
  · 耗时（除断言的超时外）
```

## 必须自己观察的七件事

**① 断言 `category === "quality"` 是零信息量**

因为假上游返回的就是你硬编码的 `"quality"`。

**这条测试验证的是"helper 和断言写的一样"，不是"你的代码对"。**

**② 边界双测（4000 / 4100）能抓住 `>=` 写成 `>`**

```javascript
if (input.length > 4000) fail("TOO_LONG");    // 正确：4000 放行
if (input.length >= 4000) fail("TOO_LONG");   // 错误：4000 被拦
```

**只测 4100 永远发现不了。**

**③ 用 `spawn` 而不是 `import`**

```text
import → 同进程 → 端口冲突、日志混、状态难清
spawn  → 独立进程 → 全新状态、能真的 kill、能验证启动校验
```

**④ 等日志信号，不用 sleep**

```javascript
if (!settled && out.includes("配置检查通过")) resolve(...);
```

`sleep(1000)` 在慢机器上会失败，在快机器上会白等。

**⑤ 断网测试是唯一能证明"你真独立"的方法**

**不测 → 你总有一天会在 CI 上发现真相，那时你已经习惯"重跑一下"。**

**⑥ 动态端口（`port: 0`）解决并行冲突**

```javascript
srv.listen(0, "127.0.0.1", () => {
  const actual = srv.address().port;
});
```

**不改成随机端口，你加第二个测试文件就会撞端口。**

**⑦ 换行保留那条测试必须写**

```javascript
const input = "第一行：坏了\n第二行：退款";
assert.equal(row.input, input);
```

**很多"输入被处理"的 bug 出在 `trim()` 整个字符串、JSON 序列化转义、数据库截断。**
**而客户提交多条投诉时，换行是唯一的分隔手段。**
