**这个文件夹故意留空。**

今天要建：

```text
你的项目/
├── RELEASE.md              上线清单（12 项：9 自动 + 3 人工）
├── scripts/
│   ├── preflight.js        九项自动检查
│   └── rollback.sh         回滚到上一个 release tag
└── package.json            加 preflight / release
```

## 一条命令

```bash
npm run preflight
```

**9 项自动检查，全绿才继续。任何一项红，退出码 1。**

## 九项自动检查

| # | 检查 | 跳过会怎样 |
|---|---|---|
| A1 | `npm test` 全绿 | 带着已知 bug 上线 |
| A2 | lint 零违反 | 硬编码 key 被提交 |
| A3 | 无真实 key | key 泄露到 git |
| A4 | `.env` 不在 git | 同上 |
| A5 | `/health` 可达 | 上线即挂 |
| A6 | 生产配置三项形状 | 连错库 / debug 日志 |
| A7 | 提示词与代码枚举一致 | 某类别永远不生效 |
| A8 | 测试集没被改 | 历史分数不可比 |
| A9 | lock 文件已提交 | 服务器装到不同版本 |

## 必须自己观察的七件事

**① 清单超过 12 项你一定会跳**

```text
30 项 → 40 分钟 → 第 3 次开始跳 → 第 5 次不看
12 项 → 5 分钟  → 每次都做
```

**12 是认知负荷的硬限制，不是随便定的。**

**② 能自动化的必须自动化，不要写进清单**

```text
"记得检查数据库连接" → 永远不会被执行
A6（读 .env.production 检查形状）→ 3 秒自动跑完
```

**写"记得做 X"的人，其实是在承认"我做 X 时经常忘"。正确做法是做成脚本。**

**③ A7（枚举一致）是最容易出错的地方**

```text
你给数据库加了 complaint
→ 改 ticket.js 的 CATEGORIES
→ 改数据库约束
→ 忘了改 prompt.txt
→ 模型永远不返回 complaint
→ 你以为"这个类别没人用"
```

**这一项能抓住它。**

**④ A8 检测"测试集被偷改"**

```bash
git diff eval-v1 -- eval/cases.jsonl | grep '^-'
```

**第 121 节讲了"只加不改"。但你会偷改（"就改这一条"），然后历史分数全废。**

**⑤ "跳过会怎样"这一列让你能理直气壮地跳**

```text
A9 跳过 → 后果轻 → 赶时间可以跳
A6 跳过 → 数据丢失 → 绝不跳
```

**没有这一列，你不知道哪些能跳，最后全部跳掉。**

**⑥ "部署成功 ≠ 发布成功"**

```text
部署成功 = npm start 没报错
发布成功 = 用户能正常用
```

**差的三件事，10 分钟能确认：**

```text
① /api/admin/env → 连的是生产库，行数不是 0
② 日志无新错
③ 事件漏斗有请求进来
```

**⑦ 数据回滚比代码回滚难十倍**

```text
只改代码 → git 回滚就够
加列/表  → 保留（反向迁移风险大），代码不再用它 ← 最优解
删了数据 → 只能从备份恢复，有丢失窗口
```

**规则：永远不改变已有字段的语义，只加新字段。这条能救你。**
