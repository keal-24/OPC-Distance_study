## 为什么要先做 mock

```text
管道错 + 模型错，两件事一起调，你分不清是谁的错。
先让 mock 跑通，再接真模型 —— 真出问题时你立刻知道"管道是好的"。
```

**这个习惯要跟着你一辈子。** 任何一个"我调别人的服务"的功能，**先做一个假的上游。**

## 必须自己观察的五件事

**① 首字耗时 vs 总耗时**

```text
首字 0.4 秒 / 总 3 秒
```

**用户体验看的是第一个数字，成本看的是第二个。** 别拿"总时长"去优化"感觉慢"。

**② Network 里 Size 持续增长**

**静态的 Size 说明没有在流。** 一直在变才叫流式。

**③ 中文乱码只在真模型上出现**

mock 的字是单独的，真模型的 chunk 可能切在半个汉字上。**这是 `{ stream: true }` 存在的理由。**

**④ `[DONE]` 出现之后页面停止**

如果 `[DONE]` 之后还在追加内容，说明你的循环没退出。

**⑤ 出错时的页面状态**

把 key 改错再跑一次，**页面必须显示错误，不能一直转圈。**
