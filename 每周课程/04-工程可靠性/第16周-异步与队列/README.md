# 第16周 · 异步与队列 · 第 106—112 节课

## 长任务不卡死、失败能重跑、到点能自己跑

---

## 这一周的目标

前 15 周你写的所有接口都是**"请求进来，等结果，返回"**。这个模型有个硬上限：

```text
一次请求能撑多久？  用户能等多久？
```

用户等不了 30 秒，网关撑不过 60 秒，你的进程还占着内存。**超过 10 秒的活，就不能让请求等着。**

这一周要做到六件事：

1. **分清同步和异步** —— 知道什么时候进程被卡死，什么时候只是"等着"；
2. **判断哪些活必须挪到后台** —— 不是所有慢接口都要改，会算那条线；
3. **设计一张任务表** —— 状态机、原子认领、防重复执行；
4. **失败会重试，重试有上限，超了进死信** —— 不用人盯着；
5. **定时任务跑得对** —— 时区不错、多个进程不会重复跑；
6. **用户看得见进度** —— 提交完给个任务号，轮询查状态。

## 为什么排在这一周

第 16 周是新阶段的开始。前面你一直在"加功能"，从这周开始**加的是"能不能交付"**。

真实场景：

```text
客户说：上传 200 页 PDF，帮我提取要点
你写的接口：同步等 40 秒 → 浏览器转圈 → 网关 502 → 客户点第二次 → 你又跑一遍 → 客户的 token 被烧两倍
```

**这不是性能问题，是架构问题。** 同步接口做不了长任务，加机器也没用。

**这一周就是那条分界线：从"能跑"到"能交付"。**

## 这一周要改一个旧习惯

前 15 周你的接口长这样：

```javascript
app.post("/api/summarize", async (req, res) => {
  const result = await callModel(req.body.text);   // 等 40 秒
  res.json({ result });
});
```

这周之后长这样：

```javascript
app.post("/api/summarize", async (req, res) => {
  const job = createJob("summarize", req.body);    // 只写一行数据库，5 毫秒
  res.json({ jobId: job.id });                      // 立刻返回
});
```

**干的活一点没少，只是不再让用户站在门口等。**

## 这一周的技术选型（先说清楚，别乱搜）

你会搜到一堆教程让你装 Redis + BullMQ。**这周不装。**

| 方案 | 需要什么 | 这周用不用 | 什么时候用 |
|---|---|---|---|
| 数据库当队列（SQLite 表 + worker 进程） | 什么都不用装 | **用这个** | 一台机器、每天几万任务以内 |
| BullMQ + Redis | 装 Redis（Windows 上还得 WSL/Docker） | 不用 | 多台机器、任务量上去之后 |
| 云队列（SQS 等） | 云账号 + 钱 | 不用 | 不想自己维护 Redis 的时候 |

**理由：** 你现在只有一台机器、一个客户。**用数据库当队列，能在 Windows 上今天下午就跑起来，而且你会真正理解队列在干什么。**

第 29 周装了 Docker 之后，把 worker 换成 BullMQ 只是替换 100 行代码 —— **概念是一样的，概念才是要学的。**

## 这一周的四条铁律

```text
一、worker 必须是独立进程。
    不要写在 Express 里，不要用 setInterval 硬塞。
    API 挂了 worker 还能跑，worker 挂了 API 还能接任务。

二、认领任务必须是一条原子 SQL。
    先 SELECT 再 UPDATE 是错的——两个 worker 会同时抢到同一个任务。

三、每个任务必须有 attempts 和 max_attempts。
    没有上限的重试等于死循环。

四、写数据库的地方，就要想幂等。
    重试是必然会发生的，重复执行一次会不会多扣一次钱，你必须能回答。
```

## 这一周最容易白干的三件事

**第一：把 `await` 当成"异步"**

`await` 只是写法。你写 `await sleep(20000)`，进程确实没卡，但**用户的浏览器还卡着 20 秒**。第 107 节会把这个区别钉死。

**第二：以为加了队列就快了**

队列不加快任何东西。它只是**把等待从用户身上挪到后台**。原本 40 秒还是 40 秒，只是用户不用盯着。

**第三：忘了 worker 是自己起的进程**

`node worker.js` 关掉终端就没了。**这个进程要跟 API 一样常驻**（第 31 周讲怎么让它开机自启）。
