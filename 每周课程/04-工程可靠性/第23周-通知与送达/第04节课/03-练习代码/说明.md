## 四个 SMTP 码的分工

```text
550 / 551 / 554  → HARD    不重试，进抑制名单
552              → SOFT    重试（邮箱满）
421 / 450        → SOFT    重试（临时拒收）
EAUTH            → FATAL   不重试，要人看
ECONNECTION 等   → TRANSIENT 重试
```

## 必须自己观察的七件事

**① 552 是软退，不是硬退**

```text
550 User unknown   → 地址不存在 → 硬退
552 Mailbox full   → 地址存在但满了 → 软退（腾出空间就能收）
```

**一刀切把 5xx 全当硬退，会让"邮箱满"的客户永远收不到你的邮件。**

**② 硬退重试的代价是"全部用户"**

```text
1 万地址，200 个无效
重试 3 次 → 800 次无效 SMTP 请求
→ 你的 IP 被列入灰名单
→ 剩下 9800 个正常地址的邮件也开始进垃圾箱
```

**③ 预算检查必须在"等待"之前**

```javascript
// ❌ 白等 16 秒然后放弃
await sleep(16000);
if (elapsed > budget) return;

// ✅ 先算再等
if (elapsed + wait > budget) return;
await sleep(wait);
```

**④ 硬退只消耗 1 次 attempt**

```text
HARD / FATAL → 立刻返回，不进重试循环
→ 日志里能看到 attempt=1，耗时 12ms（没有等待）
```

**⑤ 只有 HARD 进抑制名单**

```text
SOFT 重试耗尽 → 不进（对方可能只是忙）
FATAL        → 不进（是我们的配置问题）
```

**这条判断错了，会把"暂时联系不上"的客户永久拉黑。**

**⑥ `skipped: true` 不是失败**

```text
skipped → 不该发（地址无效/已退订），不是错误
failed  → 该发但没发成
```

**混在一起，你的统计里"失败率"会包含"本来就该跳过的"，失真。**

**⑦ 退信里有两个 Message-ID，取最后一个**

```text
① 退信通知自己的
② 退信里"附带的原邮件"的 ← 这个才是你要的
```
