## 三条记录

```text
TXT @                        "v=spf1 include:_spf.provider.com -all"
TXT s1._domainkey            "v=DKIM1; k=rsa; p=MIIBIjAN..."
TXT _dmarc                   "v=DMARC1; p=none; rua=mailto:dmarc@yourdomain.com"
```

## 必须自己观察的七件事

**① 两条 SPF 记录 = 完全没有 SPF**

```text
v=spf1 include:a.com -all
v=spf1 include:b.com -all
→ permerror → 所有 SPF 验证失败
→ 比"没有 SPF"更糟
```

**正确：合并成一条。**

**② DKIM 比 SPF 更重要（对齐）**

```text
From:        noreply@yourdomain.com      ← 用户看到的
MAIL FROM:   bounce@provider.com         ← SPF 检查的
→ SPF pass 但与 From 不对齐 → DMARC 失败
→ 只有 DKIM（d=yourdomain.com）能与 From 对齐
```

**③ 不能一上来 `p=reject`**

```text
你还没配好所有合法发信源的 SPF/DKIM
→ reject 会把它们全拒掉
→ 包括"用户注册验证码"
```

**必须走四阶段：none → quarantine 10% → quarantine 100% → reject。**

**④ `rua` 必须填，否则等于闭眼**

```text
没有 rua → 收不到 DMARC 报告
→ 不知道"谁在冒用你"
→ 也不知道"哪些信被拒了"
```

**⑤ 配好三条只是入门，信誉才是门槛**

```text
新域名 → 信誉从零 → 大量进垃圾箱
需要 2–4 周，通过"小量稳定发送 + 低退信率"积累
```

**⑥ `example.com` 只配了 SPF（`v=spf1 -all`）**

```text
含义："任何 IP 都不许代表 example.com 发信"
这是正确配置（它不发信）
```

**⑦ 必须真的收一封邮件才能看到验证结果**

```text
Authentication-Results 是收件方写的
→ 你不能自己证明自己
→ 所以第 155 节的假 SMTP + 真实 Gmail 都是必需的
```
