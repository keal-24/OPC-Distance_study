## 必须自己观察的七件事

**① `Authentication-Results` 只出现在收到的邮件里**

```text
你发出的邮件：没有这个头
收件方收到后：加上这个头，告诉你"验证结果"
```

**所以你必须有一个"能收"的地方 —— 这就是假 SMTP 的唯一理由。**

**② `Subject` 是 RFC 2047 编码**

```text
=?UTF-8?B?5oKo55qE6aqM6K+B56CB5pivIDEyMzQ1Ng==?=
```

**解码：`Buffer.from(...,'base64').toString()`**

**SMTP 头部只允许 ASCII，中文必须编码。**

**③ `multipart/alternative` = 同一内容的多种格式**

```text
客户端选"最好的那个"显示
HTML 客户端 → HTML
纯文本客户端 → text
```

**两个版本内容必须一致**（反垃圾会检查）。

**④ `messageId` 是唯一能追一封邮件的标识**

```text
退信通知里带 original message-id
查状态按 message-id
算送达率按 message-id 去重
```

**没有它，你只有"时间 + 收件人"，都不唯一。**

**⑤ 550 被 nodemailer 转成 `EENVELOPE`**

```javascript
{ ok: false, code: "EENVELOPE", responseCode: 550 }
```

**要靠 `responseCode`（550 vs 421）区分硬退/软退，不是靠 `message`。**

**⑥ `console.log("邮件已发送")` 会骗你三个月**

**它只证明"fetch/await 没抛错"，不证明"发出去了"。**

**⑦ `MAIL_FROM` 用 `.test` 域名**

```text
noreply@yourdomain.test
```

**`.test` 是保留顶级域，永远不会真实投递 → 测试时绝对安全。**
