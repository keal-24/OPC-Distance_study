## 四条健康线

```text
送达率      > 95%      ← 90% 是"需关注"，不是"还不错"
硬退信率    < 2%
投诉率      < 0.1%     ← 最严的一条
状态覆盖率  > 85%      ← 低说明回执挂了，不是送达失败
```

## 必须自己观察的七件事

**① 90% 在邮件领域不是高分**

```text
其他行业 90% → 优秀
邮件行业 90% → 需关注（健康线 95%）
```

**数字的"高低"取决于行业基准。**

**② `delivered` 不等于"进收件箱"**

```text
delivered = 收件方服务器接受了
→ 可能进收件箱、垃圾箱，或被静默丢弃
→ 真实进箱率通常比送达率低 10–20 个百分点
```

**所以你能承诺"送达率 95%"，不能承诺"95% 的用户会看到"。**

**③ 整体数字会掩盖局部**

```text
整体投诉率 0.05%（健康）
营销类投诉率 3%（远超健康线）

→ "整体健康"掩盖了"营销必须停"
```

**必须按类别拆开。**

**④ `pending` 高 ≠ 送达率低**

```text
pending > 50% → 是"没有状态回执"
              → 去查 webhook / 轮询
              → 不是去查 SPF/DKIM

不区分的话，你会花 2 小时查 DNS，实际问题在 webhook。
```

**⑤ 分母要排除"被跳过的"**

```text
抑制名单里的是"从没发出去"（skipped）
不计入 mail_log
→ 所以 mail_log 的 COUNT 已经是"实际发了多少"
```

**⑥ 健康检查的判定逻辑本身会写反**

```javascript
// 送达率是"越高越好"
c.val >= c.good ? "✅" : ...

// 退信率是"越低越好"（invert）
c.val <= c.good ? "✅" : ...
```

**写反了会让你"退信率 20% 也显示 ✅"。**

**⑦ 投诉率 > 0.1% 是 P0，不是 P1**

```text
退信率高 → 服务商警告
投诉率高 → 服务商可能直接暂停你的发信权限
```

**投诉是"用户主动说你是垃圾"，最直接的信号。**
