## 七个状态

```text
submitted → accepted → delivered → opened
     ↓          ↓          ↓
   bounced    bounced   bounced / complained
     ↓
   failed
```

**终态：bounced / complained / failed / opened（opened 之后只能到 complained）**

## 必须自己观察的七件事

**① `delivered` 只证明"服务器收下了"**

```text
可能进收件箱、垃圾箱，或者被静默丢弃
→ 状态到 delivered 就该停
→ 不要编造"已送达收件箱"
```

**② `delivered → bounced` 必须允许**

```text
时间线：
  T1 250 accepted
  T2 250 delivered
  T3 反垃圾判定垃圾 → 退回 → 你收到退信
```

**不允许的话，T3 的退信会被忽略，状态永远停在 delivered。**

**③ `opened → delivered` 必须拒绝**

```text
打开了 = 一定投递了
后到的 delivered 事件应该"忽略"而不是"倒退"
```

**④ webhook 必须用 `express.raw`**

```text
签名是对"字节"算的
json() 解析再序列化 → 字段顺序/空格可能变 → 签名验证必失败
```

**⑤ 签名错返回 401，处理失败返回 200**

```text
401 → 请求不是服务商发的，不该接受
200 + handled:false → 事件收到了但处理不了，别让服务商重试
```

**返回 500 会让服务商重试 N 次，并可能停掉回调。**

**⑥ 事件流水（mail_event）不能省**

```text
mail_log 只有"当前状态"
mail_event 有"每次变化的来源和时间"
→ 排查"为什么变成 bounced"必须看流水
```

**⑦ 状态覆盖率是健康指标**

```text
(delivered + bounced + opened) / total 应该 > 85%
低于 50% → webhook 或轮询有问题
```
