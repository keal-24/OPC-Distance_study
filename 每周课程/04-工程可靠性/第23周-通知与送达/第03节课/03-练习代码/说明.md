## 三个防线

```text
① 渲染后检查残留占位符（{{x}} / ${x} / {x}）
② 变量值不能是 undefined / null / "undefined" / "null" / ""
③ 渲染失败 → throw，绝不发出半成品
```

## 必须自己观察的七件事

**① `String(undefined)` 是 `"undefined"`**

```javascript
render("尊敬的 {{name}}", { name: undefined })
// 简单实现 → "尊敬的 undefined"   ← 用户看到这个词
// 正确实现 → 抛错"变量 name 的值会渲染成 undefined"
```

**这是"废邮件"最常见的原因，而且它不报错。**

**② 必须用 `split().join()`，不能用 `replace()`**

```javascript
"价格 ${price}".replace("${price}", "$100")     // → "价格 00"（$1 被当捕获组）
"价格 ${price}".split("${price}").join("$100")  // → "价格 $100" ✅
```

**价格、代码这类值里 `$` 很常见。**

**③ 三种语法都要防残留**

```text
模板用 {{x}} 但代码传 { x: 1 } → 残留
模板用 ${x} 但渲染器只认 {} → 残留
```

**渲染后统一检查三种，才能兜住"混用"。**

**④ 链接必须验，因为"发出去了就不会知道是死的"**

```text
① 非 https → 用户浏览器警告，或者被邮件客户端拦截
② 域名不在白名单 → 可能是钓鱼（变量被污染）
③ 含 {token} / undefined → 链接是死的
```

**⑤ 静态检查 vs 真实探测，用在不同场合**

```text
静态检查 → 单元测试、CI（0 秒）
真实探测 → 发布前、每天巡检（25 秒）
```

**真实探测不能进 `npm test`** —— 它会让测试变慢且随机失败。

**⑥ "渲染失败"要 throw，"网关失败"返回 ok:false**

```text
渲染失败 = 代码/数据 bug → 重试也没用 → 必须炸出来
网关失败 = 外部服务问题 → 可重试（第 158 节）
```

**混在一起，你的重试逻辑会去重试"永远失败"的渲染错误。**

**⑦ 模板数量要控制，能用变量就别新建**

```text
"订单已发货" + "订单已签收" → 用一个模板 + {{status}}
```

**每多一个模板 = 多一处可能渲染失败 + 多一处可能审核不过。**
