# 第29周 · Docker · 第 197—203 节课

## 本地能跑，服务器上也能跑

---

## 这一周的目标

不只是"学会几个 Docker 命令"。你要能做到这五件事：

1. **装好 Docker Desktop，并知道它到底为什么装不上** —— WSL2、重启、虚拟化，这三件事各卡在哪儿；
2. **手写一个 Dockerfile**，把你的 `chat-app` 装进镜像，而且改一行代码不用重装依赖；
3. **把容器跑起来并能排查** —— 端口为什么连不上、日志在哪看、怎么进到容器里看文件；
4. **密钥不进镜像、数据不随容器消失** —— 这两件事做错一次，就是安全事故和数据丢失；
5. **用 compose 一条命令起 app + 数据库** —— 并且知道 `depends_on` 不等于"数据库已经好了"。

## 为什么排在这一周

第 28 周你交付了小程序和公众号。下一周（第 30 周）代码要交给机器自动构建，第 31 周要上服务器。

**在这两件事之前，必须先解决一个老问题：**

```text
你的电脑 Windows 11
   ├── Node 22.x
   ├── PostgreSQL 16
   └── 你手动装过的一堆东西，你自己都记不清
        ↓ 直接往服务器搬
服务器 Ubuntu 22.04
   ├── Node 18（版本不一样）
   ├── 没装数据库
   └── 少一个系统库 → 报错 ENOENT / GLIBC
```

**"我本地能跑"这句话，在交付现场等于零。** 因为你本地能跑的不是"你的项目"，是"你的电脑"。

Docker 干的事只有一件：**把"你的电脑"里跟程序有关的那一部分，打包成一个能整体搬走的文件。**

```text
你的电脑                          服务器
┌──────────────┐                ┌──────────────┐
│ docker build │ → 镜像 image → │  docker run  │
└──────────────┘      ↓         └──────────────┘
                 推到镜像仓库
                  （第 30 周学）
```

**两边跑的是同一个镜像。** 里面 Node 是几版、装了什么依赖，跟你电脑上装了什么完全无关。

**不学会会怎样：**

```text
第 30 周 CI 要 docker build  → 你没有 Dockerfile，卡住
第 31 周服务器部署           → 你只能一台一台手装环境，装一次错一次
第 34 周客户内网离线安装     → 没有镜像就没法交付，这个单子接不了
```

**这一周不是"多学一个工具"，是把后面 9 周的地基先打好。**

## 一个必须先讲清楚的规矩

这一周所有实验都在 `03-练习代码/` 里**单独建的目录**做，**不要在 `chat-app` 的正式目录里直接实验**。

因为这一周的命令里，有四类会真的删东西：

```text
docker system prune -a       删掉所有没用到的镜像、容器、构建缓存
docker compose down -v       连数据卷一起删（数据库里的数据没了）
docker rm -f $(docker ps -aq)  强删所有容器，不管它在干什么
docker build .               会把当前目录整个打包送给 Docker
                             如果目录里有 .env 和 node_modules，一起进去
```

最后一条最容易忽略：**`docker build .` 那个点，意思是"把当前目录全部上传给 Docker 引擎"。**

没有 `.dockerignore` 的话，你的 `.env`（里面有模型 API key）会被打进镜像层。**镜像能推到仓库、能被别人 pull 下来、能 `docker history` 一层层扒出来。**

所以第 2 节课的第一件事就是写 `.dockerignore`，第 4 节课会亲手验证"镜像里搜不到 key"。

## 这一周的四条铁律

这四条会跟着你到第 34 周做私有化部署：

```text
一、任何 docker build 之前，先看一眼 .dockerignore。
    里面必须有两行：node_modules 和 .env。
    少一行，你就可能把密钥打进镜像。

二、密钥永远只从外面注入（--env-file / env_file），
    永远不 COPY .env 进镜像。

三、端口映射 -p 3000:3000，左边是宿主机，右边是容器。
    讲反了的现象不是报错，是"页面打不开"，你会查两小时。

四、容器里的 localhost 指容器自己，不是你的电脑。
    compose 里访问数据库，主机名写服务名 postgres，不写 localhost。
```

## 这一周最危险的四个操作

**第一：`docker system prune -a`**

⚠️ 会删掉**所有没在运行的容器** + **所有没有被容器使用的镜像** + **全部构建缓存**。

跑一次，你的 `node:22` 基础镜像、你 build 了十次的 `chat-app` 镜像，全部没了，下次要重新拉几个 GB。

**第二：`docker compose down -v`**

⚠️ `-v` 的意思是"连数据卷一起删"。**你的 postgres 数据全在里面。**

想停服务用 `docker compose down`（不带 `-v`）。**多打一个字母，数据库回到出厂状态。**

**第三：`-v $(pwd):/app` 把整个项目挂进容器**

⚠️ 这不是删数据，但会把镜像里装好的 `node_modules` **盖掉**。现象是容器一启动就报 `Cannot find module 'express'`。

**第四：在 `chat-app` 正式目录里 `docker build .`**

⚠️ 如果 `.env` 在里面且没有 `.dockerignore`，key 就进了镜像层。**删掉镜像也没用，它已经存在于构建缓存里。**

**这四个不是"不能用"，是"用之前必须知道自己在干什么"。**

## 周末的验收

不要急着进下一周。先确认这几条：

- [ ] `docker run hello-world` 能跑通，`docker ps -a` 里能看到它
- [ ] 我的 `chat-app` 有 Dockerfile，`docker build -t chat-app:1.0 .` 能成功
- [ ] 改一行 `server.js` 再 build，输出里有 `CACHED`，说明依赖没有重装
- [ ] 容器跑起来后，浏览器 `http://localhost:3000` 能打开页面
- [ ] `.dockerignore` 里写了 `node_modules` 和 `.env`，并且我用 `docker run --rm ... grep` 验证过镜像里没有 key
- [ ] 我做过 volume 和 bind mount 两种挂载，数据活过 `docker rm`
- [ ] `docker compose up -d` 之后，`docker compose ps` 两个服务都是 `running`
- [ ] 我能用一句话解释"为什么 compose 里数据库主机名是 `postgres` 而不是 `localhost`"

**另外：**

- [ ] 每节课的 `NOTES.md` 都填了，没有大片空白
- [ ] 「卡在哪」那一栏写了真实内容（不是"没有卡住"）
- [ ] 我能用三句话讲清"镜像 / 容器 / 数据卷各是什么"

> **最后一条才是真标准。** 讲不出来，说明你只是把七节课的命令各敲了一遍，脑子里还是七个孤立的命令。
>
> **一周七节课，落一节课没关系，但第 2、6 节不能落。** 因为 Dockerfile 和 compose 是"能不能交付"的分水岭，其他几节都是围着它们转。

## 这一周不用学什么

明确排除，避免你分心：

```text
Kubernetes / k8s         第 7 阶段的事，你只有一台服务器，用不上
Docker Swarm             已经被 k8s 淘汰，别学
Podman / containerd      知道有这么个东西就行
K8s 的 Helm / Istio      用不到
自建私有镜像仓库          第 30 周用 GHCR，免费
docker-compose（带横线）   这是 v1，已停止维护。用 docker compose（空格）
Dockerfile 的多平台构建    只在给 M 系列 Mac 交付时才需要
镜像签名的完整体系         第 33 周安全那周提一句
```

**这一周只用命令行。** 因为报错信息全在命令行里，图形界面会把它藏起来。**你必须先看懂报错。**

Docker Desktop 的图形界面可以开着，但只用来看"容器是不是绿的"，不用来操作。
