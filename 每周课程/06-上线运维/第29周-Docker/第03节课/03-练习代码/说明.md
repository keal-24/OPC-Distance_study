## 本节课你要建什么

```text
03-练习代码/
├── chat-app-docker/          ← 第 2 节建的，这一节要改里面的 server.js
│   └── server.js             ← 只改 listen 那一行
└── 命令记录.md               ← 你自己建，贴端口/日志/exec 的真实输出
```

**唯一要改的代码，是 `server.js` 里 `app.listen` 那一行。**

```js
// 改前（如果原来是 127.0.0.1）
app.listen(3000, "127.0.0.1", ...)

// 改后
app.listen(3000, "0.0.0.0", ...)
```

**改完记得重新 build。** 只 `docker start` 是不会生效的。

## 为什么这一节没有新代码

因为这一节要学的是**运行时的行为**，不是语法：

```text
端口从哪进、从哪出
日志从哪看
怎么进到容器里
容器死了怎么查
```

**这些都不写在代码里。** 它们写在 `docker run` 的参数里，写在报错信息里。

## 这一节要留下的证据

| 证据 | 为什么重要 |
|---|---|
| `docker ps` 那行完整的 PORTS | 以后看端口映射就靠它 |
| `curl: (56) Connection reset by peer` 原文 | reset 和 refused 是两回事 |
| `curl: (52) Empty reply from server` 原文 | 这是 `-p` 右边写错 |
| `ps aux` 里 PID 1 是 node | 证明 `CMD` 用了 exec 格式 |
| `docker logs` 的 3 行真实输出 | 以后要知道日志长什么样 |

## 实验用的两个小心机

**① 制造 137：**

```bash
docker run -d --name oom-test --memory=32m chat-app:3.1
docker inspect --format '{{.State.ExitCode}} {{.State.OOMKilled}}' oom-test
```

**② 制造"起来就退出"：**

在容器里 `kill 1`，或者故意把 `CMD` 指向一个不存在的文件，重新 build。
