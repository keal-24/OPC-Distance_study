## 本节课你要建什么

```text
03-练习代码/
├── chat-app-docker/                 ← 第 2 节的副本，这一节要动它的 data/
│   └── data/
│       └── messages.json            ← bind mount 的目标
├── backup/                          ← 你自己建
│   └── chat-data-backup.tar.gz      ← tar 导出来的卷备份
└── 命令记录.md                      ← 贴 rm 前后的对比
```

## 两个目录的区别（别搞混）

| 目录 | 是干什么的 | 谁在用 |
|---|---|---|
| `chat-app-docker/data/` | **bind mount 的源**，你电脑上的文件 | 开发时调试 |
| `backup/` | **备份文件**，从卷里导出来的 tar | 出事时恢复 |

**`backup/` 里的 tar 不要改名，不要删。** 这是你练习"恢复"的唯一素材。

## 这一节不写新代码，但可能要改一处

**如果你的代码没有"目录不存在就创建"，容器第一次启动会报错：**

```text
Error: ENOENT: no such file or directory, open './data/messages.json'
```

**加上：**

```js
if (!fs.existsSync("./data")) fs.mkdirSync("./data", { recursive: true })
```

**为什么需要：** `data/` 在 `.dockerignore` 里被排除了，镜像里没有这个目录。挂载卷之后 Docker 会创建挂载点，但**第一次写入前**如果你代码直接 `readFileSync`，在目录还没建好时就会炸。

## 这一节要留下的证据

| 证据 | 证明什么 |
|---|---|
| `cat` 在 `rm` 前有内容、`rm` 后 `No such file` | 数据真的在可写层 |
| 挂卷后 `rm` 再 `cat` 还有内容 | 卷活过了容器 |
| `Mounts` 的 `Destination` 是 `/app/data` | 没被 Git Bash 翻译 |
| `tar tzf` 能看到 `./messages.json` | 备份是有效的 |
| 恢复后 `cat` 有内容 | 恢复流程走通了 |

## 这一节最容易出错的地方

```text
① Git Bash 把 /app/data 翻译成 C:/Program Files/Git/app/data
   → export MSYS_NO_PATHCONV=1

② 卷名写成 chat_data，结果新建了一个空卷
   → docker volume ls 看一眼

③ 挂 -v "$(pwd):/app" 忘了加 -v /app/node_modules
   → Cannot find module 'express'
```
