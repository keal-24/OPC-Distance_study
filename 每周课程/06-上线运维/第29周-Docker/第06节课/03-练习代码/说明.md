# 03-练习代码

**这个文件夹故意不留代码。** 这一节要新建一个 **compose 项目目录**，里面只有 yaml 和一个 `.env`。

---

## 本节课你要建什么

```text
03-练习代码/
├── chat-app-docker/            ← 第 2 节的镜像源，这一节不动它
├── chat-stack/                 ← 你自己建
│   ├── compose.yaml            ← 你手写
│   ├── .env                    ← 密码等变量（不进 Git）
│   └── app.env                 ← 应用自己的变量（可选，见 5.2）
└── 命令记录.md                 ← 贴三种"连不上"的报错
```

## 为什么 `chat-stack` 要单独一个目录

因为 compose 会**用目录名当项目名**：

```text
目录名 chat-stack → 网络名 chat-stack_default
                  → 容器名 chat-stack-postgres-1（如果你没写 container_name）
```

**这个项目名是"隔离边界"。** 两个不同目录的 compose 项目，默认互不干扰。

**所以不要把 `compose.yaml` 直接放在 `03-练习代码/` 根目录。** 那会让整个练习目录变成一个项目。

## `compose.yaml` 里必须有的东西

```text
① 两个服务：postgres、app
② postgres 的 volume（pg-data）
③ postgres 的 healthcheck（pg_isready）
④ app 的 depends_on（condition: service_healthy）
⑤ app 的 ports（"3000:3000"，带引号）
⑥ 不要写 version
```

## ⚠️ 这个目录里绝不能出现的东西

```text
❌ 真实的数据库密码（用 devpass 这种假值）
❌ 真实的 API key
❌ 提交到 Git 的 .env（.gitignore 要有它）
```

**练习用的密码写成 `devpass` 就行，别用你真实项目那个。**

## 这一节要留下的证据

| 证据 | 证明什么 |
|---|---|
| `docker network inspect` 的容器列表 | 名字和 IP 对得上 |
| `ECONNREFUSED 127.0.0.1:5432` 原文 | 容器里 `localhost` 是自己 |
| `ENOTFOUND postgresql` 原文 | 名字解析失败 |
| `compose ps` 里的 `(healthy)` | 健康检查生效 |
| `Restarting (1)` 的状态 | 没有 healthcheck 的后果 |

## 检验自己有没有真学会

- 为什么 `localhost` 在 app 容器里连不到 postgres？
- `depends_on` 保证的是什么？不保证什么？
- compose 的服务名和 `container_name` 有什么区别？
- compose 的 `.env` 和 `env_file` 指的 `.env` 是同一个吗？

**四题都答得出来再进第 7 节。** 第 7 节是收口，默认你这一节的东西都能跑。
