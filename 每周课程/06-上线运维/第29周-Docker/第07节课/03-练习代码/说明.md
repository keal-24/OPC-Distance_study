# 03-练习代码

**这个文件夹故意不留代码。** 这一节是第 29 周的收口，你要在这里留下**一个能一条命令起来的全栈项目**，加上三份证据。

## 本节课你要建什么

```text
03-练习代码/
├── chat-app-docker/          ← 第 2—5 节的镜像源，这一节先量它的基线
├── chat-stack/               ← 第 6 节的 compose 项目，这一节升级成最终版
│   ├── compose.yaml          ← 最终版：两个服务 + healthcheck + 版本 tag
│   ├── .env                  ← 变量（不进 Git）
│   ├── smoke.sh              ← 五条冒烟检查
│   └── 命令记录.md           ← 贴回滚前后的 ps 输出
└── 瘦身记录.md               ← 六条手段逐条试的大小表
```

## 这一节的四件正事

```text
① 量基线          docker images / docker system df -v
② 多阶段构建      从 1.2GB 干到 200MB 以下
③ 一条命令起全栈  docker compose up -d --build 之后 ./smoke.sh 通过
④ 回滚           改 tag + up -d，ps 里 IMAGE 真的变了
```

**四件都留下证据。** 没有证据的"我做过了"等于没做。

## `compose.yaml` 里必须有的东西

```text
① 两个服务：app、postgres
② app 的 image 用版本 tag（如 chat-app:${APP_VERSION:-local}），不许只用 latest
③ postgres 的 volume（pg-data，命名卷）
④ postgres 的 healthcheck（pg_isready）
⑤ app 的 depends_on（condition: service_healthy）
⑥ app 的 ports（"3000:3000"，带引号）
⑦ 不写 version 字段（现在的 compose 不认它了）
```

## `smoke.sh` 至少五条

```bash
# 提示：这五行是思路，不是让你复制
# 1. 进程活着吗
# 2. /health 返回 200 吗（-f 才会让 curl 在 4xx/5xx 时退出非 0）
# 3. 首页能拿到 HTML 吗
# 4. 数据库连得上吗
# 5. 版本号是这次部署的那个吗
```

**第 5 条最容易漏，也最有用。** 部署"成功"了但跑的还是旧版本，就是靠它抓出来的。

## ⚠️ 这个目录里绝不能出现的东西

```text
❌ 真实的 API key（用 sk-test-xxxx）
❌ 真实的数据库密码（用 devpass）
❌ 提交进 Git 的 .env
❌ node_modules（.dockerignore 里要有它）
```

**跑 `docker system prune -a` 之前先看清楚**：它会删掉所有没在运行的容器、所有没被使用的镜像、所有没被使用的网络。**你上一节辛苦 build 的镜像会一起没。**

## 这一节要留下的证据

| 证据 | 证明什么 |
|---|---|
| 瘦身前后的 `docker images` 输出 | 多阶段真的省了空间 |
| `docker compose ps` 里两个 `(healthy)` | 编排和健康检查都对 |
| `./smoke.sh` 的完整通过输出 | 服务真的可用，不只是容器绿 |
| 回滚前后两次 `ps` 的 IMAGE 列 | 回滚靠 tag，不是重新 build |
| 一次故意失败的冒烟输出 | 你知道失败长什么样 |
