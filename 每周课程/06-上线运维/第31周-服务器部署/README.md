# 第31周 · 服务器部署 · 第 211—217 节课

## 从"我电脑上能跑"到"别人打 IP 就能用"

---

## 这一周的目标

不只是"买台服务器把代码传上去"。你要能做到这五件事：

1. **花明白一台机器的钱** —— 知道起步该买 2 核 2G，也能说出为什么不是 8 核 16G；
2. **用密钥而不是密码登录** —— 并且知道关掉密码登录这一步有多危险；
3. **在没有图形界面的机器上装环境** —— 不打错一个字，看得出哪一步失败了；
4. **让程序一直活着** —— 关掉终端不断、重启服务器自己起来；
5. **能照着八步表，从外往里查出网站为什么打不开**。

**这一周的交付物只有一个：一个你能直接发出去的 IP。**

```text
http://47.98.xx.xx  →  你的 chat-app 页面
```

**别小看这条。** 这个 IP 打通了，后面域名、HTTPS、监控、备份全是在它上面加东西。这条不通，第 32 周一个字都写不下去。

## 为什么排在这一周

到第 30 周结束，你有这些东西：

```text
chat-app 代码（在 GitHub 上）
一条 CI 流水线（测试能过、镜像能构建）
一堆本地跑过的 docker 命令
```

**但你没有一台机器。**

你写的"自动部署"最后一步永远是空的 —— 因为它不知道要部署到哪儿去。

**这就是这一周要补的那块地板。**

```text
第 3 周   程序能跑          （在你电脑上）
第 4 周   改坏了能退         （Git）
第 5 周   数据能存下来       （SQL）
第 29 周  打包成镜像         （Docker）

```

**不学会这一周会怎样：**

```text

③ 你没地方放域名、没地方放证书、没地方放备份

```

**换句话说：前 30 周练的是"造东西"，这一周开始才是"卖东西"。**

## 一个必须先讲清楚的规矩

**这一周花的每一分钱都是真钱，而且有两个不可逆的坑。**

### 坑一：备案，7 到 20 个工作日，等不了就是等不了

**服务器在中国大陆，域名必须备案。没有例外。**

| 情况 | 要不要备案 | 说明 |
|---|---|---|
| 服务器在**中国大陆** | **必须** | 腾讯云 / 阿里云 / 华为云都一样 |
| 服务器在**香港** | 不用 | 国内访问稍慢，但能立刻用 |
| 服务器在**海外** | 不用 | 国内访问很慢，客户会骂 |
| 只在本地开发 | 不用 | 你电脑上没有"公网"这回事 |

**备案要 7—20 个工作日。** 这期间 **网站不能对外访问**。

**所以这一周的课件，全程用 IP 访问，不用域名。** 域名和备案放到第 32 周。这样你不用等。

**如果你急着给国内客户上线，最省事的路径是：**

```text
① 买域名（几十块一年）
② 买国内轻量服务器（2 核 2G）
③ 立刻提交备案（用服务器给的备案服务码）
④ 备案期间：本地开发 + 香港服务器试跑
⑤ 备案下来后，把域名解析到国内这台
```

**顺序不能错。** 先买服务器不提交备案，是最常见的浪费 —— 机器在计费，网站不能开。

### 坑二：安全组，默认只开 22

云服务器买回来，**外面只能连 SSH，其他端口全是关的**。

所以你一定会有这个经历：

```text
程序跑起来了 → 浏览器打开 → 一直转圈 → 超时
```

**不是代码问题，是 80 端口没开。**

**这一周的所有"打不开"，一半以上是这一条。**

### 另外：这一周不许在课程仓库里放任何密钥

```text
.env                 → 只在服务器上手动建，不进 git
id_ed25519（私钥）    → 只在你自己电脑上，永远不上传
服务器 root 密码      → 不写进任何 .md、不写进任何脚本
```

**课件里出现的 IP 一律是 `47.98.xx.xx`，域名一律是 `your-domain.com`。** 那是占位符，不是真地址。

## 这一周的四条铁律

这四条会跟着你一辈子：

```text
一、改 sshd_config 之前，先开第二个终端窗口验证密钥能登进去。
    验证不过就关密码登录 = 把自己锁在门外。

二、nginx 每次改完配置，先 nginx -t，再 systemctl reload nginx。
    不 -t 就 reload，配置错了 Nginx 还跑旧的，你以为改了其实没生效。

三、3000 和 3306 永远不对公网开放。
    Node 只监听 127.0.0.1，外面一律走 Nginx 的 80/443。

四、.env 不在 git 里，服务器上要手动建一份，建完 chmod 600。
    忘了建，程序起来就 500，而你会在代码里找两小时。
```

## 这一周最危险的四个操作

**第一：改完 `PasswordAuthentication no` 就重启 SSH，但密钥其实没配好**

后果：**你再也登不进去了。** 密码登不上，密钥也登不上。

补救只有一条路：**云控制台的 VNC / 远程连接**（网页版的"接显示器"）。它能绕过 SSH，但界面很糙、粘贴不了、还可能卡。

**规则：改之前，开一个**新窗口**跑 `ssh root@47.98.xx.xx`，不问密码直接进，才允许改。**

**第二：`systemctl restart ssh` 之前没跑 `sshd -t`**

后果：配置有语法错，重启失败，**SSH 服务直接停掉**。老会话还能用，一关窗口就再也进不去。

**规则：`sshd -t` 输出为空才算通过。**

**第三：把 `.env` 提交到 git**

后果：密钥进了 GitHub 历史，**即使你下一秒删掉，历史里还在**。别人 fork 一下就有了。

补救：立刻去模型平台吊销那个 key，重新发一个。**不是改密码，是吊销。**

**第四：在服务器上跑 `ufw enable` 但没先放过 22**

后果：防火墙一开，SSH 立刻断，和第一条一样的下场。

**规则：这一周不用 `ufw`。安全组在云控制台配，改错了网页上还能改回来。** 服务器里锁死自己，就只能重装系统。

## 周末的验收

不要急着进下一周。先确认这几条：

- [ ] 我有一台自己的服务器，控制台显示"运行中"，我能 `ssh` 进去
- [ ] 我登录**不需要输密码**（密钥），而且我验证过"密码登录已经关掉"
- [ ] 服务器上 `node -v` 是 20.x，`nginx -v` 有输出，`free -h` 里 swap 是 2.0Gi
- [ ] 代码在 `/srv/app`，`.env` 是我手动建的，`git status` 里看不到它
- [ ] `pm2 list` 里我的应用是 `online`，而且我**真的重启过一次服务器**，它自己起来了
- [ ] 浏览器打开 `http://47.98.xx.xx` 能看到我的页面，不是 404 也不是 502
- [ ] 我能在 `access.log` 里找到我自己刚才那一次访问
- [ ] 我有一个 `deploy.sh`，并且真的用它回滚过一次

**另外：**

- [ ] 每节课的 `NOTES.md` 都填了，没有大片空白
- [ ] 「卡在哪」那一栏写了真实内容（不是"没有卡住"）
- [ ] 我能不看课件，按顺序说出八步排查法的前四步

> **最后一条才是真标准。** 讲不出来，说明你只是照着敲了七天命令，遇到"打不开"还是只能重启试试。
>
> **一周七节课，落一节课没关系，但第 212 和 216 节不能落。** 因为 SSH 登不进去你就什么都做不了，Nginx 配不对你永远只能看到 404。
