# 第34周 · 私有化部署 · 第 232—238 节课

## 客户的数据不能出内网，你得把整套系统搬进去

---

## 这一周的目标

不是"再学一个部署方式"。这一周你要能做到这五件事：

1. **问清需求** —— 12 个问题，当场判断这个单能不能接、要报多少钱；
2. **写出方案** —— 一张客户能看懂的架构图，一份能跑的单机 compose；
3. **离线装进去** —— 没有网、没有 curl、机器是 ARM，也能装起来；
4. **把模型也搬进去** —— 本地跑一个 7B 模型，代码只换 `baseURL`；
5. **交得干净、退得回来** —— 权限交接、备份、升级、回滚、四份文档。

## 为什么排在这一周

前五周你做的所有事，都有一个前提：**服务器能上外网**。

```text
第29周  Docker         docker pull 要联网
第30周  CI/CD          GitHub Actions 要联网
第31周  服务器部署      apt install 要联网
第32周  域名与运维      DNS 解析、Let's Encrypt 要联网
第33周  安全与合规      依赖审计、漏洞库要联网
```

**私有化把这个前提整个抽掉。**

```text
不能 docker pull   → 第 234 节课：镜像打包带进去
不能 npm install   → 第 234 节课：node_modules 一起带
不能调云端模型      → 第 235 节课：本地 Ollama
不能 certbot       → 内网证书手动换
不能远程           → 第 236 节课：临时账号 + 工单
```

**所以这一周不是"新知识"，是"把前五周的能力装进一个没有网的盒子"。**

**这也是这一阶段唯一"直接收钱"的一周。** 前面五周做的是能力，这一周做的是交付。

## 一个必须先讲清楚的规矩

**私有化的钱不是软件钱，是交付钱。而交付的最大成本，是"你以为是那样，实际不是"。**

这一周的所有实验，都在**你自己能控制的机器**上做：

```text
03-练习代码/          放你的文档、脚本、离线包结构
你自己的 Docker       做 save / load / compose 实验
一台测试机（可选）     模拟"客户内网"
```

**绝对不要做的事：**

```text
✗ 在客户生产机上试 docker system prune -a
✗ 在客户生产库上做恢复演练
✗ 把真实客户数据拷回自己电脑"测试"
✗ 在合同里写"高可用""7×24""效果与演示一致"
```

**前三条会毁掉客户的数据，第四条会毁掉你的利润。**

## 这一周的四条铁律

这四条，每一条都能单独救你一次：

```text
一、没签需求确认单，不开工。
    客户口头说的"就按演示的做"，等于没有需求。

二、镜像只用版本号 tag，永远不用 latest。
    用 latest 的那一天，你就失去了回滚的能力。

三、升级前必须备份，备份失败就终止升级。
    没有备份的升级，是把客户的数据押在一次操作上。

四、交接后，你自己不能再登进去。
    只要你还进得去，出了事你就是第一嫌疑人。
```

## 这一周最容易踩的五个坑

**第一：镜像架构不对**

```text
客户是鲲鹏（aarch64），你带的是 x86 镜像。
docker load 成功，docker run 报 exec format error。
现场没有 ARM 构建环境，项目停摆。
```

**第二：以为离线包只带镜像就够**

```text
忘了带 Docker 引擎 → docker: command not found
忘了带 compose 插件 → 'compose' is not a docker command
忘了带 node_modules → npm ERR! ENOTFOUND
```

**第三：承诺了做不到的效果**

```text
演示用云端大模型，交付用本地 7B。
客户一句"不如演示的时候"，你就没有验收依据。
验收标准要写"能用"，不是"一样好"。
```

**第四：给自己留了后门**

```text
一个 support 账号、一把 SSH 公钥、一个心跳 cron。
审计一查就出来，整改单上写的是你的名字。
```

**第五：文档写得像回忆录**

```text
"启动服务：docker compose up -d"
—— 在哪个目录？用什么账号？成功什么样？报错怎么办？
客户照着做，第一步就卡住。
```

**这五个坑，第 234、235、236、232、238 节课分别拆解。**

## 这一周不用学什么

明确排除，避免你分心：

```text
Kubernetes / K8s              私有化单机用不到，双机方案才需要
高可用 / 双机热备 / 主从      另一个方案、另一个价格，本期不做
国产数据库深度调优            只做 SQL 兼容适配，不做性能调优
等保测评流程                  你只提供材料，不做出测评
模型微调（fine-tune）         本期只用现成模型 + 提示词
GPU 驱动与 CUDA 调优          有显卡就用，没有就 CPU，不深入
内网 CA 搭建                  用客户现有的，或商业证书
多租户改造                    第 5 周已经做过
```

**这一周的重心是"交付流程"，不是"基础设施深度"。**
