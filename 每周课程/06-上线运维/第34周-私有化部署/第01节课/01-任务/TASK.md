# 第 0 步：为什么要有这一步（10 分钟）

## 0.1 你现在会什么

到上一节课为止，你已经能把一个应用放到公网：

```text
一台云服务器（2 核 2G，Ubuntu 22.04）
一个域名，解析到这台机器
Nginx 在 80/443 收请求，转给本机的 3000
pm2 让进程常驻，开机自启
certbot 签了证书，90 天自动续
每天备份一次数据库
一份 RUNBOOK.md 写清了出事找谁
```

**这套东西有一个共同前提：服务器能上外网。**

`apt install` 能装包，`npm install` 能下依赖，`certbot` 能连 Let's Encrypt，`docker pull` 能拉镜像。

**私有化部署把这个前提抽掉了。**

## 0.2 你以后会遇到什么

```text
① 某医院信息科：我们的服务器在内网，物理隔离，不能上互联网。
   你装吧。你问：那我怎么装？他说：你带电脑进来装。

② 某集团采购：发一份报价单过来，我们要走招标流程。
   你问：需求是什么？他说：就是那个 AI 问答，装在我们机房。

③ 你到了现场才发现机器是鲲鹏 CPU（ARM 架构），
   你笔记本上 build 出来的镜像是 x86 的，docker load 进去起不来。

④ 验收会上客户说：这个回答质量不如你演示的时候。
   你没法解释，因为合同里没写"效果标准"。

⑤ 交付三个月后客户 IT 说：你那个账号还能登进来。
   你说：我留着排查问题用的。他说：这是安全问题，写进整改单了。
```

**这五件事，没有一件是写代码能解决的。**

## 0.3 今天要建立的三个概念

```text
① 私有化部署：软件装进客户自己的机房，数据不出客户的内网。

③ 需求确认单：一张纸，12 个问题，客户签字。它同时是你的报价依据和你的免责证据。
```

**第三个概念最值钱。** 一张签过字的需求确认单，能挡掉后面 80% 的扯皮。

# 第 1 步：先搞清楚谁在买（15 分钟）

## 1.1 五类客户，五种难处

私有化不是"所有客户都要"，是**特定几类客户必须要**。

| 客户类型 | 为什么必须私有化 | 预算区间（看项目规模） | 谁拍板 | 最难的地方 |
|---|---|---|---|---|
| 医院 | 病人数据、病历，法律不允许出院 | 8 万—40 万 | 信息科 + 院办 | 等保、内网隔离、验收流程长 |
| 政府 / 事业单位 | 数据分级分类，涉密不上网 | 10 万—60 万 | 信息中心 + 采购 | 招标流程、国产化要求 |
| 律所 | 客户案情、合同，保密义务 | 3 万—15 万 | 合伙人 | 预算小、要求细、决策快 |
| 制造业 | 工艺参数、图纸，商业机密 | 5 万—30 万 | IT 主管 + 生产副总 | 车间网络烂、机器老旧 |
| 国企 / 大型集团 | 集团发文要求数据不出园区 | 20 万—100 万 | 集团 IT + 子公司 | 层级多、签字的人多 |

**注意最后一行。** 集团类项目金额大，但**决策链最长**，一个人不签字就停。

**价格会变，客户规模差别也大。** 上表只是让你有数量级概念，不是报价标准。

## 1.2 为什么私有化单价高

同样一个应用，公网部署你收 2 万，私有化能收 8 万。差在哪：

| 成本项 | 公网部署 | 私有化部署 | 说明 |
|---|---|---|---|
| 环境准备 | 0.5 天 | 2—3 天 | 要适配客户的系统、架构、数据库 |
| 安装 | 0.5 天 | 2—4 天 | 离线包制作 + 现场安装 + 反复重试 |
| 差旅 | 0 | 2—6 天 | 很多内网必须人到场，不能远程 |
| 文档 | 0.5 天 | 3—5 天 | 安装手册、运维手册、验收单、培训 |
| 验收 | 0 | 1—3 天 | 现场演示、逐条勾、双方签字 |
| 首年运维 | 0 | 持续 | 客户随时打电话，且你不能远程连 |
| **合计人力** | **1.5 天** | **10—20 天** | 差 7—13 倍 |

**结论：私有化的钱不是软件钱，是交付钱。**

**你不算清这笔账，就会按公网的价格报私有化，然后干一个月亏两万。**

## 1.3 一句卖点和一句风险

**卖点（对客户说）：**

```text
数据一行都不出你们的机房，断网也能用。
```

**风险（对自己说）：**

```text
客户的内网，你说了不算。所有"应该没问题"的地方，都会变成现场卡住的地方。
```

**这两句话要同时记住。** 只记住第一句，你会低估工作量；只记住第二句，你不敢接单。

## 1.4 逐行读：一张私有化项目的成本表

假设某律所项目，报价 6 万：

| 项目 | 金额 | 怎么来的 |
|---|---|---|
| 合同额 | 60000 | 谈下来的价 |
| 人力成本 | 18000 | 12 天 × 1500 元/天（按你自己的时间成本算） |
| 差旅 | 3000 | 2 次现场，高铁 + 住宿 |
| 硬件（若含） | 0 | 合同写明不含硬件，客户自备 |
| 首年运维 | 包含 | 合同含首年，实际占用约 5 天 |
| 毛利 | 39000 | 60000 − 18000 − 3000 |

**逐行读：**

| 行 | 意思 |
|---|---|
| 人力成本按天算 | 私有化的核心成本是"你不在做别的项目"的机会成本 |
| 差旅单独列 | 内网项目经常要去两趟：一趟勘察，一趟安装 |
| 硬件写 0 | 一旦你代采硬件，就要垫资、开票、保修，全是坑 |
| 首年运维"包含" | 意味着这 5 天不能另外收钱，报价时必须预留 |

**不这样算会怎样：** 你会觉得 6 万很多，干完发现时薪不如送外卖，第二年客户再找你，你不想接又不敢拒。

# 第 2 步：12 个问题，一个都不能少（40 分钟）

## 2.0 这 12 个问题怎么分组

```text
第一组（1—3）：网络      —— 决定了你怎么把东西送进去
第二组（4—6）：机器      —— 决定了你的镜像能不能跑
第三组（7—9）：依赖与数据 —— 决定了你要改多少代码
第四组（10—12）：合规、验收、商务 —— 决定了你能不能收到钱
```

**先问第一组。** 如果客户说"完全物理隔离、不能带任何电子设备进机房"，后面 11 个问题问法都不一样。

## 2.1 第 1 问：内网有没有外网出口

**为什么问：**

这一个答案决定你的安装方式，是整份方案的分水岭。

**怎么问（原话）：**

```text
你们这套系统要装的那几台服务器，能访问互联网吗？
是完全不能，还是能访问某些地址，还是能出不能进？
```

**三种答案，三种做法：**

| 答案 | 术语 | 你要做什么 | 工作量 |
|---|---|---|---|
| 完全不能上外网 | 物理隔离 / 全内网 | 所有东西离线打包，U 盘或光盘带进去 | 最大 |
| 能出不能进（能下载，外部连不进来） | 单向出口 / NAT 出口 | 可以在机器上 `docker pull`，但你不能远程 | 中等 |
| 有代理，能访问白名单 | 代理出口 | 要拿到代理地址和端口，配 `HTTP_PROXY` | 中等，配置烦 |

**记在哪：** 需求确认单第 1 行，写清"能否访问互联网 / 代理地址 / 是否允许 U 盘"。

**不懂这个会怎样：** 你按在线安装写好方案，现场 `docker pull` 卡在 `Trying to pull...`，一等二十分钟，客户在旁边看着你。

## 2.2 第 2 问：服务器谁给、给几台、什么配置

**为什么问：**

你不问，客户就会说"你们看着办"，然后给你一台 4 年前的旧机器。

**怎么问：**

```text
服务器是我们提供还是你们现有？
现有的话，能不能给我 CPU、内存、磁盘、操作系统的具体型号？
一共几台？是虚拟机还是物理机？
```

**必须拿到的四个数：**

| 项目 | 为什么必须知道 | 及格线（本课程的应用） |
|---|---|---|
| CPU 核数 | 决定并发 | 4 核起 |
| 内存 | 决定能不能跑本地模型 | 8G 起；跑 7B 模型 16G 更稳 |
| 磁盘 | 决定数据能存多久 | 200G 起，且要有独立数据盘 |
| 台数 | 决定要不要做集群 | 1 台就够，别主动提集群 |

**客户说"虚拟机行不行"：**

```text
行。但要确认两件事：一是能装 Docker（有些虚拟机不支持嵌套虚拟化，
不影响 Docker，但影响你自己跑测试）；二是磁盘是 SSD，不要机械盘。
```

**记在哪：** 第 2 行，把型号原样抄下来。

## 2.3 第 3 问：你能不能远程

**为什么问：**

这决定你要不要出差，出差要算钱，也算时间。

**怎么问：**

```text
实施和以后的运维，我能远程连进来吗？
是直连，还是要过堡垒机，还是要每次提交申请？
```

**四种答案：**

| 答案 | 影响 |
|---|---|
| 可以直连（给你一个内网 VPN 或跳板机） | 最理想，运维成本低 |
| 要过堡垒机，账号要审批 | 每次排查要等审批，响应时间按天算 |
| 只能客户 IT 操作，你口述他敲 | 最难，一条命令可能沟通十分钟 |
| 完全不能远程，必须到场 | 运维成本最高，年费要报高 |

**关键动作：** 如果是第三种或第四种，**当场把"响应时间"写进合同**。

```text
我方提供远程技术支持；因甲方网络限制无法远程接入时，
响应时间按甲方 IT 人员可用时间计算，不适用 4 小时响应承诺。
```

**这句话能救你。** 不写，客户半夜出问题，你没权限进，第二天就被投诉。

## 2.4 第 4 问：操作系统是什么

**为什么问：**

Linux 发行版之间包管理不同，国产化系统还有自己的坑。

**怎么问：**

```text
服务器装的是什么系统？版本号是多少？
是 CentOS、Ubuntu，还是麒麟、统信 UOS？
```

**常见系统对照：**

| 系统 | 包管理 | 注意 |
|---|---|---|
| Ubuntu 20.04 / 22.04 | `apt` | 最好适配，教程最多 |
| CentOS 7 | `yum` | 已停止维护，`docker` 要装旧版 |
| 麒麟 Kylin V10 | `yum` / `dnf` | 国产化常见，内核版本特殊 |
| 统信 UOS Server | `apt`（部分 `dnf`） | 不同版本差异大 |
| Windows Server | — | 跑 Docker 要走 WSL2 或 Hyper-V，**极不推荐** |

**让客户当场敲这三条：**

```bash
cat /etc/os-release
uname -m
df -h
```

**应该看到（Ubuntu 22.04，x86 机器）：**

```text
PRETTY_NAME="Ubuntu 22.04.4 LTS"
NAME="Ubuntu"
VERSION_ID="22.04"
VERSION="22.04.4 LTS (Jammy Jellyfish)"
ID=ubuntu
ID_LIKE=debian
```

```text
x86_64
```

```text
Filesystem      Size  Used Avail Use% Mounted on
/dev/vda1       196G   38G  148G  20% /
tmpfs           3.9G     0  3.9G   0% /dev/shm
/dev/vdb1       500G   12G  463G   3% /data
```

**逐行读：**

| 行 | 意思 | 你要关注什么 |
|---|---|---|
| `PRETTY_NAME` | 系统全名 | 抄进确认单，别写"Linux" |
| `VERSION_ID` | 版本号 | 22.04 和 20.04 的包版本不同 |
| `ID_LIKE=debian` | 属于 Debian 系 | 决定用 `apt` 还是 `yum` |
| `x86_64` | CPU 架构 | **下一问的核心** |
| `/dev/vda1` 196G | 根分区 | 剩 148G，够用 |
| `/dev/vdb1` 500G 挂 `/data` | 独立数据盘 | **数据要放这里，不要放 `/`** |

**为什么强调数据盘：** 根分区被日志写满，整台机器会挂。数据盘满了只影响数据。

## 2.5 第 5 问：CPU 是什么架构（最容易翻车的一问）

**为什么问：**

Docker 镜像和 CPU 架构绑死。**x86 的镜像在 ARM 机器上，`docker load` 能成功，`docker run` 直接报错。**

**怎么问：**

```text
这台机器的 CPU 是 Intel/AMD 的，还是鲲鹏、飞腾？
```

**不会问就让他们敲：**

```bash
uname -m
```

**三种输出：**

| 输出 | 架构 | 常见机器 |
|---|---|---|
| `x86_64` | Intel / AMD 64 位 | 绝大多数云服务器、普通服务器 |
| `aarch64` | ARM 64 位 | 华为鲲鹏、飞腾、部分国产整机 |
| `loongarch64` | 龙芯 | 少见，Docker 支持不完整，**建议不接** |

**应该看到（鲲鹏机器）：**

```text
aarch64
```

**逐字读：**

```text
aarch64      ARM 64 位架构的 Linux 叫法
            等同于 ARM64，也写作 arm64/v8
```

**这意味着什么：**

```text
你在 Windows + Docker Desktop 上 build 出来的镜像，默认是 linux/amd64。
拿到 aarch64 机器上，启动会报：

WARNING: The requested image's platform (linux/amd64) does not match
the detected host platform (linux/arm64/v8) and no specific platform was requested
exec /usr/local/bin/docker-entrypoint.sh: exec format error
```

**`exec format error` 就是"这个程序不是给这台机器编译的"。**

**两个解法（第 3 节课会实操）：**

| 解法 | 做法 | 成本 |
|---|---|---|
| 交叉构建 | `docker buildx build --platform linux/arm64` | 免费，构建慢，部分依赖编不过 |
| 在目标架构机器上构建 | 找一台 ARM 机器 build | 要有机子，最稳 |

**记在哪：** 第 5 行，写 `x86_64` 或 `aarch64`，**并写清"镜像架构必须匹配"**。

**不懂这个会怎样：** 你带着 3 个 G 的镜像包到现场，导入成功，启动失败，现场没有外网也没有 ARM 构建环境，项目直接停摆。

## 2.6 第 6 问：磁盘怎么分、数据放哪

**为什么问：**

数据库、日志、备份、镜像全要占空间。你按 50G 设计，跑三个月就满。

**怎么问：**

```text
有没有独立的数据盘？挂载点是什么？
数据库文件、日志、备份，你们有规定的存放路径吗？
```

**容量估算（本课程的应用，40 个用户）：**

| 用途 | 一年占用 | 说明 |
|---|---|---|
| Docker 镜像 | 3—8 G | 应用 + postgres + 可选模型 |
| 数据库 | 2—10 G | 按每天 2000 条对话估 |
| 日志 | 1—5 G | 不轮转会无限涨 |
| 备份 | 数据库大小 × 保留天数 | 保留 30 天就是 30 份 |
| 本地模型（如果跑） | 5—8 G/个 | 7B 模型约 4.7 G |

**合计及格线：200 G。**

**如果客户只给 100 G：**

```text
100G 能跑，但备份只能保留 7 天，且日志必须按周清理。
这一点我会写进方案，验收时按这个标准。
```

**提前说清，比事后解释便宜。**

## 2.7 第 7 问：数据库用什么

**为什么问：**

这是**代码改动量最大**的一问。PostgreSQL 的 SQL 和达梦的 SQL 不完全一样。

**怎么问：**

```text
数据库是我们自带一个，还是用你们现有的？
现有的话是什么库？Oracle、MySQL、SQL Server，还是达梦、人大金仓？
```

**四种情况：**

| 答案 | 你要做什么 | 改动量 |
|---|---|---|
| 没规定，用你自带的 | 用 PostgreSQL 容器，最省事 | 0 |
| 现有 MySQL | 改连接串，检查 SQL 方言 | 小 |
| 现有达梦 DM8 / 人大金仓 | 改连接串 + 改分页语法 + 改自增主键 + 可能要换驱动 | **大** |
| 现有 Oracle | 改连接串 + 改分页 + 数据类型映射 | 大 |

**国产库具体会踩什么（举例）：**

```sql
-- PostgreSQL 写法
SELECT * FROM messages ORDER BY id DESC LIMIT 20 OFFSET 40;

-- 达梦 / Oracle 风格
SELECT * FROM (
  SELECT t.*, ROWNUM rn FROM (SELECT * FROM messages ORDER BY id DESC) t
  WHERE ROWNUM <= 60
) WHERE rn > 40;
```

**`LIMIT / OFFSET` 在很多国产库里不支持。** 你项目里每一处分页都要改。

**还有：**

```text
自增主键         PostgreSQL 用 SERIAL / IDENTITY
                 达梦用 IDENTITY(1,1)，写法不同
字符串拼接       PostgreSQL 用 ||
                 有些库要 CONCAT()
布尔类型         PostgreSQL 有 true/false
                 有些库只有 0/1
```

**记在哪：** 第 7 行，写清库名 + 版本 + "是否需要适配 SQL"。

**不懂这个会怎样：** 你按 PostgreSQL 写完，现场要求用达梦，改完发现分页、主键、时间函数全要重写，工期从 3 天变 10 天，还不一定能调通。

## 2.8 第 8 问：有没有端口和中间件冲突

**为什么问：**

内网机器上经常已经跑着别的东西，80 端口被占是常事。

**怎么问：**

```text
这台机器上还跑着别的系统吗？
80、443、5432、3000 这几个端口有没有被占用？
```

**让客户敲：**

```bash
ss -lntp
```

**应该看到：**

```text
State  Recv-Q Send-Q Local Address:Port  Peer Address:Port Process
LISTEN 0      128          0.0.0.0:22         0.0.0.0:*     users:(("sshd",pid=1121,fd=3))
LISTEN 0      100        127.0.0.1:25         0.0.0.0:*     users:(("master",pid=2044,fd=13))
LISTEN 0      511          0.0.0.0:80         0.0.0.0:*     users:(("nginx",pid=3311,fd=6))
```

**逐行读：**

| 列 | 意思 |
|---|---|
| `LISTEN` | 这个端口有人在等连接 |
| `0.0.0.0:22` | 所有网卡都能连 22 |
| `127.0.0.1:25` | **只有本机能连**，外部连不上，不冲突 |
| `0.0.0.0:80` | 已被 nginx 占了，**你的应用不能再用 80** |
| `users:(("nginx"...))` | 占用者是谁 |

**看到 80 被占，你有三个选择：**

```text
① 复用客户现有的 nginx，加一个 location 转发（要客户 IT 配合）
② 你的应用换成 8080，让客户访问 IP:8080（丑，但能用）
③ 让客户腾出 80（通常最难）
```

**记在哪：** 第 8 行，写清"80 已占用，方案为复用现有 nginx"。

## 2.9 第 9 问：数据从哪来、怎么进内网

**为什么问：**

很多私有化项目的第一件事不是装软件，是**把历史数据导进去**。而数据进来这一步，往往比装软件难十倍。

**怎么问：**

```text
有没有历史数据要导入？什么格式？大概多少条？
数据怎么进内网——U 盘、光盘、还是有一台摆渡机？
```

**三种数据通道：**

| 通道 | 说明 | 你要准备什么 |
|---|---|---|
| U 盘 / 移动硬盘 | 最常见 | 文件要能单文件拷，别依赖目录结构 |
| 光盘 | 政府项目常见 | 要刻盘，容量 4.7G / 25G |
| 摆渡机 / 网闸 | 有专门的文件交换区 | 通常限制文件类型和大小，**要提前问清** |

**数据量对照：**

| 数据量 | 导入方式 | 预计耗时 |
|---|---|---|
| 1 万条以内 | 页面导入或 CSV | 几分钟 |
| 10 万条 | 脚本 + CSV | 半小时 |
| 100 万条以上 | 数据库直接 `COPY` / `LOAD DATA` | 几小时，要分批 |

**必须问的一句：**

```text
导入失败的话，能重来吗？还是数据只能导一次？
```

**有些客户的数据只允许进一次**（比如从老系统导出的原始数据），导坏了没有第二份。

**记在哪：** 第 9 行，写清数据量、格式、通道、能否重来。

## 2.10 第 10 问：有没有等保要求

**为什么问：**

等保（网络安全等级保护）会带来一堆硬要求：日志留存 6 个月、密码复杂度、双因素、漏洞扫描报告。

**怎么问：**

```text
这套系统要不要过等保？几级？
是我们交付前就要过，还是上线后你们自己整改？
```

**等保二级 / 三级的常见要求：**

| 要求 | 二级 | 三级 | 对你的影响 |
|---|---|---|---|
| 日志留存 | 6 个月 | 6 个月 | 日志不能只留 7 天，磁盘要够 |
| 身份鉴别 | 用户名密码 | 密码 + 双因素 | 要加短信/OTP，是新增开发 |
| 访问控制 | 有 | 细粒度 | 要做角色权限 |
| 数据完整性 | — | 要校验 | 备份要做校验和 |
| 漏洞扫描 | 建议 | 必须 | 要出报告，可能要买服务 |

**关键边界这句话必须说：**

```text
软件本身的功能我们负责。
等保测评、整改施工、安全设备（防火墙、堡垒机、日志审计）不在本次范围内。
如需要，我们可配合提供材料。
```

**不写这句，客户会让你"顺便"把等保过了。** 那是另一个项目的钱。

## 2.11 第 11 问：验收标准是什么、谁签字

**为什么问：**

验收标准不写清，等于没有终点。

**怎么问：**

```text
上线后怎么算验收通过？有没有验收清单？
谁来签这个字？信息科自己就能签，还是要走院办/集团？
```

**三种验收方式：**

| 方式 | 说明 | 风险 |
|---|---|---|
| 功能清单逐条勾 | 最常见，最公平 | 清单要提前给，别现场加 |
| 试运行 30 天无重大故障 | 客户喜欢 | "重大故障"要定义 |
| 第三方测评 | 政府/医院常见 | 时间不可控，可能拖三个月 |

**必须当场确认的三件事：**

```text
① 验收清单谁出？（最好你出，客户确认）
② 试运行期多久？试运行期间算不算交付？
③ 签字人是谁？他今天在不在这个会上？
```

**如果签字人不在场：**

```text
那今天这份确认单能不能请他补签？或者下次会议我们当面对一遍。
```

**记在哪：** 第 11 行，写清验收方式 + 签字角色 + 试运行期。

## 2.12 第 12 问：运维谁负责、多久升级、怎么付款

**为什么问：**

这三件事决定你交付后还有多少活，以及钱什么时候到账。

**怎么问：**

```text
上线以后日常运维是你们 IT 负责，还是我们负责？
系统多久升级一次？升级要谁批准？
付款怎么安排？预付多少，验收后多少，质保金多少？
```

**运维分工的三种模式：**

| 模式 | 你做什么 | 报价影响 |
|---|---|---|
| 客户 IT 全权运维 | 你只处理"他们搞不定"的问题 | 年费低（合同额 10—15%） |
| 你远程运维 | 你负责重启、备份、升级 | 年费中（15—20%） |
| 你全包（含巡检） | 每季度到场或远程巡检 | 年费高（20—25%） |

**付款节点（常见三种）：**

```text
方式一：3 : 6 : 1     预付 30%，验收 60%，质保金 10%（一年后付）
方式二：5 : 5         预付 50%，验收 50%
方式三：4 : 4 : 2     预付 40%，上线 40%，验收 20%
```

**预付款低于 30% 要警惕。** 私有化项目周期长，你垫不起。

**记在哪：** 第 12 行，写清运维模式、升级频率、付款比例。

# 第 3 步：现场这 45 分钟怎么开（15 分钟）

## 3.1 谁必须在场

**这份名单要提前发给客户，让他们叫人。**

| 角色 | 为什么必须在 | 不在会怎样 |
|---|---|---|
| 客户 IT / 信息科 | 只有他知道机器真实情况 | 你后面所有假设都是猜的 |
| 业务负责人 | 只有他知道要解决什么问题 | 做出来不是他要的 |
| 能签字的人（或能影响签字的人） | 确认单一句话就能定 | 会开完等于没开 |
| 采购 / 商务（大项目） | 付款和合同条款 | 报价发过去没人接 |

**如果客户只来一个 IT：**

```text
今天技术问题我们对得很清楚。但验收标准和付款这两块，
需要业务和商务的同事确认。能不能约个时间一起过一遍？
```

**不要在这个会上把价格定死。** 人没到齐，定了也会被推翻。

## 3.2 45 分钟的流程

| 时间 | 做什么 | 你要拿到的东西 |
|---|---|---|
| 0—5 分钟 | 自我介绍 + 说明今天目标 | 大家都知道今天只做"确认需求" |
| 5—25 分钟 | 过 12 个问题 | 12 个答案，写在本子上 |
| 25—35 分钟 | 演示现有系统（如果能连外网） | 客户对"要做成什么样"有共识 |
| 35—40 分钟 | 讲边界：不做什么 | 客户当场听到"这些不在范围内" |
| 40—45 分钟 | 确认下一步和时间 | 谁在几天内给什么 |

**关键：第 35—40 分钟不能省。**

**你不主动说"不做什么"，客户就会默认"你什么都做"。**

## 3.3 三句绝对不能说

| 不能说 | 为什么 | 应该怎么说 |
|---|---|---|
| "这个都能做" | 后面每个"都能做"都是一次免费开发 | "这个可以做，属于新增需求，我单独报个价" |
| "效果和演示一样" | 本地模型效果一定下降 | "效果以验收标准为准，我们按'可用'来定" |
| "7×24 小时随叫随到" | 你一个人做不到 | "工作日 9—18 点响应，紧急问题 4 小时内" |

**这三句话，一句能让你白干一个月。**

## 3.4 会后 24 小时内发确认单

**邮件正文模板：**

```text
X 主任，您好：

今天沟通的内容我整理成一份需求确认单，见附件。
重点请您确认三处：

1. 第 2 项服务器配置（4 核 16G / 200G 数据盘 / 麒麟 V10 / aarch64）
2. 第 10 项等保要求（本次交付不含等保测评与整改）
3. 第 11 项验收方式（功能清单逐条勾选，信息科签字）

如有出入请直接在这份文件上批注回我。
确认后我据此出正式方案和报价，工期约 15 个工作日。

顺祝
XX
```

**为什么是 24 小时：**

```text
超过 24 小时，客户记不清会上说了什么，你的记录就变成"你自己说的"。
```

**邮件 + 附件，是最好的证据形式。** 微信聊天记录不算。

# 第 4 步：把 12 个答案翻译成技术约束（20 分钟）

## 4.1 一张对照表

这一步是这节课的核心技能：**听到一句话，立刻知道它在技术上报什么错。**

| 客户的话 | 技术约束 | 你方案里要改什么 |
|---|---|---|
| "内网不能上网" | 不能 `docker pull`、不能 `npm install` | 全部离线包，第 3 节课 |
| "服务器是鲲鹏" | `aarch64` | 镜像必须 `linux/arm64` |
| "系统是麒麟 V10" | 非 Ubuntu，`yum` 系 | 装 Docker 的方式不同 |
| "数据库用达梦" | SQL 方言不同 | 分页、主键、函数要改 |
| "80 端口被占了" | 不能直接监听 80 | 复用现有 nginx 或换端口 |
| "要过等保三级" | 日志 6 个月、双因素 | 日志轮转策略 + 认证改造 |
| "不能远程" | 你不能 SSH | 现场支持，年费上浮 |
| "数据只能 U 盘拷进去" | 文件要单包 | 打成一个 tar，带校验和 |
| "验收要试运行 30 天" | 回款延后一个月 | 现金流要留余量 |
| "预付款 20%" | 你垫资 | 要么争取 30%，要么不接 |
| "以后每年升级两次" | 要有升级脚本 | 第 6 节课 |
| "运维我们自己来" | 要交文档 + 培训 | 第 5、7 节课 |

**这张表要背下来。** 它是"需求 → 工作量"的换算表。

## 4.2 三种典型组合

**组合 A：全内网 + x86 + 麒麟**

```text
能上网吗      不能
CPU          x86_64
系统          麒麟 V10
数据库        自带 PostgreSQL
结论          离线安装 + x86 镜像 + yum 装 docker
难度          ★★★☆☆
```

**组合 B：有单向出口 + x86 + Ubuntu**

```text
能上网吗      能出不能进（可以 pull，但连不进来）
CPU          x86_64
系统          Ubuntu 22.04
数据库        MySQL 8
结论          可以在机器上 pull，改 MySQL 方言
难度          ★★☆☆☆（相对最舒服）
```

**组合 C：全内网 + ARM + 达梦**

```text
能上网吗      不能
CPU          aarch64（鲲鹏）
系统          麒麟 V10
数据库        达梦 DM8
结论          离线 + ARM 镜像 + SQL 全面适配
难度          ★★★★★
```

**组合 C 的报价要乘 1.8。** 不是贪心，是工时真的翻倍。

## 4.3 红旗清单：这几种单子不要接

| 红旗 | 为什么危险 |
|---|---|
| 预算 3 万，要求全内网 + 国产库 + 等保三级 | 工时至少 25 天，必亏 |
| 客户说不出验收标准，只说"做好就行" | 永远验收不了 |
| 要求"先上线后付款"，没有预付款 | 你垫资且没有筹码 |
| 机器是龙芯（`loongarch64`） | Docker 生态支持差，风险不可控 |
| 要求你驻场三个月 | 你一个人，驻场就没法做别的项目 |
| 甲方 IT 明确说"我们不配合" | 你连门都进不去 |

**看到两条以上，直接放弃。** 放弃一个烂单，比做完一个烂单赚得多。

# 第 5 步：当场把价报出来（20 分钟）

## 5.1 三段式报价

私有化的钱分三段收，**混在一起报，客户会觉得贵，你也会亏**。

| 段 | 收什么 | 收多少 | 什么时候收 |
|---|---|---|---|
| 第一段：项目费 | 一次性交付 | 按工时 + 复杂度 | 预付 30—50%，验收后尾款 |
| 第二段：首年运维 | 第一年支持 | 项目费的 15—20% | 通常含在项目费里，或验收后收 |
| 第三段：后续年费 | 第二年起 | 项目费的 15—20%/年 | 每年年初 |

**为什么分开：**

```text
项目费是一次性劳动，年费是持续义务。
混在一起，客户会觉得"我都付过钱了，你怎么还收"。
```

## 5.2 一个完整的例子：某医院，40 个用户

**场景（这是虚构的，用来练算法）：**

```text
客户          某医院信息科
用户数        40 人
部署          全内网，x86，麒麟 V10，自带 PostgreSQL
功能          文档问答 + 对话记录
要求          过等保二级，日志留 6 个月
工期          20 个工作日
```

**成本先算：**

| 项 | 数量 | 单价 | 小计 |
|---|---|---|---|
| 需求与方案 | 2 天 | 1500 元/天 | 3000 |
| 离线包制作 | 3 天 | 1500 元/天 | 4500 |
| 现场安装调试 | 4 天 | 1500 元/天 | 6000 |
| 文档（四件套） | 4 天 | 1500 元/天 | 6000 |
| 验收与培训 | 2 天 | 1500 元/天 | 3000 |
| 差旅 | 2 次 | 1500 元/次 | 3000 |
| 不可预见（+15%） | — | — | 3900 |
| **成本合计** | **17 天 + 差旅** | | **29400** |

**报价：**

| 段 | 金额 | 说明 |
|---|---|---|
| 项目费 | 68000 | 成本 × 2.3 左右 |
| 首年运维 | 含在项目费内 | 约 5 天工作量 |
| 第二年起年费 | 12000/年 | 约项目费的 17% |
| **首年客户支出** | **68000** | |
| **第二年起每年** | **12000** | |

**为什么是 2.3 倍：**

```text
1 倍是成本，0.5 倍是你的利润，0.3 倍是风险准备金（返工、拖期、免费加班），
0.5 倍是销售与售前的时间（这些时间你没算进工时）。
```

**这个倍数不是标准，是让你知道自己在赚什么钱。**

## 5.3 不含项必须一条条写

**报价单上的"不含"比"含"更重要。**

```text
不含硬件（服务器、交换机、防火墙）
不含差旅（实报实销，或按次包干 XXXX 元）
不含等保测评与整改施工
不含安全设备（堡垒机、日志审计、WAF）
不含二次开发（新增功能另行报价）
不含数据清洗与历史数据整理
不含模型效果调优到"和公网大模型一致"
不含客户网络改造
不含驻场
```

**每一条都要能对应到一句"为什么"：**

| 不含项 | 为什么 |
|---|---|
| 硬件 | 你代采要垫资、开票、承担保修，利润不够填坑 |
| 差旅 | 内网项目差旅不可控，包干会亏 |
| 等保整改 | 那是安全集成商的活，你只提供软件材料 |
| 二次开发 | 需求是无底洞，必须单独计价 |
| 模型效果 | 本地 7B 模型和云端大模型差距客观存在，不能承诺一致 |

## 5.4 报价单模板

```markdown
# 私有化部署报价单

客户：某医院
项目：智能文档问答系统 私有化部署
报价有效期：30 天
日期：2026-XX-XX

## 一、项目费

| 序号 | 内容 | 说明 | 金额（元） |
|---|---|---|---|
| 1 | 需求确认与方案设计 | 含现场勘察 1 次 | 5000 |
| 2 | 离线安装包制作 | 含 ARM/x86 双架构 | 9000 |
| 3 | 现场部署与调试 | 含 4 个工作日 | 14000 |
| 4 | 交付文档四件套 | 安装/运维/验收/培训 | 12000 |
| 5 | 验收支持与培训 | 含 1 次 2 小时培训 | 6000 |
| 6 | 首年运维支持 | 工作日 9:00—18:00 | 12000 |
| 7 | 不可预见费 | 按 10% 计 | 5800 |
| **合计** | | | **63800** |

## 二、后续年费

| 年度 | 内容 | 金额（元/年） |
|---|---|---|
| 第二年起 | 远程支持、版本升级 2 次/年 | 12000 |

## 三、不包含

1. 服务器、网络设备等硬件

- 合同签订后 5 个工作日内：40%
- 验收通过后 10 个工作日内：50%
- 质保金（验收后 6 个月）：10%

## 五、工期

合同生效并收到预付款后 20 个工作日。

## 六、其他

- 报价不含税，税率按国家规定另计
- 现场条件不满足方案要求导致的返工，工期顺延
```

**这份模板可以直接改数字用。** 但每一项都要能解释。

## 5.5 逐行读：报价单里最容易吵起来的四行

| 行 | 客户会怎么问 | 你要能答出 |
|---|---|---|
| `首年运维 12000` | "这不就是保修吗，还要钱？" | "保修是修 bug，运维是重启、备份、升级、答疑，是持续劳动" |

# 第 8 步：故意犯 6 个错（30 分钟）

## 错误 1：只问"服务器什么配置"，没问 CPU 架构

**操作：**

需求会上问了一句"机器什么配置"，客户答"8 核 16G"，你记下来就走了。

**会怎样：**

现场安装时：

```text
$ docker load -i app.tar
Loaded image: chat-app:1.2.0

$ docker compose up -d
[+] Running 1/1
 ✘ Container app Error
Error response from daemon: failed to create task for container:
failed to create shim task: OCI runtime create failed:
runc create failed: unable to start container process:
exec: "/usr/local/bin/node": stat /usr/local/bin/node: exec format error: unknown
```

**为什么：**

```text
镜像里的 node 二进制是 x86_64 的机器码。
鲲鹏 CPU 看不懂 x86 指令，内核直接拒绝执行。
"exec format error" 就是这个意思。
```

**怎么修：**

```bash
# 在能联网的 x86 机器上（有 buildx）
docker buildx build --platform linux/arm64 -t chat-app:1.2.0-arm64 --load .

# 或者在 ARM 机器上直接 build
docker build -t chat-app:1.2.0 .
```

**修完之后：**

```bash
docker image inspect chat-app:1.2.0 --format '{{.Architecture}}'
```

**应该看到：**

```text
arm64
```

**教训：** 第 5 问和第 2 问是两回事。"8 核 16G"里没有架构信息。

## 错误 2：没问外网出口，按在线安装写方案

**操作：**

方案里写"在服务器上执行 `docker pull` 拉取镜像"。

**会怎样：**

```text
$ docker pull postgres:16-alpine
Error response from daemon: Get "https://registry-1.docker.io/v2/":
dial tcp 44.208.254.194:443: i/o timeout
```

**为什么：**

```text
机器没有到 registry-1.docker.io 的路由。
DNS 可能解析成功，但 TCP 连不上，所以是 i/o timeout 而不是 not found。
```

**怎么修：**

```bash
# 在能联网的机器上
docker pull postgres:16-alpine
docker save -o postgres16.tar postgres:16-alpine

# 拷进内网
docker load -i postgres16.tar
```

**教训：** "能不能上网"是第一个要问的问题，不是最后一个。

## 错误 3：口头承诺"效果和演示一样"

**操作：**

演示用的是云端大模型，客户问"装到我们这儿效果一样吗"，你说"一样的"。

**会怎样：**

验收会上：

```text
客户：这个回答明显不如你演示的时候，语句都不通顺。
你：因为内网只能用本地 7B 模型……
客户：那你当时为什么说一样？
```

**为什么：**

```text
云端大模型参数量在千亿级，本地 7B 是 70 亿参数。
差一到两个数量级，输出质量差距是客观的，不是调参能补上的。
```

**怎么修：**

**在确认单上写清：**

```text
模型效果验收标准：系统能对文档内容给出相关回答，
回答与文档内容不矛盾，单次响应时间不超过 10 秒。
不承诺与公网大模型输出质量一致。
```

**教训：** 效果这件事，宁可当场说低，也不要事后解释。

## 错误 4：没问数据库，按 PostgreSQL 写完

**操作：**

你默认客户用你自带的 PostgreSQL，SQL 全按 PG 写。

**会怎样：**

```text
ERROR: syntax error at or near "LIMIT"
第 1 行: SELECT * FROM messages ORDER BY id DESC LIMIT 20 OFFSET 0
```

**为什么：**

```text
达梦的 SQL 方言不支持 LIMIT/OFFSET。
它用 ROWNUM 或者 TOP 来分页。
```

**怎么修：**

```sql
SELECT * FROM (
  SELECT t.*, ROWNUM rn FROM (
    SELECT * FROM messages ORDER BY id DESC
  ) t WHERE ROWNUM <= 20
) WHERE rn > 0;
```

**更好的修法：在代码里做方言适配。**

```js
const isDM = process.env.DB_DIALECT === "dm";
const sql = isDM
  ? "SELECT * FROM (SELECT t.*, ROWNUM rn FROM (SELECT * FROM messages ORDER BY id DESC) t WHERE ROWNUM <= ?) WHERE rn > ?"
  : "SELECT * FROM messages ORDER BY id DESC LIMIT ? OFFSET ?";
```

**教训：** 数据库方言要在第 7 问就问清，不要等报错。

## 错误 5：没问谁签验收

**操作：**

项目做完了，一直等验收，等了三个月没动静。

**会怎样：**

```text
你：张工，验收单什么时候能签？
张工：这个要院办签，我们信息科签不了。
你：那当时会上怎么没说？
张工：你也没问啊。
```

**为什么：**

```text
医院、政府、国企的签字权往往不在技术部门。
信息科只能出"技术确认"，商务验收要更高层。
```

**怎么修：**

**在第 11 问里必须问：**

```text
验收单最终由谁签字？是信息科，还是要走院办/采购？
他今天在不在？不在的话下次能不能一起过一遍？
```

**并且合同里写：**

```text
甲方应在系统上线后 15 个工作日内组织验收；
逾期未组织且未提出书面异议的，视为验收通过。
```

**教训：** 验收不是一个技术动作，是一个组织动作。

## 错误 6：没问等保，交付后被要求补日志留存

**操作：**

日志按 7 天轮转，磁盘只留了 50G。

**会怎样：**

```text
客户：等保测评要求日志留存 6 个月，你们这个只有 7 天。
你：那要改配置，还要加磁盘。
客户：这是交付要求，你们补上。
```

**为什么：**

```text
等保二级/三级都要求网络日志留存不少于 6 个月。
7 天轮转是为了省磁盘，两者直接冲突。
```

**怎么修：**

**在 docker-compose 里配日志轮转，但保留更久：**

```yaml
services:
  app:
    logging:
      driver: json-file
      options:
        max-size: "50m"
        max-file: "10"
```

**同时把业务日志单独写到文件，按天切，保留 180 天。**

**教训：** 等保这一问，问的不是"要不要过"，是"日志留多久、磁盘够不够"。

# 附：常见问题速查

| 现象 | 原因 | 怎么做 |
|---|---|---|
| 客户说"我们内网很安全，不用管这些" | 他不知道你要问什么 | 把 12 问打印出来，一条条念给他听 |
| 客户答"服务器配置够用" | 他不懂技术，或者不想查 | 要求给型号，或让他敲 `uname -m` / `df -h` 截图 |
| 客户不给远程权限 | 内网安全规定 | 合同写清响应时间按客户 IT 可用时间算 |
| 报价发过去没回音 | 采购流程长，或你报高了 | 一周后跟进一次，问"卡在哪个环节" |
| 客户要求"先做后付" | 试探你的底线 | 至少 30% 预付，否则不排期 |
| 客户说"就照演示的做" | 他没想过差异 | 当场说明本地模型和云端模型的差距 |
| 客户要求用国产数据库 | 上级要求 | 先做 3 天兼容测试，再决定报多少 |
| 客户机器是 ARM | 国产化替代 | 确认架构，准备 ARM 镜像或 ARM 构建机 |
| 客户 80 端口被占 | 已有系统 | 复用现有 nginx，或改用 8080 |
| 验收一直拖着 | 签字人不在技术部门 | 合同加"逾期视为验收通过" |
| 现场发现机器比说的差很多 | 确认单没写型号 | 按变更处理，工期顺延，费用另计 |
| 客户要求"顺便加个功能" | 没有变更条款 | 拿确认单第 3 条给他看，走变更单 |
