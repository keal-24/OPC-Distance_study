# 03-练习代码

**这个文件夹故意不留代码。** 这一节要建一个**只有两个账号和一张表的最小实验场**，专门用来越权。

---

## 本节课你要建什么

```text
03-练习代码/
├── idor-lab/                    ← 你自己建
│   ├── server.js                ← 你有洞的那版，注释里标出"这行有洞"
│   ├── server-fixed.js          ← 补好之后的版本
│   ├── seed.js                  ← 建表 + 两个用户 + 各一条消息
│   └── 越权记录.md              ← 10 条测试逐条贴请求和响应
└── 权限清单.md                   ← 你项目里所有带编号的接口
```

## 为什么单独建一个 `idor-lab`

因为这一节要**故意留一个洞**，然后自己打进去。

**在正式项目里留洞，哪怕只有 10 分钟，也可能被扫描器撞上。** 你刚在第 32 周上线，公网上有人 24 小时在遍历。

**在练手目录里做，最坏的后果是你自己看到自己的测试数据。**

## `seed.js` 要造的最小数据

```text
用户：alice(id=1)  bob(id=2)
消息：alice 1 条   bob 1 条
```

**两个人各一条就够。** 关键是"每人都有别人的 id 可试"。

## 这一节的四步

```text
① 写一个有洞的接口     只判断登录，不判断归属
② 亲手越一次权         用 Alice 的身份读 Bob 的那条
③ 改成带 user_id 的查询 同一个请求，现在返回 404
④ 用两个账号跑 10 条    每一条都贴请求和响应原文
```

## ⚠️ 这一节最容易漏的三处

```text
❌ 只改了详情接口，列表接口还在返回全部
❌ 只改了 GET，UPDATE / DELETE 还在裸奔
❌ user_id 从 req.body 里取（等于让攻击者自己报身份）
```

**第二条尤其致命：** 一个能读别人数据的洞叫"泄露"，一个能删别人数据的洞叫"事故"。

## ⚠️ 数据库降权这一步要小心

课件第 7 步会让你给数据库账号降权。**降之前先 dump 一份。**

```bash
# MySQL
mysqldump -u root -p 库名 > backup.sql
# PostgreSQL
pg_dump -U postgres 库名 > backup.sql
```

降错了的现象是 `Access denied`，应用全站 500。有这个备份，五分钟能回去。

## 这一节要留下的证据

| 证据 | 证明什么 |
|---|---|
| 越权那一次的完整响应（含别人的数据） | 洞是真的存在 |
| 修好之后同一个请求的 404 | 洞是真的堵了 |
| 列表接口返回的条数（1 条，不是 2 条） | 列表也堵了 |
| `SHOW GRANTS` 的输出 | 数据库账号真的降权了 |
| 外网连 3306 超时的报错 | 端口真的关了 |

## 检验自己有没有真学会

- `changes === 0` 为什么不能区分"不存在"和"不是我的"？这是好事还是坏事？
- 登录（认证）和权限（授权）差在哪？用一句话说。
- 列表接口为什么最容易漏？四个容易漏的形态是哪四个？
- 应用账号为什么不能给 `DROP`？
