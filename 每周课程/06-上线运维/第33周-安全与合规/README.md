# 第33周 · 安全与合规 · 第 225—231 节课

## 你的网站已经上线了，现在轮到你被人试密码

---

## 这一周的目标

上一周你有了域名、HTTPS、备份、监控。网站能打开了。

**能打开，和能让人放心用，是两件事。**

这一周不学新框架、不学新语言。这一周只做一件事：**把你已经写好的代码，从头到尾按攻击者的视角看一遍。**

七节课，你要能做到这五件事：

1. **知道自己的钥匙有几把、分别放在哪** —— 不是"我有个 `.env`"，是能列出一张表；
2. **确认没有任何一把钥匙躺在 Git 历史里** —— 包括三个月前那次手滑；
3. **让每一个写接口都自己校验一遍数据** —— 不管请求是从浏览器来的还是从 `curl` 来的；
4. **让每个人都只能看自己的数据** —— 改一个数字就能看别人东西的洞，必须堵死；
5. **留下一张能给别人看的安全自查表** —— 20 项，逐项有命令、有输出、有结论。

## 为什么排在这一周

第 31 周你把代码放上了服务器。第 32 周你把域名和 HTTPS 配好了。

**从那一刻起，你的程序就在公网上，24 小时被扫描。**

不是你出名了才被扫。是全网有机器在**不间断地遍历每一个 IP 的每一个端口**，找没关的数据库、找能直接下载的 `.env`、找带 `?id=` 的地址试数字。

```text
第 31 周：程序跑起来了        → 你关心"能不能访问"
第 32 周：域名 + HTTPS        → 你关心"别人能不能访问"
第 33 周：安全与合规          → 你关心"别人能访问到什么"
```

**这中间有个残酷的差别：**

```text
功能有 bug    → 用户抱怨，你修，用户还在
安全有洞      → 用户不抱怨，因为用户不知道；你知道的时候，数据已经在别人手里了
```

**功能 bug 是响的，安全漏洞是哑的。**

所以这一周的顺序不能跳：

```text
先堵"钥匙丢了"（第 225 节）       —— 最严重，一次就够
再堵"门没锁好"（226—229 节）     —— 最常见，天天有人试
最后收口（230—231 节）           —— 把做过的事变成能复查的表
```

**第 225 节必须第一个做。** 因为如果你的密钥已经在 Git 历史里，后面六节课做的一切都白搭：攻击者拿着你的 key，根本不需要走你的登录。

## 一个必须先讲清楚的规矩

这一周所有实验，都在**你自己电脑上的练手项目**里做，**不在已经上线的那份代码里做**。

因为这一周要做的动作包括：

```text
往数据库里插 <script> 标签            真的会执行
用 curl 传一个假 .html 文件上去        上线环境会真的可访问
把一份假 .env 提交进 Git              然后要删历史
给数据库账号降权                      降错了应用直接连不上
```

**在线上那份代码里做，最轻的结果是服务挂掉，最重的结果是真的把洞开在公网上。**

规矩三条：

1. **练手用 `03-练习代码/` 里新建的目录**，或者干脆 `cp -r` 一份项目出来改；
2. **线上服务器只做"检查"和"改配置"，不拿它当靶子**；
3. **所有示例密钥都是假的**（`sk-test-xxxx`），所有示例域名都是 `your-domain.com`，所有示例 IP 都是 `47.98.xx.xx`。

**⚠️ 有一条例外必须提前说：第 227 节要给数据库账号降权。** 降权前先确认应用**真的**用那个账号连过一次库。降错了的现象是 `Access denied`，应用全站 500。**改之前先 `mysqldump` 或 `pg_dump` 备份一份。**

## 这一周的四条铁律

这四条会跟着你一辈子：

```text
一、密钥泄露，先吊销，再换，最后才清代码。
    顺序反了，等于你换了锁但把旧钥匙留在门上。

二、前端能做的一切校验，都是"体验"，不是"安全"。
    任何判断，服务端必须再做一遍，一次都不能省。

三、每一个查数据的语句，都要能回答："这条 SQL 为什么只可能返回我自己的数据？"
    答不出来，就是有越权洞。

四、用户输入进 SQL 只能走参数化；进 HTML 只能走转义；
    进命令行只能用参数数组。三条都没有例外。
```

## 这一周最容易踩的六个坑

**第一：以为"删掉 `.env` 就安全了"**

`git rm` 只删最新版本，**历史里那一份完好无损**。`git log -p -- .env` 一条命令就能把它打印出来。**只要它进过 git，就按"已泄露"处理。**

**第二：以为"前端已经限制了"**

浏览器上的 `maxlength`、`required`、下拉框，全都能改。攻击者根本不打开你的网页，他直接 `curl`。**你写的每一行前端校验，对他都是零成本。**

**第三：以为"登录了就是有权限"**

登录只证明"你是谁"，不证明"这个东西是不是你的"。`GET /api/messages/123` 只判断了登录，改个数字就能看别人的。**这是全世界最常见的线上事故，没有之一。**

**第四：以为"参数化查询就是加引号"**

字符串拼接 + 手工转义，永远会漏。**只有占位符（`?` / `$1`）才是参数化。** 表名、列名、`ORDER BY` 不能占位，只能走白名单映射。

**第五：以为"改了扩展名就不能执行"**

`Content-Type` 是客户端自己填的，随便伪造。**判断文件类型要看文件头几个字节（魔数），不是看名字，更不是看它自己说的类型。**

**第六：以为"依赖能跑就别动"**

`npm audit` 报 10 个 high，你点"以后再说"。**其中一个是三个月前公开的远程执行，利用代码网上能直接搜到。** 你不修，不代表没人知道。

## 周末的验收

不要急着进下一周。先确认这七条：

- [ ] 我能列出自己项目里所有密钥，写下每一把的用途和吊销入口
- [ ] `git log --all --oneline -- .env` 在我所有仓库里都是空的
- [ ] 我用 `curl` 给每个写接口发过非法数据，全部返回 400，不是 500，也不是 200
- [ ] 我用两个账号验证过：A 拿着 B 的 id 请求，返回 404
- [ ] 三处注入（SQL / 命令 / XSS）我都亲手打过一次，都被挡住
- [ ] 我传过一个 `.html` 文件和一张 5MB 的图，一个被拒，一个有明确提示
- [ ] 我的安全自查表 20 项都填了，没通过的项目写进了修复清单

**另外：**

- [ ] 每节课的 `NOTES.md` 都填了，没有大片空白
- [ ] "怎么验证补住了"那一栏，写的是**具体请求和具体响应**，不是"应该没问题"
- [ ] 我能用三句话讲清"为什么服务端校验不能省"

> **最后一条才是真标准。**
>
> 讲不出"为什么"，说明你只是照着课件改了几行代码。**下次 AI 给你一段有洞的代码，你照样会点头。**
>
> **一周七节课，第 225 和第 227 节不能落。** 因为密钥和越权是"一次就够"的事故，其它五节是"迟早会中"的隐患。

## 这一周不用学什么

明确排除，避免你分心：

```text
渗透测试工具全家桶（Burp Suite / sqlmap / nmap）   这一周用 curl 就够
WAF（Web 应用防火墙）的部署与调优                  钱能解决，先用代码解决
Kubernetes 的 RBAC 与 NetworkPolicy               第 34 周之外都不需要
OAuth2 / OIDC 完整协议栈                          本课程不讲（登录在第 8 周已经做完，OAuth 要企业资质才能真跑）
密码学原理（AES、RSA、椭圆曲线怎么算）              你只需要知道"用库，不自己实现"
等保测评、ISO 27001 的具体流程                     这是公司级合规，一个人做产品用不上
代码审计工具（SonarQube 等）的搭建                 以后团队化再说
区块链 / 智能合约安全                              用不到
```

**这一周只用 `curl`、`git`、`npm` 和你的编辑器。**

不装扫描器，是因为**你要先懂"洞长什么样"，才看得懂扫描器报的是什么**。拿工具扫出一堆红字但不知道怎么修，比不扫更焦虑。

## 下一步

第 34 周做**私有化部署**：把同一套系统装进客户的内网。

那一周会反复用到这一周的三样东西：

| 这一周学的 | 第 34 周怎么用 |
|---|---|
| 密钥清单与 `.env` 权限 | 客户内网里，密钥交接和轮换是交付条款 |
| 越权与最小权限 | 客户的 IT 会问"你的应用账号能干什么" |
| 安全自查表 | 直接变成验收单的一页 |

**换句话说：这一周的产出不是"学到的知识"，是"能拿给客户看的文件"。** 第 231 节的 20 项自查表，第 34 周会贴在交付文档里。

**一处提前说明：路径会变，做法不变。**

```text
第 31—33 周：/srv/app     （你自己运营的服务器）
第 34 周：   /opt/app     （交付给客户的机器，/opt 更像"装了一个软件"）
```

**变的只有路径字符串。** 这一周做的每一件事——密钥 600 权限、服务端校验、归属检查、上传隔离、日志脱敏、自查表——到第 34 周一个字都不用改，只是目录前缀换了。

**唯一要警惕的：一个项目里只许用一个路径。** 文档写 `/opt/app`、脚本写 `/srv/app`，是私有化交付最经典的事故。
