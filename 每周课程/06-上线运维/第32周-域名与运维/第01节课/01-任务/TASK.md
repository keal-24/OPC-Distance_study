# 第 1 步：先把域名拆开看（15 分钟）

## 1.1 一个域名是从右往左读的

拿 `api.your-domain.com` 举例。

**注意：`your-domain.com` 是你自己买的域名的占位写法。下面所有地方都一样。**

```text
api . your-domain . com
 │         │          └── 顶级域名（TLD）
 │         └───────────── 二级域名（你买的那一层）
 └─────────────────────── 三级域名（子域名，你自己加的）
```

**读的顺序是从右往左：**

```text
先看 .com           → 这是哪个"片区"
再看 your-domain    → 这个片区里哪一户
最后看 api          → 这户人家的哪个房间
```

**为什么必须从右往左：**

因为**越往右越"大"**。全世界有成千上万个 `api`，但 `.com` 只有一个。DNS 查询也是这个顺序：先去问 `.com` 的服务器，它告诉你 `your-domain.com` 归谁管，再去问那个服务器。

## 1.2 三级 / 二级 / 顶级，各是谁的

| 层级 | 例子里的部分 | 谁拥有 | 要不要花钱 |
|---|---|---|---|
| 顶级域名 | `.cc` / `.com` / `.cn` | 注册局（ICANN 授权） | 包含在你买的域名里 |
| 二级域名 | `your-domain` | **你**（按年租） | **这是你花钱买的那一层** |
| 三级域名 | `api` | **你**（免费加） | **0 元** |
| 四级域名 | `v2.api` | **你**（免费加） | **0 元** |

**关键结论：**

```text
你买的是 your-domain.com，不是 api.your-domain.com。
在 your-domain.com 下面，你能加无限个子域名，一分钱不多花。
```

**这不是"优惠"，这是域名系统的设计。** 域名本来就是分层的，子域名是这一层自带的能力。

## 1.3 一个域名给多个客户用

这是接活时最实用的一招。

```text
your-domain.com              你的主站
www.your-domain.com          同上（习惯性加 www）
api.your-domain.com          你的接口服务
admin.your-domain.com        后台
demo.your-domain.com         给潜在客户看的演示
client-a.your-domain.com     A 客户的项目
client-b.your-domain.com     B 客户的项目
```

**成本对比：**

| 做法 | 一年成本 | 客户看到的网址 |
|---|---|---|
| 每个客户买一个域名 | 60–100 元 × 客户数 | `client-a.com` |
| 用你的子域名 | **0 元**（只付主域名） | `client-a.your-domain.com` |

> 价格会变，以域名商官网为准。

**但要提醒两件事：**

```text
① 子域名是"租"你的名字。
   客户哪天要搬走，他的链接全部作废。
   合同里要写清"域名归甲方所有"还是"由乙方提供子域名"。

② 备案主体是你，不是客户。
   如果客户要求"备案主体必须是我们公司"，
   那就得用客户的域名 + 客户的备案，不能借你的。
```

**第二点很多人栽过。** 客户是正规公司，要发票、要合规，一看备案主体是个体户名字，合同就卡住了。

## 1.4 域名不是"买断"，是"按年租"

| 事实 | 后果 |
|---|---|
| 域名按年付费 | 到期不续，名字立刻释放 |
| 有 30 天左右的宽限期 | 这期间还能原价续回来 |
| 之后进入赎回期 | 要花几百到几千元赎回 |
| 再之后公开释放 | 谁都能注册，**包括你的竞争对手** |

**这就是第 223 节要讲"续费清单"的原因。**

**现在只需要记住一句：**

> **域名是你租来的名字。房东不提醒你交房租，他只会在到期那天把门锁换掉。**

# 第 2 步：五种记录类型（20 分钟）

## 2.1 解析记录是什么

**大白话：域名后台里的一张表格，每行写一条"什么名字 → 去哪里"。**

全世界有无数台 DNS 服务器，它们会来读这张表（通过层层同步）。**你在这张表里写什么，全世界就按什么找你的服务器。**

## 2.2 五种类型，一张表看懂

| 类型 | 填什么 | 大白话 | 什么时候用 |
|---|---|---|---|
| **A** | 一个 IPv4 地址 | "这个名字住在这个门牌号" | **最常用**，指向你的服务器 |
| **AAAA** | 一个 IPv6 地址 | 同上，但是 IPv6 的门牌号 | 服务器有 IPv6 时 |
| **CNAME** | **另一个域名** | "这个名字跟那个名字走" | 别名，指向第三方服务 |
| **TXT** | 一段文本 | "我在这儿贴了张纸条" | **验证域名是你的** |
| **MX** | 邮件服务器域名 | "寄到这个名字的信，送到那台机器" | 收邮件 |

## 2.3 A 记录：你 90% 的时间只用这一种

```text
主机记录：@
记录类型：A
记录值：  47.98.xx.xx
```

**`47.98.xx.xx` 是你服务器的公网 IP。** 在第 31 周你已经用过它。

**A 记录的本质：**

```text
your-domain.com  →  47.98.xx.xx
```

**一个名字只能指向一个 IP（同一个线路下）。** 想指向两台机器做负载均衡，那是更高级的玩法，这一周不学。

## 2.4 AAAA：现在可以先不管

```text
主机记录：@
记录类型：AAAA
记录值：  2408:xxxx:xxxx::1
```

**IPv6 地址长这样：带冒号，比 IPv4 长得多。**

**为什么现在不用管：**

```text
① 你的服务器大概率只有 IPv4
② 加错了 AAAA 反而会让部分用户走 IPv6 访问失败
③ 现在的用户量，IPv4 完全够
```

**⚠️ 一个真实的坑：** 有些域名商在你买域名时会**自动加一条 AAAA 记录**指向一个占位地址。如果你的服务器没有 IPv6，这条记录会让一部分用户（尤其是手机流量用户）打不开，而你在电脑上完全复现不出来。

**检查方法：**

```bash
nslookup -type=AAAA your-domain.com
```

**如果返回了一个你不认识的 IPv6 地址，把它删掉。**

## 2.5 CNAME：别名

```text
主机记录：www
记录类型：CNAME
记录值：  your-domain.com
```

**意思是："访问 `www.your-domain.com` 时，按 `your-domain.com` 的规则来。"**

**CNAME 和 A 的区别，用一个场景说清：**

```text
你的服务器 IP 是 47.98.xx.xx

用 A 记录：
  www  →  47.98.xx.xx
  换服务器时，你要手动把这条改成新 IP

用 CNAME：
  www  →  your-domain.com
  换服务器时，你只改 @ 那一条，www 自动跟着变
```

**所以 CNAME 的价值是"少改一处"。**

**第三个用途：指向第三方。**

```text
blog.your-domain.com   CNAME   xxx.vercel.app
shop.your-domain.com   CNAME   shops.myshopify.com
```

**这时候你不知道对方的 IP，而且对方的 IP 会变。CNAME 是唯一正确的做法。**

**⚠️ CNAME 的记录值必须是域名，不能是 IP。**

```text
✅ www  CNAME  your-domain.com
❌ www  CNAME  47.98.xx.xx
```

**第二条在很多后台会直接保存失败，或者存进去了但不生效。**

## 2.6 TXT：你不懂它，但你一定会用到它

**TXT 记录就是"在某条名字下面贴一段文本"。**

**它的唯一用途：证明"这个域名真的是你的"。**

**为什么一段文本能证明？**

```text
因为只有能登录域名后台的人，才能加这条记录。
第三方让你"加一段随机字符串"，你能加，就说明后台在你手里。
```

**你会在这些地方遇到它：**

| 场景 | 让你加什么 |
|---|---|
| 申请免费 SSL 证书（DNS 验证方式） | `_acme-challenge` 下的一段随机串 |
| 接入 Cloudflare | 一对 TXT 记录 |
| 验证 Google Search Console | `google-site-verification=...` |
| 验证百度站长 / 必应站长 | 类似的一段串 |
| 企业邮箱域名验证 | `v=spf1 ...` |

**操作方式（和 A 记录一样）：**

```text
主机记录：_acme-challenge
记录类型：TXT
记录值：  xxxxxxxxxxxxxxxxxxxx（第三方给你的那串）
```

**⚠️ 注意：** TXT 的值通常**不要加引号**，但有些后台会自动帮你加。如果验证失败，先检查是不是变成了 `""xxx""` 这种双层引号。

## 2.7 MX：现在别动

```text
主机记录：@
记录类型：MX
记录值：  mx1.example-mail.com
优先级：  5
```

**MX 决定"寄到这个域名的邮件送到哪台服务器"。**

**你现在不需要收邮件，所以不需要 MX。**

**⚠️ 但有一条：如果域名商默认给你配了 MX，不要随便删。** 有些域名商的"域名到期提醒邮件"是发到这个域名的邮箱的。删了 MX，你就收不到续费提醒 —— 然后域名过期 —— 闭环了。

**这一周唯一要动 MX 的场景：** 你要用企业邮箱（比如腾讯企业邮），对方会给你两条 MX 让你加。**按对方给的优先级填，不要自己改数字。**

## 2.8 一张决策表

**以后每次要加记录，先问自己：**

```text
目标是"指向一台我知道 IP 的服务器"     → A
目标是"指向另一个域名（别人的服务）"   → CNAME
目标是"证明域名是我的"                 → TXT
目标是"收邮件"                         → MX
目标是"支持 IPv6"                      → AAAA（可以不做）
```

# 第 3 步：加三条 A 记录（25 分钟）

## 3.1 先准备好两个东西

```text
① 你的域名（假设是 your-domain.com，实际用你买的那个）
② 你服务器的公网 IP（假设是 47.98.xx.xx，在第 31 周的安全组页面能看到）
```

**IP 在哪找（腾讯云 / 阿里云都一样）：**

```text
控制台 → 服务器列表 → 你的实例 → 公网 IP
```

**⚠️ 不要把"内网 IP"当成公网 IP。**

内网 IP 长这样：

```text
10.x.x.x
172.16.x.x — 172.31.x.x
192.168.x.x
```

**这三个段是"机房内部地址"，全世界都连不上。填进 A 记录，域名会指向一个只有机房内部能到的地方，等于没解析。**

## 3.2 进域名解析后台

**操作（腾讯云为例，阿里云类似，界面会变，以你看到的为准）：**

1. 登录域名商控制台；
2. 找到「域名与网站」→「我的域名」；
3. 点你的域名 →「解析」；
4. 看到一张记录列表，通常已经有两三条默认记录（NS、CNAME 之类）；
5. 点「添加记录」。

**你应该看到一个表单，字段大致是：**

```text
主机记录    [            ]
记录类型    [ A          v]
线路类型    [ 默认       v]
记录值      [            ]
MX 优先级   [   (只有 MX 才有) ]
TTL         [ 600        v]
```

**先不要填。看完 3.3 再填。**

## 3.3 我们要加的三条

| 主机记录 | 类型 | 记录值 | 覆盖的网址 |
|---|---|---|---|
| `@` | A | `47.98.xx.xx` | `your-domain.com` |
| `www` | A | `47.98.xx.xx` | `www.your-domain.com` |
| `api` | A | `47.98.xx.xx` | `api.your-domain.com` |

**为什么是这三条：**

```text
@    客户不加 www 直接输域名时能用（这是最常见的输入方式）
www  客户习惯性加 www 时也能用
api  第 5 周的多租户版接口，留给它一个入口
```

**如果你只有一个应用，`api` 那条可以先不加。但建议加上 —— 加了不花钱，等你要用的时候不用再等生效。**

## 3.4 `@` 到底是什么

**`@` 是"根域名"，也就是"不带任何前缀的那个名字"。**

```text
@            →  your-domain.com
www          →  www.your-domain.com
api          →  api.your-domain.com
```

**为什么不用写全 `your-domain.com`：**

因为后台已经知道你在给哪个域名加记录了（你是在 `your-domain.com` 的解析页面里操作）。**主机记录只填"前缀"。**

**⚠️ 这是新手第一大错：**

```text
❌ 主机记录填：your-domain.com
   → 实际生效的是：your-domain.com.your-domain.com
   → 这个域名不存在，永远解析不出来
```

**记住：主机记录填的是"前缀"，不是"完整域名"。** 根域名用 `@`。

## 3.5 TTL 先填 600

**TTL = Time To Live，"这条记录能被缓存多久"，单位是秒。**

| TTL | 含义 | 什么时候用 |
|---|---|---|
| 600（10 分钟） | 全世界每 10 分钟来问一次 | **刚配置时用这个** |
| 3600（1 小时） | 每小时问一次 | 稳定之后 |
| 86400（1 天） | 每天问一次 | **不要用** |

**为什么刚配置时要短：**

```text
你今天大概率会填错一次。
TTL 短 → 改完 10 分钟就生效，你能立刻验证
TTL 长 → 改完要等 1 天，你还以为是自己填错了
```

**为什么稳定后可以调长：**

```text
TTL 越长，你的 DNS 服务器压力越小，用户解析越快（命中缓存）
```

**⚠️ 但有一个反直觉的点：**

> **TTL 是你"改之前"设的值，决定了"改之后要等多久"。**

改记录的那一刻，全世界的 DNS 服务器手里都还攥着旧值的副本，副本的保鲜期就是**你改之前设的 TTL**。

**所以换服务器前一周，要先把 TTL 调短，等一天，再改 IP。** 这个操作叫"预热 TTL"，第 6 步会讲。

## 3.6 保存，然后看列表

**点「保存」或「确定」。**

**你应该看到列表里多了三行：**

```text
主机记录     记录类型   线路类型   记录值            TTL     状态
@            A          默认       47.98.xx.xx       600     正常
www          A          默认       47.98.xx.xx       600     正常
api          A          默认       47.98.xx.xx       600     正常
```

**逐列读这张表：**

| 列 | 意思 | 你要确认什么 |
|---|---|---|
| 主机记录 | 名字的前缀 | 是 `@` / `www` / `api`，**不是完整域名** |
| 记录类型 | A / CNAME / TXT… | A |
| 线路类型 | 电信/联通/移动/默认 | 选"默认"，别选具体运营商 |
| 记录值 | 指向哪里 | **一个数字一个数字对 IP** |
| TTL | 缓存秒数 | 600 |
| 状态 | 正常 / 暂停 / 审核中 | 必须是"正常" |

**⚠️ 如果状态是"审核中"：**

```text
新域名、或者改了敏感记录时，域名商可能会人工审核。
通常几十分钟到几小时。这期间解析不生效，不是你的错。
```

**⚠️ 如果状态是"serverHold"或"未实名"：**

```text
域名没做实名认证。
.cn 域名不实名会直接被 serverHold，解析永远不生效。
去「域名信息」里做实名，1—3 个工作日。
```

**存到：**

# 第 4 步：验证解析到底通没通（25 分钟）

## 4.1 为什么要"验证"，不是"看后台显示正常"

**后台显示"正常"只说明：记录已经写进域名商的数据库。**

**它不说明：**

```text
① 记录已经同步到全世界的 DNS 服务器
② 你本地拿到的是新值（可能是缓存）
③ 那个 IP 真的是你的服务器
```

**所以必须用命令从"外面"看。**

## 4.2 第一个命令：`ping`

**打开 Git Bash（Windows 的 PowerShell 也行，命令一样）：**

```bash
ping your-domain.com
```

**⚠️ 注意：Git Bash 里的 `ping` 调用的是 Windows 的 ping，输出是中文的。**

**应该看到类似：**

```text
正在 Ping your-domain.com [47.98.xx.xx] 具有 32 字节的数据:
来自 47.98.xx.xx 的回复: 字节=32 时间=28ms TTL=52
来自 47.98.xx.xx 的回复: 字节=32 时间=27ms TTL=52
来自 47.98.xx.xx 的回复: 字节=32 时间=29ms TTL=52
来自 47.98.xx.xx 的回复: 字节=32 时间=28ms TTL=52

47.98.xx.xx 的 Ping 统计信息:
    数据包: 已发送 = 4，已接收 = 4，丢失 = 0 (0% 丢失)，
往返行程的估计时间(以毫秒为单位):
    最短 = 27ms，最长 = 29ms，平均 = 28ms
```

**逐行读：**

| 行 | 意思 | 你要确认什么 |
|---|---|---|
| `正在 Ping your-domain.com [47.98.xx.xx]` | 先把域名解析成 IP，**这个 IP 在方括号里** | **是不是你服务器的 IP** |
| `来自 47.98.xx.xx 的回复` | 对方回应了 | 通了 |
| `字节=32` | 每次发 32 字节 | 固定值，不用管 |
| `时间=28ms` | 一个来回 28 毫秒 | 国内服务器通常 20—60ms |
| `TTL=52` | **这里是网络包的存活跳数，不是 DNS 的 TTL** | 别搞混，见 4.5 |
| `丢失 = 0 (0% 丢失)` | 四个包全回来了 | 0% 最好 |

**注意一个非常容易混的点：**

```text
ping 输出里的 TTL=52         →  网络包还能经过多少个路由器（IP 协议字段）
解析记录里的 TTL=600         →  这条 DNS 记录能被缓存多少秒
```

**两个 TTL 完全没关系，只是名字撞了。**

## 4.3 `ping` 不通，但有 IP —— 这是最常见的情况

**先看这一行：**

```text
正在 Ping your-domain.com [47.98.xx.xx] 具有 32 字节的数据:
```

**只要方括号里有正确的 IP，解析就是成功的。**

**后面的"请求超时"可能是：**

```text
来自 47.98.xx.xx 的回复: 请求超时。
来自 47.98.xx.xx 的回复: 请求超时。
```

**为什么超时但网站能打开：**

```text
云服务器的安全组默认只放行 TCP 22 / 80 / 443。
ICMP（ping 用的协议）通常不放行。
所以 ping 不通，但浏览器能打开 —— 这是正常的。
```

**⚠️ 所以"ping 不通"绝对不能直接判定"网站挂了"。**

**判断解析有没有成功，看方括号里的 IP；判断网站通不通，用 `curl`：**

```bash
curl -I http://your-domain.com
```

**应该看到：**

```text
HTTP/1.1 200 OK
Server: nginx/1.24.0 (Ubuntu)
Date: Mon, 16 Nov 2026 09:12:33 GMT
Content-Type: text/html; charset=utf-8
...
```

**如果这里返回 `502 Bad Gateway`，说明解析成功了、请求到了 Nginx，是 Nginx 到后端的问题 —— 那是第 219 节和第 224 节的事，不是解析的问题。**

**这个区分能力很重要：**

```text
DNS 打不开     →  浏览器说"找不到服务器"，curl 说 "Could not resolve host"
502           →  DNS 通了，Nginx 通了，后端没通
```

## 4.4 第二个命令：`nslookup`

**`ping` 只给你一个 IP。`nslookup` 能告诉你"是谁回答的"。**

```bash
nslookup your-domain.com
```

**应该看到（中文 Windows）：**

```text
服务器:  UnKnown
Address:  192.168.1.1

非权威应答:
名称:    your-domain.com
Address:  47.98.xx.xx
```

**英文版长这样：**

```text
Server:         192.168.1.1
Address:        192.168.1.1#53

Non-authoritative answer:
Name:   your-domain.com
Address: 47.98.xx.xx
```

**逐行读：**

| 行 | 意思 | 说明 |
|---|---|---|
| `服务器: UnKnown` | **你问的是哪台 DNS 服务器** | `UnKnown` 是它没反查到自己名字，不影响 |
| `Address: 192.168.1.1` | 这台 DNS 的地址 | 通常是你的路由器 |
| `Address: 192.168.1.1#53` | 同上，`#53` 是 DNS 的端口 | 英文版才有 |
| `非权威应答` | **这个答案来自缓存，不是域名商的权威服务器** | 关键信息，见下 |
| `名称: your-domain.com` | 你要查的名字 | |
| `Address: 47.98.xx.xx` | 解析出来的 IP | **必须和你的服务器一致** |

**"非权威应答"是什么意思：**

```text
权威服务器  = 域名商那台"原始档案柜"，答案 100% 可信
非权威应答  = 中间某台服务器（你的路由器 / 运营商）的复印件
```

**复印件可能是旧的。**

**想看权威答案，直接问域名商的 NS：**

```bash
nslookup your-domain.com 8.8.8.8
```

**这条命令的意思是"别问我的路由器，去问 8.8.8.8（Google 的公共 DNS）"。**

**应该看到：**

```text
服务器:  dns.google
Address:  8.8.8.8

非权威应答:
名称:    your-domain.com
Address:  47.98.xx.xx
```

**如果 `8.8.8.8` 返回的是新 IP，而你本地返回的是旧 IP —— 那就是本地缓存问题，去第 5 步。**

**如果两个都返回旧 IP —— 那是域名商还没同步完，继续等（或者检查你改没改对）。**

## 4.5 第三个命令：`dig`

**`dig` 是 Linux / macOS 自带的，Windows 默认没有。**

**两个办法用它：**

```text
① 在你的服务器上跑（服务器是 Ubuntu，一定有）
② 在 WSL 里跑（如果装了）
```

**在服务器上：**

```bash
dig your-domain.com A
```

**应该看到：**

```text
; <<>> DiG 9.18.18-0ubuntu0.22.04.2-Ubuntu <<>> your-domain.com A
;; global options: +cmd
;; Got answer:
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 41234
;; flags: qr rd ra; QUERY: 1, ANSWER: 1, AUTHORITY: 0, ADDITIONAL: 1

;; OPT PSEUDOSECTION:
; EDNS: version: 0, flags:; udp: 65494
;; QUESTION SECTION:
;your-domain.com.               IN      A

;; ANSWER SECTION:
your-domain.com.        600     IN      A       47.98.xx.xx

;; Query time: 12 msec
;; SERVER: 183.60.83.19#53(183.60.83.19) (UDP)
;; WHEN: Mon Nov 16 17:12:40 CST 2026
;; MSG SIZE  rcvd: 56
```

**逐段读：**

| 段 | 意思 | 你要看什么 |
|---|---|---|
| `status: NOERROR` | 查询成功 | 如果是 `NXDOMAIN`，说明这个名字不存在 |
| `ANSWER: 1` | 有 1 条答案 | 0 条就是没查到 |
| `QUESTION SECTION` | 你问了什么 | `your-domain.com. IN A` |
| `ANSWER SECTION` | 答案 | **`600` 是 TTL，`A` 是类型，最后是 IP** |
| `Query time: 12 msec` | 查询耗时 | 正常 |
| `SERVER: 183.60.83.19#53` | 谁回答的 | 你在服务器上跑，问的是云厂商内网 DNS |

**`dig` 比 `nslookup` 好在哪：**

```text
① 直接告诉你 TTL（还剩多少秒过期）
② 直接告诉你 status（NOERROR / NXDOMAIN / SERVFAIL）
③ 可以只输出 IP：dig +short your-domain.com
```

**最常用的一条：**

```bash
dig +short your-domain.com
```

**应该看到一行：**

```text
47.98.xx.xx
```

**干净利落。写脚本的时候用这个。**

## 4.6 三个命令的分工

| 命令 | 在哪用 | 强项 | 弱项 |
|---|---|---|---|
| `ping` | 哪都有 | 最快，顺手 | 只看 IP；ICMP 被封就误判 |
| `nslookup` | 哪都有 | 能换 DNS 服务器对比 | 不显示 TTL |
| `dig` | Linux/macOS/WSL | 信息全，能看 TTL 和状态 | Windows 没有 |

**日常判断顺序：**

```text
① ping 看一眼 IP 对不对（10 秒）
② 不对 → nslookup 加 8.8.8.8 对比，判断是缓存还是没配好
③ 需要细节 → 服务器上 dig，看 TTL 和 status
```

# 第 5 步：DNS 缓存这个坑（20 分钟）

## 5.1 为什么"改了不生效"

**因为你改了源头，但全世界手里都有复印件。**

```text
你改的是：域名商数据库里的原始记录       ← 这一份是新的
全世界用的是：各级 DNS 的缓存副本         ← 这些还是旧的
```

**缓存在哪几层：**

| 层 | 谁 | 缓存多久 |
|---|---|---|
| 浏览器 | Chrome / Edge | 自己的 DNS 缓存，几十秒到几分钟 |
| 操作系统 | Windows | 有缓存，可以手动清 |
| 路由器 | 你家的路由器 | 通常几小时 |
| 运营商 | 电信/联通/移动 | **跟 TTL 走**，最长 48 小时 |
| 公共 DNS | 8.8.8.8 / 114.114.114.114 | 跟 TTL 走 |

**你要清的是"操作系统"这层，因为这是你唯一能直接控制的。**

## 5.2 `ipconfig /flushdns`

**Git Bash 里：**

```bash
ipconfig //flushdns
```

**⚠️ 注意 Git Bash 的路径转换问题：** Git Bash 会把 `/flushdns` 当成一个路径去转换，导致命令失败。**两个斜杠 `//flushdns` 可以绕过。**

**或者在 PowerShell / cmd 里：**

```powershell
ipconfig /flushdns
```

**应该看到：**

```text
Windows IP 配置

已成功刷新 DNS 解析缓存。
```

**英文版：**

```text
Successfully flushed the DNS Resolver Cache.
```

**看到"已成功刷新"，再去 `ping` 一次。**

## 5.3 清完还是旧的，怎么办

**按顺序试：**

```text
① 换一个 DNS 服务器查：nslookup your-domain.com 8.8.8.8
   → 新值 = 你本地/运营商缓存，不是配置问题
   → 旧值 = 域名商还没同步，或者你根本没保存成功

② 用手机 4G 测（关掉 WiFi）
   → 手机走的是移动网络，完全不经过你家路由器
   → 手机是新值、电脑是旧值 = 100% 本地缓存

③ 用在线工具查（站长工具 / DNSChecker 之类）
   → 它们从多个地区同时查，能看出"哪些地区生效了"
```

**第 ② 条最有用。** 手机 4G 是"另一条完全独立的路"，它能看到新值，就说明你的配置是对的。

**⚠️ 手机测的时候记得关 WiFi。** 开着 WiFi 的手机和你电脑走同一个出口，测了等于没测。

## 5.4 浏览器自己也有缓存

**Chrome 的 DNS 缓存：**

```text
地址栏输：chrome://net-internals/#dns
点 "Clear host cache"
```

**这个页面的具体位置和按钮名称会随版本变，以你看到的为准。**

**Edge 类似：`edge://net-internals/#dns`**

**⚠️ 还有一个更隐蔽的：HSTS 缓存。**

如果你之前访问过 `https://your-domain.com` 并且它返回了 HSTS 头，浏览器会**强制**以后都走 https，连 http 都不试。这时候你改了配置，浏览器还在按老规则走。

**清理入口：**

```text
chrome://net-internals/#hsts
在 "Delete domain security policies" 里输入你的域名，点 Delete
```

**这个坑在第 220 节上 HTTPS 之后会遇到。**

## 5.5 生效时间到底多久

| 阶段 | 时间 |
|---|---|
| 域名商数据库写入 | 立刻 |
| 同步到域名商的 NS 服务器 | 几十秒到几分钟 |
| 你本地（清缓存后） | 立刻 |
| 你所在运营商 | 跟 TTL 走，10 分钟到几小时 |
| 全国基本生效 | 通常 10 分钟到 2 小时 |
| **最坏情况** | **48 小时** |

**为什么最坏 48 小时：**

```text
有些运营商的 DNS 不严格遵守 TTL，
它们会"多缓存一会儿"，行业里默认把 48 小时当上限。
```

**所以：**

```text
给客户交付前一天，不要改解析。
要改，提前两天改，留出 48 小时缓冲。
```

# 第 6 步：域名 → IP → Nginx 的完整链路（15 分钟）

## 6.1 把这一节课和第 31 周接起来

**现在你的请求走这条路：**

```text
浏览器输 your-domain.com
   ↓ ① DNS 查询（今天学的）
拿到 47.98.xx.xx
   ↓ ② 建立 TCP 连接（安全组 80 放行）
到达服务器
   ↓ ③ Nginx 接收（第 31 周配的）
按 server_name 决定交给谁
   ↓ ④ proxy_pass 到 127.0.0.1:3000
Node 程序
```

**今天你只完成了 ①。②③④ 在第 31 周已经通了。**

**所以现在的状态是：**

```text
curl -I http://your-domain.com   →  200（如果 ③ 配的是默认站点，也能 200）
```

**⚠️ 但"200"不等于"对"。**

**因为第 31 周的 `server_name` 可能还写着 `_` 或者 IP。**

**`server_name _;` 的意思是"我是默认站点，谁来找我都行"。**

**所以现在可能出现：**

```text
访问 your-domain.com  →  打开了你的应用  ✅ 看起来对
但实际上是"因为它是唯一的站点，所以什么都给它"
```

**这不是"配置对了"，这是"只有一个站点时碰巧能用"。**

**等你有第二个站点（`api.your-domain.com`）时，就会暴露：两个域名都打开同一个应用。**

**这就是第 219 节要做的事：把 `server_name` 写对。**

## 6.2 现在就验证一下

**在服务器上跑：**

```bash
curl -I -H "Host: your-domain.com" http://127.0.0.1
```

**`-H "Host: ..."` 是什么：** 手动指定请求里的"我要访问哪个域名"。

**为什么要这么测：**

```text
用 127.0.0.1 访问，绕过了 DNS 和防火墙，
只测"Nginx 看到这个域名时，交给谁"。
```

**应该看到：**

```text
HTTP/1.1 200 OK
Server: nginx/1.24.0 (Ubuntu)
```

**如果看到 404，或者看到的是 Nginx 的欢迎页：**

```text
说明 server_name 没匹配上，落到默认站点了。
这是第 219 节要修的。今天先记下来。
```

**再看一眼当前的配置：**

```bash
sudo cat /etc/nginx/sites-available/default | head -20
```

**应该看到类似：**

```nginx
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    server_name _;
    ...
}
```

**看到 `server_name _;` 就记下来：这节课不用改，下节课改。**

**⚠️ 不要在这节课改 Nginx 配置。** 一次只动一个变量：今天只动 DNS。DNS 出问题的时候，你不希望同时怀疑 Nginx。

## 6.3 一个完整链路的分层判断表

**这张表以后会一直用：**

| 你看到的现象 | 断在哪一层 | 怎么验证 |
|---|---|---|
| 浏览器"找不到服务器" | DNS | `ping` 看有没有 IP |
| `curl: Could not resolve host` | DNS | 同上 |
| 浏览器"连接超时" | 安全组 / 服务器关机 | `telnet IP 80` |
| 浏览器"拒绝连接" | 程序没跑 / 端口不对 | 服务器上 `curl localhost:3000` |
| 404 | Nginx `server_name` 没匹配 | `curl -H "Host: 域名" 127.0.0.1` |
| 502 | 后端挂了 / 端口错 | `pm2 list` |
| 锁图标是红的 | 证书问题 | 第 220 节 |

**⚠️ 大多数人的错误是"从下往上查"：先看代码、先重启服务、先重装 Nginx。**

**正确顺序是从上往下：DNS → 端口 → Nginx → 程序。**

**为什么：**

```text
DNS 错了，你看一万行代码也没用。
而 DNS 错了的表现（找不到服务器）和 Nginx 错了的表现（404）完全不同。
先看一眼现象，就能砍掉 80% 的可能性。
```

# 第 7 步：故意犯七个错（30 分钟）

**下面的实验都在域名后台做。做完记得改回来。**

**⚠️ 如果你的域名已经在给客户用了，不要在工作时间做这些实验。挑一个没人的时候。**

## 错误 1：A 记录填错一个数字

**操作：**

1. 把 `@` 那条 A 记录的记录值从 `47.98.xx.xx` 改成 `47.98.xx.xy`（最后一位改掉）；
2. 保存；
3. 等 10 分钟（因为你 TTL 是 600）；
4. `ipconfig //flushdns`；
5. `ping your-domain.com`。

**会怎样：**

```text
正在 Ping your-domain.com [47.98.xx.xy] 具有 32 字节的数据:
来自 47.98.xx.xy 的回复: 请求超时。
请求超时。
```

**或者更可怕的情况 —— 那个 IP 是别人的：**

```text
正在 Ping your-domain.com [47.98.xx.xy] 具有 32 字节的数据:
来自 47.98.xx.xy 的回复: 字节=32 时间=15ms TTL=54
```

**为什么可怕：**

```text
47.98.xx.xy 是同一家云厂商的另一个用户的服务器。
你的客户访问你的域名，看到的是别人的网站。
如果那个网站是博彩/诈骗，你的域名会被举报、被封。
```

**为什么：**

IP 地址是连续的，改错一位很可能落在**同一家云厂商的地址池里**——那里全是别人的服务器，而且很可能开着 80 端口。

**怎么修：**

```text
改回 47.98.xx.xx，保存，等 TTL，清缓存。
```

**怎么防止：**

```text
填 IP 的时候，把 IP 复制到记事本，对着服务器控制台一个一个数字对。
不要手打。
```

## 错误 2：主机记录填成完整域名

**操作：**

1. 加一条新记录；
2. 主机记录填 `api.your-domain.com`（而不是 `api`）；
3. 类型 A，值 `47.98.xx.xx`；
4. 保存；
5. 等生效后查：

```bash
nslookup api.your-domain.com
```

**会怎样：**

```text
服务器:  UnKnown
Address:  192.168.1.1

*** UnKnown 找不到 api.your-domain.com: Non-existent domain
```

**或者英文：**

```text
** server can't find api.your-domain.com: NXDOMAIN
```

**为什么：**

域名商会在你填的主机记录后面**自动补上域名**。所以你实际创建的是：

```text
api.your-domain.com.your-domain.com
```

**这个域名不存在，所以 `NXDOMAIN`（Non-Existent Domain，域名不存在）。**

**验证你的猜想：**

```bash
nslookup api.your-domain.com.your-domain.com
```

**如果这条能查出 IP，就 100% 确认是这个错。**

**怎么修：**

```text
删掉那条错误的记录，重新加一条主机记录为 api 的。
```

**顺便记一下：**

```text
NXDOMAIN       = 这个名字不存在（配错了 / 没配）
SERVFAIL       = DNS 服务器自己出问题了（域名商故障）
NOERROR + 空   = 名字存在，但没有这种类型的记录（比如只配了 A，你去查 MX）
```

## 错误 3：只加了 `www`，没加 `@`

**操作：**

1. 删掉 `@` 那条 A 记录（或者暂停它）；
2. 只留 `www`；
3. 清缓存；
4. 分别访问：

```bash
ping your-domain.com
ping www.your-domain.com
```

**会怎样：**

```text
C:\> ping your-domain.com
Ping 请求找不到主机 your-domain.com。请检查该名称，然后重试。

C:\> ping www.your-domain.com
正在 Ping www.your-domain.com [47.98.xx.xx] 具有 32 字节的数据:
```

**为什么：**

```text
`@` 和 `www` 是两条完全独立的记录。
DNS 没有"继承"这回事。
```

**这是新手最常见的线上事故之一：**

```text
你自己习惯输 www.xxx.com，测试全过。
客户习惯直接输 xxx.com，打不开。
然后客户说"你们的网站是坏的"。
```

**怎么修：**

```text
把 @ 加回来。两条都留。
```

**⚠️ 恢复记录的时候注意：** 如果域名商有"暂停"而不是"删除"，优先用暂停 —— 暂停可以一键恢复，删除要重新填。

## 错误 4：TTL 设 86400，然后要改 IP

**操作：**

1. 把三条 A 记录的 TTL 都改成 `86400`（1 天）；
2. 保存；
3. 等 1 天（或者不等，直接继续）；
4. 现在把 IP 改成一个错的；
5. 立刻清本地缓存，`ping`。

**会怎样：**

分两种情况，都很真实：

```text
情况 A（你等了 1 天，TTL 已经生效）：
  改完 IP 后，你自己清缓存能看到新值，
  但客户的运营商缓存要 24 小时才更新。
  这 24 小时里，一部分客户能打开，一部分打不开。

情况 B（你没等，立刻改）：
  全世界手里还是 TTL=600 的旧副本，
  所以 10 分钟就更新了 —— 你"侥幸"没事。
  但这说明你的 TTL 设置还没生效，下次就没这么幸运了。
```

**为什么这是最贵的一种错：**

```text
网站"一半人能打开一半人打不开"，是最难排查的故障。
因为你测的时候是好的。
```

**正确做法（换服务器的标准流程）：**

```text
提前 2 天：把 TTL 从 86400 改成 600，保存，等 1 天让它生效
第 3 天：改 IP
第 4 天：确认新 IP 稳定后，把 TTL 改回 3600
```

**这个流程叫"TTL 预热"。** 记住它，第 224 节的 RUNBOOK 里会写。

**怎么修（这次实验）：**

```text
把 TTL 改回 600，IP 改回正确的。
如果已经造成了"部分地区打不开"，只能等。
```

## 错误 5：域名没实名认证就加解析

**操作：**

1. 如果你买的是 `.cn` 域名，先不做实名（或者找一个刚买还没实名的域名）；
2. 直接加 A 记录；
3. 等；
4. `ping`。

**会怎样：**

后台记录状态显示：

```text
serverHold
```

**或者：**

```text
未实名认证
```

**`ping` 的结果：**

```text
Ping 请求找不到主机 your-domain.com。请检查该名称，然后重试。
```

**为什么：**

```text
.cn 域名受工信部管理，必须实名。
未实名的域名会被注册局设为 serverHold（暂停解析）。
这不是"没生效"，是"被冻结了"。
```

**怎么查：**

```bash
nslookup -type=ns your-domain.com
```

**如果连 NS 记录都查不到，说明整个域名被 hold 了，不是你的 A 记录问题。**

**怎么修：**

```text
域名控制台 → 域名信息 → 实名认证
上传身份证 / 营业执照，等 1—3 个工作日。
```

**⚠️ `.com` 域名现在也要求实名（国内注册商），只是宽限期稍长。买了就立刻做，不要拖。**

## 错误 6：本地缓存没清，以为没生效

**操作：**

1. 把 `@` 的 IP 改成一个明显的错值（比如 `1.1.1.1`）；
2. 等 15 分钟；
3. **不清缓存**，直接 `ping`。

**会怎样：**

```text
正在 Ping your-domain.com [47.98.xx.xx] 具有 32 字节的数据:
```

**还是旧 IP。**

**这时候你的判断会是："改了没生效，可能是域名商的问题，再等等。"**

**实际上：**

```text
改是生效了，只是你电脑还在用缓存。
```

**验证：**

```bash
nslookup your-domain.com 8.8.8.8
```

**应该看到：**

```text
名称:    your-domain.com
Address:  1.1.1.1
```

**新值出来了 —— 说明配置早就生效了，是本地缓存。**

**怎么修：**

```bash
ipconfig //flushdns
ping your-domain.com
```

**记住这个判断顺序：**

```text
本地查是旧值  →  先查 8.8.8.8
8.8.8.8 是新值  →  本地缓存，flushdns
8.8.8.8 也是旧值 →  配置没生效，继续等或检查后台
```

## 错误 7：CNAME 指向一个 IP

**操作：**

1. 加一条记录；
2. 主机记录 `blog`；
3. 类型选 **CNAME**；
4. 记录值填 `47.98.xx.xx`（一个 IP）；
5. 保存。

**会怎样：**

**情况 A：后台直接拒绝。**

```text
记录值格式不正确，请输入域名
```

**情况 B：后台让你存了，但解析不出来。**

```bash
nslookup blog.your-domain.com
```

```text
*** UnKnown 找不到 blog.your-domain.com: Non-existent domain
```

**为什么：**

```text
CNAME 的语义是"这个名字是另一个名字的别名"。
它的值必须是"名字"，不能是"地址"。
DNS 协议里 CNAME 记录的类型就是域名，不是 IP。
```

**正确的两种写法：**

```text
blog  CNAME  your-domain.com        ← 指向自己的另一个名字
blog  CNAME  xxx.vercel.app         ← 指向第三方
blog  A      47.98.xx.xx            ← 直接指 IP，用 A 不用 CNAME
```

**怎么修：**

```text
要指 IP 就用 A 记录。要指名字才用 CNAME。
```

# 附：常见问题速查

| 现象 | 原因 | 怎么做 |
|---|---|---|
| `Ping 请求找不到主机` | 没配记录 / 没生效 / 域名被 hold | 先 `nslookup 8.8.8.8`，再查后台状态 |
| `NXDOMAIN` | 名字不存在，多半是主机记录填成了完整域名 | 删掉重加，主机记录只填前缀 |
| `ping` 超时但方括号有 IP | ICMP 被安全组挡了 | 正常，改用 `curl -I` 测 |
| `ping` 出来的 IP 不是我的 | A 记录填错 / 被别人改了 | 对着控制台一个数字一个数字核对 |
| 改了记录，本地还是旧 IP | 本地 DNS 缓存 | `ipconfig //flushdns` |
| 清完缓存还是旧 IP | 运营商缓存 | 用手机 4G 测，或等 TTL |
| 手机能开、电脑不能开 | 电脑缓存 / hosts 文件 | 清缓存，检查 `C:\Windows\System32\drivers\etc\hosts` |
| 电脑能开、手机不能开 | 手机走了 IPv6，AAAA 记录有问题 | `nslookup -type=AAAA`，删掉可疑的 AAAA |
| 后台显示"审核中" | 域名商人工审核 | 等，几十分钟到几小时 |
| 后台显示 `serverHold` | 未实名 | 去做实名认证 |
| `curl` 返回 404 | 解析通了，Nginx `server_name` 没匹配 | 第 219 节 |
| `curl` 返回 502 | 解析和 Nginx 都通了，后端挂了 | `pm2 list` |
| `curl: Could not resolve host` | 完全没解析 | 回到第一步 |
| 全国有的地方能开、有的不能 | TTL 太长，各地缓存不同步 | 只能等，下次改前先预热 TTL |
| 域名到期后打不开 | 忘了续费 | 第 223 节，现在就设日历 |
| `.cn` 域名一直不生效 | 实名没做完 | 域名信息里看认证状态 |
| 换了 IP 后一部分人打不开 | TTL 太长 | 提前两天把 TTL 调短 |
| 子域名访问到了主站 | `server_name` 只配了一个 | 第 219 节，多个 server 块 |
| `nslookup` 显示两个 IP | 加了多条 A 记录（轮询） | 确认是不是你有意为之 |
| `dig` 命令不存在 | Windows 没有 | 去服务器上跑，或用 `nslookup` |
