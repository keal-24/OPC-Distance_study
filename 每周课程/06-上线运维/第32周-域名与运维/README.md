# 第32周 · 域名与运维 · 第 218—224 节课

## 从"一串数字"到"能收钱的名字"

---

## 这一周的目标

第 31 周结束，你的应用在 `http://47.98.xx.xx` 上能打开了。

这一周把它变成一个**别人敢用的服务**。七节课之后，你要能做到这五件事：

1. **把自己的域名解析到自己的服务器** —— 不是点完保存就算，要用 `ping` 证明出来的是你的 IP；
2. **搞清国内备案这条硬门槛** —— 买之前就知道要等多久，不在备案上白等两周；
3. **让地址栏出现锁** —— HTTPS 签下来、自动跳转、续期演练过；
4. **先把"它一定会坏"当成前提** —— 有健康检查、有每日备份、真的做过一次恢复；
5. **坏了你在客户之前知道** —— 监控告警上线，并且有一页纸写清"打不开怎么办"。

## 为什么排在这一周

第 31 周的成果是"IP 能打开"。IP 有两个问题，都是致命的：

```text
① 人记不住         客户不会把 47.98.xx.xx 存进通讯录
② 换机器就全废     你换台服务器，所有旧链接、所有宣传物料全指向空
```

更现实的是第三条：

```text
微信支付、小程序、公众号、大多数第三方 API
→ 全部要求"已备案的域名 + HTTPS"
→ 只有 IP 的开发者，连申请入口都进不去
```

所以顺序只能是：**先通（IP）→ 再有名字（域名）→ 再有名分（备案）→ 再上锁（HTTPS）→ 再做兜底（备份监控）**。

**这五步跳一步，后面每一步都会回来找你。**

```text
IP 能开
  ↓ 加域名          第 218 节
名字能开
  ↓ 过备案 + 绑站点  第 219 节
国内能合法开
  ↓ 上 HTTPS        第 220 节
客户敢用
  ↓ 备份 + 监控      第 221、222 节
你敢睡觉
  ↓ 日志 + 成本 + 续费 第 223 节
你能收钱
  ↓ RUNBOOK         第 224 节
出事你不慌
```

## 一个必须先讲清楚的规矩

这一周有三类操作会**直接影响线上**，也有两类会**直接花钱**：

```text
改 DNS 解析        线上可能立刻中断，最长要等 48 小时才恢复
改 Nginx 配置      写错一个分号，整站 502
删库做恢复演练      在正式库上做，客户数据当场消失

买域名             按年付费，自动续费
买服务器           按月付费，到期可能释放数据
```

**规矩一：这一周所有"改配置"的操作，动手前先备份能回滚的那一份。**

```bash
# 改 nginx 配置前，永远先复制一份
sudo cp /etc/nginx/sites-available/default /etc/nginx/sites-available/default.bak
```

**规矩二：恢复演练绝对不在正式库上做。**

课件里会让你建一个 `restore_test` 库来恢复。**不要在 `production` 库上敲 `DROP DATABASE`。**

**规矩三：域名和服务器，第一次买就把自动续费打开。**

这一周会讲"忘记续费，网站在某个凌晨直接消失"。那不是吓人，是每年都在发生的事。

## 这一周的铁律

这四条会用在你以后每一个项目上：

```text
一、改任何 DNS 记录之前，先记下原来的值。
    截图，或者抄进笔记。改错了要能改回去。

二、nginx -t 通过才允许 reload。
    不带 -t 直接 reload，等于闭着眼睛改线上。

三、没做过恢复演练的备份，等于没有备份。
    备份文件存在，不等于能恢复。

四、域名、证书、服务器，三个到期日全部进日历，提前 30 天提醒。
    忘记续费不会报错，它只会让网站某天早上直接不见。
```

## 这一周最危险的六条命令

**第一：`rm -rf /etc/nginx/sites-available/default`**

删掉配置文件本身。Nginx 还在跑（用的是内存里的旧配置），但下次 reload 或重启就起不来。**先 `cp` 备份，再改。**

**第二：`DROP DATABASE production;`**

恢复演练时最容易手滑的一条。**看清楚库名。演练库叫 `restore_test`。**

**第三：`systemctl stop nginx`**

停掉门卫。所有域名立刻全部打不开。**如果这时你正好在外面，只能等回去。**

**第四：`iptables -F` / `ufw disable`**

关防火墙。看起来"解决了访问问题"，实际是把数据库端口和 SSH 一起暴露给全网。**几小时内就会被扫。**

**第五：在后台上"删除解析记录"**

不是改，是删。删掉之后域名立刻不解析，而且**有些厂商删除后不能恢复原记录，只能重新加**。

**第六：`certbot delete`**

删证书。删完 HTTPS 立刻失效，浏览器直接红色警告。**证书可以重签，但重签有频率限制。**

**这六条不是"不能用"，是"用之前必须知道自己在干什么"。**

## 周末的验收

不要急着进下一周。先确认这八条：

- [ ] `ping your-domain.com` 返回的是我服务器的 IP（不是别人的，不是 `127.0.0.1`）
- [ ] 我知道自己的域名要不要备案，要的话现在是什么状态
- [ ] `https://your-domain.com` 地址栏有锁，`http://` 会自动跳到 `https://`
- [ ] `certbot renew --dry-run` 跑过，没有报错
- [ ] `/health` 在数据库挂掉时返回 503（我制造过一次，看过）
- [ ] 我有一个每日自动备份，并且**真的恢复过一次**，比对过数据
- [ ] UptimeRobot 在监控我的域名，我故意停服务收到过告警，也收到过恢复通知
- [ ] `RUNBOOK.md` 存在，里面有八步排查法、常用命令、找谁

**另外：**

- [ ] 每节课的 `NOTES.md` 都填了，没有大片空白
- [ ] 「卡在哪」那一栏写了真实内容（不是"没有卡住"）
- [ ] 我能不看笔记说出"网站打不开，第一步查什么"

> **最后一条才是真标准。** 前面七条是"做过了"，最后一条是"会了"。
>
> **一周七节课，第 04、05 节不能落。** 因为备份和监控是"敢不敢接客户"的分水岭 —— 没有它们，你接的不是项目，是定时炸弹。

## 这一周不用学什么

明确排除，避免你分心：

```text
Kubernetes / 容器编排        个人项目用不到，第 29 周 Docker 已经够
CDN 加速                    流量小的时候是负优化
负载均衡（多台服务器）        一台 2 核 2G 能撑几十个用户
DNS 的高级玩法（智能解析、
  分线路、权重）             客户量到几百再考虑
自建邮件服务器               一定会进垃圾箱，用第三方
WAF / DDoS 高防             被打了再买，别提前花钱
监控大盘（Grafana + Prometheus） UptimeRobot 免费版够用一整年
ICP 备案的加急/代办          自己能办，别花钱找中介
```

**这一周只做一件事：让一个小项目"能交给别人用"。**

不是做大规模，是做完整。
