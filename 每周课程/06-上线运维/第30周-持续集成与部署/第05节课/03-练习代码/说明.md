# 03-练习代码

**这个文件夹故意不留代码。** 这一节要把"自动部署"这条链真正接起来：服务器端的脚本 + CI 里的 job + 一把只能部署的钥匙。

## 这一节的四件正事

```text
① 生成一把专用密钥      不用你自己的 SSH key
② 让这把钥匙只能干一件事  command="..." 限制
③ 写幂等的 deploy.sh     跑一次和跑三次，结果一样
④ 配置 SSH_KNOWN_HOSTS   不许用 StrictHostKeyChecking=no 蒙过去
```

## 为什么 `deploy.sh` 必须幂等

CI 会重跑。你在 GitHub 页面上点一次 "Re-run jobs"，或者在本地推一次空提交，它就是再跑一遍。

**不幂等的脚本会出现这些现象：**

```text
第二次跑：目录已存在 → mkdir 报错 → 脚本退出 → 部署失败
第二次跑：容器名冲突 → docker run 报 Conflict → 部署失败
第二次跑：日志被清空   → 出问题想查，发现日志没了
```

**幂等的写法：** `mkdir -p`、`docker compose up -d`（本身就是幂等的）、日志用 `>>` 不用 `>`。

## `deploy.sh` 至少要做的六件事

```bash
# 1. 进目录（cd 失败就退出，别在错的目录里继续）
# 2. 记下当前版本（这是回滚的前提）
# 3. 拉新镜像
# 4. 起容器（up -d，不是 run）
# 5. 等健康检查（不要 up 完就宣布成功）
# 6. 打一行明确的成功标记（CI 靠这行判断）
```

**第 2 步和第 5 步最容易漏。** 漏第 2 步，回滚没得回；漏第 5 步，容器还在启动就报"部署成功"。

## ⚠️ 这个目录里绝不能出现的东西

```text
❌ SSH 私钥（一律写进 GitHub Secrets）
❌ 真实服务器 IP（用 47.98.xx.xx）
❌ 真实密码 / API key
❌ StrictHostKeyChecking=no（除非你能说清为什么这里可以）
```

## 这一节要留下的证据

| 证据 | 证明什么 |
|---|---|
| `deploy.sh` 连跑三次都成功 | 脚本是幂等的 |
| `ssh -i deploy_key` 带 `command=` 限制后执行 `id` 的输出 | 钥匙只能干一件事 |
| Actions 里 deploy job 的完整日志 | CI 真的连上了服务器 |
| 服务器上 `cat .current_sha` 和 `docker inspect` 的对比 | 部署的是这次构建的镜像 |
| 一次故意失败的部署 + 恢复 | 你知道失败长什么样 |
