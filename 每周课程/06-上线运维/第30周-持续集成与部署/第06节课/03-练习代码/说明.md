# 03-练习代码

**这个文件夹故意不留代码。** 这一节要在这里建一个 `secrets-lab/`，专门用来**把密钥泄露这件事亲手做一遍**。

---

## 本节课你要建什么

```text
03-练习代码/
├── secrets-lab/                 ← 你自己建
│   ├── .env                     ← 里面放假 key（sk-test-xxxx）
│   ├── secrets-check.sh         ← 你写的扫描脚本
│   └── 泄露记录.md              ← 四条路径逐条试的记录
└── notify/                      ← 通知相关的 yml 草稿
    └── notify.yml
```

## `secrets-lab/` 要做什么

```text
① 把假 key 写进 .env  →  commit  →  git log -p 还能看到吗
② 把假 key 写进 yml   →  commit  →  打开仓库历史能看到吗
③ 把假 key 写进 Dockerfile 的 ENV  →  build  →  docker history 能看到吗
④ echo 一个 secret 到日志 →  看 Actions 日志里是 *** 还是明文
```

**四条都要留证据。** 尤其第 3 条：`docker history` 会把 `ENV` 那条原样打出来，很多人以为"镜像是私有的就没事"。

## `secrets-check.sh` 至少查这五种格式

```text
ghp_         GitHub 个人访问令牌
gho_         GitHub OAuth 令牌
sk-          OpenAI 风格 key
AKIA         AWS Access Key
-----BEGIN   私钥文件头
```

**再补一条：查 Git 历史。** 只查工作区等于只查了 5%。

## 这一节的三个"必须真做"

| 动作 | 为什么不能只看不做 |
|---|---|
| 泄露后真的去吊销一次 | 你会发现在哪个后台、点几个页面、多久生效 |
| 真的建一个群机器人 | webhook 存进 secrets 这一步不亲手做，你会一直写在 yml 里 |
| 真的让 CI 失败一次 | 你才会知道通知长什么样、多久到 |

## ⚠️ 这个目录里绝不能出现的东西

```text
❌ 任何真实在用的 key（一律 sk-test-xxxx）
❌ 真实的 webhook URL（用 https://qyapi.weixin.qq.com/xxx 占位）
❌ 真实的 SSH 私钥
❌ 真实域名 / 真实 IP
```

**练习用的假 key 也不要长得像真的。** 用 `sk-test-0000` 这种，避免被别的扫描器当真。

## 这一节要留下的证据

| 证据 | 证明什么 |
|---|---|
| `git log -p` 打出来的假 key | 删文件 ≠ 删历史 |
| `docker history` 里的 `ENV OPENAI_KEY` | 密钥打进镜像层就永远在里面 |
| Actions 日志里 `***` 的截图 | GitHub 会自动遮蔽 secrets |
| 企业微信收到的 JSON 和消息 | 通知是真的通的 |

## 检验自己有没有真学会

- `git rm .env` 之后，历史里还有吗？用什么命令证明？
- `echo ${{ secrets.X }}` 在日志里是明文还是 `***`？为什么不是 100% 安全？
- `permissions: write-all` 最坏能造成什么后果？
- fork 的 PR 拿不到 secrets，这是 bug 还是设计？为什么？
- `if: failure()` 和 `if: always()` 各该挂在哪个 job 上？

**五题都答得出来再进收口那一节。**
