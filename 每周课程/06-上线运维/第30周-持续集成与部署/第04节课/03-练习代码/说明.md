## 为什么要 `.dockerignore`

**因为它决定了"构建上下文"有多大。**

```text
没有它：docker build . 会把 node_modules（60MB+）整个打包送给构建引擎
有它：  只送 2MB 左右的源码
```

**在 CI 里这个差别更明显：** runner 每次都要重新传一遍。

**验证办法：** build 时看这一行的耗时：

```text
=> [internal] load build context        62.1s
=> => transferring context: 284.32MB    61.9s
```

**有 `.dockerignore` 之后应该是：**

```text
=> [internal] load build context         0.1s
=> => transferring context: 2.14MB       0.1s
```

## 今天的实验顺序

```text
① 先写一个"最简单的 Dockerfile"（COPY . .）
② build，记录大小，ls -la /app 看进去的东西
③ 写 .dockerignore
④ 改成多阶段
⑤ 再 build，对比大小和耗时
⑥ 改一行源码再 build，看 CACHED 出现在哪几行
⑦ 写 build.yml，push
⑧ 去 GHCR 看两个 tag
⑨ 本地 docker pull 下来跑一次
```

**第 ⑥ 步是关键。** 你要亲眼看到"只有 COPY src 那一层没有 CACHED"。

## 一个必须注意的点

**`docker run --rm ci-lab:local whoami` 必须输出 `app`，不能是 `root`。**

**如果输出 `root`，说明 `USER app` 没生效。** 常见原因：

```text
① USER 写在了 CMD 后面（后面的指令不影响已经切换过的用户，但 CMD 之后不能再写指令）
② USER 写了但前面没有 chown（会报权限错误，不是静默变 root）
③ 你 build 的是旧的镜像（tag 相同，build 失败但用了缓存）
```

**用 `docker history` 确认 `USER` 那一层存在。**

## 这一课的检查重点

不是"build 成功"，是"**GHCR 上有 `sha-xxxxxxx` 这个 tag**"。

```text
Packages → ci-lab → Tags
  latest       sha256:...
  sha-3f7a1c2  sha256:...   ← 这个必须存在
```

**只有 `latest` 的镜像，等于没有退路。**
