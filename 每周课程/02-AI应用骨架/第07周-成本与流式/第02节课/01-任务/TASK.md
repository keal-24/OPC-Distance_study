## 手把手操作

### 第 1 步：建立今天的练习文件

1. 打开本节课的 `03-练习代码/` 文件夹。
2. 在空白处点击鼠标右键，选择“新建”→“文本文档”。
3. 根据本节课工具需要，把文件改成合适的名字，例如 `练习说明.md`、`index.html` 或 `练习.js`。
4. 如果电脑提示是否更改文件扩展名，点击“是”。
5. 打开文件，先写下今天要解决的问题：`统计输入输出`。
6. 保存文件。

**做完后应该看到：** `03-练习代码/` 中出现一个以本节课主题命名的文件。

### 第 2 步：先让人工智能讲清楚，不要直接复制

打开 WorkBuddy 或 Codex，发送下面的要求：

```text
我正在学习“成本与流式”，今天要完成“统计输入输出”。
请先用完全不懂编程的人能听懂的话解释：
1. 这个东西解决什么问题；
2. 它和普通做法有什么区别；
3. 今天最容易出错的地方是什么。
一次只讲一个小点，出现英文或专业词时先解释中文意思，不要直接假设我知道。
先不要写完整代码，等我回复“我明白了”后再继续。
```

读完后，用自己的话写三行笔记。不会写就先回答：它是什么、为什么需要、什么时候会出错。

### 第 3 步：让工具给出最小版本

接着发送：

```text
现在请带我做一个最小可运行版本。
要求：
1. 一次只给我一个步骤；
2. 每一步说明“为什么做”；
3. 说明文件放在哪；
4. 说明完成后屏幕上应该看到什么；
5. 不要省略代码，不要用“等等”；
6. 不要修改没有提到的文件；
7. 出错时先告诉我如何保存完整错误，再解释原因。
```

按照它给出的第一步操作，完成后再继续下一步。**不要一次把所有步骤跳过去。**

### 第 4 步：完成核心练习

按照下面的顺序推进：

1. 看清楚工具要求你打开哪个文件；
2. 确认文件路径和文件名；
3. 复制完整代码或完整配置；
4. 保存；
5. 运行或打开它；
6. 对照“应该看到的结果”检查；
7. 如果不一致，先截图或复制完整错误，再询问工具；
8. 修正后重新运行，直到结果一致。

每完成一个小步骤，在 `02-笔记/NOTES.md` 写一句“我做了什么，看到什么”。

### 第 5 步：故意测试错误情况

不要只测试顺利情况。至少测试下面三类：

1. 正常输入；
2. 空输入；
3. 错误输入或缺少必要文件。

每种情况都记录：

```text
我输入了什么：
我原本以为会看到什么：
实际看到了什么：
下一步怎么处理：
```

### 第 6 步：请人工智能检查，但不把判断完全交给它

发送：

```text
请按照下面四项检查我刚才的成果：
1. 正常情况能不能运行；
2. 空输入会不会导致程序崩溃；
3. 错误输入有没有清楚提示；
4. 是否改动了我没有要求改动的文件。
请列出每一项的检查方法和结果，不要只回答“没问题”。
```

把它的检查结果和你自己的实际结果对比。如果它说“没问题”，但你实际运行失败，以实际运行结果为准。

## 常见问题

| 现象 | 先检查什么 | 处理办法 |
|---|---|---|
| 找不到文件 | 是否进入了本节课的 `03-练习代码/` | 从仓库根目录重新打开，不要在桌面乱找 |
| 文件打不开 | 文件名是否被保存成了 `.txt` | 打开文件扩展名显示，再改成正确后缀 |
| 结果和预期不一样 | 是否漏复制了一行，是否保存 | 重新复制完整内容，保存后再次运行 |
| 工具突然讲很多新词 | 要求没有限制表达方式 | 让它一次解释一个词，并用生活例子说明 |
| 工具改了其他文件 | 没有提前限制修改范围 | 停止操作，记录文件名，先恢复再单独提问 |
| 出现错误 | 没保存完整错误信息 | 复制完整错误、文件名和操作步骤再询问 |
