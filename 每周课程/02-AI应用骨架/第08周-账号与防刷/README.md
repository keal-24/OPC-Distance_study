# 第08周 · 账号与防刷 · 第50—56节课

## 没有登录就没有"我的数据"，没有限频就等着被刷

---

## 这一周的目标

前七周你的应用"能用"，但**任何人打开浏览器就是一个匿名用户，谁都能调你的接口，谁都能刷你的额度。**

这一周补上六件事：

1. **把用户存进数据库** —— 不再是 `anon`，有 `id`、有唯一约束、有密码哈希；
2. **密码只存哈希** —— 明文入库等于把客户密码发给全世界；
3. **登录状态** —— Cookie 属性、JWT 内容、过期，以及为什么 `localStorage` 存 token 是错的；
4. **权限判断** —— 中间件 + **数据归属**，防住最常见的越权（IDOR）；
5. **限频与验证码** —— 短信费一夜几千，就是从这一步漏出去的；
6. **防重复提交** —— 双击、重放、支付重复扣款。

## 为什么排在这一周

**因为第 7 周的账本上，所有记录的用户都是 `anon`。**

## 这一周必须建立的五个认知

### 认知一：密码不是"加密存储"，是"哈希存储"

```text
加密 = 能解回来（有密钥就能还原）
哈希 = 不能解回来（只能比对）
```

**密码用哈希，因为：**

```text
① 你不需要知道用户密码原文（只在登录时比对）
② 数据库被拖走，攻击者也拿不到明文
③ 你连"找回密码"都只能"重置"，这是正确的
```

**如果有人跟你说"我们数据库里密码是加密的"，那说明他不懂。**

### 认知二：任何"前端校验"都不是安全措施

```text
前端限制输入长度  → F12 改掉
前端隐藏按钮      → 直接调接口
前端校验权限      → curl 一行就绕过
```

**前端校验是"体验优化"，服务端校验才是"安全"。**

**这句话你会在这周听七遍。**

### 认知三：认证（你是谁）和授权（你能做什么）是两件事

```text
认证失败 → 401，去登录
授权失败 → 403，登录了但没权限
```

**最常见的越权不是"没登录能访问"，是"登录了能访问别人的"。**

**这叫 IDOR（Insecure Direct Object Reference）。** 第 53 节会让你亲手打穿一次。

### 认知四：限频的目的不是"防住攻击者"，是"让攻击变贵"

**你防不住一个愿意花时间的人。**

**但你可以让他变成"每分钟只能试 5 次"。**

```text
4 位数字验证码 = 10000 种可能
不限频 → 几分钟跑完，短信费几千
限 5 次/分钟 → 要 33 小时，且你先收到告警
```

**限频是"把无限攻击变成有限攻击"，不是"消灭攻击"。**

### 认知五：重复提交是"体验问题"，也是"钱的问题"

```text
双击提交表单 → 两条订单
刷新页面     → 再提交一次
网络超时重试 → 三次扣款
```

**用户会投诉，你会退款，支付渠道会罚你。**

**防它的工具叫"幂等键"，第 55 节讲。**

## 三条铁律

```text
一、密码只进哈希，永远不进日志。
   console.log(req.body) 这一行，就能让密码进日志文件。

二、"谁能看这条数据"的判断，必须写在服务端，而且必须基于 session 里的用户 id，
   不能基于请求里传来的 user_id。

三、任何发送短信/邮件的接口，必须有"每分钟 N 次 + 每号码每天 M 次"两道限制。
   只有一道，等于没限。
```

## 这一周最容易卡住的六个地方

### 第一处：`bcrypt.hash` 是异步的，忘了 await

```javascript
const hash = bcrypt.hash(password, 10);   // 返回 Promise，不是字符串
// 存进库的是 "[object Promise]"
```

**症状：注册成功，登录永远失败。**

**排查：看数据库里 `password_hash` 的长度。正常哈希是 60 个字符，如果是 15 左右，就是这个问题。**

### 第二处：`SameSite=Lax` 导致跨站 POST 丢 Cookie

**你在 `localhost:5173` 开发前端，后端在 `localhost:3000`。**

**这是跨站（端口不同）。** `SameSite=Lax` 不会带 Cookie。

**要么同源部署，要么开发时用 `SameSite=None; Secure`（需要 HTTPS）。**

**这一周前后端同源（Express 直接发 `public/`），所以不会有这个问题。**

### 第三处：JWT 里放了密码或敏感信息

**JWT 的 payload 是 Base64 编码，不是加密。**

**任何人复制你的 token，去 jwt.io 一贴就能看到全部内容。**

**所以 payload 里只放 `{ uid }`。** 别放邮箱、手机号、身份证。角色名可以放（它不是秘密）。

### 第四处：`/api/register` 泄露邮箱是否存在

```javascript
if (existing) return res.status(400).json({ error: "邮箱已注册" });
```

**这句话攻击者能用来枚举你的用户库。**

**正确做法：统一返回"注册成功，请查收邮件"（不管邮箱是否已存在）。**

### 第五处：内存限频在多进程下失效

**`new Map()` 存限频计数，一个进程内是准的。**

**但你启动两个进程（`pm2 -i 2`），每个进程有自己的 Map，实际限额翻倍。**

**这一周先接受这个限制，在 README 里写明。第 29 周有了数据库再换。**

### 第六处：手动 `curl` 测注册，密码明文进了 shell 历史

```text
curl -d '{"email":"a@b.c","password":"MyPass123"}' ...
```

**这个密码会进 `~/.bash_history`。**

**调试时用明显的假密码（`test1234`），不要用你真实习惯用的密码。**
