# 第 241 节课：制作案例——把"我会做"变成"他看得懂的证据"

> **这份文件是你（学员）一步一步照着做的操作手册。**
> 这节课把前面 20 多周做的东西，改造成**客户能看懂、能信、能转发的三个案例**。
> 案例不是简历，不是截图合集，是**"客户原来怎样 → 现在怎样 → 差多少"**。

**建议用时**：120 分钟
**你需要先完成**：第 36 节课（有能跑的 AI 应用）、第 240 节课（有一份需求清单）

---

# 第 0 步：为什么案例比"技术能力"值钱（10 分钟）

## 0.1 客户不评估你的技术，评估风险

**客户脑子里的真实问题不是"他会不会写代码"，而是：**

| 客户真实担心 | 你的技术栈能回答吗 |
|---|---|
| 他做过类似的东西吗 | 不能 |
| 做砸了怎么办 | 不能 |
| 我这行他懂不懂 | 不能 |
| 要多久、要多少钱 | 不能 |

**案例能同时回答前三个。**

> **技术栈解决的是"你能不能做"，案例解决的是"我敢不敢让你做"。**
>
> **客户买的不是能力，是"降低自己的风险"。**

## 0.2 案例的三段结构

| 段 | 写什么 | 常见错误 |
|---|---|---|
| **背景** | 什么公司、多少人用、原来怎么做、一次花多久 | 写成"客户有数字化需求" |
| **做法** | 你做了什么（3 句以内，用客户语言） | 写成一堆技术名词 |
| **结果** | 数字：时间从 X 到 Y、错误率、人数 | 写"客户很满意" |

**"客户很满意"是零信息。数字才是信息。**

## 0.3 今天的交付物

| 文件 | 位置 | 内容 |
|---|---|---|
| `案例.md` | `03-练习代码` | **三个案例，每个含背景/做法/结果/一句话版** |
| `screenshots/` | `03-练习代码` | 每个案例至少 1 张脱敏截图 |

# 第 1 步：盘一下你手里有什么（15 分钟）

## 1.1 三个案例从哪来

**你现在大概率没有付费客户。没关系，案例分三种：**

| 类型 | 来源 | 能不能给客户看 |
|---|---|---|
| **真实付费项目** | 有最好 | 最强，但通常第 1-2 个月还没有 |
| **自建项目** | 第 3 周的 chat-app、第 13 周的笔记问答、第 25 周的支付 demo | **能，但必须标注"自建"** |
| **模拟项目** | 拿真实场景，自己做一遍（不交付，只做出来） | 能，标注"演示项目" |

**规矩：不许把自建项目写成"某客户项目"。**

> **为什么：** 客户一问细节就露馅，一句谎话毁掉全部信任。
>
> **"我自己做的工具，用来解决我自己的问题"** 这句话本身就有说服力——它证明你会用自己的东西。

## 1.2 从 20 多周的作品里挑三个

**挑的标准不是"哪个最难"，是"哪个最像客户的问题"：**

| 优先挑 | 因为 |
|---|---|
| 带登录 + 数据持久化的 | 客户能理解"这是真系统，不是玩具" |
| 有文档解析 / 知识库的 | 企业最常见的需求 |
| 有后台管理的 | 客户第一反应就是"我能自己改吗" |
| 有文件上传的 | 客户一定会有图片、Excel |

**明显别挑：**

| 别挑 | 因为 |
|---|---|
| 命令行工具 | 客户看不懂在干什么 |
| 跑在本地的 demo | 客户会问"我能打开看看吗"，你打不开 |
| 只做了 3 小时的练习 | 一张图就说完了，撑不起一个案例 |

## 1.3 现在就补一个"能给陌生人点开的链接"

**案例的第一要求：有链接，不是截图。**

| 现状 | 动作 |
|---|---|
| 已经部署了 | 直接记下 URL，自己用手机打开测一遍 |
| 只在本地跑 | 按第 29-31 节课的方法部署一次，或者用临时内网穿透 |
| 部署了但打不开 | **这个案例不能用**，先修好 |

# 第 2 步：给每个案例写"背景"（20 分钟）

## 2.1 背景怎么写

**模板：**

```text
【谁】有【多少人】，每周要【做什么事】，一次大概【多久】，
做错了会【什么后果】。
```

**差：**

```text
客户是一家制造业企业，面临数字化转型挑战。
```

**好：**

```text
一家 120 人的机械厂，销售内勤每周要手工整理 8 个 Excel 的库存和价格，
一次 3 小时，报错一次客户就可能拿错价。
```

**差别在哪：** 好版本里的每个数字，客户都能对上自己的情况。

## 2.2 自建项目的背景怎么写才不虚

**不要编客户。写自己：**

```text
我自己有 600 多篇技术笔记（Obsidian 库），找一条三个月前记的命令要翻 10 分钟。
我做了个问答助手，现在 5 秒能定位到原文。
```

**这句话的说服力在哪：**

| 它证明了 | 客户会想到 |
|---|---|
| 你真的用过 | "他自己都在用，应该不是忽悠" |
| 你知道细节 | "他知道文档乱起来什么样" |
| 你能维护 | "自己的东西他会认真做" |

> **不要小看"自用工具"。很多人的第一单，客户就是被"你自己在用"打动的。**

---

# 第 3 步：写"做法"，三句话以内（15 分钟）

## 3.1 用客户的语言，不用你的语言

| 你原来想写 | 改成 |
|---|---|
| 用 RAG + 向量库做检索增强 | 把 600 份文档变成"问一句就出答案" |
| 前端 Vue3 + 后端 Express + Postgres | 网页打开就能用，数据存在你自己的服务器上 |
| 接入 streaming SSE | 答案一个字一个字出，不用干等 10 秒 |
| 加了 JWT 鉴权 | 每人一个账号，看不到别人的东西 |

**规则：一段话里出现技术名词，就改成"它能让你干什么"。**

## 3.2 做法里必须有一句"我处理了哪个坑"

**这句是案例里最值钱的一行。**

```text
坑：参数表有 3 个版本，同一个型号在不同文件里数字不一样。
我的处理：答案后面标出来源文件和页码，让新人能自己核对。
```

**为什么值钱：**

| 作用 | 说明 |
|---|---|
| 证明你真做过 | 没做过的人想不到这种坑 |
| 提前回答质疑 | 客户心里正想"答错了怎么办"，你替他说了 |
| 建立专业感 | 你比他更懂这件事的难点在哪 |

---

# 第 4 步：写"结果"，必须带数字（20 分钟）

## 4.1 没有真实客户，数字从哪来

**三种合法来源：**

| 来源 | 例子 | 标注方式 |
|---|---|---|
| 自己实测 | "我自己用 30 次，平均定位时间从 10 分钟降到 5 秒" | 写"实测" |
| 客户原话 | "内勤说原来 3 小时，现在 40 分钟" | 写"客户反馈" |
| 合理推算 | "按 3 个内勤、每周一次算，一年省 400 小时" | 写"按 X 推算" |

**不许写：** "效率提升 300%""大幅降低成本""显著改善体验"——**这些词没有信息量，客户会自动打折到 0。**

## 4.2 结果的三种写法，按可信度排

| 写法 | 例子 | 可信度 |
|---|---|---|
| 时间对比 | "3 小时 → 40 分钟" | 高 |
| 频次对比 | "每天问 60 次，答不上来 15 次 → 答不上来 2 次" | 高 |
| 金额对比 | "一年少丢 2 单，约 40 万" | 中（要标注推算） |
| 感受描述 | "内勤说省事多了" | 低，只能当补充 |

## 4.3 别忘了写"没做到的部分"

**每个案例后面加一行：**

```text
目前还做不到：复杂表格里的合并单元格识别不准，需要人工修。
```

**为什么主动说自己不行：**

| 效果 | 原因 |
|---|---|
| 可信度暴涨 | 只讲好话的人像销售，讲缺点的人像工程师 |
| 提前筛掉不合适的客户 | 他要的正好是你做不到的，早知道早省事 |
| 避免交付纠纷 | 你说的和做的一致，验收时少吵一半架 |

# 第 5 步：组装成案例卡（20 分钟）

## 5.1 案例卡模板（写进 `案例.md`）

```markdown
## 案例 1：笔记问答助手（自建项目）

**一句话版**
600 篇笔记，从"翻 10 分钟找不到"到"5 秒出答案，还带原文出处"。

**背景**
我自己有 600 多篇技术笔记……（3 行以内）

**做法**
1. 把笔记切成小段，按语义建索引
2. 提问时先找最相关的 5 段，再让模型基于这 5 段回答
3. 答案下面列出引用的原文片段和文件名

**踩过的坑**
同一件事在 3 篇笔记里写法不一致，模型会混着答。
处理：答案必须带出处，让用户自己核对。

**结果（实测）**
| 指标 | 之前 | 之后 |
|---|---|---|
| 找一条命令 | 10 分钟 | 5 秒 |
| 是否敢信答案 | 不敢（怕记错） | 敢（有原文） |

**还做不到**
扫描版 PDF 里的图，识别不了。

**链接**
https://xxx.example.com

**截图**
![问答界面](screenshots/case1-qa.png)
```

## 5.2 截图的三条规矩

| 规矩 | 为什么 |
|---|---|
| **脱敏**：把真实客户名、手机号、金额涂掉 | 泄露客户数据是事故，不是小事 |
| **只截一条路径**：输入 → 结果，别截满屏 | 客户看不懂复杂界面 |
| **加一行标注**：截图下面写"这是问一句话到出答案的完整过程" | 不然客户不知道你在演示什么 |

**截图工具就用系统自带（Win + Shift + S）。不要用手机拍屏幕。**

## 5.3 三个案例要覆盖三种能力

| 案例 | 覆盖什么 | 对应客户担心 |
|---|---|---|
| 案例 1 | 文档/知识 → 问答 | "他懂不懂我的资料长什么样" |
| 案例 2 | 登录 + 数据 + 后台 | "客户能自己改吗、数据安全吗" |
| 案例 3 | 文件/图片/Excel 处理 | "我们数据都是 Excel，他能搞吗" |

> **三个案例不是三份作业，是三张"不同担心的解药"。**
>
> **如果三个案例都是问答助手，等于只有一个案例。**

# 第 6 步：让 AI 挑刺 + 改成客户语言（15 分钟）

## 6.1 挑刺提示词

```text
下面是我的三个项目案例。请你扮演一位 45 岁的制造业老板，不懂技术，时间很少，只看两分钟。

对每个案例回答：
1. 我看完知道这东西能干什么吗？哪句话我没看懂？
2. 我凭什么相信这个结果是真的？
3. 这三句话里哪句像广告，我会自动忽略？

只说问题，不要夸我，不要给建议。
```

## 6.2 改写提示词

```text
把下面这段案例背景改写成"客户语言"。

规则：
1. 不许出现技术名词（RAG、向量、API、SSE、JWT 等），出现就换成"能干什么"；
2. 保留所有数字；
3. 每句话不超过 25 个字；
4. 不要用"赋能""一站式""数字化转型""提升效率"这类词；
5. 输出不超过 4 行。

原文：
（贴你的案例）
```

## 6.3 人工最后一遍：念出来

**把三个案例的"一句话版"念给自己听。**

| 念完的感觉 | 判断 |
|---|---|
| 像在跟朋友说"我做了个东西" | 合格 |
| 像在做自我介绍 | 不合格，还太正式 |
| 自己都觉得空 | 不合格，缺数字 |

# 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 三个案例写出来都一样 | 都是从同一个项目改的 | 去翻第 9/10/25 周的作品，各挑一个 |
| 数字写不出来 | 没实测过 | 现在自己跑 10 次，掐表 |
| 客户说"看着挺厉害"就没下文 | 只有"厉害"，没有"我的问题" | 背景里加客户能对上的细节 |
| 案例太长没人看 | 把做法写成了教程 | 做法压到 3 行 |
| 不好意思写"自建项目" | 怕显得没客户 | 诚实 + 有链接，比编客户强一百倍 |
| 截图里有客户数据 | 忘了脱敏 | 重新截，或者涂掉再提交 |
