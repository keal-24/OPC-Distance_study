> **这份文件是你（学员）一步一步照着做的操作手册。**
> 前面 238 节课你练的是"把东西做出来"。从今天起，练的是**"让某个人愿意为它付钱"**。
> 这节课不写代码。你做出来的是**三张客户画像卡**和一份**30 人名单**。

**建议用时**：90 分钟
**你需要先完成**：第 36 节课（有自己的 AI 应用）、第 45 节课（有能给别人看的链接）

# 第 0 步：先接受一个不好听的事实（10 分钟）

## 0.1 技术不是瓶颈，客户才是

一个人做开发，最常见的死法**不是"做不出来"，是"做出来了没人买"**。

**三种典型失败开场，你以后一定会遇到其中一种：**

| 开场 | 结果 |
|---|---|
| "我什么都能做，前端后端小程序都接" | 对方记不住你，回头找了别人 |
| "有没有项目给我做？" | 答案永远是"暂时没有" |
| "我做 AI 应用开发，需要的话联系我" | 他没需求时不会想起你，有需求时想不起你是谁 |

**这三句话的共同问题：没有具体到"某一类人的某一个麻烦"。**

> **客户不会因为你会什么付钱，只会因为"他正卡着的那件事"付钱。**

## 0.2 什么是"客户画像"，什么不是

**不是这个：**

```text
目标客户：25-45 岁，中小企业老板，有数字化转型需求。
```

**这是废话。** 按这句话你找不到任何一个具体的人，也没法写一句让他有反应的话。

**是这种：**

| 字段 | 内容 |
|---|---|
| 行业 + 规模 | 制造业，80-300 人，有 2-3 个销售内勤 |
| 具体岗位 | 销售总监 / 老板本人 |
| 触发事件 | 新招的销售不熟悉产品，报价单发错、技术参数答不上来 |
| 现在怎么凑合 | 建了个微信群，老销售在群里人工答；答不过来就丢单 |
| 谁会掏钱 | 老板（销售总监提，老板批） |
| 预算区间 | 1-3 万，走"软件采购"科目 |
| 我能联系到谁 | 我表哥在 XX 机械做销售总监 |

**判断一张画像卡合不合格，只有一个标准：**

> **看着这张卡，你今天能不能想到一个具体的人名或公司名。**
>
> 想不到 → 这张卡作废。不是你写得不好，是这类客户你够不着。

## 0.3 三个筛选条件，缺一不可

| 条件 | 意思 | 怎么验证 |
|---|---|---|
| **有痛** | 这件事现在正在让他损失钱或时间 | 他能说出"上周因此丢了一单" |
| **有钱** | 他以前为类似的事花过钱 | 他说"我们现在用的是 XX，一年 X 万" |
| **够得着** | 你能通过 1-2 层关系触达决策人 | 你能报出一个中间人的名字 |

**大多数人卡在第三条。** 有痛点、有钱的客户满地都是，但**你够不着的人不是客户，是新闻里的人**。

# 第 1 步：先把自己会的排一遍（15 分钟）

## 1.1 列"能力清单"，不许写虚词

**在 `03-练习代码/` 里新建 `客户画像.md`，先写这一段：**

```markdown
# 我的能力清单

## 我已经做出来的东西（有链接的）
1.
2.
3.

## 我能做但还没做过的
1.
2.

## 我完全不会的
1.
2.
```

**填的时候守三条规矩：**

| 规矩 | 反例 | 正例 |
|---|---|---|
| 写具体功能，不写技术名 | "精通 RAG" | "能把 50 份 PDF 变成一个能问答的助手" |
| 写客户能感知的结果 | "会写 Node.js 后端" | "员工登录后能看到自己的历史记录" |
| 写你实际交付过的 | "AI 全栈" | "做过 1 个带登录和支付的小工具" |

> **为什么先排能力：** 客户画像必须落在你**真能交付**的范围里。
>
> 你画像写着"帮医院做病历结构化"，但你连 DICOM 是什么都不知道，这不是获客，是许愿。

## 1.2 从能力反推"谁的麻烦"

**对着你写出的能力，问三个问题：**

1. 这个东西做出来，**谁的工作会变轻**？
2. 他现在**不用这个的话，是怎么熬过去的**？
3. 他**一周会为此烦几次**？

**举例（对着"50 份 PDF 变问答助手"这条）：**

| 问题 | 回答 |
|---|---|
| 谁的工作变轻 | 需要反复查资料的人：法务、售后、投标专员、HR |
| 现在怎么熬 | Ctrl+F 一个个文件搜；或者问老员工 |
| 一周烦几次 | 售后每天 10 次以上；法务一周 3 次但每次 2 小时 |

**这样一推，候选画像就出来了。** 不用凭空想。

# 第 2 步：让 AI 帮你扩候选，但你来砍（20 分钟）

## 2.1 发给 WorkBuddy / Codex 的提示词

**复制下面这段，把括号里的内容换成你自己的：**

```text
我是独立开发者，一个人接企业软件项目。我的能力范围是：
（把你第 1 步写的能力清单贴进来）

请帮我列出 8 类可能的付费客户，每类按下面格式给出：
1. 行业 + 公司规模（人数区间）
2. 具体岗位（谁会提出需求、谁签字付钱）
3. 触发事件（什么事情发生了他才会开始找解决方案）
4. 现在怎么凑合解决
5. 这类客户的预算通常从哪个科目出

要求：
- 每条必须具体到"能想象出一家公司长什么样"，不要写"中小企业""传统行业"这种词；
- 如果某一类的需求其实很弱（只是听起来合理），直接标出来并说明理由；
- 不要给我建议，只给清单。
```

## 2.2 关键动作：砍到 3 个

**AI 会给你 8 个，其中 5 个你不能做。** 按这个表逐个过：

| 筛子 | 淘汰条件 | 例子 |
|---|---|---|
| 能做吗 | 交付不了，或要学 3 个月以上 | 医疗影像、金融风控建模 |
| 够得着吗 | 报不出一个具体中间人 | 国企总部、外资集团 |
| 付得起吗 | 预算明显低于 1 万 | 街边店、个人博主（除非做批量） |
| 会持续吗 | 一锤子买卖，做完就没 | 一次性活动页、毕业设计 |

**砍完之后剩下的 3 个，才写进画像卡。**

> **不要留 5 个 8 个"备选"。** 画像超过 3 个你就不会去联系任何一个。
>
> **3 个是能在一周内全联系一遍的数量。**

## 2.3 一个必须做的反向检查

**对每个画像，回答这句话（写进卡片）：**

```text
如果这个人明天就找我，我第一句话说什么？
```

**说不出来 → 这个画像还不够具体，回到第 1 步重写。**

# 第 3 步：填三张画像卡（25 分钟）

## 3.1 卡片模板（直接抄进 `客户画像.md`）

```markdown
## 画像 1：（给这类客户起个代号，比如"机械厂销售总监"）

| 字段 | 内容 |
|---|---|
| 行业 + 规模 | |
| 岗位（提需求的人） | |
| 岗位（掏钱的人） | |
| 触发事件 | |
| 现在的凑合方案 | |
| 为什么凑合方案快撑不住了 | |
| 预算区间 + 出处科目 | |
| 我能通过谁触达 | |
| 我第一句话说什么 | |
| 我能交付的东西（对应能力清单第几条） | |
| 这类客户最可能拒绝我的理由 | |
```

**最后两个字段别跳过：**

- **"我能交付的东西"**：把画像和能力对上，否则就是空想。
- **"最可能拒绝的理由"**：提前想好，第 244 节课要用它练应答。

## 3.2 三张卡要长得不一样

| 卡片 | 定位 | 作用 |
|---|---|---|
| 画像 1 | **最容易成的**（有熟人） | **第一单从这里出**，用来攒案例 |
| 画像 2 | **最值钱的**（预算高） | 中期目标，需要案例背书 |
| 画像 3 | **最容易复制的**（同行业多家） | 长期做标准化产品 |

> **第一单一定要从"有熟人"的那类出。**
>
> 原因不是你谈不下来，是**第一单一定出问题**。熟人会给你改的机会，陌生客户会直接要退款。

## 3.3 一个反例，看完再动笔

**下面这张卡是不合格的，你能看出几处问题？**

```text
画像：中小企业老板
痛点：想用 AI 提升效率，但不知道怎么用
预算：看情况
触达：网上找
```

| 问题 | 为什么致命 |
|---|---|
| "中小企业老板" | 不是一类人，是几千万人 |
| "想用 AI 提升效率" | 这不是痛，这是愿望。愿望不付钱 |
| "预算看情况" | 说明你没和任何一个这类客户聊过 |
| "网上找" | 等于够不着 |

# 第 4 步：写出 30 个具体名字（20 分钟）

## 4.1 这一步才是分水岭

**画像卡谁都能写。名单才是真东西。**

**在 `客户画像.md` 末尾加这张表，填满 30 行：**

```markdown
## 30 人名单

| # | 名字/公司 | 属于哪个画像 | 关系路径（谁介绍） | 触达方式 | 状态 | 下一步 |
|---|---|---|---|---|---|---|
| 1 | 张 XX / XX 机械 | 画像1 | 我表哥在这做销售总监 | 微信 | 未联系 | 让他帮我问一句 |
| 2 | | | | | | |
```

**状态只有四种，别自创：**

```text
未联系 → 已触达 → 有回应 → 约到了
```

**填不满 30 行怎么办：**

| 情况 | 动作 |
|---|---|
| 熟人太少 | 把前同事、同学、亲戚、球友、业主群全过一遍，能想到 15 个 |
| 行业太窄 | 每个熟人**再想他认识的 2 个人**，60 个目标就有了 |
| 实在没有 | 去行业群、B 站评论区、知乎问题下**找人**，但标记为"弱关系"，别当第一单 |

> **30 行不是 KPI，是让你意识到"够得着的人比你想的多"。**
>
> **大部分人的第一单，来自第 3 行到第 8 行之间的某个人。**

## 4.2 名单里不要放这三类

| 类型 | 为什么别放 |
|---|---|
| 大厂/国企总部 | 采购流程 6 个月起，你现在耗不起 |
| 明确说过"我们不需要"的人 | 半年内别回头，浪费情绪 |
| 同行开发者 | 他不是客户，是竞争对手或者外包上游 |

# 第 5 步：让 AI 挑刺，别让它夸你（10 分钟）

**把三张画像卡贴给 AI，发这段：**

```text
下面是我的三张客户画像。请你扮演一个刻薄的销售顾问，只做一件事：找漏洞。

对每张卡，指出：
1. 哪个字段写得太模糊，导致你没法判断这是不是一个真客户；
2. "触发事件"够不够急（不急的事不会有人掏钱）；
3. "我能通过谁触达"这句是不是在自我安慰；
4. 这类客户最可能说的拒绝理由是什么。

不要给建议，不要鼓励我，只列问题。每条不超过两行。
```

**拿到问题后，只改一件事：把模糊的地方换成具体的人、数字、时间。**

> **AI 的挑刺有一半是错的。** 但错的那一半也会逼你说清"为什么它对"——这个过程就是画像变清晰的过程。

# 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 想不出客户是谁 | 从"我能做什么"开始想，而不是从"谁有钱"开始想 | 回到第 1 步重排能力清单 |
| 画像写完自己都不信 | 缺"触发事件" | 问自己：什么事发生了他今晚就得找人 |
| 名单填到第 10 行就空了 | 只想了直接关系 | 每个熟人再想 2 个他能介绍的人 |
| AI 给的行业都很高大上 | 提示词没限制"我能交付" | 把能力清单原样贴进提示词，并要求它标出做不到的 |
| 总觉得"我认识的人不会买" | 你在用"卖软件"的框架想 | 换成"帮个忙看看这事有没有解"的开场 |
