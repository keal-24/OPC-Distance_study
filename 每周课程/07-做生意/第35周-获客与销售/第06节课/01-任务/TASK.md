# 第 244 节课：沟通与提案——一页纸定输赢

> **这份文件是你（学员）一步一步照着做的操作手册。**
> 这节课做两份东西：**一页纸提案**和**六句话应答卡**。
> 提案不是 PPT。一页纸能让老板在电梯里看完，PPT 只会让他"回头再看"。

**建议用时**：110 分钟
**你需要先完成**：第 240 节课（需求清单）、第 243 节课（三档报价）

---

# 第 0 步：客户不读提案，他找三样东西（10 分钟）

## 0.1 客户打开你的文件，只想知道三件事

| 他找什么 | 在第几屏能看到 |
|---|---|
| 你懂不懂我的问题 | 第 1 屏，前 3 行 |
| 要花多少钱、多久 | 第 1 屏，中间 |
| 下一步干什么 | 最后一行 |

**三样都没在前两屏出现，他就不看了。**

## 0.2 提案的四个反例

| 反例 | 问题 |
|---|---|
| 20 页 PPT，前 5 页是"关于我们" | 他最不关心的就是你 |
| 大段技术架构图 | 他看不懂，只会觉得你在拖时间 |
| 全是"赋能""闭环""抓手" | 他不知道你要卖什么 |
| 结尾写"期待与您合作" | 没有下一步动作，这单就停在"期待" |

## 0.3 一页纸的五格结构

```text
┌─────────────────────────────────────┐
│ 1. 你的问题（我理解的，3 条）        │
├─────────────────────────────────────┤
│ 2. 我打算怎么做（3 步，客户视角）    │
├─────────────────────────────────────┤
│ 3. 钱和时间（三档 + 工期）           │
├─────────────────────────────────────┤
│ 4. 我需要你配合什么（很重要）        │
├─────────────────────────────────────┤
│ 5. 下一步（一个具体动作 + 时间）     │
└─────────────────────────────────────┘
```

**这五格，一页 A4 装得下。装不下就是话太多。**

## 0.4 今天的交付物

| 文件 | 位置 | 内容 |
|---|---|---|
| `提案.md` | `03-练习代码` | **一页纸提案（五格）** |
| `话术卡.md` | `03-练习代码` | 六句话 + 四种异议 + 演示三条纪律 |

# 第 1 步：第 1 格——复述他的问题（20 分钟）

## 1.1 直接用他的原话

**这是整份提案最值钱的部分。**

```markdown
## 一、我理解的问题

1. 新销售查产品参数要问老销售，老销售不在就只能等，等到客户没耐心。
2. 同一型号的参数在 3 个文件里不一样，谁也不敢确定哪个对。
3. 答错了没人知道，要等客户投诉才发现。
```

**为什么用他的原话：**

| 效果 | 说明 |
|---|---|
| 他立刻信你听懂了 | 这些话是他自己说的 |
| 他会在心里补一句"对，就是这样" | 三次点头，信任就建立了 |
| 后面报价就有了依据 | 每一条对应一项功能 |

## 1.2 加一句"如果不做会怎样"

```text
按你说的，一年丢 3-5 单，一单 20-30 万。这个问题每年在花掉 60-150 万。
```

**这句话把"要不要做"变成"什么时候做"。**

> **注意：数字必须是他自己说的。** 你自己编的损失，他一眼就看出来，信任直接归零。

# 第 2 步：第 2 格——三步法，不讲技术（20 分钟）

## 2.1 写法：动词开头，客户视角

**差（技术视角）：**

```text
1. 用 LangChain 搭建 RAG 流程，接入 embedding 模型
2. 用 pgvector 建向量索引
3. 流式输出，前端 SSE 接收
```

**好（客户视角）：**

```text
1. 把你们现有的 120 份文档整理成"能查的库"（脏的数据先清洗一遍）
2. 新销售在手机上问一句，系统从库里找最相关的几段，给出答案
3. 每条答案下面标出"来自哪个文件第几页"，可以点开核对原文
```

## 2.2 三条标准

| 标准 | 检验方法 |
|---|---|
| 每一步都是"客户能得到什么" | 读一遍，如果没有出现"你能……"，就是没写好 |
| 三步以内 | 超过三步，说明你想做的太多 |
| 有一句"我怎么防坑" | 这句决定他信不信你 |

## 2.3 那句"我怎么防坑"必须写

```text
你们最担心的是"AI 答错了怎么办"。
我的做法是：每条答案都必须带出处，答不出来就说"文档里没有"，
不许编。宁可说没有，不许猜。
```

> **这一句比任何技术描述都值钱。** 因为它回答的是客户半夜会想起来的那件事。

---

# 第 3 步：第 3 格——钱和时间（15 分钟）

## 3.1 直接放三档表，别绕

```markdown
## 三、钱和时间

| | 基础版 | **标准版（建议）** | 完整版 |
|---|---|---|---|
| 价格 | ¥9,000 | **¥16,500** | ¥30,000 |
| 工期 | 8 个工作日 | 15 个工作日 | 25 个工作日 |
| 一句话 | 先能用起来 | 日常够用 | 全流程管起来 |

模型调用按实际用量另计（约 ¥0.002/千字），服务器约 ¥100/月。

付款：签约 30%，验收 40%，上线稳定一周 30%。
```

## 3.2 三句必须在提案里出现的话

| 话 | 防什么 |
|---|---|
| "工期以你方提供完整文档之日起算" | 他拖两个月，你不背锅 |
| "清单外的功能视为新增，另行报价" | 无限加需求 |
| "模型调用按实际用量另计" | 你倒贴模型费 |

## 3.3 时间要留缓冲

**你算出来 11 天，提案上写 15 个工作日。**

| 原因 | 说明 |
|---|---|
| 客户会有会议、审批、改主意 | 一定会发生 |
| 提前交付是惊喜，延期是事故 | 心理账户完全不同 |
| 留出的 4 天是你的命 | 万一踩坑，你还有时间 |

# 第 4 步：第 4 格——需要客户配合什么（15 分钟）

## 4.1 这一格所有人都漏写，但它最保命

```markdown
## 四、需要你方配合

| 事项 | 什么时候要 | 不给会怎样 |
|---|---|---|
| 120 份文档的电子版（Word/PDF 原文件） | 签约后 3 天内 | 工期顺延 |
| 1 位业务负责人，能拍板"这个词是什么意思" | 全程 | 需求会反复 |
| 服务器和域名（我提供清单，你们买） | 开发中期 | 无法部署 |
| 验收时 3 位实际使用者参与测试 | 验收当天 | 验收无法完成 |
```

## 4.2 为什么必须写"不给会怎样"

| 情况 | 没写这一格 | 写了这一格 |
|---|---|---|
| 客户拖文档 | 你干等，工期还是按原计划算 | 顺延，责任清楚 |
| 没人拍板 | 需求改三次，你重做三次 | 你有一句话可以拿出来 |
| 验收没人来 | 尾款无限拖 | 你能说"验收条件未满足，责任在甲方" |

> **"不给会怎样"这一列，是你未来唯一的挡箭牌。**
>
> **写的时候语气要客气，内容要硬。**

# 第 5 步：第 5 格——下一步，只能有一个动作（10 分钟）

## 5.1 差 vs 好

| 结尾 | 结果 |
|---|---|
| "期待与您合作！" | 停在这里，等他想起你 |
| "如有疑问随时联系" | 把决定权全交给他，他不会联系 |
| **"如果标准版可以，我周三下午两点给你打个电话，10 分钟确认三件事，然后我出合同。"** | **有具体动作、有具体时间、成本极低** |

## 5.2 这一步的设计原则

| 原则 | 说明 |
|---|---|
| 动作极小 | "打个电话确认三件事"，不是"签合同" |
| 时间具体 | "周三下午两点"，不是"下周" |
| 你主动 | 你说你要打，不是问他"方便吗" |
| 只有一个 | 不要给三个选项让他选 |

> **销售的本质不是说服，是"降低对方做决定的成本"。**
>
> **"确认三件事"的成本远低于"签合同"。先让他答应小事。**

# 第 6 步：写六句话应答卡（15 分钟）

## 6.1 六句话（背下来）

| 场景 | 你说什么 |
|---|---|
| 客户加需求 | "这个可以做。我看一下工作量，明天给你报价。" |
| 客户说"很简单" | "对，逻辑不复杂。不过要跟你们现有的 XX 打通，这块我评估一下。" |
| 客户催进度 | "目前完成 60%，卡在你们那边的 XX 还没给。给了之后三天能交付。" |
| 客户说不满意 | "具体是哪里不满意？我们对着验收标准一条条看。" |
| 客户要免费加功能 | "这个不在原范围里。我可以做个报价，你看了再决定。" |
| 客户拖尾款 | "尾款到账后我立刻交付源码和账号。这是合同约定的流程。" |

## 6.2 这六句话的共同结构

```text
不拒绝 + 不承诺 + 给下一个动作
```

| 要素 | 反例 | 为什么差 |
|---|---|---|
| 不拒绝 | "这个做不了" | 断关系，他去找别人 |
| 不承诺 | "没问题包在我身上" | 断自己，白干 |
| 给下一个动作 | "再说吧" | 对话死了 |

## 6.3 四种异议的标准应答

| 客户说 | 你别说 | 你该说 |
|---|---|---|
| "太贵了" | "那打个折" | "贵在哪一块？如果是总价，我们可以先做基础版跑起来。" |
| "再考虑考虑" | "好的，您考虑" | "行。是价格的问题，还是不确定能不能做成？我按你的顾虑再说明一下。" |
| "别人报价一半" | "他做不出来" | "他这个价大概率只做问答，不含文档清洗。让他出一份功能清单，我们对一下。" |
| "先做个 demo 看看" | "可以，免费做" | "可以，先付 30% 定金，我一周给你一版能点的。定金是双方保障。" |

> **"再考虑考虑"是最大的坑。** 它不是拒绝，是"我还不敢决定"。
>
> **你必须问出"不敢"的原因，否则这单就沉了。**

# 第 7 步：演示的三条纪律（10 分钟）

## 7.1 只演示一条路径

| 做法 | 结果 |
|---|---|
| 把所有功能点一遍 | 他一个都记不住 |
| **只演示他最痛的那条**：问一句 → 出答案 → 点开原文 | 他会说"这个可以" |

## 7.2 三条纪律

| 纪律 | 说明 |
|---|---|
| **有断网预案** | 录一段 3 分钟屏，网络挂了就放录屏 |
| **不现场改需求** | "这个我记下来，回去评估"——现场改会当场翻车 |
| **不演示你还没做完的** | 演示了做不出来，等于承诺了做不到 |

## 7.3 演示结束必须问一句

```text
"如果现在就能用，你第一个会拿它干什么？"
```

**他的回答会告诉你：真实需求是不是你以为的那个。**

# 第 8 步：用 AI 演练一遍难缠客户（10 分钟）

```text
你要扮演一位 50 岁的工厂老板，正在听我讲一个 1.65 万的软件方案。

你的设定：
1. 你不懂技术，关心"能不能真的解决我的问题""会不会做到一半跑了"；
2. 你会砍价，会说"别人报价一半"；
3. 你会问"我先给你 5000，做出来好用再给剩下的"；
4. 你说话短，不爱听长解释。

规则：我说一句，你回一句。不要替我说话，不要给我建议。
现在开始，你先开口。
```

**练三轮，每轮记下你被问住的那一句。**

> **被问住的地方，就是你下次会丢单的地方。**

# 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 提案写成了 5 页 | 想把所有优势都写上 | 删掉"关于我们"，删掉技术架构 |
| 客户看完说"我们再研究研究" | 结尾没有具体动作 | 结尾改成"周三两点我打给你确认三件事" |
| 客户一直问价格 | 你把价值和价格放反了 | 价值（他的损失）必须在第 1 格，价格在第 3 格 |
| 演示时被问住 | 演示了你没做完的 | 只演示做完的那条路径 |
| 客户当场砍价，我答应了 | 没有退让筹码 | "降范围不降价"，从完整版往标准版退 |
| "再考虑考虑"之后就没消息了 | 没问出"不敢决定"的原因 | 追问："是价格，还是不确定能做出来？" |
