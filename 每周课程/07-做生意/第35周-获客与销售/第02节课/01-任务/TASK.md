# 第 240 节课：发现真实需求——把"我觉得他需要"换成"他原话说的"

> **这份文件是你（学员）一步一步照着做的操作手册。**
> 上节课你圈出了三类客户。这节课你要做的是：**真的和其中 1 个人聊一次，把他的话变成一份能报价的需求清单。**
> 不做这一步，后面所有报价都是猜的。

**建议用时**：120 分钟（含 30-40 分钟真实对话）
**你需要先完成**：第 239 节课（有三张画像卡和 30 人名单）

---

# 第 0 步：先分清三样东西（10 分钟）

## 0.1 抱怨、任务、需求，不是一回事

**客户说的话，90% 停在第一层。**

| 层次 | 客户说的话 | 能干什么 |
|---|---|---|
| **抱怨** | "现在这些系统太麻烦了" | 什么都干不了，只能接话 |
| **任务** | "每周一我要把 8 个表格合成一份发给老板" | 能算工时，能评估 |
| **需求**（可报价） | "周一早上 9 点前必须发出去，一次大概 3 小时，做错了老板会打我电话" | **能写进合同** |

**只有第三层能报价。** 前两层你聊得再热络，也做不出方案。

## 0.2 一个必须避开的陷阱：客户会给你"方案"而不是"问题"

**客户最常见的开场是这样的：**

```text
"我想做一个 AI 客服机器人，能自动回复客户问题。"
```

**这句话里没有需求，只有一个方案。**

**你必须往下钻三层：**

| 钻法 | 问什么 | 可能得到的真相 |
|---|---|---|
| 第一层 | "现在客户问题谁在回？" | 老板娘 + 两个销售内勤 |
| 第二层 | "一天多少条？答不过来会怎样？" | 60-80 条，晚上 10 点还在回，回慢了客户就跑 |
| 第三层 | "响应慢一单损失多少？" | 一个月跑掉 3-5 个，一个客户一年 2 万 |

**钻到第三层，需求才出现：不是"AI 客服"，是"晚上没人回消息导致跑单"。**

> **客户要的是他脑子里的方案，你要找的是他钱包背后的痛。** 两者经常不是一回事。

## 0.3 今天的交付物

| 文件 | 位置 | 内容 |
|---|---|---|
| `访谈记录.md` | `03-练习代码` | **一场真实（或模拟）访谈的原话记录** |
| `需求清单.md` | `03-练习代码` | **8-15 条需求，每条带原话引用 + 付费意愿判断** |

# 第 1 步：约人（15 分钟）

## 1.1 约人的话术，不要用"请教"

**差的：**

```text
X 总，想请您喝个咖啡，向您请教一下行业经验。
```

**问题：** 对方不知道要花多久、要付出什么，本能拒绝。

**好的：**

```text
X 总，我在做企业内部的资料问答工具（就是员工问一句、系统从公司文档里找答案那种）。
想找 2-3 个一线用得上的人聊 20 分钟，看看真实场景长什么样，不做推销。
您这周哪天方便？我按您时间来。
```

**这句话做了四件事：**

| 动作 | 效果 |
|---|---|
| 说清自己做什么（一句话、有场景） | 对方能判断值不值得聊 |
| 明确 20 分钟 | 降低心理成本 |
| 明确"不做推销" | 解除防御 |
| 让对方定时间 | 提高答应率 |

## 1.2 被拒绝怎么办

| 回应 | 你的下一句 |
|---|---|
| "最近忙" | "理解。那我下周再问一次，您要是有空随时说。" |
| "我们已经有系统了" | "正好，我就是想听听现有系统哪里不顺手。" |
| "你直接说多少钱" | "得先看场景，不然报的价你也不敢信。20 分钟够我判断了。" |

**记住：被拒绝 3 次以内不叫失败，叫还没开始。**

## 1.3 找不到真人聊怎么办

**用 AI 做一次"模拟访谈"，但要按规矩来：**

```text
你要扮演一位【制造业、120 人、有 3 个销售内勤】的销售总监。
你 48 岁，不懂技术，说话直接，讨厌被推销。

规则：
1. 你只回答我问的问题，不主动提供信息；
2. 你的回答要带具体细节（时间、人数、数字、上周发生的事）；
3. 如果我问得太抽象（比如"你的痛点是什么"），你会不耐烦，回答"没什么痛点，就是忙"；
4. 你不许说"AI""数字化""赋能"这类词。

我先开始问，你一句一句答。
```

> **模拟访谈能练提问，但不能代替真实访谈。**
>
> 因为 AI 扮演的客户**不会真的拒绝你**，也不会说出你没预想到的答案。真实访谈的价值就在"意料之外"。

# 第 2 步：访谈提纲，只问七句（15 分钟）

## 2.1 七句话，按顺序问

| # | 问什么 | 为什么这么问 |
|---|---|---|
| 1 | "这件事**上一次**是什么时候发生的？" | 逼他说具体场景，不说抽象感受 |
| 2 | "当时**谁**在做？花了**多久**？" | 拿到工时数据，后面算报价要用 |
| 3 | "做错了或者做慢了，会**怎样**？" | 找到痛的价格 |
| 4 | "现在用什么办法凑合？为什么凑合不下去了？" | 判断紧迫度 |
| 5 | "这事**谁说了算**？他自己会用吗？" | 找决策链 |
| 6 | "你们以前为这类事**花过钱**吗？大概多少？" | 验证预算真实性 |
| 7 | "如果这个东西明天就有，你**第一个**拿它干什么？" | 判断真实优先级 |

## 2.2 三个绝对不能问的问题

| 别问 | 为什么 |
|---|---|
| "你的痛点是什么？" | 没人会这么说话，你会得到一个编出来的答案 |
| "如果我做个 XX 功能，你会用吗？" | 假想问题得到假想答案，全是"会用啊" |
| "你觉得这个值多少钱？" | 他给的数字一定远低于真实支付意愿，还会锁死你的报价 |

## 2.3 现场三条纪律

1. **录音或速记原话**，不要总结。客户的原话是最贵的资产。
2. **不要在他说话时想方案。** 你一想方案，就不听了。
3. **不要当场报价。** 统一回答："我回去算一下，明天给你。"
4. **最后一定要问一句**："我能不能下周再问您两个问题？"——**留着复访的口子。**

# 第 3 步：写访谈记录（20 分钟）

## 3.1 记录格式（新建 `访谈记录.md`）

```markdown
# 访谈记录 · 【公司/行业】 · 【日期】

## 基本信息
- 对象：张总，销售总监，48 岁
- 公司：XX 机械，120 人，年营收约 6000 万
- 关系路径：我表哥介绍
- 时长：32 分钟

## 原话（照抄，不要改写）

> "上周三有个客户问我们 8 米车床的承重，我们那个新来的销售答成了 6 米的，报了价，客户直接不理了。"

> "现在这些问题都在群里问，老销售在就答一句，不在就等。"

> "一年因为这种事丢个三五单吧，一单二三十万。"

## 我听到的关键数字
| 数字 | 出处 |
|---|---|
| 丢单 3-5 单/年 | 原话 |
| 单均 20-30 万 | 原话 |
| 内勤 3 人 | 原话 |

## 他没说但我推断的（必须标注"推断"）
- 推断：老板不知道丢单的具体原因，因为没人统计过
- 推断：他真实想要的是一个"能查参数"的东西，不是"AI 客服"

## 他明确拒绝/不关心的
- 不关心手机端
- 不愿意改现有的 CRM
```

## 3.2 关键动作：把"推断"和"原话"分开

**这张表决定了你后面会不会自己骗自己：**

| 类型 | 可信度 | 能不能写进方案 |
|---|---|---|
| 原话（有引号） | 高 | 能，可以原文引用给客户看 |
| 数字（他说的） | 中高 | 能，但要复述确认 |
| 你的推断 | 低 | **必须标"推断"，复访时验证** |

> **一人公司最容易犯的错：把自己的推断当客户需求，做完了客户说"我没要这个"。**
>
> **分开写，就是防这个。**

# 第 4 步：把记录变成需求清单（25 分钟）

## 4.1 提示词（复制使用）

```text
下面是我和一位客户的访谈原始记录。请把它整理成需求清单。

规则（必须严格遵守）：
1. 每条需求后面必须附上客户的原话作为依据，用引号原文引用；
2. 原话里没有依据的，一律不要写，哪怕你觉得很有道理；
3. 按"客户提到的频次 + 他表达的情绪强度"排序，最痛的排前面；
4. 每条标注：这是"必须有"还是"有了更好"；
5. 不要写技术方案，不要写实现方式，只写"客户要什么结果"；
6. 最后单独列一节：记录里前后矛盾或者说不清的地方。

原始记录：
（贴你的访谈记录）
```

## 4.2 输出格式（`需求清单.md`）

```markdown
# 需求清单 · XX 机械

| # | 客户要的结果 | 原话依据 | 必须有/有了更好 | 我的判断 |
|---|---|---|---|---|
| 1 | 新销售能自己查到产品参数，不用等人 | "新来的答成了 6 米的，客户直接不理了" | 必须有 | 这是丢单主因 |
| 2 | 答案要能追溯到是哪份文件 | "他答错了我们也不知道错在哪" | 必须有 | 决定客户信不信 |
| 3 | 手机上能看 | —（未提及，我推断） | 有了更好 | 待验证 |

## 付费意愿判断

| 依据 | 结论 |
|---|---|
| 一年丢 3-5 单，单均 20-30 万 | 潜在损失 60-150 万/年 |
| 内勤 3 人，月薪约 6000 | 人力成本 21.6 万/年 |
| **他愿意为"减少丢单"付多少** | **1-3 万是合理区间，超过 5 万需要老板点头** |

## 记录里说不清的地方（下次必须问）
1. 参数表是谁维护的？更新频率？
2. 报价单是系统出还是手工填？
```

## 4.3 只保留 3 条，其余全砍

**一份需求清单里，客户真正会掏钱的通常只有 1-3 条。**

| 处理 | 动作 |
|---|---|
| 前 3 条 | 进 MVP，进报价，进合同 |
| 第 4 条以后 | 写进"后续可选"，单独报价 |
| 客户没提过的 | **不写进第一期**，哪怕技术上一分钟就能做 |

> **为什么不多做一点？**
>
> 多做的东西客户不验收、不加钱、出问题还算你的。**免费加功能是一人公司最快的死法之一。**

# 第 5 步：复访确认（10 分钟）

**把需求清单的前三条，发给客户确认。原话这样说：**

```text
张总，我整理了一下上次聊的，只留了最要紧的三条，您看看对不对：

1. 新销售能自己查参数，不用等人
2. 答案要能指出是哪份文件里的
3. 能在手机上打开

如果这三条对，我按这三条出个方案和报价。哪条不对您直接说。
```

**为什么要发这一遍：**

| 作用 | 说明 |
|---|---|
| 防扯皮 | 后期他说"我不是这个意思"，你有书面记录 |
| 显专业 | 90% 的同行聊完就没影了 |
| 探真实优先级 | 他会主动说"其实第 2 条最重要" |

# 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 聊了半小时，没拿到数字 | 没问"上一次""花了多久" | 下次带提纲，七句话照着念 |
| 客户一直说"都挺好" | 你在问"有没有问题" | 改问"上一次出问题是什么时候" |
| 客户只说方案不说痛 | 你没往下钻三层 | "现在谁在做？做慢了会怎样？" |
| 清单写了 30 条 | 把"有了更好"也当需求了 | 只留前 3 条进 MVP |
| 客户当场问价 | 你被带节奏了 | "回去算，明天给你"——报价必须在成本算完后再出 |
| 约不到人 | 开场太像推销 | 换成"聊 20 分钟看看真实场景，不做推销" |
