# 第 246 节课：项目成本——先算清这一单到底花了你多少

> **这份文件是你（学员）一步一步照着做的操作手册。**
> 这节课不写代码，做一张**成本核算表**。
> 目的很直接：让你看清**一个 2 万的项目，最后你其实赚了多少**。
> 大多数人算完这张表才发现，自己一直在给别人打工。

**建议用时**：110 分钟
**你需要先完成**：第 243 节课（三档报价）、第 245 节课（获客页面）

# 第 0 步：四种成本，你只算了两种（15 分钟）

## 0.1 大多数人只算"看得见"的那部分

| 成本类型 | 你算了吗 | 大概占多少 |
|---|---|---|
| **时间**（你自己的工作小时） | 算了，但只算了写代码 | **40-50%** |
| **现金**（服务器、域名、软件、模型） | 算了 | 5-10% |
| **税费**（增值税、附加、所得税） | **基本没算** | 5-15% |
| **隐性**（免费维护、垫款、返工） | **完全没算** | 20-30% |

## 0.2 一个真实的账（这是本节课的核心）

**项目：产品参数问答助手，报价 ¥16,500。**

**你以为的成本：**

```text
写代码 6 天 × 800 = 4,800
```

**实际发生的：**

| 项目 | 数量 | 单价 | 金额 |
|---|---|---|---|
| 写代码 | 48 小时 | — | — |
| 文档清洗（120 份，格式乱） | 16 小时 | — | — |
| 沟通（微信 + 3 次会议 + 反复确认） | 18 小时 | — | — |
| 需求变更（客户改了 2 次） | 10 小时 | — | — |
| 部署 + 排查环境问题 | 8 小时 | — | — |
| 培训（线上 1 小时 + 答疑） | 3 小时 | — | — |
| 上线后修改（3 个月内改了 6 处） | 12 小时 | — | — |
| **总工时** | **115 小时** | | |

**按日薪 1000 元（8 小时 = 1000 元，即 125 元/小时）算：**

```text
时间成本 = 115 小时 × 125 = 14,375 元
```

**加上其他成本：**

| 项目 | 金额 | 说明 |
|---|---|---|
| 时间成本 | 14,375 | 上面算的 |
| 服务器（3 个月，你垫的） | 300 | |
| 模型调用（测试 + 客户试用期用超） | 480 | **客户试用那两周没充钱** |
| 税费（小规模 3% 增值税 + 附加） | 约 600 | 按 16,500 算 |
| **合计** | **15,755** | |

```text
毛利 = 16,500 - 15,755 = 745 元
```

**干了一个半月，赚了 745 元。**

**而且这还没算：** 你如果去接别的活，这 115 小时能赚多少（**机会成本**）。

> **这就是这节课要让你看清的事。**
>
> **不是让你涨价，是让你知道：不涨价的后果不是"少赚"，是"白干"。**

# 第 1 步：先承认你根本没有工时数据（15 分钟）

## 1.1 为什么"估"一定偏低

| 你估的时候 | 实际发生 |
|---|---|
| 只算"写功能" | 沟通、部署、改需求、答疑全没算 |
| 假设一次成功 | 环境问题、依赖冲突、客户改主意 |
| 按"顺利路径"算 | 客户给的数据永远是脏的 |

**经验值：你估的工时 × 1.8 ≈ 实际工时。**

| 你估 | 实际（×1.8） |
|---|---|
| 6 天 | 11 天 |
| 11 天 | 20 天 |
| 20 天 | 36 天 |

> **1.8 不是保守，是经验。** 你可以在下一个项目里验证这个系数。

## 1.2 从今天开始记工时（模板）

**新建 `工时记录模板.md`：**

```markdown
# 工时记录 · 【项目名】

| 日期 | 开始 | 结束 | 小时 | 做了什么 | 类别 |
|---|---|---|---|---|---|
| 11-16 | 09:10 | 12:30 | 3.3 | 清洗 40 份手册 | 文档处理 |
| 11-16 | 14:00 | 15:10 | 1.2 | 微信回复客户关于参数口径 | 沟通 |
| 11-17 | 09:00 | 12:00 | 3.0 | 检索问答调通 | 开发 |
```

**"类别"只有五个，别自创：**

```text
开发 / 文档处理 / 沟通 / 部署 / 返工
```

> **90% 的人第一次记完都会发现：沟通和返工占了快一半。**
>
> **这就是为什么"按天报价"必亏——你的天里有一半不是在写代码。**

## 1.3 记工时的三条纪律

| 纪律 | 说明 |
|---|---|
| **当场记** | 晚上回忆一定漏，而且会往少了记 |
| **不到 0.5 小时也算** | 回一条微信 5 分钟，一天 20 条就是 1.5 小时 |
| **返工单独标** | 返工率高说明你需求没问清（回到第 240 节课） |

# 第 2 步：四类成本逐项算（30 分钟）

## 2.1 时间成本：先把你的小时单价定下来

**算法：**

```text
你的小时单价 = 你希望的年收入 ÷ 一年实际可工作的小时
```

**一人公司的一年（真实数字）：**

| 项 | 数值 |
|---|---|
| 一年 365 天，去掉周末 104 天 | 261 天 |
| 去掉法定假日 + 生病 + 家里事 | 约 240 天 |
| **去掉"没项目的时间"**（新手一年可能有一半时间没活） | **约 120-160 天** |
| 每天有效工作（去掉沟通、刷手机、发呆） | **5-6 小时** |

```text
一年有效工时 ≈ 150 天 × 5.5 小时 = 825 小时
```

**如果你希望一年挣 15 万：**

```text
小时单价 = 150,000 ÷ 825 ≈ 182 元/小时
```

> **注意这个数字：182 元/小时。**
>
> **你按 ¥800/天报，等于 100 元/小时——连"希望年入 15 万"都做不到。**

## 2.2 现金成本：一张清单，别靠记忆

| 项 | 你这一单要花多少 | 谁付 |
|---|---|---|
| 云服务器 | 60-200 元/月 | 客户或你垫 |
| 域名 | 50-80 元/年 | 客户 |
| 对象存储 / CDN | 按量，通常几元 | 客户 |
| 模型调用 | **最容易失控** | 客户充或你 1.3 倍代收 |
| 软件订阅（设计、压缩、录屏） | 0-100 元/月 | 你 |
| 备份 / 测试机 | 0-100 元/月 | 你 |

**最容易漏的三笔：**

| 漏项 | 后果 |
|---|---|
| 模型调用在"测试和试用期"的消耗 | 客户试用两周，你付了三百 |
| 客户要"多一套测试环境" | 两台服务器，客户只认一台 |
| 数据迁移/清洗用的工具 | 你说"顺手做了"，其实是两天 |

## 2.3 税费：这一笔会真金白银扣走

**（税率以当地税务机关最新规定为准，这里只讲结构，不当依据）**

| 税种 | 大致比例 | 说明 |
|---|---|---|
| 增值税（小规模） | 3%（有减免期） | 按开票额算 |
| 附加税（城建/教育） | 增值税的约 12% | 跟着增值税走 |
| 个人所得税 / 经营所得 | 5%-35% 累进 | 个体户按经营所得 |

**粗略记法：开票额的 6%-10% 会被税拿走。**

| 报价 | 税大约 |
|---|---|
| 16,500 | 1,000-1,650 |
| 50,000 | 3,000-5,000 |
| 100,000 | 6,000-10,000 |

> **报 16,500 的时候心里要想的是"到手 15,000"。**
>
> **报价时就把税算进去，不要等到报税那天才发现不够。**

## 2.4 隐性成本：这一笔最大，也最没人算

| 隐性成本 | 典型值 | 怎么变成显性 |
|---|---|---|
| **免费维护期**（3 个月） | 10-20 小时 | 报价时把维护期写清：含几次、超出多少钱 |
| **垫款**（客户 3 个月后付尾款） | 几千元的现金流压力 | 定金 30% 是底线 |
| **返工**（需求没问清） | 10-30 小时 | 第 240 节课的需求清单就是防这个 |
| **免费咨询**（客户随时问） | 每周 1-2 小时 | 设"响应时段"，或转成付费运维 |
| **机会成本**（这一个月你没法接别的） | 一整个项目的价 | 报价时至少留 40% 毛利 |

## 3.2 三个必须算出来的数字

| 数字 | 为什么关键 |
|---|---|
| **毛利率** | 低于 30% 就别做了，不如去打工 |
| **实际小时收入** | 和你"希望的小时单价"比，差多少 |
| **返工占比** | 超过 20% 说明需求没问清 |

## 3.3 一个判断标准

| 毛利率 | 判断 |
|---|---|
| > 60% | 好单，可以多做几个同类的 |
| 40%-60% | 正常，一人公司的合理区间 |
| 30%-40% | 偏低，要么涨价要么压缩范围 |
| < 30% | **不该接**，除非为了拿案例（且只能一次） |

> **"为了拿案例亏一次"是可以的，但必须写下来，而且要限定次数。**
>
> **不写下来，你会亏很多次，还以为自己在攒案例。**

# 第 5 步：把结论变成规则（10 分钟）

**在 `成本核算.md` 最后加一节"下次怎么报"：**

```markdown
## 下次怎么报

1. 沟通时间按开发时间的 40% 单列，不再"包含在内"。
2. 免费维护改成：交付后 1 个月内，含 3 次修改，超出 300 元/次。
3. 模型调用从第一天就要求客户自己充，不给试用额度。
4. 文档超过 50 份，单独报"数据整理费"。
5. 报价 = 实际工时 × 小时单价 × 1.5，且毛利率不低于 40% 才接。
```

> **这五条比任何"报价技巧"都值钱，因为它是你自己算出来的。**

# 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 算出来毛利是负的 | 工时估少了，或维护期没算 | 正常，先接受，再改报价结构 |
| 不知道自己的小时单价 | 从没算过一年能工作多少小时 | 用 150 天 × 5.5 小时，先按这个算 |
| 觉得"这单不做就没单了" | 新手常见心态 | 记下这一单，做完看毛利率，低于 30% 下次不接 |
| 税费算不清 | 政策会变 | 先按 6%-10% 粗算，具体问当地税务局 |
| 客户不愿付定金 | 你没把"定金"说成流程 | "签约定金 30%，这是我们的标准流程" |
| 不知道隐性成本怎么折钱 | 用小时单价折 | 维护 15 小时 = 15 × 你的小时单价 |
