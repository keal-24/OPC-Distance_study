# 第 248 节课：合同重点——正文只是框架，附件才是合同

> **这份文件是你（学员）一步一步照着做的操作手册。**
> 今天做三份东西：**合同模板（可填空）**、**功能清单**、**验收标准**。
> 后两份比第一份重要——**80% 的纠纷，吵的都是附件没写清。**
>
> 本文不是法律意见。单个项目超过 10 万，花 1000-3000 找律师看一遍，值。

**建议用时**：130 分钟
**你需要先完成**：第 240 节课（需求清单）、第 243 节课（三档报价）

# 第 0 步：为什么合同救不了你（15 分钟）

## 0.1 合同不是用来打官司的

**打官司的时间成本：** 立案到判决 6-12 个月，律师费几千起，你一个人做项目耗不起。

**合同的真实作用只有三个：**

| 作用 | 怎么实现 |
|---|---|
| **让对方知道边界在哪** | 写清范围、次数、时间点 |
| **在吵架时有一份共同的文本** | 双方对同一段话的解释没有分歧 |
| **让对方不敢随便违约** | 有定金、有尾款、有暂停服务权 |

> **合同的价值在"签之前"，不在"打官司时"。**
>
> **一份好的合同，会让不合适的人一开始就不签。**

## 0.2 最大的坑：合同正文写得漂亮，附件是空的

```text
"乙方按甲方需求开发产品参数问答系统。"
```

**"需求"是什么？** 没写。**这就是无穷加需求的入口。**

**正确结构：**

```text
合同正文（3 页）→ 说清双方、钱、时间、边界
   ├── 附件一《功能清单》→ 具体做哪些功能，逐条编号
   └── 附件二《验收标准》→ 每条功能怎么算通过
```

> **附件一决定你要做多少活，附件二决定你什么时候能拿到尾款。**
>
> **这两份写不清，正文写得再漂亮也没用。**

## 0.3 今天的交付物

| 文件 | 位置 | 内容 |
|---|---|---|
| `合同模板.md` | `03-练习代码` | 可填空的合同正文（10 条） |
| `功能清单.md` | `03-练习代码` | 逐条编号的功能表（含"不做"清单） |
| `验收标准.md` | `03-练习代码` | 每条功能可验证的通过条件 |

# 第 1 步：五条必须写进正文（30 分钟）

## 1.1 条款一：范围以书面为准

```text
本合同范围以附件一《功能清单》为准。清单外的需求视为新增，
需双方书面确认工作量与费用后另行执行，工期相应顺延。
```

**为什么最值钱：**

| 没有这条 | 有这条 |
|---|---|
| 客户说"顺便加个导出吧" | "这是新增，我报个价" |
| 加十次，你免费干两个月 | 每次都有一个书面动作 |

**客户反对时怎么说：**

```text
"这条是保护双方的，我加东西也要你签字确认，不会偷偷加钱。"
```

## 1.2 条款二：验收标准可验证

```text
验收标准见附件二。甲方应在收到验收通知后 5 个工作日内完成验收；
逾期未提出书面异议的，视为验收通过。
```

**关键在最后半句。** 没有它，客户可以永远"还在看"。

**验收标准必须是这种：**

| 反例（不可验证） | 正例（可验证） |
|---|---|
| "界面美观" | "在 1366×768 与 375×667 两种宽度下无横向滚动条" |
| "回答准确" | "随机抽 20 个问题，其中 16 个以上答案包含正确参数且标出出处" |
| "性能良好" | "单次问答响应时间 ≤ 5 秒（不含模型排队）" |
| "能导入数据" | "能导入 1 万行 Excel，错误行有提示，成功率 ≥ 95%" |

## 1.3 条款三：运维另计

```text
上线后提供 1 个月免费维护，含 3 次功能修改（每次不超过 2 小时）。
超出部分按 300 元/次或 500 元/小时计。免费维护期满后，
运维服务按 2000 元/月计，含每月 5 次修改。
```

**没有这条，你会变成终身免费客服。**

| 三个月后客户说 | 你的回答 |
|---|---|
| "帮我改个按钮颜色"（第 7 次） | "超出免费维护的 3 次了，这次 300。" |
| "加个导出 Excel 吧" | "这是新增功能，我报个价。" |

## 1.4 条款四：数据归属

```text
甲方数据的所有权归甲方。乙方不得将甲方数据用于本合同之外的任何用途，
不得向第三方提供。乙方在项目结束后 30 日内删除本地副本。
```

**这一条保护你，也保护客户。**

| 没写 | 写了 |
|---|---|
| 客户怀疑你拿他的数据训练模型 | 你有书面承诺 |
| 你把数据留在电脑上，出事说不清 | 有删除义务，也有依据 |

## 1.5 条款五：AI 免责

```text
本系统包含人工智能生成内容，输出结果仅供参考，可能存在错误。
乙方已在产品中标注内容来源以便核对，但不对生成内容的准确性、
完整性及由此产生的决策后果承担责任。甲方应自行核对关键信息。
```

**这是 AI 项目特有的一条，传统外包合同里没有。**

> **它不一定能完全免责，但它是你唯一的书面依据。**
>
> **客户如果拿 AI 的输出做决策出了事，这句话决定你是"技术提供方"还是"责任方"。**

# 第 2 步：三条建议加上的条款（25 分钟）

## 2.1 需求变更流程

```text
任何需求变更，须由甲方以书面形式（含微信、邮件）提出，
乙方评估工作量与费用后书面回复，双方确认后方可执行。
口头变更无效。
```

**为什么写"含微信"：** 客户不会发正式函件，但会发微信。**微信截图也是书面证据，前提是合同里认了。**

## 2.2 源码交付条件

```text
甲方结清全部款项后，乙方交付完整源码及相关文档。
款项结清前，乙方保留源码及软件的著作权。
```

**这是你唯一的筹码。**

| 先交源码 | 尾款结清后交 |
|---|---|
| 客户拿到就能找别人改，尾款可以不付 | 你手里有东西，他有动力付钱 |

**客户说"我们要先看源码才放心"：**

```text
"可以看，签保密协议，来我这边看或者远程演示。交付是尾款结清后。"
```

## 2.3 终止与暂停服务权

```text
任一方可提前 30 天书面通知终止本合同，已完成部分按比例结算。
甲方逾期付款超过 15 日，乙方有权暂停服务且不承担违约责任，
暂停期间不计入工期。
```

**"暂停服务权"这四个字，比催款话术有用一百倍。**

> **没有它，客户拖尾款时你只能一直提供服务，还得笑着说"不急"。**

# 第 3 步：写附件一《功能清单》（30 分钟）

## 3.1 格式：编号 + 描述 + 优先级 + 是否含在报价内

```markdown
# 附件一 · 功能清单

| 编号 | 功能 | 具体描述 | 优先级 | 含在本期 |
|---|---|---|---|---|
| F01 | 文档导入 | 支持上传 Word / PDF / TXT，单个 ≤ 20MB，批量 ≤ 50 个 | 必须 | 是 |
| F02 | 文档解析 | 提取正文，保留文件名与页码 | 必须 | 是 |
| F03 | 问答 | 输入问题，返回答案 + 引用出处（文件名 + 页码） | 必须 | 是 |
| F04 | 无答案处理 | 检索不到相关内容时，回答"文档中未找到"，不得编造 | 必须 | 是 |
| F05 | 账号 | 支持 20 个账号，用户名密码登录 | 必须 | 是 |
| F06 | 权限 | 管理员 / 普通用户两种角色 | 必须 | 是 |
| F07 | 后台 | 修改欢迎语、上传/删除文档 | 必须 | 是 |
| F08 | 日志 | 记录每次提问与回答 | 有了更好 | **否** |
| F09 | 导出 | 问答记录导出 Excel | 有了更好 | **否** |
| F10 | 对接 ERP | 从 ERP 同步产品参数 | 有了更好 | **否** |

## 本期明确不包含

| 编号 | 不做的内容 | 说明 |
|---|---|---|
| N01 | 手机 App | 只提供网页，手机用浏览器访问 |
| N02 | 扫描件 OCR | 只接受电子版文档，扫描件另议 |
| N03 | 语音输入 | 另议 |
| N04 | 与 ERP 自动同步 | 另议 |
| N05 | 内容录入 | 文档由甲方提供电子版 |
```

## 3.2 三个关键细节

| 细节 | 为什么 |
|---|---|
| **每个功能都带数量/上限** | "支持上传文档"没上限，客户传 5000 份你也得撑住 |
| **单独列"明确不包含"** | 这是挡箭牌，比正文里的"范围以清单为准"更硬 |
| **"有了更好"标"否"** | 客户看到"否"，就知道要另外加钱，不会默认包含 |

## 3.3 数量上限怎么写

| 模糊 | 明确 |
|---|---|
| 支持批量上传 | 单次批量 ≤ 50 个，单文件 ≤ 20MB |
| 支持多用户 | 20 个账号，超出按 50 元/个/年 |
| 响应快 | 单次问答 ≤ 5 秒（不含模型排队） |
| 支持多种格式 | Word（.docx）/ PDF（文字版）/ TXT |

> **每一个"支持"，后面都要跟一个数字。**
>
> **没跟数字的地方，就是你未来免费加班的地方。**

# 第 4 步：写附件二《验收标准》（25 分钟）

## 4.1 格式：每条功能对应一个可执行的测试

```markdown
# 附件二 · 验收标准

验收方式：甲方指定 3 名实际使用者，在测试环境中按下列用例操作，
逐条记录结果。全部"必须"项通过即为验收通过。

| 编号 | 对应用例 | 通过条件 |
|---|---|---|
| A01 | 导入 10 份 Word、10 份 PDF、10 份 TXT | 全部解析成功，文件名与页码正确 |
| A02 | 导入 1 个 25MB 的 PDF | 有明确提示"超过 20MB"，不崩溃 |
| A03 | 提问"8 米车床承重多少" | 5 秒内返回答案，且答案含"8 米"参数值 + 出处文件名 + 页码 |
| A04 | 提问"我们公司的年会什么时候开"（文档里没有） | 回答"文档中未找到相关内容"，不得编造 |
| A05 | 用错误答案抽查 10 个问题 | 至少 8 个答案与原文一致 |
| A06 | 用第 21 个账号登录 | 提示"账号数已达上限"，不报错 |
| A07 | 普通用户访问后台地址 | 被拒绝，跳回首页 |
| A08 | 管理员修改欢迎语 | 保存后刷新页面生效 |
| A09 | 在手机（375px）打开问答页 | 无横向滚动条，输入框可用 |

## 验收流程

1. 乙方书面通知"可验收"，附本表；
2. 甲方 5 个工作日内组织 3 名使用者测试；
3. 逐条打勾，双方签字确认；
4. 有未通过项：乙方 5 个工作日内修复，重新验收；
5. 甲方逾期未提出书面异议，视为验收通过。
```

## 4.2 验收标准的三条铁律

| 铁律 | 说明 |
|---|---|
| **每条都能被第三方执行** | 换个人照着做，结论一样 |
| **必须有"必须"和"可选"的区分** | 可选不通过不影响验收 |
| **必须有数量阈值** | "10 个里 8 个对"比"基本准确"强一百倍 |

## 4.3 这一条最容易被忽略，但最保命

```text
甲方逾期未提出书面异议的，视为验收通过。
```

**没有这句，验收期可以无限长，尾款可以无限拖。**

# 第 5 步：组装合同正文（20 分钟）

## 5.1 十条结构（写进 `合同模板.md`）

```markdown
# 软件开发合同

甲方：____________  乙方：____________

## 第一条 项目内容
乙方为甲方开发 ______ 系统，功能范围以附件一《功能清单》为准。

## 第二条 交付物
1. 可运行的软件系统（部署于甲方提供的服务器）
2. 源码（尾款结清后交付）
3. 部署文档与使用说明
4. 3 分钟演示录屏

## 第三条 工期
自甲方提供完整文档之日起 ____ 个工作日内完成。
甲方原因导致的延误，工期顺延。

## 第四条 费用与支付
合同总价：¥______（含税）
1. 签约后 3 个工作日内付 30%：¥______
2. 验收通过后 5 个工作日内付 40%：¥______
3. 上线稳定运行 7 日后付 30%：¥______
模型调用费用按实际用量另计，由甲方充值或乙方按 1.3 倍代收。

## 第五条 验收
见附件二《验收标准》。甲方应在收到验收通知后 5 个工作日内完成验收，
逾期未提出书面异议视为通过。

## 第六条 知识产权
甲方结清全部款项后取得本系统的使用权；乙方保留通用组件、
框架及工具的著作权，有权在其他项目中复用。
甲方数据所有权归甲方。

## 第七条 维护
上线后 1 个月免费维护，含 3 次功能修改（每次 ≤ 2 小时）。
其后运维 2000 元/月，含每月 5 次修改。超出部分另行计费。

## 第八条 AI 内容免责
本系统包含人工智能生成内容，仅供参考。乙方不对生成内容的准确性、
完整性及决策后果承担责任。

## 第九条 保密
双方对本合同内容及履约中知悉的对方商业信息保密，期限 3 年。

## 第十条 违约与终止
甲方逾期付款超过 15 日，乙方有权暂停服务且不承担违约责任。
任一方可提前 30 天书面通知终止，已完成部分按比例结算。

甲方（签字/盖章）：______  日期：______
乙方（签字/盖章）：______  日期：______

附件一：功能清单
附件二：验收标准
```

## 5.2 签字前十分钟的自检（10 条）

| # | 检查 | 不通过的后果 |
|---|---|---|
| 1 | 附件一每条都有数量/上限 | 无限加量 |
| 2 | 附件二每条都可验证 | 验收无限拖 |
| 3 | 有"逾期未异议视为通过" | 尾款拿不到 |
| 4 | 定金 ≥ 30% | 客户随时能跑 |
| 5 | 有"暂停服务权" | 拖款你只能干等 |
| 6 | 源码交付与尾款绑定 | 交了源码就没筹码 |
| 7 | 运维次数和单价写清 | 变终身免费客服 |
| 8 | 有 AI 免责条款 | 客户拿错答案找你赔 |
| 9 | 有"清单外视为新增" | 免费干三个月 |
| 10 | 工期起算点绑定"甲方提供文档" | 客户拖你不背锅 |

> **10 条里有 3 条没写，这份合同就是漏的。**

# 第 6 步：五种单，签字前就该拒（10 分钟）

| 类型 | 特征 | 为什么别接 |
|---|---|---|
| **不给定金** | "先做出来看看，好用再谈钱" | 做完了他说不好用，你白干 |
| **描述极模糊** | "很简单，就改几个字" | 打开一看是重写 |
| **要求与预算严重不符** | "我们要过等保"，预算 3 万 | 等保本身就要几万 |
| **要复制别人产品** | "做个和 XX 一样的" | 法律风险 |
| **不肯签合同** | 只肯口头 | 出问题你连证据都没有 |

**判断标准一句话：**

> **不愿意给定金、不愿意签合同的客户，一定会在后面出问题。**

# 第 7 步：让 AI 挑合同的洞（15 分钟）

```text
下面是我准备用的一份软件开发合同（含两个附件）。
请你扮演一个专门代理甲方（客户方）的律师，任务是找出对我方不利的地方。

请按这个格式输出：
1. 这条对我方（甲方）有利在哪；
2. 我方可以怎么利用它要求更多；
3. 乙方应该在哪个位置补一句话堵住。

重点看：范围、验收、工期起算、付款、知识产权、终止。
不要给总体评价，只逐条挑。

合同：
（贴合同 + 两个附件）
```

**拿到结果后，把"乙方应该补的那句话"抄进模板。**

> **用对手的视角读一遍，是审合同最有效的办法。**

# 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 客户不肯签合同 | 你说得太正式，他怕麻烦 | 给一页纸简化版 + 微信确认也行，但要有文字 |
| 客户要求删掉"逾期视为通过" | 他知道这条对他不利 | "这条是双向的，你也可以用它催我交付" |
| 客户要全部著作权 | 正常要求 | 加价，或者写"甲方获独占使用权，乙方保留通用组件" |
| 附件写得太细，客户嫌烦 | 你没解释它的作用 | "这是为了验收时我们不吵架" |
| 不知道要不要找律师 | 金额决定 | 单项目 > 10 万，花 1000-3000 值 |
