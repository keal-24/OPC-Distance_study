# 第 0 步：交付不是"给他代码"（10 分钟）

## 0.1 三种交付，三种结局

| 你交付了什么 | 三个月后 |
|---|---|
| 只给了代码 | "怎么部署？""服务器挂了怎么办？"——你变成免费运维 |
| 代码 + 文档 | 好一些，但他还是看不懂文档 |
| **代码 + 文档 + 录屏 + 验收单 + 交接表 + 明确的运维边界** | **他能自己搞定 90%，你只处理剩下的 10%** |

> **交付的目标不是"我做完了"，是"他不需要你了"。**
>
> **听起来反直觉，但这正是你能接下一个项目的前提。**

## 0.2 一人公司最大的单点风险：你自己

| 如果你明天住院一周 | 会怎样 |
|---|---|
| 客户服务器挂了 | 没人会重启 |
| 域名要续费 | 没人知道在哪个账号 |
| 客户要改一个字 | 没人能改 |
| 客户联系不上你 | 只能干等，然后骂你 |

**这不是危言耸听，这是每个独立开发者都会遇到一次的事。**

# 第 1 步：交付八件套（30 分钟）

## 1.1 清单（少一件都是坑）

| # | 交付物 | 内容要求 | 少了会怎样 |
|---|---|---|---|
| 1 | **源代码** | 完整、能跑、无本地硬编码路径 | 换人接手要重写 |
| 2 | **`README.md`** | 怎么装、怎么跑、怎么部署，三步以内 | 你自己三个月后也看不懂 |
| 3 | **`.env.example`** | **只写变量名，不写值** | 交出真实 key = 泄露 |
| 4 | **部署文档** | 换个人照着做能重新部署一次 | 服务器一挂就完 |
| 5 | **常见问题（FAQ）** | 客户会问的十个问题 + 答案 | 你变成客服 |
| 6 | **演示录屏** | 3 分钟，走一遍核心流程 | 培训讲十遍 |
| 7 | **验收签字单** | 附件二逐条打勾，双方签字 | 尾款没依据 |
| 8 | **运维期约定** | 免费多久、几次、之后多少钱 | 终身免费 |

## 1.2 `README.md` 的最低要求

**它能被一个没参与过项目的人读懂，才算合格。**

```markdown
# 项目名

## 这是什么
一段话说清：给谁用、解决什么、有哪些角色。

## 技术栈
Node.js 20 / Express / PostgreSQL 16 / 前端原生 JS

## 本地跑起来（三步）
1. `npm install`
2. 复制 `.env.example` 为 `.env`，填入下面四个值
3. `npm run dev`，打开 http://localhost:3000

## 环境变量说明
| 变量名 | 作用 | 从哪拿 |
|---|---|---|
| DATABASE_URL | 数据库连接串 | 服务器面板 → 数据库 |
| OPENAI_API_KEY | 模型调用 | 平台后台 → API Keys |

## 部署
见 `docs/deploy.md`

## 常见问题
见 `docs/faq.md`

## 已知问题
- 扫描版 PDF 无法解析
- 单次导入上限 50 个文件
```

> **"已知问题"这一节很重要。** 它既是免责，也是专业。

## 1.3 `.env.example` 的三条规矩

| 规矩 | 说明 |
|---|---|
| **只写名字和说明，不写值** | `OPENAI_API_KEY=` 后面空着 |
| **每个变量一行注释** | 从哪拿、格式是什么 |
| **敏感变量单独标 `[必填]`** | 少一个就跑不起来 |

**交付前检查一遍：**

```bash
# 确认 .env 没被提交、没被打包
git status --ignored | grep -i ".env"
# 确认代码里没有硬编码 key
grep -rn "sk-" --include="*.js" --include="*.ts" .
```

> **把真实 key 交出去 = 客户能查你的用量。把 key 提交到 GitHub = 几小时内被刷。**
>
> **必须做的一件事：交付前把所有 key 轮换一次。**

## 1.4 演示录屏怎么录（3 分钟）

| 段落 | 时长 | 内容 |
|---|---|---|
| 1 | 20 秒 | 这是干什么的（一句话） |
| 2 | 90 秒 | 走一遍最核心的路径（问一句 → 出答案 → 点开原文） |
| 3 | 40 秒 | 后台怎么改文案、怎么传文档 |
| 4 | 30 秒 | 出问题找谁、怎么找你 |

**工具：** Win + G（Xbox Game Bar）自带，或 OBS。

**录音要比录屏重要。** 客户看录屏是听你说，不是看鼠标动。

## 2.2 签字的三个规矩

| 规矩 | 为什么 |
|---|---|
| **必须逐条打勾，不写"整体满意"** | 整体满意可以反悔，逐条通过不能 |
| **必须有日期** | 尾款账期从这天起算 |
| **必须纸质或 PDF 扫描件** | 微信"好的"不算签字 |

> **客户不肯签？**
>
> **"签字只是确认这些功能都在，后面的维护范围按这个来。你签了我也少打扰你。"**

| 提交软著申请 | 完成日期有了 |

# 第 3 步：账号交接（25 分钟）

## 3.1 交接表模板

```markdown
# 账号交接表

| 系统 | 用途 | 账号 | 密码存放位置 | 所有权 | 谁负责续费 |
|---|---|---|---|---|---|
| 云服务器 | 运行系统 | 客户公司账号 | 客户 IT 保管 | **甲方** | 甲方 |
| 域名 | 访问入口 | 客户账号 | 客户 IT 保管 | **甲方** | 甲方 |
| 数据库 | 存数据 | admin | 客户 IT 保管 | 甲方 | 甲方 |
| 模型平台 | 调用模型 | 客户账号 | 客户 IT 保管 | **甲方** | 甲方 |
| 对象存储 | 存文档 | 客户账号 | 客户 IT 保管 | 甲方 | 甲方 |
| 代码仓库 | 源码 | 客户组织下的仓库 | 客户 IT 保管 | 甲方 | — |
| 短信/邮件服务 | 通知 | 客户账号 | 客户 IT 保管 | 甲方 | 甲方 |
```

## 3.2 三条铁规矩

| 规矩 | 为什么 |
|---|---|
| **账号全部转移到客户名下** | 你不用替客户保管资产，也不背续费责任 |
| **密码不要写在交接表里** | 表会被转发、会被打印。密码单独用密码管理器共享 |
| **明确"谁负责续费"** | 服务器欠费停机，客户第一句是"你怎么搞的" |

## 3.3 密码怎么交（三个方案）

| 方案 | 做法 | 适合 |
|---|---|---|
| **一次性分享链接** | 用密码管理器的"共享"功能（Bitwarden Send / 1Password） | **推荐** |
| 当面输入 | 客户 IT 在旁边，你输入，他不记录 | 小客户 |
| 加密文件 | 密码通过电话告知 | 临时 |

**绝对不要：**

```text
❌ 微信发密码
❌ 写进 Word 发邮件
❌ 写在交接表里
```

> **微信聊天记录会被截图、会被转发、会留在服务器上。**
>
> **客户一旦泄露，第一个被怀疑的是你。**

## 3.4 代码仓库怎么交

| 方式 | 做法 |
|---|---|
| **推荐**：客户建组织，你邀请他 | 仓库所有权从一开始就在客户那边 |
| 备选：转移仓库 | GitHub Settings → Transfer ownership |
| 最后手段：打包 zip | 客户拿不到提交历史，你也没法再维护 |

> **一开始就让仓库在客户名下，交付时你只需要"退出"**，不用"转移"。

# 第 4 步：脱身预案（30 分钟）

## 4.1 这一节听起来不吉利，但它是对客户负责

**你要回答三个问题：**

| 问题 | 你的答案写在哪 |
|---|---|
| 我出事了，客户的数据在哪、谁能拿到？ | `脱身预案.md` |
| 服务谁来重启？ | 部署文档 + 交接表 |
| 客户怎么联系到我（或我的家人）？ | 合同 + 紧急联系人 |

## 4.2 最小可行的四件事

| # | 动作 | 具体怎么做 |
|---|---|---|
| 1 | **所有账号进密码管理器** | Bitwarden（免费），开双重验证 |
| 2 | **设一个紧急访问人** | Bitwarden 有"紧急访问"功能，指定一个人，失联 N 天后可获取 |
| 3 | **部署文档写到别人能接手** | 检验方法：让一个朋友照着做一遍，他能跑起来 |
| 4 | **合同里写终止条款** | 双方都能体面退出，按比例结算 |

## 4.3 部署文档的"别人能接手"标准

**拿这份文档，找一个没参与过项目的开发者（朋友、同行），让他照做。观察：**

| 他卡在哪 | 说明文档缺什么 |
|---|---|
| 找不到代码在哪 | 缺仓库地址和权限说明 |
| 装不上依赖 | 缺 Node 版本、系统依赖 |
| 起不来服务 | 缺环境变量说明 |
| 访问不了 | 缺域名/端口/防火墙说明 |
| 数据是空的 | 缺数据恢复步骤 |

> **他卡住的每一处，就是你出事那天客户会卡住的地方。**

| 姓名 | 关系 | 联系方式 | 能做什么 |

| | | |

## 5.3 三个真话

**真话一：学完不等于会。**
> 252 节课你能全做完，已经超过 95% 的人。但"做完"和"能靠这个吃饭"之间，还差**至少一次完整交付**。

**真话二：第一单大概率不赚钱。**
> 它的价值是**案例、评价、和"我做过了"的底气**。接受这一点，你会轻松很多。

**真话三：技术不是你的护城河，交付能力才是。**
> 会写代码的人越来越多。**能把"需求 → 报价 → 合同 → 交付 → 收钱 → 脱身"走完一遍的人，很少。**

# 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 交付后客户天天找你 | 没写运维边界 + 没 FAQ | 补 FAQ，把常见问题转成文档 |
| 客户要我留着服务器账号 | 他不想管 | 明确说："账号在您名下，续费是您这边，我提供操作步骤" |
| 部署文档自己都看不懂 | 写的时候跳步了 | 让朋友照着做一遍，他卡的地方就是漏的 |
| 交接表被转发出去 | 里面有密码 | 立刻改密码，密码只走密码管理器 |
| 客户不肯签验收单 | 怕签字等于付钱 | "签字是确认功能，付款按合同账期" |
| 复盘写不出来 | 没留笔记 | 翻自己的 NOTES.md 和 git log，按周过 |
| 学完了不知道下一步 | 缺具体动作 | 只做 5.4 那三件事，别想太多 |
