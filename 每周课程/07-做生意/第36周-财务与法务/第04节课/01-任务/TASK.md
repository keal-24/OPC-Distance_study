# 第 249 节课：收款节点——钱什么时候到，比报多少更重要

> **这份文件是你（学员）一步一步照着做的操作手册。**
> 今天做两份东西：**收款台账**和**催款话术**。
> 一人公司最常见的死法不是"没单"，是**"有单、做完了、钱没到"**。现金流一断，什么都停了。

**建议用时**：110 分钟
**你需要先完成**：第 248 节课（合同里的付款条款）、第 246 节课（成本核算）

---

# 第 0 步：现金流比利润重要（10 分钟）

## 0.1 一个真实的死法

```text
1 月：接单，报价 2 万，约定"验收后一次性付清"
2 月：干活，自己垫服务器、垫模型费
3 月：交付，客户说"还在验收"
4 月：还在验收
5 月：你手上没钱了，接了另一个便宜单救急
6 月：两个单同时延期，都被骂
```

**这个项目毛利可能有 40%，但你在第 5 个月就撑不住了。**

> **利润是"这一单赚多少"，现金流是"这个月有没有钱吃饭"。**
>
> **前者决定你一年后什么样，后者决定你能不能活到年底。**

## 0.2 三个必须守住的数字

| 数字 | 底线 | 为什么 |
|---|---|---|
| **定金比例** | ≥ 30% | 低于这个，客户随时能跑，你没有任何筹码 |
| **最长账期** | ≤ 30 天 | 超过一个月，你就开始垫钱 |
| **在手现金覆盖月数** | ≥ 3 个月 | 一人公司没有工资，也没有融资 |

## 0.3 今天的交付物

| 文件 | 位置 | 内容 |
|---|---|---|
| `收款台账.md` | `03-练习代码` | 每个项目的收付款状态表 |
| `催款话术.md` | `03-练习代码` | 从"到期前"到"逾期 30 天"的五段话 |

# 第 1 步：把付款节点设计出来（25 分钟）

## 1.1 最常见的三种结构

| 结构 | 节点 | 适合 |
|---|---|---|
| **3-4-3** | 签约 30% / 验收 40% / 上线一周 30% | 大多数项目，**推荐** |
| **5-3-2** | 签约 50% / 中期 30% / 验收 20% | 周期长（> 2 个月）、垫款压力大 |
| **4-4-2** | 签约 40% / 交付 40% / 维护期满 20% | 客户强势、要求质保金 |

**绝对不要用的两种：**

| 结构 | 问题 |
|---|---|
| "验收后一次性付清" | 你垫两个月，且没有任何筹码 |
| "做完再谈钱" | 这不是合作，是免费劳动 |

## 1.2 3-4-3 的时间线长什么样

```text
第 0 天   签约，收 30%（¥4,950）
第 15 天  交付，客户验收
第 20 天  验收通过，收 40%（¥6,600）
第 27 天  上线满一周，收 30%（¥4,950）
```

**关键：每个节点都要有一个"客观事件"作为触发条件。**

| 节点 | 触发条件 | 不能写成 |
|---|---|---|
| 签约 | 合同签字 + 首款到账 | "启动后" |
| 验收 | 附件二逐条通过 + 签字 | "客户满意" |
| 尾款 | 上线满 7 个自然日 | "稳定运行后" |

> **"客户满意""稳定运行"都是主观的，可以无限拖。"上线满 7 个自然日"是客观的。**

## 1.3 定金怎么开口要

**客户说"我们先做起来，钱后面一起给"：**

```text
"我们的流程是签约定金 30%，然后开始排期。
这不是不信任，是双方的时间保障——我排了期，就不能接别的活。"
```

**客户说"我们公司流程要走一个月"：**

```text
"理解。那我们把签约日期定在你们付款审批通过那天，
我按那个日期往后排期。这样两边都不耽误。"
```

> **核心：把"要不要付定金"变成"什么时候能付定金"。**
>
> **不问"能不能付"，问"什么时候能付"。**

## 1.4 尾款和交付物绑定

**合同里必须有一句：**

```text
甲方结清全部款项后，乙方交付源码及账号权限。
```

**交付什么、什么时候交，按这张表来：**

| 交付物 | 什么时候给 |
|---|---|
| 系统访问地址（客户自己服务器上） | 验收通过即可用 |
| 演示录屏 + 使用文档 | 验收通过即给 |
| 源码 | **尾款到账后** |
| 服务器 / 数据库 / 域名后台账号 | **尾款到账后** |
| 部署文档 | 尾款到账后（可以先给一份简版） |

> **注意：系统本身要能用。** 压在客户自己的服务器上，他能用；你不能"锁系统"逼付款——那是违法的。
>
> **你压的是源码和账号，不是"停服务"。**

# 第 2 步：建收款台账（25 分钟）

## 2.1 台账模板（写进 `收款台账.md`）

```markdown
# 收款台账

| # | 项目 | 合同额 | 已收 | 未收 | 最近账期 | 状态 | 下一步动作 | 下次跟进 |
|---|---|---|---|---|---|---|---|---|
| 1 | XX机械-问答助手 | 16,500 | 4,950 | 11,550 | 11-30 | 待验收 | 11-25 提醒验收 | 11-25 |
| 2 | | | | | | | | |
```

## 2.2 状态只有六种

```text
未签约 → 已签约待开工 → 进行中 → 待验收 → 待尾款 → 已结清
```

**加一个异常状态：**

```text
逾期
```

**"逾期"要单独标红。** 一个人同时跟 4 个项目时，只有标红的那行会被记住。

## 2.3 三个必须填的字段

| 字段 | 为什么 |
|---|---|
| **最近账期** | 没有日期的应收款，永远不会被收 |
| **下一步动作** | "等客户"不是动作，"发验收通知"才是 |
| **下次跟进** | 写具体日期，不写"下周" |

## 2.4 每周固定做一次（15 分钟）

**每周一早上，打开台账，做三件事：**

| 动作 | 判断 |
|---|---|
| 有"逾期"的 → 今天必须处理 | 按第 3 步的阶梯走 |
| 有"待验收/待尾款"超过 7 天的 → 发提醒 | 用话术卡的第 2 段 |
| 有"进行中"但两周没动的 → 问客户卡在哪 | 进度不动，账期就危险 |

> **不做这一件事，你的应收款就会慢慢变成"历史遗留问题"。**

# 第 3 步：催款阶梯（25 分钟）

## 3.1 五级阶梯，一级比一级硬

| 级别 | 时点 | 动作 | 语气 |
|---|---|---|---|
| **0 级** | 到期前 5 天 | 友好提醒 | 帮忙式 |
| **1 级** | 到期前 1 天 | 确认到账时间 | 确认式 |
| **2 级** | 逾期 3 天 | 电话，问卡在哪 | 关心式 |
| **3 级** | 逾期 7 天 | **书面**（微信+邮件）通知，写明合同条款 | 正式 |
| **4 级** | 逾期 15 天 | 依据合同暂停服务 | 通知式 |

> **关键原则：越早开口越容易。**
>
> **到期前 5 天提醒，是"确认"；逾期 15 天再问，是"讨债"。同一句话，效果差十倍。**

## 3.2 五段话（复制到 `催款话术.md`）

**0 级 · 到期前 5 天：**

```text
X 总，提醒一下，按合同 11-30 是验收款的节点。
我这边材料都备好了（验收单 + 录屏），您看这周哪天方便安排人测一下？
```

**1 级 · 到期前 1 天：**

```text
X 总，明天是付款日，我确认一下财务那边流程走到哪了？
如果需要我提供发票或者别的材料，我现在就准备。
```

**2 级 · 逾期 3 天（打电话，说这几句）：**

```text
"X 总，我这边还没收到款，想确认一下是流程卡住了，还是有别的问题？
如果是流程问题，需要我做什么我配合。如果有不满意的地方，你直接说，我们对一下验收标准。"
```

**3 级 · 逾期 7 天（书面）：**

```text
X 总，关于 XX 项目的验收款（合同第四条第 2 款，¥6,600），
截至今天已逾期 7 天。附件是验收单和沟通记录。

麻烦在 3 个工作日内安排付款。如果确有困难，请告诉我一个明确的日期，
我们按新日期执行；如果对验收结果有异议，请书面列出具体条款，我逐条处理。
```

**4 级 · 逾期 15 天（依据合同暂停）：**

```text
X 总，按合同第十条，付款逾期超过 15 日，我方有权暂停服务。
从今天起我将暂停本项目的维护响应，已交付的系统仍可正常使用。

款项到账后我立即恢复服务。这不是我想走到的一步，
但我需要按合同执行。有困难随时打电话给我。
```

## 3.3 为什么"暂停服务"比"催"有效

| 只催 | 催 + 暂停 |
|---|---|
| 客户没有成本，可以一直拖 | 客户开始承担后果 |
| 你每次催都在消耗关系 | 你只通知一次，责任回到合同 |
| 你显得很急 | 你显得很专业 |

> **注意：暂停的是"服务"（维护、修改、支持），不是"系统"。**
>
> **把客户已经在用的系统关掉，可能构成违约，甚至违法。别干。**

# 第 4 步：垫款和现金流（15 分钟）

## 4.1 你必须准备的三个数

**在 `收款台账.md` 最上面加一节：**

```markdown
## 现金流底线

| 项 | 我的数字 |
|---|---|
| 每月固定支出（房租+吃饭+软件+社保） | ____ 元 |
| 手上现金 | ____ 元 |
| 能撑几个月 | ____ 个月 |
| 我最多能同时垫几个项目 | ____ 个 |
```

**"能撑几个月"低于 3，就不要接需要垫款的项目。**

## 4.2 三种减少垫款的办法

| 办法 | 怎么做 | 效果 |
|---|---|---|
| **提高定金** | 30% → 40-50% | 直接减少垫款 |
| **服务器/模型费客户付** | 提供清单，客户自己买 | 消灭两笔垫款 |
| **分期交付** | 拆成两期，第一期结清再做第二期 | 账期缩短一半 |

## 4.3 分期交付的写法

```text
第一期（¥8,000）：文档问答 + 登录，验收后付清
第二期（¥8,500）：后台管理 + 培训，验收后付清
```

**为什么这对双方都好：**

| 你的好处 | 客户的好处 |
|---|---|
| 每期都有回款 | 每期都能看到东西 |
| 客户中途跑只亏一期 | 风险也可控 |
| 现金流不会断 | 预算可以分两次批 |

# 第 5 步：把台账跑起来（10 分钟）

## 5.1 现在就填两行

**即使你现在没有项目，也把模板里的示例行改成你自己的真实情况（哪怕是"朋友的小单，3000 元"）。**

**台账跑起来的标志：**

| 标志 | 说明 |
|---|---|
| 你每周一会打开它 | 它成了习惯，不是作业 |
| 每行都有"下次跟进"的日期 | 没有日期的行等于死行 |
| 逾期行你能一眼看到 | 用 `**加粗**` 或者标"逾期" |

## 5.2 一个提醒设置

**在手机日历里设一个每周一 9:00 的重复提醒：**

```text
打开收款台账，处理逾期，发提醒。
```

> **收钱这件事，靠纪律，不靠记性。**

# 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 客户不肯付定金 | 你没说成"流程" | 换成"我们的流程是 30% 定金后开始排期" |
| 客户验收无限拖 | 合同没有"逾期视为通过" | 回到第 248 节课补上 |
| 不好意思催款 | 你把它当"求人" | 它是"提醒对方履行约定"，语气可以客气，动作不能软 |
| 客户说"财务在走流程" | 最常见的拖延话术 | 问"具体走到哪一步、预计哪天"，把模糊变具体 |
| 想直接关系统逼付款 | 违法风险 | 只暂停服务，不关系统 |
| 台账填了但从不看 | 没有固定节奏 | 设周一 9:00 的重复提醒 |
