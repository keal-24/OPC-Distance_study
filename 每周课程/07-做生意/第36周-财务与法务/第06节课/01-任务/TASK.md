# 第 0 步：三个最贵的问题（10 分钟）

## 0.1 客户最常提的三个要求

| 客户说 | 真实含义 | 你要加钱吗 |
|---|---|---|
| "交付源码" | 我要能自己改，或者换人维护 | 不加，但**绑定尾款** |
| "著作权归我们" | 我不能让你把这套东西卖给别人 | **要加**（30%-100%） |
| "你不能给别人做类似的" | 我要区域/行业独占 | **要加**，且要约定范围和期限 |

## 0.2 侵权的三种常见场景（都是无意的）

| 场景 | 后果 |
|---|---|
| 从 GitHub 抄了一段 GPL 代码进项目 | 客户被要求开源整个系统 |
| 用了设计师给的字体（商用未授权） | 被追索赔几万 |
| 图片从百度搜来直接用 | 图片公司批量维权，一张几千 |

> **这三种都不是"故意作恶"，是"没人告诉过你"。**
>
> **一次赔偿，可能吃掉三个项目的利润。**

# 第 1 步：代码归谁（25 分钟）

## 1.1 法律默认：归创作者

**你写的代码，著作权默认归你。** 客户付了钱，买的是"能用的系统"，不是"著作权"。

**但现实是：** 客户通常会在合同里写"著作权归甲方"。**你不提，默认就变成全给他。**

## 1.2 三种写法，三种价格

| 写法 | 含义 | 报价影响 |
|---|---|---|
| **A. 客户获独占，著作权归甲方** | 这套代码只能他用，你不能再卖 | **+50%~100%** |
| **B. 客户获使用权，你保留通用组件** | 他能用，你也能拿同样的底层做别的项目 | 标准价（**推荐**） |
| **C. 客户获使用权，你保留全部著作权** | 他只是"被授权使用" | 可能被压价 |

## 1.3 B 写法怎么落到合同里

**直接抄这段：**

```text
甲方付清全部款项后，取得本系统在【甲方及其关联公司内部】的
永久、非独占使用权，可用于自身经营活动。

乙方保留本系统及其底层通用组件（包括但不限于账号与权限模块、
文档解析与检索模块、后台管理框架）的著作权，有权在其他项目中
复用、修改和许可他人使用，但不得将甲方的业务数据、行业术语库、
定制化业务逻辑提供给甲方的直接竞争对手。

甲方不得将本系统转售、分发或对外提供 SaaS 服务。
```

**这段话做了五件事：**

| 条款 | 保护谁 |
|---|---|
| 甲方有永久使用权 | 客户放心 |
| 非独占 | 你能复用 |
| 保留通用组件著作权 | 你的核心资产 |
| 不提供给直接竞争对手 | 客户能接受（**这是关键的让步点**） |
| 甲方不得转售 | 你不会被白嫖成别人的产品 |

> **"不提供给你的直接竞争对手"这句话，是让客户点头的关键。**
>
> **他要的是"我的同行不能和我用一样的东西"，不是"你必须饿死"。**

## 1.4 客户坚持要 A（独占）怎么办

**别硬顶，加价。**

```text
"独占可以，价格要从 3 万到 4.5 万。
原因很直接：这套东西我只能卖你一次，我得把重复销售的机会算进去。"
```

**或者给一个折中：**

```text
"独占可以，但只限【这个行业 + 这个省】。其他行业和地区我保留权利。"
```

## 1.5 一个必须提前说的事：通用组件的复用

**你从第 8/9/10/13 周开始攒的那些模块（登录、权限、上传、检索），是你的资产。**

**如果每个项目都"著作权全给客户"，你干三年还是一个项目一个项目地从头做。**

> **一人公司能规模化，靠的就是"同一套底层，卖很多次"。**
>
> **放弃复用权 = 放弃规模化。**

# 第 2 步：软件著作权登记（30 分钟）

## 2.1 它有什么用

| 用途 | 说明 |
|---|---|
| **证明是你开发的** | 被抄时是直接证据 |
| 申请高新技术企业 | 需要知识产权 |
| 政府补贴 / 项目投标 | 有些要求软著数量 |
| 融资/合作时增加可信度 | 看得见的资产 |

## 2.2 成本和时间

| 项 | 情况 |
|---|---|
| 官费 | **免费**（中国版权保护中心已免收登记费） |
| 时间 | 常规 30 个工作日左右；有加急服务（收费） |
| 材料 | 全程线上提交 |
| 有效期 | 自然人：终生 + 50 年；法人：50 年 |

> **免费 + 线上 + 30 天。没有理由不申请。**

## 2.3 需要的材料（清单）

```markdown
# 软著申请材料清单

## 1. 申请表
- 软件全称（建议：XX产品参数智能问答系统 V1.0）
- 简称（可选）
- 版本号：V1.0
- 开发完成日期
- 首次发表日期（未发表选"未发表"）
- 开发方式：独立开发
- 权利取得方式：原始取得
- 权利范围：全部权利

## 2. 源程序
- 前 30 页 + 后 30 页（不足 60 页则全部提交）
- 每页 50 行以上
- 页眉写：软件名称 + 版本号 + 页码
- 去掉注释里的第三方版权信息（如果有）
- 不要出现明显的空行堆砌（会被要求补正）

## 3. 文档
- 用户手册 或 设计说明书（二选一）
- 前 30 页 + 后 30 页
- 要有截图、功能说明、运行环境
- 页眉同样写软件名称 + 版本号 + 页码

## 4. 身份证明
- 个人：身份证
- 个体户：营业执照 + 经营者身份证
- 公司：营业执照

## 5. 其他（视情况）
- 委托开发合同（如果是给别人做的，且约定著作权归你）
- 合作开发协议
```

## 2.4 三个最容易被打回的坑

| 坑 | 怎么避免 |
|---|---|
| **软件名称太泛**（"管理系统"） | 加行业和功能："XX机械产品参数智能问答系统" |
| **源码里有别人的版权头** | 提交前全局搜 `Copyright` `License`，把第三方文件的头去掉或剔除该文件 |
| **文档没截图** | 用户手册必须有界面截图，纯文字会被要求补正 |

> **软著审查不查"这代码是不是你写的"，只查材料是否合规。**
>
> **但一旦发生纠纷，"登记时间"就是你的时间证据。所以**做完就登记，别等出事。**

## 2.5 什么时候申请

| 时机 | 说明 |
|---|---|
| **每个交付项目验收后立刻申请** | 客户签了验收单，你就有"完成日期"的依据 |
| 自己的产品类项目 | 上线即申请 |
| 通用组件 | 可以合并成一个"XX开发框架"申请 |

**一年做 5 个项目，就有 5 个软著。三年 15 个，这是一份看得见的资产。**

# 第 3 步：商标（20 分钟）

## 3.1 什么时候该注册

| 情况 | 建议 |
|---|---|
| 只是接项目，没有品牌 | 不急 |
| 有自己的产品名 / 域名要做品牌 | **要注册** |
| 打算长期做、要投放 | 必须注册 |

**不注册的风险：**

```text
你把 qiancan.cc 做成品牌，两年后有人抢注了"千灿"商标，
他可以要求你停止使用，或者要你花钱买回去。
```

## 3.2 成本和周期

| 项 | 情况 |
|---|---|
| 官费 | 约 300 元/类（10 个商品/服务项目内），网上申请有优惠 |
| 代理费 | 500-1000 元/类（自己报可省） |
| 周期 | 6-12 个月（含初审公告 3 个月） |
| 有效期 | 10 年，可续展 |

**要注册几个类：**

| 类别 | 覆盖什么 | 建议 |
|---|---|---|
| 第 9 类 | 计算机软件、APP | **必选** |
| 第 42 类 | 软件开发、SaaS 服务 | **必选** |
| 第 35 类 | 广告、商业经营 | 做产品/平台时选 |

> **只注册一类，别人可以在另一类上用同样的名字。核心就 9 和 42。**

## 3.3 注册前必须查近似

**在中国商标网（sbj.cnipa.gov.cn）免费查。**

| 查什么 | 为什么 |
|---|---|
| 同名 | 有同名就换 |
| 读音相同 / 字形相似 | "千灿" vs "千璨" 也算近似 |
| 同类别下的近似 | 不同类别可以同名 |

> **自己查一遍，能省掉 80% 的驳回。** 驳回不退官费。

# 第 4 步：别踩别人的坑（开源协议 + 素材）（25 分钟）

## 4.1 开源协议速查（只用记这张表）

| 协议 | 你能商用吗 | 你能闭源交付吗 | 要注意什么 |
|---|---|---|---|
| **MIT** | 能 | **能** | 保留版权声明即可 |
| **Apache 2.0** | 能 | **能** | 保留声明 + NOTICE 文件；有专利授权条款 |
| **BSD** | 能 | **能** | 保留声明 |
| **LGPL** | 能 | 能（动态链接） | 修改了库本身要开源 |
| **GPL v2/v3** | 能 | **不能** | **传染**：链接了就得整个开源 |
| **AGPL** | 能 | **不能** | 更狠：**网络提供服务也算分发** |
| **无协议（NO LICENSE）** | **不能** | 不能 | 默认"保留所有权利"，用了就是侵权 |

**最危险的两类：**

| 类型 | 场景 |
|---|---|
| **GPL** | 你在项目里 `require` 了一个 GPL 库，客户要求闭源 → 你违约 |
| **无协议仓库** | GitHub 上一堆没写协议的代码，**不能直接用** |

> **GitHub 上没有 LICENSE 文件 = 你不能用。** 这是最多人不知道的一条。

## 4.2 给自己的项目加协议

**你自己的开源项目（作品集用）建议：**

| 目的 | 选 |
|---|---|
| 想让人随便用，包括商用 | **MIT** |
| 想让人用，但要保留专利授权 | **Apache 2.0** |
| 只是展示，不想让人商用 | 不加协议，或写"仅供参考" |

**做法：仓库根目录加一个 `LICENSE` 文件，内容直接抄 MIT 模板，改年份和名字。**

## 4.3 素材三个雷区

| 雷区 | 正确做法 |
|---|---|
| **图片**：百度搜来就用 | 用 Unsplash / Pexels / 自己截图；国内商用图库买授权 |
| **字体**：随便装个字体做 logo | 用**思源黑体 / 阿里巴巴普惠体**（免费商用），或买授权 |
| **图标**：从某站下载 | 用 Font Awesome Free / 字节跳动图标库（看清协议） |

**特别提醒：**

```text
"微软雅黑"不能商用（方正授权）。
"苹方"不能商用（苹果授权）。
"思源黑体"可以（SIL OFL）。
"阿里巴巴普惠体"可以（免费商用）。
```

> **字体侵权是国内维权最凶的一类。一张图、一个 logo，赔几千到几万。**

## 4.4 交付前 5 分钟扫一遍

```bash
# 在项目根目录搜第三方版权头
grep -rn "Copyright" --include="*.js" --include="*.ts" --include="*.css" .
grep -rni "license" --include="*.js" .
```

**搜出来的一律看一眼：是 MIT/Apache 就保留声明；是 GPL 就换掉或者告诉客户。**

## 5.2 让 AI 帮你查依赖协议（很实用）

**在项目根目录跑：**

```bash
npm ls --depth=0
```

**把结果贴给 AI：**

```text
下面是我项目的直接依赖列表。请帮我做三件事：
1. 标出哪些是 GPL / AGPL 类传染性协议（会导致我必须开源整个项目）；
2. 标出哪些协议不明或可能是"保留所有权利"；
3. 其余标"安全"。

输出一张表：包名 / 协议 / 风险等级 / 我要做什么。

（贴 npm ls 结果）
```

> **AI 在这件事上会答错（很多包的协议它记不住）。**
>
> **做法：它标"高风险"的，你去 npm 页面看 `license` 字段确认。它标"安全"的，抽查两个。**

# 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 客户合同里写"全部知识产权归甲方" | 你没提替代方案 | 主动给 B 写法，加"不提供给直接竞争对手" |
| 客户不愿加钱又要独占 | 他想白拿 | 给折中：限行业、限区域 |
| 软著被补正 | 源码页数不够 / 文档没截图 | 按清单补齐再提交 |
| 不确定某个库的协议 | 没看 LICENSE | 去 npm/GitHub 页面看 `license` 字段 |
| 客户要求开源（政府项目） | 有些项目有开放要求 | 提前说清：可以开源，但价格与排他条款要重谈 |
| 用了别人的图被找 | 从网上直接下载 | 立刻换掉 + 保留沟通记录，别拖 |
| 商标被驳回 | 没查近似 | 换名或换类别，官费不退 |
