# 03-练习代码

**这个文件夹故意留空。** 本节课你要把上一节的项目复制过来，再新建几个脚本：

```text
03-练习代码/
└── collector/            ← 从第02节课 xcopy 过来，node_modules 一起带过来
    ├── mock-server.js    上一节的，一行不改
    ├── node_modules/     里要有 express 和 cheerio
    ├── raw-list.html     你自己抓的原始页面（正常版）
    ├── raw-v2.html       你自己抓的原始页面（改版）
    ├── grab-html.js      抓 HTML 存文件
    ├── parse-manual.js   纯字符串截取
    ├── parse-cheerio.js  选择器 + 结构变化检查点
    └── selector-test.js  四种精度的选择器对比
```

## 为什么这些文件必须你自己敲

这一节有两个文件长得几乎一样（`parse-manual.js` 和 `parse-cheerio.js`），很多人会想"写一个就够了"。

**两个都要写，因为它们的差别不在结果，在"失败时的表现"：**

```text
手写版：v2 页面上"抓到 0 条"，退出码 0 —— 安静地失败
选择器版：v2 页面上"抓到 0 条"，退出码 1  —— 大声地失败
```

只写一个，你不会真正体会"静默失败"有多危险。而第 77 节做定时任务时，这个体会直接决定你会不会写运行记录。

`raw-v2.html` 也必须自己抓。**它是你唯一能复现"对方改版"的道具**，不是课件里的截图。

## 怎么建（一步步）

1. 打开 `第03节课\03-练习代码`，地址栏输入 `cmd` 回车；
2. `xcopy /E /I /Y "..\第02节课\03-练习代码\collector" collector`；
3. `cd collector`，`del` 掉上一节用不到的六个脚本；
4. 确认 mock-server 在跑（另一个窗口），然后 `curl.exe ... -o raw-list.html` 和 `-o raw-v2.html`；
5. 写 `grab-html.js`，跑一次，看它打印的 HTML 长度是不是 1339 左右；
6. 写 `parse-manual.js`，在 v1 上跑通，再把文件名换成 v2 跑一次；
7. `npm install cheerio`，写 `parse-cheerio.js`，先不带检查点跑通，再加检查点；
8. 写 `selector-test.js`，把四种选择器的条数填进笔记第五节。

## 检验自己有没有真学会

做完后，不看课件回答：

- 你在浏览器里按 `Ctrl+U` 看到的内容，和 `fetch` 拿到的，是同一个东西吗？为什么这个区别重要？
- 为什么 `parse-manual.js` 在 v2 上"成功"返回了 0 条，而不是抛错？这是好设计还是坏设计？
- `#list tbody tr` 抓 10 个、`tr` 抓 11 个，多的那一个是什么？
- 如果对方把 `<td class="price">` 改成 `<td class="cost">`，你的程序会报什么？**会不会报？**
- 你的检查点里 `EXPECTED_MIN = 5` 是怎么定出来的？如果抓的是搜索结果页，这个值还能用吗？
- 为什么退出码必须是 1 而不是打印一句"失败"就完事？
