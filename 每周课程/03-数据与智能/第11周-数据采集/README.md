# 第11周 · 数据采集 · 第71—77节课

## 数据不会自己走进数据库

---

## 这一周的目标

这一周不是"学爬虫"，是学会**对一份数据需求做出判断，并把判断执行到底**。七节课结束时，你要能做到这五件事：

1. **判断一个数据需求该走哪条路** —— 官方 API、静态页面、浏览器自动化、现成数据集，先选对再动手；
2. **用原生 `fetch` 把一个公开接口读干净** —— 状态码、限流、超时、返回 HTML 报错页，四种情况都能处理；
3. **从 HTML 里稳定抽出字段** —— 并用一个检查点，在对方改版的第一时间知道；
4. **把一批数据完整抓下来并洗干净** —— 分页抓全、断点续抓、字段清洗、增量更新，一条不漏一条不重；
5. **把采集做成有记录的定时任务** —— 每次跑完留一行运行记录，失败能看出失败在第几步。

---

## 为什么排在这一周

前十周，你手上的所有数据都是**别人手动给你的**：用户填的表单、用户上传的图片、你自己写死的几条种子数据。

这就是问题所在。

第 13 周要做检索（RAG）。检索的上限不是你算法写得多好，是**你手上有什么料**。拿三篇自己编的假文档做 RAG，能跑通，但一上真实场景就废：

| 你以为是检索的问题 | 实际是数据的问题 |
|---|---|
| 搜"报销"搜不到"费用核销" | 你的语料里根本没收录那篇制度 |
| 答出来的数字是错的 | 语料里那份表格在采集时丢了列 |
| 同一个问题两个答案 | 同一份文件被采集了两次，内容还不一样 |
| 检索结果里全是页脚和广告 | 采集时没清洗，导航文字全进了库 |

**这四件事全部发生在采集环节，不是检索环节。**

所以顺序必须是：先有干净数据（W11），再能读各种文档（W12），最后才是切分检索（W13）。

**不学这一周的后果很具体：** 第 13 周你会花两天调检索参数，最后发现是数据里有一半是重复行。

## 这一周的一个特殊安排

**这一周全程不碰任何第三方网站。**

七节课所有的抓取对象，都是你自己第 72 节课写的一个本地服务 `mock-server`，跑在 `http://localhost:3001`。

理由有三个，都是实打实的：

```text
一、真实网站会改版。今天课上能跑的代码，下周你复习时可能就抓不到了，
    而你会以为是自己的代码错了。

二、真实网站会封你。练分页要连续请求十几次，练限流要故意打快，
    拿真站练等于拿自己的 IP 交学费。

三、真实网站的数据有版权。你不需要为了练习去碰别人的数据。
```

**mock-server 提供的六个坑，和真实站点一模一样：**

| 端点 | 模拟什么 |
|---|---|
| `/api/items?page=1&size=10` | 正常的分页接口（共 3 页） |
| `/api/items?page=999` | 翻过头，返回空数组 |
| `/api/dirty` | 脏数据：全角空格、`¥1,299.00`、三种日期格式、缺字段 |
| `/api/limit` | 连着请求，第 3 次返回 `429` |
| `/api/html-error` | 500 的时候返回一张 HTML 错误页（`res.json()` 会炸） |
| `/slow` | 故意拖 5 秒（测超时） |

第 72 节课最后一节会讲清"换成真实站点要改哪三行"。

## 这一周最容易卡住的六个地方

### 一、`EADDRINUSE: address already in use :::3001`

**原因：** 上一次的 mock-server 还在跑，你没关。Windows 上一个端口只能被一个程序占用。

**解法：** 回到那个终端按 `Ctrl + C`；找不到那个终端就 `netstat -ano | findstr :3001` 查到 PID，再 `taskkill /PID <PID> /F`。

### 二、`SyntaxError: Unexpected token '<', "<!DOCTYPE "... is not valid JSON`

**原因：** 你以为对方返回 JSON，其实返回的是一张 HTML 错误页。`res.json()` 直接拿 HTML 去解析，必炸。

**解法：** 先看 `res.headers.get("content-type")` 里有没有 `application/json`，再决定要不要 `.json()`。

### 三、分页循环停不下来，或者少抓最后一页

**原因：** 终止条件只写了一个，而且写错了位置 —— `page += 1` 放在 `continue` 后面，或者只看 `has_next` 不看空数组。

**解法：** 同时用两个信号（空数组 + `has_next`），再加一个 `page > 100` 的硬上限兜底。

### 四、选择器写得好好的，对方一改版全部抓空

**原因：** 选择器写到了第 4 层（`div > div:nth-child(2) > table > tbody > tr > td:nth-child(3)`），任何一个外层 div 变了就全崩。

**解法：** 选择器只锚定最稳的那一层（`#list tbody tr`），并且每次都统计"抓到几条、字段空了几条"，空了就报警。

### 五、第二次抓，30 条全部算"新增"

**原因：** 表里没有唯一键，或者用了 `INSERT OR REPLACE`，每次跑都是 30 条新行。

**解法：** 业务主键（源站的 `id`）做 `PRIMARY KEY`，用 `ON CONFLICT ... DO UPDATE`，并且先用 `content_hash` 判断内容有没有变。

### 六、`node cron.js` 一关终端就停了

**原因：** `node-cron` 是"在这个进程里定时"，进程死了定时就没了。它不管进程活不活。

**解法：** 开发用 `node-cron` 图方便；要"电脑重启也照样跑"，用 Windows 任务计划去拉起这个脚本。

## 这一周的四条铁律

```text
一、先找 API，再抓页面，最后才自动化。
    顺序反了，你会用两天写一个本来 20 行就能搞定的事。

二、不进登录态，不抓个人信息，请求间隔不低于 1 秒。
    这三条不是建议，是不做的理由。

三、原始数据永远保留一份，清洗只能新增文件，不能覆盖。
    洗错了还能重洗，覆盖了就只能重新抓。

四、每次抓都写一条运行记录。
    没有记录的采集，出问题时你连"昨天跑没跑"都说不清。
```

## 周末的验收

```text
- [ ] 我能对三个不同的数据需求，说出该走哪条路，并说出理由
- [ ] 我能说出 robots.txt 里的 Disallow 是什么意思，以及它是不是法律
- [ ] 我的 mock-server 能起来，六个端点我都亲手请求过
- [ ] 我处理过 429 和超时，两种都在终端里看到过真实报错
- [ ] 我用 cheerio 抽出了 10 条记录，并且故意改坏选择器看到过"抓空"
- [ ] 我用三种分页方式各抓了一遍，抓到的条数一样
- [ ] 我洗过 /api/dirty，能把 "¥1,299.00" 变成 1299，把空字符串变成 null
- [ ] 我第二次跑采集时，新增是 0，改动 /api/change 之后更新是 1
- [ ] 我能 `SELECT` 出 runs 表最近五次运行，看出哪次失败了、失败在第几步
```

> **第 74 节和第 76 节不能落。**
>
> 第 74 节（分页）落了，你只会抓第一页，永远只有 10 条数据 —— 而你自己不会觉得有问题，因为程序"跑通了"。

> 第 76 节（去重增量）落了，你的库会被同一批数据灌成几十份副本，第 13 周检索时排在前面的全是重复内容。

## 这一周不用学什么

明确划掉，别在这上面花时间：

```text
Scrapy / puppeteer / playwright     本课程不用，原生 fetch + cheerio 够用
代理池、IP 轮换                      那是另一个行业的工具
验证码识别                           不学，也不做
浏览器指纹伪装                       不学，也不做
分布式爬虫、消息队列                 第 6 阶段（上线运维）讲调度时才提
反爬对抗                             永远不学。对方不让你抓，正确答案是换数据源
XPath                                cheerio 用法和 CSS 选择器一样，够用
```

**关于"反爬对抗"多说一句：** 这门课教你的是"合法地拿到公开数据"，不是"绕过别人的限制"。这两件事的技术栈看起来像，立场完全相反。你把频率压到 1 秒 1 次、遵守 robots.txt、不碰登录态，就不需要任何对抗技术。

## 下一步

第 12 周：**文档解析**。

这一周你抓到的是**结构化的 JSON 和 HTML** —— 字段对字段，好处理。
