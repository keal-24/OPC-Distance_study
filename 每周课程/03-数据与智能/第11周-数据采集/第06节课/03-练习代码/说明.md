## 为什么这些文件必须你自己敲

`upsert.js` 里那三个 `Prepare`（`selectBySourceId` / `insertStmt` / `updateStmt`）你抄一遍不会觉得有什么，但抄的过程中你会看到：

- `@source` 这种命名参数和 `?` 位置参数的差别；
- `UPDATE` 的 `WHERE` 里为什么必须同时带 `source` 和 `source_id`（只带 `source_id` 会误伤别的源）；
- `touchStmt` 为什么要单独写一个（因为内容没变时不该重写所有字段）。

**这三件事，抄不出来，只能敲错一遍才看见。**

## 怎么建

1. `cd` 到本节课的 `03-练习代码\`；
2. `xcopy /E /I /Y "..\第05节课\03-练习代码\collector" collector`；
3. `cd collector`，`npm install better-sqlite3`；
4. 按课件顺序建文件，一个一个跑，**每跑一个都核对屏幕输出**；
5. 先在另一个终端 `node mock-server.js` 起好服务，再跑 `change.js` / `refetch.js`。

**顺序不能乱：** `db.js` → `check-schema.js` → `upsert.js`（首跑）→ `upsert.js`（重跑）→ `change.js` + `refetch.js` + `upsert.js`（第三跑）。**顺序错了你分不清"哪个数字不对是因为哪一步"。**

## 检验自己有没有真学会

做完后，**不看课件**回答：

1. 如果不加 `UNIQUE (source, source_id)`，`ON CONFLICT DO UPDATE` 会怎样？为什么？
2. 你的 `contentHash` 里现在有几个字段？如果明天数据源多了一个 `stock` 字段，你会怎么迁移？
3. 原样重跑十遍，`updated_at` 会变十次。这算不算"脏数据"？为什么？
4. 如果源站删掉了一个商品，你的库不会知道。你会用软删除还是硬删除？说出你的业务理由。
5. `wrong-tx.js` 里"剩 4 条"和"剩 0 条"，哪一种情况更难在事后发现？为什么？
6. 你的采集脚本第一次部署到服务器，跑了三个月，某天客户说"价格不对"。你会按什么顺序排查？

**第 6 个问题是真正的验收。** 前五个是知识，第六个是能力。
