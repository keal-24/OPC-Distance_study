# 第 0 步：为什么要有这一步（10 分钟）

## 0.1 你现在会什么

到第 70 节课为止，你手上的数据全部是**别人给你的**：用户在表单里填的、点上传传的、你自己 `INSERT` 进去的几条演示数据。

**你从来没做过"主动去别人的服务器上把数据拿回来"。**

这件事的难点不在代码 —— `fetch` 你第 3 周就会了，五行就能取到一个 URL 的内容。难点在**选择**：

```text
这个数据该从哪拿？拿了算不算违规？拿回来能不能用？
拿不到的时候，是我代码错了，还是对方本来就不让拿？
```

四个问题里只有一个和代码有关。

## 0.2 今天这个坑长什么样

> 做 HR 的朋友找你："我们想分析本地互联网公司的薪资。能不能把某招聘网站 5 万个岗位抓下来？岗位名、公司、薪资、学历，就这四列。"

大多数人的第一反应是打开编辑器写爬虫。**这个反应是错的。**

有四样东西会在你写完两小时后拦住你：

| 拦住你的 | 具体表现 |
|---|---|
| 登录态 | 不登录只能看前 3 页，第 4 页要求登录 |
| 个人信息 | 岗位详情页里带 HR 的姓名和手机号 |
| 服务条款 | 注册协议写着"禁止使用任何自动化程序获取本站数据" |
| 频率限制 | 同一 IP 一分钟超 20 次就 `403`，再继续封 24 小时 |

**这四件没有一件是技术问题。** 但你写代码前不知道，跑完被封了才知道。

## 0.3 今天的三个概念

| 术语 | 一句话人话 | 今天在哪用 |
|---|---|---|
| API（Application Programming Interface，应用程序接口） | 对方**主动开给你**的取数窗口，按约定格式返回数据 | 第 1 步四条路之一，优先级高 |
| robots.txt | 网站根目录下的纯文本，写着"哪些路径不希望被自动程序访问" | 第 4 步，判断对方允不允许 |
| 请求频率（rate limit） | 单位时间内你能请求几次，超了就被拒 | 第 4 步，硬标准 1 秒 1 次以内 |

**补一个词：登录态（login state）** —— 指"带着你的账号 cookie 去请求"。这一周所有代码都不带登录态。

## 0.4 今天的交付物

| 文件 | 位置 | 内容 |
|---|---|---|
| `数据来源判断表.md` | `第01节课/03-练习代码/` | 四条路对比 + 判断顺序 + 合规五问 + 三个需求结论 |
| `decide.js` | 同上 | 把判断顺序写成函数 |
| `NOTES.md` | `第01节课/02-笔记/` | 第 7 步填 |

**这一节不写任何抓取代码。** 90 分钟全部用来把"该不该抓、从哪抓"想清楚。省下的时间会在第 74、77 节加倍还给你。

# 第 1 步：把四条路摆到桌上（20 分钟）

## 1.1 做什么 / 为什么

**做什么：** 建 `数据来源判断表.md`，把四条路的识别信号、成本、风险写清楚。

**为什么：** 因为这四条路的成本差 10 倍以上。大部分人只熟悉第三条（浏览器自动化），因为它最"像爬虫"；但它是四条路里最贵、最脆、最容易违规的一条。

| 路 | 是什么 | 长什么样 |
|---|---|---|
| 一、官方 API | 对方给你一个 URL，返回 JSON | `https://api.example.com/v1/items?page=1` |
| 二、静态 HTML | 数据已写在网页源码里，下载 HTML 再切字符串 | 右键"查看网页源代码"能看到商品名 |
| 三、浏览器自动化 | 要浏览器执行 JS 之后数据才出现，得开真浏览器去点 | 源码里只有 `<div id="app"></div>` |
| 四、现成数据集 | 别人整理好，打包成 CSV / JSON 供下载 | 政府开放数据平台、数据集的下载页 |

```markdown
|---|---|---|---|---|---|

```

**4. 填"怎么判断"这一列**，用你自己的话，但信号必须是这四个：

| 路 | 判断信号 |
|---|---|
| 官方 API | 站上有"开发者 / 开放平台 / API 文档"入口；或 F12 → Network → Fetch/XHR 里，页面数据来自一个返回 JSON 的地址 |

| 路 | 成本（到能稳定跑起来） |
|---|---|

| 现成数据集 | 0.5 小时（下载、看字段、导入） |

**为什么必须写小时：** "成本高"不会改变你的决定，"10 小时"会 —— 你只有一个人，10 小时是一天半。

# 第 2 步：定判断顺序（15 分钟）

## 2.1 做什么 / 为什么

**做什么：** 把四条路排成一个**固定的**检查顺序，写进判断表。

**为什么固定：** 人着急时会跳步。你会因为"我记得那个站有 API"就直接写调用，结果那个 API 只能查单条、不能列表 —— 白干两小时。固定顺序的作用是：**每次从最便宜的试起，试不通再往下走一格。**

```text
第 0 格：有现成数据集吗？       有 → 直接用，结束
第 1 格：有官方 API 吗？        有 → 用 API，结束
第 2 格：数据在 HTML 源码里吗？ 在 → 抓 HTML，结束
第 3 格：只能靠 JS 渲染吗？     是 → 自动化，但先算账
第 4 格：四格都不成立          → 换数据源
```

**为什么"现成数据集"排第 0，而规范说"先找 API"：** 因为数据集是**唯一一条零风险的路** —— 已脱敏、已整理、已允许下载。规范说的"先 API 再页面最后自动化"是**"抓"内部的顺序**；数据集不属于"抓"，它是"取"。有得取，就不要抓。

## 2.2 操作

把下面这节写进判断表：

```markdown
## 二、判断顺序

| 顺序 | 检查项 | 通过就停 | 判断要花多久 |
|---|---|---|---|
| 0 | 有没有现成数据集 | 下载导入，结束 | 10 分钟 |
| 1 | 有没有官方 API | 读文档申请，结束 | 30 分钟 |
| 2 | 数据在不在 HTML 里 | 写选择器，结束 | 5 分钟 |
| 3 | 是不是只能靠 JS | 上自动化（先估 10 小时） | 先算账 |
| 4 | 都不成立 | 换数据源 | 立刻停 |
```

**盯住第 2 格的"5 分钟"和第 3 格的"10 小时"。** 这个对比就是这一节全部的意义：花 5 分钟确认一下，能省掉 10 小时。

## 2.3 屏幕上应该看到什么

判断表里出现上面那张五行的表，且"判断要花多久"一列有具体数字，不是"很快"。

## 2.4 如果不是这样

**你会犯的具体错误：** 把第 1 格和第 2 格调换 —— 先看源码再找 API。

**后果：** 你在源码里看到数据，写三小时选择器；三个月后发现这个站有官方 API，字段多一倍还有更新时间。

**规则：API 永远在 HTML 前面。** 因为 API 是对方"设计给人用"的，改版会通知；HTML 是"设计给浏览器看"的，改版不通知。

# 第 3 步：把顺序写成代码（25 分钟）

## 3.1 做什么 / 为什么

**做什么：** 写 `decide.js`：输入一个需求的七个特征，输出"该走哪条路 + 理由"。

**为什么要把判断写成代码：** 因为写代码会强迫你把例外想全。脑子里想的时候你会自动跳过"如果这数据里有手机号呢"；写代码时必须给它一个分支，写的时候就会逼自己想清"那到底判成什么"。

## 3.2 操作

在 `03-练习代码` 新建 `decide.js`，自己敲：

```javascript
// decide.js —— 把"先 API，再页面，最后自动化"写成代码
// 用法：node decide.js

const ROUTES = {
  DATASET: "现成数据集",
  API: "官方 API",
  HTML: "静态 HTML",
  BROWSER: "浏览器自动化",
  NO: "不做",
};

function decide(input) {
  // 三条硬红线，一条成立就否决
  if (input.needsLogin === true) {
    return { route: ROUTES.NO, reasons: ["数据要登录才看得到：不做登录态爬取"] };
  }
  if (input.hasPersonalInfo === true) {
    return { route: ROUTES.NO, reasons: ["数据里含个人信息：不抓"] };
  }
  if (input.termsForbid === true) {
    return { route: ROUTES.NO, reasons: ["服务条款禁止自动抓取：不做"] };
  }

  if (input.datasetAvailable === true) {
    return { route: ROUTES.DATASET, reasons: ["有现成数据集：成本最低、风险最低"] };
  }
  if (input.hasOfficialApi === true) {
    return { route: ROUTES.API, reasons: ["有官方 API：稳定、有字段说明、改版会通知"] };
  }
  if (input.dataInHtml === true) {
    return { route: ROUTES.HTML, reasons: ["数据在 HTML 源码里：选择器能抽，但要防改版"] };
  }
  if (input.needsJsRender === true) {
    return { route: ROUTES.BROWSER, reasons: ["数据要执行 JS 才出现：先估 10 小时成本，再决定"] };
  }
  return { route: ROUTES.NO, reasons: ["四条路都不成立：换数据源"] };
}

const CASES = [
  {
    name: "政府网站的补贴政策文件",
    input: { datasetAvailable: false, hasOfficialApi: true, dataInHtml: true, needsJsRender: false, needsLogin: false, hasPersonalInfo: false, termsForbid: false },
  },
  {
    name: "招聘网站的岗位与薪资",
    input: { datasetAvailable: false, hasOfficialApi: false, dataInHtml: false, needsJsRender: true, needsLogin: true, hasPersonalInfo: true, termsForbid: true },
  },
  {
    name: "电商平台的商品价格监控",
    input: { datasetAvailable: false, hasOfficialApi: false, dataInHtml: false, needsJsRender: true, needsLogin: false, hasPersonalInfo: false, termsForbid: true },
  },
  {
    name: "全国行政区划代码",
    input: { datasetAvailable: true, hasOfficialApi: true, dataInHtml: false, needsJsRender: false, needsLogin: false, hasPersonalInfo: false, termsForbid: false },
  },
];

console.log("=== 数据来源判断 ===");
for (const c of CASES) {
  const result = decide(c.input);
  console.log("");
  console.log(c.name);
  console.log("  路径：" + result.route);
  for (const r of result.reasons) {
    console.log("  理由：" + r);
  }
}
```

跑它：

```text
node decide.js
```

```text
政府网站的补贴政策文件
  路径：官方 API
  理由：有官方 API：稳定、有字段说明、改版会通知
```

# 第 4 步：划法律边界（20 分钟）

## 4.1 做什么 / 为什么

**做什么：** 把五件事搞清楚，在判断表里写"合规五问"。

**先说态度：** 这门课不教你绕过限制。你要建立的是**"什么情况下正确答案是不做"**的判断力。这不是道德说教，是成本核算 —— 你一个人做项目，被封 IP、收律师函、被平台下架，代价远大于换个数据源。

## 4.2 操作

### 一、robots.txt

地址固定是 `网站域名/robots.txt`。格式示例（不是某个具体站的内容）：

```text
User-agent: *
Disallow: /admin/
Disallow: /search
Allow: /article/
Crawl-delay: 1

User-agent: BadBot
Disallow: /

Sitemap: https://example.com/sitemap.xml
```

| 行 | 意思 |
|---|---|
| `User-agent: *` | 下面规则对"所有自动程序"生效 |
| `Disallow: /admin/` | 不希望被抓的路径前缀 |
| `Disallow: /search` | 搜索结果页不要抓 —— 它由参数动态生成，一个人能造出无限 URL，抓它等于无限翻页 |
| `Allow: /article/` | 在禁止的大范围里开口子 |
| `Crawl-delay: 1` | 建议请求间隔 1 秒 |
| `User-agent: BadBot` + `Disallow: /` | 针对特定程序：全站别抓 |
| `Sitemap:` | 站点地图 |

**三点必须分清：**

1. `Disallow: /` **不代表技术上做不到**，代表"主人明确说了不希望你来"。硬去，技术上做得到，但争议里会被当作"明知故犯"。
2. **robots.txt 不是法律**，是 1994 年提出、后来成为事实标准的行业惯例。违反它本身不违法，但它是判断"你是否善意"的关键证据。
3. **允许抓 ≠ 可以随便用。** robots 是"进门许可"，能不能复制转载是另一件事。

### 二、请求频率

**硬标准：1 秒 1 次以内。**

| 频率 | 你的感受 | 对方服务器的感受 |
|---|---|---|
| 10 次/秒 | "一分钟就抓完" | 相当于 10 个真人同时刷，落在"疑似攻击"区间 |
| 1 次/秒 | "1000 条要 17 分钟" | 相当于一个很有耐心的读者，绝大多数站能接受 |
| 1 次/10 秒 | "太慢" | 完全无感，但你自己受不了 |

**算一笔账：**

```text
抓 5000 条：1 秒 1 次 → 83 分钟；0.1 秒 1 次 → 8 分钟。
省 75 分钟。代价：对方运维看日志把你封了，重新找 IP、重测、重跑，损失 3 小时起。
```

**省 75 分钟赌 3 小时，不划算。** 更麻烦的是软封禁：很多平台封了不告诉你，直接返回空数据。你会以为"这站只有 200 条"，其实是被限了。

### 三、个人信息

能单独或组合起来**定位到某个具体自然人**的信息，一律不抓：

```text
真实姓名、手机号、固定电话、身份证号、护照号
家庭住址、具体工作地址、个人邮箱、微信号 / QQ 号
能识别人脸的照片、行踪轨迹、打卡位置
健康、金融账户、犯罪记录
```

**两个最容易漏的：**

| 容易漏 | 为什么算 |
|---|---|
| 招聘信息里的"联系人：张经理 138xxxx" | 手机号能定位到具体人 |
| 公示文件里的作者邮箱 | 公示的目的是"可查证"，不是"可批量收集" |

**判断方法：问自己"这条数据能不能让我找到具体某个人"，能，就不抓。**

**"公开可见"不等于"可以收集"。** 手机号写在公开网页上，你看到不违法；抄进数据库批量存起来，性质就变了。

### 四、著作权

| 你在做什么 | 性质 |
|---|---|
| 抓下来自己看、自己做分析、不对外 | 风险低 |
| 抓下来原样转载到自己网站 | 高风险，这是复制发行 |
| 抓下来喂给模型做检索，用户能看到原文片段 | 中风险，取决于怎么展示 |

**这一周只做第一层。** 两条操作规矩：

```text
一、不整站复制。抓你要的字段，不抓整页 HTML 存档。
二、每条记录存一个 url 字段，指向原始页面。
```

第二条不只是合规，也是为了你自己能查 —— 第 76 节去重时 `url` 就是三个依据之一。

### 五、服务条款

**这是最容易被忽略、又最容易被追究的一条。** 服务条款是合同：注册点"同意"就成立，条款写"禁止自动化获取"，你去抓就是违约 —— 不需要证明你造成了损失。

常见的三种表述（意思一样）：

```text
"禁止使用任何机器人、蜘蛛、爬虫或其他自动化手段获取本站内容"
"未经书面许可，不得对本服务任何一部分进行复制、镜像、抓取"
"不得使用自动化脚本批量访问、下载或存储本站数据"
```

**看到任何一种，结论就是不做。** 不用论证"我抓 100 条算不算批量" —— "算不算"由对方律师定义。

## 4.3 屏幕上应该看到什么

判断表里出现：

```text
## 三、合规五问（任何一条不过，结论就是不做）

| 问 | 判断依据 | 我的结论 |
|---|---|---|
| 1. robots.txt 允许吗 | 看 网站/robots.txt 里 Disallow 的路径 | 允许抓列表页，不许抓 /search |
| 2. 频率压到 1 秒 1 次以内了吗 | 代码里有没有等 1000 毫秒 | 有 |
| 3. 有没有个人信息 | 字段清单里有没有姓名/手机/身份证/邮箱 | 没有，只有岗位名、公司、薪资区间、学历 |
| 4. 会不会整站复制 | 只取需要的字段，不存整页 | 只存 4 个字段 + url |
| 5. 条款禁止吗 | 协议里搜"爬虫/自动化/抓取/机器人" | 没有相关表述 |
```

**看第 3 行：** 不写"没有个人信息"，写"没有，只有哪四个字段"。**模糊的结论等于没做判断。**

## 4.4 如果不是这样

# 第 6 步：故意犯四个错（15 分钟）

## 错误 1：先写代码，再想数据在哪

**现象：** 花两小时写了浏览器自动化脚本，跑起来发现目标站要登录才能看第 4 页，而你需要的 5000 条在第 200 页以后。

**原因：** 把"最容易想到的"当成"默认的"。自动化最像爬虫，所以最先被想起，但它该排最后。

**怎么查：** 动手前问三句 —— 有没有开放平台？view-source 能不能搜到字段？F12 的 XHR 里有没有返回 JSON 的请求？第三问答案是"有"，就走 API，不是自动化。

## 错误 2：把 robots.txt 当成两种极端

**现象 A：** 看到 `Disallow: /search` 就以为连 `/article/` 也不能抓，项目卡死。
**现象 B：** 心想"robots 又不是法律"，把整站连 `/search` 一起抓。

**原因：** 把它当法律或废纸。它两个都不是，是**对方表达的意愿**。

**怎么查：** 看 `Disallow` 的具体路径 —— 禁 `/search` 是因为搜索页能生成无限 URL，抓列表页（`/article/`）没问题。**判据：禁止的全不抓；没禁止的可抓，但仍要过频率、个人信息、条款三关。**

## 错误 3：不留间隔，一口气打 1000 次

**现象：** 前 20 次正常，第 21 次开始 `403`，再跑 10 次连接被重置：

```text
FetchError: request to https://example.com/api/items failed, reason: read ECONNRESET
```

**原因：** 请求速率超过对方阈值，而阈值多半按"每秒次数"算，不是按总次数。

**怎么查：** ① 代码里两次请求之间有没有 `await sleep(1000)`；② 响应头里有没有 `Retry-After`；③ 是不是"前 N 条正常，之后全空" —— 这是软封禁。

**反直觉的事实：** 软封禁比硬封禁常见。**你的代码会"正常跑完"，只是抓到 0 条。** 所以第 74 节必须校验"抓到的条数"，不能只看"没报错"。

## 错误 4：把"公开可见"当成"可以随便用"

**现象：** 把某平台 5 万条商品标题价格存库，做成对外比价工具。三个月后收到通知要求下线。

**原因：** 你的判断标准是"我能不能看到"，而不是"我能不能复制存储"。

**怎么查：** 对号入座：

| 你在做什么 | 判断 |
|---|---|
| 自己看 | 风险低 |
| 内部统计，不对外 | 风险低，但不对外发布原始数据 |
| 存库对外提供搜索 | 中到高风险 |
| 原样转载 | 高风险 |
| 卖给客户 | 最高 |

# 附：常见问题速查

| 现象 | 先查什么 | 怎么办 |
|---|---|---|
| 不知道一个站有没有 API | 搜"站点名 + 开放平台"，再看 F12 → Network | 有返回 JSON 的请求就按 API 处理 |
| view-source 搜不到字段 | 数据是 JS 渲染的 | 先追 XHR；追不到再考虑自动化，先算 10 小时成本 |
| robots.txt 404 | 这站没写 | 没有明确禁止，但仍过第 2—5 问 |
| robots.txt 里 `Disallow: /` | 全站不希望被抓 | 不做，换数据源 |
| 条款看不懂 | Ctrl+F 搜四个词 | 看不懂按禁止处理 |
| `node decide.js` 没输出 | 文件没 `console.log` 或文件名不对 | `dir` 确认，`type decide.js` 看内容 |
| 中文乱码 | 代码页问题 | `chcp 65001` |
| 抓 500 条后全是空 | 软封禁 | 加 1 秒间隔隔段时间重试，不要加快 |
| 判断表不渲染 | 缺 `|---|` | 补分隔行 |
