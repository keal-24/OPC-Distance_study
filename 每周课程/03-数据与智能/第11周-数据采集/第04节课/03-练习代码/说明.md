# 03-练习代码

**这个文件夹故意留空。** 本节课你要把上一节的项目复制过来，只新建一个脚本和一个状态文件：

```text
03-练习代码/
└── collector/            ← 从第03节课 xcopy 过来
    ├── mock-server.js    一行不改
    ├── node_modules/
    ├── fetch-pages.js    三种分页 + 终止条件 + 断点续抓
    ├── state.json        程序自己写的，不要手改
    └── items-paged.json  程序自己写的，30 条
```

## 为什么这些文件必须你自己敲

`fetch-pages.js` 里的三个循环长得几乎一样，很多人会复制粘贴改两个词。

**但这一节要练的不是"写三个循环"，是"给每个循环定一个终止条件"。** 复制粘贴会让你跳过这个思考：三个函数的终止判断其实是三种不同的东西 ——

```text
page：  has_next === false  +  空数组  +  页码上限
offset：data.length < limit +  空数组  +  偏移上限
cursor：next_cursor === null +  空数组  +  轮数上限
```

**`state.json` 也必须由程序自己生成**，不要手写。手写的状态文件会让你跳过"什么时候写"这个问题，而"抓完一页就写"才是断点续抓的关键。

## 怎么建（一步步）

1. 打开 `第04节课\03-练习代码`，地址栏输入 `cmd` 回车；
2. `xcopy /E /I /Y "..\第03节课\03-练习代码\collector" collector`；
3. `cd collector`，`del` 掉上一节的 HTML 相关文件；
4. 确认 mock-server 在跑；先 `curl.exe -s` 把三种端点各请求一次，看清返回结构；
5. 写 `fetch-pages.js`，先只写 `byPage`，跑通看到 30 条；
6. 加 `byOffset`，跑；再加 `byCursor`，跑；确认三种 id 序列一致；
7. 加 `loadState` / `saveState`，重跑一次，看 `state.json` 变成 `done: true`；
8. 删掉 `state.json`，在第 2 页抓完时按 `Ctrl + C`，再跑一次，看它从第 3 页续上。

## 检验自己有没有真学会

做完后，不看课件回答：

- 你的循环里，哪一个判断是"主判据"？为什么它比 `has_next` 更可信？
- 如果对方的 `has_next` 永远是 `true`，你的程序会在什么时候停？停的时候数据对不对？
- `offset` 分页为什么必然比 `page` 分页多请求一次？这次请求值不值？
- 你能举一个"数据在抓取过程中被删掉一条，offset 就漏一条"的例子吗？cursor 为什么不会？
- 你的 `state.json` 里 `next_page` 和"最后抓的那一页"差几？
- 如果 `state.json` 被 Ctrl+C 写成了半截 JSON，你的程序会抛什么错？你打算怎么防？
