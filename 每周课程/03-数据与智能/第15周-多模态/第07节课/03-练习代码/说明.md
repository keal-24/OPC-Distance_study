## 为什么这些文件必须你自己敲

`lib\session.js` 里 `recentMessages` 那三行（`ORDER BY id DESC LIMIT ?` + `.reverse()`），抄一遍看不出问题。但你自己敲完、**把 `.reverse()` 删掉**再跑 `probe-session.js`，你会看到：

**消息顺序变成"第二个回答、第二句、第一个回答、第一句"——完整的倒序。**

**然后你把它接到追问里，模型会以为"用户最后说的是第一句"。**

**于是它答非所问，而你的日志显示"请求成功、token 正常、耗时正常"。**

**这类"顺序错了但不报错"的 bug，是这一节最该亲手踩一次的。**

`server.js` 里那个 `express.json({ limit: "20mb" })` 也一样。你必须自己删掉它跑一次，才会看到：

**传一张 300KB 的图，报"图片太大，请压缩到 5MB 以内"。**

**你压到 50KB，还是同样的错。** 因为真实阈值是 100KB，而提示写的是 5MB。

## 怎么建

1. `cd` 到本节课的 `03-练习代码\`；
2. `xcopy /E /I /Y "..\第06节课\03-练习代码\mm-app" mm-app`；
3. `cd mm-app`；
4. 写 `lib\session.js` → 跑 `probe-session.js` → **确认消息顺序和篡改检测都对**；
5. 写 `lib\assistant.js` → 跑 `bench-parallel.js` → **记住 min(1800,2400)=1800**；
6. 改 `server.js` 三处 → 写 `routes\assistant.js`;
7. 写 `public\assistant.html` → 浏览器里完整走一遍；
8. 写 `scripts\acceptance.js` → **换成真图再跑**；
9. 写 `scripts\cost-report.js` → 记下输入/输出比。

**第 4 步不能跳。** 消息顺序错了，后面所有追问都是错的，而且你不会发现。

**第 8 步的"换真图"不能跳。** 占位纯色图只能证明"管道通"，证明不了任何识别能力。

## 检验自己有没有真学会

做完后，**不看课件**回答：

1. 会话 id 用自增会发生什么？你怎么在自查时发现这类问题？
2. 为什么"并行省下的时间 = 较快那一步的耗时"？如果两步是 100ms 和 5s，值得并行吗？
3. 客户传一张风景照，你的系统应该返回什么？用 `Promise.all` 会返回什么？
4. 你的输入 token 是输出的 100 多倍。这说明什么？你该优化哪一块？
5. 如果客户要"一次上传 100 张发票批量识别"，你要改什么？哪一步会成瓶颈？
6. 你的验收里"看不出来"那几问，模型答对了吗？你怎么判定的？

**第 1、6 个才是真正的验收。** 前者考"你会不会发现静默漏洞"，后者考"你会不会判断幻觉"。
