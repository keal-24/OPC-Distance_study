## 这一周的目标

到周日，你要能独立做完这五件事：

1. **分清聊天和智能体** —— 知道什么时候该上循环，什么时候一行代码就够；
2. **写出模型看得懂的工具说明** —— description 写清边界，参数用 schema 卡死；
3. **在没有 API key 的情况下跑通完整工具调用** —— 假模型返回结构正确的 `tool_calls`；
4. **让循环停得住** —— 三个停止条件、每轮日志、三种死循环的定位方法；
5. **给工具加权限门** —— 只读直接跑，有副作用必须人工确认，危险工具根本不给。

**最终交付**：一个能查 `data/app.db` 并自己回答的 Agent，5 个业务问题跑通，每轮 `tool_call` 都有日志。

## 为什么排在这一周

第 13 周你做完 RAG：**资料在库里，模型照着答。**

但 RAG 只能回答"资料里写了什么"。真实问题经常是"现在有多少""哪个最多""帮我算一下"——**这些不在资料里，在数据库里，而且每次问的答案都不一样。**

不学这一周，你会卡在三个地方：

```text
想让模型查库 → 只能把整张表塞进 prompt → 表一大就爆
想让它自己决定查什么 → 写不出固定的 if
真给了它写权限 → 一次判断失误就改数据
```

**这一周解决前两个，并且用一整节讲清第三个的代价。**

## 这一周最容易卡住的五个地方

**一、模型返回 `tool_calls`，你却在看 `content`**

现象：打印出来是 `null`，以为模型坏了。

原因：调工具时 `content` 就是 `null`，答案在 `tool_calls` 里。

解法：**只看 `finish_reason`**，是 `"tool_calls"` 就执行，是 `"stop"` 才读 `content`。

**二、`.env` 写 `MOCK=false`，代码还在走假模型**

现象：改了配置没反应。

原因：`process.env.MOCK` 是字符串，`"false"` 是真值。

解法：`String(process.env.MOCK).toLowerCase() !== "false"`。

**三、循环跑到第 8 轮，没有答案**

现象：`stopReason` 是 `max_rounds`，用户什么都没看到。

原因：模型要的工具没给、参数一直不合法、或者结果没回传。

解法：**先看日志最后一条 `tool_call`**，再决定是改 prompt、改 description 还是改代码。

**四、死循环但日志显示"0 次失败"**

现象：每轮调用一模一样，工具都成功。

原因：工具结果没 `push` 进 `messages`，模型看不到。

解法：打印 `messages.map(m => m.role)`，正常应该是 `system → user → assistant → tool → assistant`。

**五、以为黑名单等于安全**

现象：加了 `DELETE|DROP` 关键词，就觉得可以给模型开写权限。

原因：黑名单是文本匹配，`SELECT load_extension(...)` 一个关键词都不含。

解法：**只读连接才是边界。** 黑名单只负责"早一点给人话报错"。

## 这一周的四条铁律

```text
一、能给只读，就不给可写。
    db.js 里那一行 readonly: true，是整周唯一不可绕过的防线。

二、任何一个有副作用的工具，必须有人按一次 yes。
    确认框里必须显示"工具 + 参数 + 影响"，只显示工具名等于没确认。

三、循环必须有上限，停下来必须说原因。
    answer / max_rounds / fatal_error，缺一个就会出现静默失败。

四、工具执行失败，也要把失败回传给模型。
    吞掉错误，模型只会换个说法再来一次。
```

## 周末的验收

不要急着进第 15 周。先确认这七条：

- [ ] `node main.js` 跑 5 个业务问题，5 个都是 `answer`

- [ ] `security-check.js` 里 `DELETE`、多条语句、`load_extension` 都被拒
- [ ] `db.readonly` 输出 `true`
- [ ] 七节课的 `NOTES.md` 都填了，没有大片空白

> **第 5 条和第 6 条不能省。** 它们证明的不是"你会写 Agent"，是"你知道 Agent 什么时候会伤到人"。
