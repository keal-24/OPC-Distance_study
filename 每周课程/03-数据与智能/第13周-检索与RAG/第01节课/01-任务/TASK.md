# 第 0 步：为什么要有这一步（10 分钟）

## 0.1 你现在会什么

第 12 周你干了一件事：把 PDF、Word、Excel 里的字抠出来，写进了三张表。

```text
documents   一篇文档一行
sections    一页或者一章一行
chunks      按页切出来的片段
```

你现在能做的是：打开数据库，按文档名查，把某一页的文字读出来。

**但你回答不了一个问题：**"客户问'出差住宿能报多少'，你该把哪几段交给模型？"

## 0.2 今天这个坑长什么样

客户把公司制度手册给你，一共 300 页。他要求做一个问答机器人。

你的第一反应是把整本手册塞进 prompt：

```text
system: 你是公司制度助手，根据下面的手册回答。
user:   【这里贴 300 页全文】
        出差住宿能报多少？
```

跑一次，三种结果，你至少会遇到一种：

| 结果 | 原因 |
|---|---|
| 接口报错，说超出上下文长度 | 300 页约 15 万字，大约 12 万 token，超过多数模型的输入上限 |
| 没报错，但答得含糊 | 中间隔了 12 万 token，模型抓不住那一行表格 |
| 答得对，但每次问答都很贵、很慢 | 每问一次都重新读 12 万 token |

**算一下差多少：**

```text
一整本手册      约 150000 字   约 120000 token
切出来的 5 个块  约 2500 字     约 2000 token
```

同样的一个问题，成本差 60 倍。**而且长文里的准确率更差。**

所以今天要干的事只有一件：**把大堆文字切成小块，让每次只带 5 块进去。**

## 0.3 今天的三个概念

| 术语 | 一句话人话 | 今天在哪用 |
|---|---|---|
| 切片（chunk） | 一段自己能读懂的连续文字，几百字，开头结尾都是完整句子 | `split.js` 的产物，第 86 节课入库 |
| 重叠（overlap） | 相邻两块故意重复的一小段，防止答案正好卡在交界处 | `OVERLAP = 120` 那个常量 |
| 召回（recall） | 用户问一句话，你能不能把含答案的那块捞出来 | 第 87、89 节课要测的东西 |

**先记住一条：切分的质量，决定了后面所有环节的上限。**

检索再聪明，也捞不回一个被切烂的块。模型再强，也读不懂一句被拦腰截断的话。

## 0.4 今天的交付物

项目根目录是：

```text
B:\OPC-Distance_study\每周课程\03-数据与智能\第13周-检索与RAG\第01节课\03-练习代码\rag-app
```

**这一周七节课的代码都放在这一个项目里。** 后面几节课不再新建项目，只往里加文件。

今天的交付物：

| 文件 | 作用 |
|---|---|
| `tools\seed-docs.js` | 造 5 个样本文档（上一周没做完时用） |
| `data\docs\*.txt` | 5 个样本文档 |
| `split.js` | 切分脚本，可反复跑 |
| `tools\check-chunks.js` | 检查切坏的块 |
| `out\chunks-preview.json` | 切分结果，第 86 节课入库用 |

**为什么不用上一周切好的 chunks？**

上一周的 `chunks` 是按"页"切的。PDF 一页有什么就切什么，一页可能 3000 字，也可能只有页眉和一个图注。它有三个毛病：

1. 没有 overlap，块边界正好卡在句子中间；
2. 大小完全由排版决定，同一份文档换一种字体，切出来的块就变了；
3. 对 txt 来说 `page` 字段没有意义，一页就是全文。

**这一周要的是"按语义切"，不是"按排版切"。** 所以今天重切一遍，写进新的表，上一周的库原样留着，不要动它。出了问题时你还能回去对照。

# 第 1 步：确认你的库里有什么（10 分钟）

## 1.1 做什么 / 为什么

先建项目目录。

新建 `package.json` 之后，打开它，把 `"type"` 那一行**删掉或者改成 `commonjs`**。这一周全部用 `require`，不要 `import`。

然后在项目根建 `tools\count-kb.js`：

```javascript
// tools/count-kb.js
// 数一下你上周的库里有多少东西
// 用法：node tools/count-kb.js "D:\你的路径\kb.db"

const fs = require("fs");

const file = process.argv[2];
if (!file || !fs.existsSync(file)) {
  console.log("用法：node tools/count-kb.js \"你的 kb.db 路径\"");
  process.exit(1);
}

let db;
try {
  const Database = require("better-sqlite3");
  db = new Database(file, { readonly: true });
} catch (e) {
  const { DatabaseSync } = require("node:sqlite");
  db = new DatabaseSync(file, { readOnly: true });
}

function one(sql) {
  try {
    return db.prepare(sql).get();
  } catch (e) {
    return null;
  }
}

const docs = one("SELECT COUNT(*) AS n FROM documents");
const pages = one("SELECT COUNT(*) AS n FROM sections");
const chunks = one("SELECT COUNT(*) AS n, AVG(LENGTH(text)) AS avg FROM chunks");

if (!docs || !pages || !chunks) {
  console.log("这三张表不齐，说明上一周没做完。往下看 1.4。");
  process.exit(2);
}

console.log(`文档 ${docs.n} 篇`);
console.log(`页/节 ${pages.n} 个`);
console.log(`切片 ${chunks.n} 块，平均 ${Math.round(chunks.avg)} 字`);
```

跑之前先把路径换成你自己的。比如你上周把库放在第 12 周第 7 节课的练习目录里：

```text
node tools\count-kb.js "B:\OPC-Distance_study\每周课程\03-数据与智能\第12周-文档解析\第07节课\03-练习代码\kb.db"
```

## 1.3 屏幕上应该看到什么

做完上一周的人，输出大概是这样（**数字是你的，不是我的**）：

```text
文档 12 篇
页/节 86 个
切片 412 块，平均 510 字
```

**这三个数字决定你后面怎么调参数：**

| 你的情况 | 怎么办 |
|---|---|
| 文档少于 3 篇 | 太少，检索演示不出差别，建议再加几篇 |
| 切片平均超过 900 字 | 上一周是按页切的，块太大，今天必须重切 |
| 切片平均不到 200 字 | 切太碎，一句话被切两半的概率很高，今天必须重切 |
| 表不存在，或者 0 行 | 上一周没做完，走 1.4 的补救路径 |

## 1.4 如果不是这样

**报错 `Cannot find module 'better-sqlite3'`，同时 `node:sqlite` 也不认：**

说明你的 Node 低于 22.5。跑 `node -v` 看一眼。低于 18 去升级；18 到 22.4 之间，先把 `npm install better-sqlite3` 装好，装不上就升级 Node。

**报错 `SQLITE_CANTOPEN`：**

路径里有中文或者空格，cmd 里引号没包住。整个路径用英文双引号包起来。

**报错 `no such table: documents`：**

你打开的不是上周那个库，或者上周只写了 `sections` 表没写 `documents`。用 `dir` 找一下 `kb.db`，确认大小不是 0。

**上一周真没做完，怎么办：**

不要回头补第 12 周。今天有替代方案：**用 5 个 txt 文件造一批数据。**

这不是偷懒。txt 没有编码坑、没有分页、没有 OCR，正好让你把注意力放在"切"这件事上。等你把这一周走完，再回头补 PDF 解析，管道是同一根。

## 3.1 做什么 / 为什么

**第一步永远是按结构切，不是按字数切。**

# 第 4 步：按段落切，再合并成 400–800 字（25 分钟）

## 4.1 做什么 / 为什么

规则定死，不要凭感觉：

```text
目标块大小    400–800 字
重叠          80–150 字
切点          句号、问号、感叹号、分号、换行
不动的东西     表格、代码块
```

**为什么是 400–800：**

| 太小（<300） | 太大（>1000） |
|---|---|
| 一句话被切两半 | 一块里有三四个话题 |
| 检索命中后上下文不够，模型答不全 | 检索命中"块"，但半块是噪音，稀释了真正的答案 |
| 块数量暴涨，索引变大 | 塞 5 块就超 token 预算 |

**为什么要有 80–150 字的重叠：**

答案正好卡在两块交界处时，没有重叠就会两边都缺一半。

举个真实例子。第一块结尾是"单笔金额超过五千元的报销，需要再上一级"，第二块开头是"负责人审批。财务在收到完整单据后……"。你检索"超过五千谁审批"，两块的字面重合度都不高，可能一块都捞不上来。

有了 120 字重叠，第二块开头会带上"单笔金额超过五千元的报销，需要再上一级负责人审批"，这一块就能被完整召回。

**重叠不是越多越好。** 150 字重叠意味着 20% 的内容存了两遍，索引变大、检索结果重复。超过 200 字就该停下来想想是不是块切太小了。

## 4.2 为什么不用现成的切分库

你在网上搜"文本切分"，八成会搜到 LangChain 的 `RecursiveCharacterTextSplitter`，一行代码就能切。

**这门课禁止用它。** 不是因为它差，是因为三个具体原因：

| 原因 | 说明 |
|---|---|
| 它不认识中文标点 | 默认分隔符是 `\n\n`、`\n`、` `、`""`，中文的"。"和"；"不在列表里，你要自己传 |
| 它不知道表格 | 表格会被当成普通文本，按逗号或者字数切开，列名和数据分家 |
| 出问题你看不懂 | 切坏了，你只能读它的源码或者猜参数，中间隔了一层 |

**手写这一百多行，换来的是：每一个切点你都能在代码里指出来。** 块为什么是 573 字、为什么在这里断、为什么这一块没有重叠，全都能回答。这在客户现场很重要——他问"你为什么把我这句话切断了"，你不能说"库就是这么切的"。

**什么时候该用库：** 你要处理十几种格式、切分规则复杂到十几条、团队里已经有人在维护这套东西。那时候用库是省时间。现在你只有一种规则，装一个依赖不划算。

```javascript
// 第二步：段落是一段连续的非空行；表格整体算一段
function splitByParagraph(body) {
  const lines = body.split(/\r?\n/);
  const blocks = [];
  let buf = [];
  let inTable = false;

  function flush() {
    const t = buf.join("\n").trim();
    if (t) blocks.push(t);
    buf = [];
  }

  for (const line of lines) {
    if (/^\s*\|/.test(line)) {
      if (!inTable && buf.length) flush();
      inTable = true;
      buf.push(line);
      continue;
    }
    if (inTable) {
      flush();
      inTable = false;
    }
    if (line.trim() === "") {
      flush();
    } else {
      buf.push(line);
    }
  }
  flush();
  return blocks;
}

  const parts = [];
  let cur = "";

  for (const s of sentences) {
    if (s.length > max) {
      if (cur) {
        parts.push(cur);
        cur = "";
      }
      for (let i = 0; i < s.length; i += max) {
        parts.push(s.slice(i, i + max));
      }
      continue;
    }
    if (cur.length + s.length > max) {
      if (cur) parts.push(cur);
      cur = s;
    } else {
      cur += s;
    }
  }
  if (cur) parts.push(cur);
  return parts;
}

// 取末尾一段作为重叠：只取完整句子，遇到表格就放弃重叠
function overlapTail(text, n) {
  if (text.includes("|")) return "";
  const sentences = text.match(/[^。！？；\n]+[。！？；]?/g) || [];
  let out = "";
  for (let i = sentences.length - 1; i >= 0; i--) {
    const s = sentences[i].trim();
    if (!s) continue;
    if (/^【.*】$/.test(s)) continue;
    if (s.length < 20) continue;
    if (out.length + s.length > n) break;
    out = s + out;
  }
  return out.trim();
}

function chunkDocument(docName, text) {
  const sections = splitByHeading(text);

  const blocks = [];
  for (const sec of sections) {
    for (const p of splitByParagraph(sec.body)) {
      for (const piece of splitLong(p, MAX)) {
        blocks.push({ heading: sec.heading, text: piece, table: piece.trim().startsWith("|") });
      }
    }
  }

  const chunks = [];
  let cur = "";
  let curHeading = "";
  let lastHeading = "";

  function flush() {
    if (!cur.trim()) return;
    chunks.push({ doc: docName, heading: curHeading, text: cur.trim() });
    cur = "";
  }

  for (const b of blocks) {
    const piece = lastHeading && b.heading !== lastHeading ? `【${b.heading}】\n${b.text}` : b.text;

    if (cur && cur.length + piece.length + 1 > MAX) flush();

    if (!cur) {
      curHeading = b.heading;
      const prev = chunks[chunks.length - 1];
      const ov = prev && !b.table ? overlapTail(prev.text, OVERLAP) : "";
      cur = ov && ov.length + piece.length + 1 <= MAX ? ov + "\n" + piece : piece;
    } else {
      cur += "\n" + piece;
    }

    lastHeading = b.heading;
    if (cur.length >= TARGET) flush();
  }
  flush();

  if (chunks.length >= 2) {
    const last = chunks[chunks.length - 1];
    const prev = chunks[chunks.length - 2];
    if (last.text.length < MIN && prev.text.length + last.text.length <= MAX) {
      prev.text = prev.text + "\n" + last.text;
      chunks.pop();
    }
  }

  return chunks.map((c, i) => ({ ...c, seq: i + 1, chars: c.text.length }));
}

function main() {
  const files = fs.readdirSync(DOC_DIR).filter((f) => f.endsWith(".txt"));
  const all = [];

  for (const file of files) {
    const text = fs.readFileSync(path.join(DOC_DIR, file), "utf8");
    const name = file.replace(/\.txt$/, "");
    const chunks = chunkDocument(name, text);
    console.log(`${name}  原文字数 ${text.replace(/\s/g, "").length}  切出 ${chunks.length} 块`);
    for (const c of chunks) {
      all.push({ id: all.length + 1, doc: name, seq: c.seq, heading: c.heading, chars: c.chars, text: c.text });
    }
  }

  fs.mkdirSync(OUT_DIR, { recursive: true });
  fs.writeFileSync(OUT_FILE, JSON.stringify(all, null, 2), "utf8");

  const sizes = all.map((c) => c.chars);
  const sum = sizes.reduce((a, b) => a + b, 0);
  console.log("");
  console.log(`总块数 ${all.length}`);
  console.log(`平均字数 ${Math.round(sum / all.length)}`);
  console.log(`最短 ${Math.min(...sizes)}  最长 ${Math.max(...sizes)}`);
  console.log(`超过 ${MAX} 字的块：${sizes.filter((s) => s > MAX).length}`);
  console.log(`已写入 ${OUT_FILE}`);
}

main();
```

# 第 5 步：检查切坏的两个症状（15 分钟）

## 5.1 做什么 / 为什么

切分脚本跑通不等于切对了。**必须用代码检查，不能靠眼睛翻 JSON。**

切坏只有两个症状，全都可检测：

| 症状 | 怎么发现 | 后果 |
|---|---|---|
| 一句话被切成两半 | 块结尾不是句末标点，或者块开头是逗号 | 检索命中后模型读到半句，答偏 |
| 一个表格被切成两块 | 某块以 `\| ---` 开头，或者有表格行但没有表头 | 表格的列名和数值分家，数字对不上 |

**为什么一定要写脚本，而不是打开 JSON 翻一遍：**

10 块你能翻，500 块你翻不完。而且"这句话被切断了"靠眼睛看不出来——单看一块，它可能是个完整的句子；要看的是它和上一块接不接得上。

脚本查得比人快、比人稳，而且每次改参数之后能立刻重跑。**你的切分参数以后一定会调，调到第五次的时候，你会庆幸有这个东西。**

## 5.2 操作

新建 `tools\check-chunks.js`：

```javascript
// tools/check-chunks.js
// 检查 out/chunks-preview.json 里有没有切坏的块
// 用法：node tools/check-chunks.js

const chunks = require("../out/chunks-preview.json");

const END_OK = /[。！？；】"”]$/;
const BAD_HEAD = /^[，。；、）》\)]/;

let problems = 0;

for (let i = 0; i < chunks.length; i++) {
  const c = chunks[i];
  const text = c.text.trim();

  // 症状一：上一块结尾没有句末标点，这一块开头又不是新标题
  if (i > 0) {
    const prev = chunks[i - 1].text.trim();
    if (!END_OK.test(prev) && !text.startsWith("【")) {
      console.log(`[${c.id}] 上一块结尾没有句末标点，可能是半句话：...${prev.slice(-20)}`);
      problems++;
    }
  }

  // 症状一：这一块开头是标点
  if (BAD_HEAD.test(text)) {
    console.log(`[${c.id}] 块开头是标点：${text.slice(0, 20)}`);
    problems++;
  }

  // 症状二：表格被切断
  const lines = text.split("\n");
  const tableLines = lines.filter((l) => l.trim().startsWith("|"));
  if (tableLines.length > 0) {
    if (text.startsWith("| ---")) {
      console.log(`[${c.id}] 表格缺少表头，块直接从分隔行开始`);
      problems++;
    }
    const sepIndex = tableLines.findIndex((l) => /^\|\s*-{3,}/.test(l.trim()));
    if (sepIndex === 0) {
      console.log(`[${c.id}] 表格分隔行是第一行，表头在上一块`);
      problems++;
    }
    if (sepIndex === tableLines.length - 1) {
      console.log(`[${c.id}] 表格只有表头和分隔行，数据行在下一块`);
      problems++;
    }
  }
}

console.log("");
console.log(`共 ${chunks.length} 块，发现问题 ${problems} 个`);
```

**操作：** 把 `splitLong` 里按句子切的那段删掉，改成：

```javascript
    parts.push(text.slice(i, i + max));
  }
  return parts;
}
```

## 练习三：给表格加一层保护

现在的代码里，表格靠 `piece.trim().startsWith("|")` 判断，只有块的第一行是表格时才不加重叠。

如果表格前面还有一句话，这句话和表格会被拼在同一块里，这没问题。但如果表格超过 800 字（比如 40 行的价格表），`splitLong` 会把它按句子切开，表格还是会被切。

改法只有一个方向：**表格不参与 `splitLong`**。给 `splitLong` 加一个参数，遇到表格直接返回原文，允许它超过 800 字。改完跑一遍，确认 `check-chunks.js` 还是 0 个问题。

## 练习四：找出这段切分代码的四个问题

```javascript
function chunk(text) {
  const parts = [];
  for (let i = 0; i < text.length; i += 500) {
    parts.push(text.slice(i, i + 500));
  }
  return parts;
}
```

提示方向：句子边界、表格、重叠、块大小是否可变。

# 附：常见问题速查

| 现象 | 先查什么 | 怎么办 |
|---|---|---|
| 块数等于节数 | `if (cur.length >= TARGET) flush()` 有没有 | 确认 TARGET 是数字 500 |
| 每块只有一段 | `blocks` 是不是每节只有一段 | 打印 `blocks.length` 看 |
| 块开头是逗号 | `splitLong` 是不是按字符切 | 换成按 `。！？；` 切 |
| 表格被切成两块 | `overlapTail` 有没有跳过表格 | 加 `if (text.includes("\|")) return ""` |
| 最短块只有 50 字 | 尾块合并条件 | 确认 `MIN = 300`，MAX 没被调小 |
| 中文全是问号 | cmd 代码页 | `chcp 65001` 再跑 |
| `Cannot find module` | 当前目录 | `cd /d` 回到 `rag-app` |
| JSON 打不开 | 有没有写完整 | 用 `node -e "require('./out/chunks-preview.json')"` 试 |
| 切出来 0 块 | `data\docs` 是空的 | `dir data\docs` 确认 |
| 字数比原文少很多 | 空白被 trim 了 | 正常，统计按去空白算 |
