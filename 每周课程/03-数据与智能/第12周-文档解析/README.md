# 第 12 周 · 文档解析 · 第 78—84 节课

## 客户发来的 PDF，不会自己变成数据

---

## 这一周的目标

1. **判断一个文件的真实格式** —— 不信扩展名，打开文件头看字节；
2. **从七种来源里取出文字** —— txt、md、csv、docx、xlsx、文字版 PDF、扫描图片；
3. **把脏文本洗成能用的文本** —— 去 BOM、修 GBK 乱码、去页眉页脚、合并断行；
4. **设计三张表把文档拆开存** —— `documents` / `sections` / `chunks`；
5. **跑通一条批量流水线** —— 扫目录、分派解析、写库、打印统计、留下失败清单。

## 为什么排在这一周

第 11 周你抓的是网页。网页是**别人已经排好版的结构**：有 HTML，有选择器，字段是字段，列表是列表。

客户给你的东西不是这样：

```text
合同.pdf          扫描件，里面一个字都取不出来
预算.xlsx         三个 sheet，表头在第三行，还合并了单元格
通知.docx         正文里夹着页眉、批注、页脚
数据.csv          用 Excel 另存过，编码是 GBK，第一格带 BOM
```

这就是"我们知识都在文档里"的真实含义。**这句话翻译过来是：几百个格式各异、脏得不行的文件。**

不学这一周，第 13 周的检索没有输入。你没法对一堆 PDF 做检索，除非先把它们变成有页码、有段落、有边界的一段段文字。**`chunks` 表就是第 13 周的地基**，这一周最后两节全部在为它服务。

## 这一周最容易卡住的六个地方

**第一：扩展名骗了你，但你不信**

现象：`报告.txt` 打开是乱码，或者 `pdf-parse` 报 `Invalid PDF structure`。
原因：Windows 只认扩展名，文件内容跟名字没关系。
解法：读前 8 个字节，对照魔数表；`%PDF` 是 PDF，`PK` 是 zip 系。

**第二：中文变成 `����` 或 `锟斤拷`**

现象：读进来一片问号，或者出现"锟斤拷"这三个字。
原因：文件是 GBK，你按 UTF-8 解码了。
解法：先用 `fatal: true` 试 UTF-8，抛错再退到 `TextDecoder('gbk')`。

**第三：CSV 用 `split(",")` 就错位**

现象：本来 5 列，解析出 7 列，后面全部错位。
原因：引号里有逗号、有换行。
解法：手写状态机，别用 `split`。这 40 行就是本课的考点。

**第四：PDF 取出来没有段落，只有碎行**

现象：一句话被切成三行，页眉页码混在正文里。
原因：PDF 只存"每个字画在哪个坐标"，不存"这是一段"。
解法：按 y 坐标聚行，去重复页眉，合并硬断行。顺序不能反。

**第五：扫描版 PDF 解析"成功"但一个字没有**

现象：程序不报错，入库 0 字，你还以为跑通了。
原因：扫描件是图片，`pdf-parse` 只能取文字层。
解法：算出"总字符数 / 页数"，小于 20 就判定为扫描版，转 OCR 路线。

**第六：一个烂文件毁掉整批**

现象：跑到第 37 个文件报错，前面 36 个也没进库。
原因：你把整批放在一个事务里，或者没捕获单文件异常。
解法：一个文件一个事务，失败写进 `documents.status = 'failed'`，下次单独重试。

## 这一周的四条铁律

```text
一、永远不信扩展名。先读文件头，再决定用哪个解析器。

二、解析器不许 throw 到流水线外面。
    每个文件的结果只有两种：成功入库，或失败入库并留下原因。

三、原始文本和清洗后的文本都要能追溯。
    清洗规则改了，要能重跑，不能靠"当时是这么洗的"。

四、扫描件 OCR 出来必须人工抽查。
    金额、日期、身份证号、编号，一个都不能直接用。
```
