# 03-练习代码

**这个文件夹故意留空。** 本节课你要自己新建（先复制上一节）：

```text
03-练习代码/
└── doc-parser/
    ├── samples/
    │   ├── 政策.pdf       ← 政府/学校官网下载，至少 5 页，能选中文字
    │   └── 扫描件.pdf     ← 照片放进 Word 再另存为 PDF，选不中文字
    ├── out/
    │   ├── pdf-before.txt
    │   └── pdf-after.txt
    └── src/
        ├── read-pdf.js
        └── pdf-raw.js
```

## 为什么必须准备两个 PDF

一个文字版、一个扫描版，缺一不可。

只跑文字版，你永远不知道"扫描件会静默返回 0 字"有多危险。
只跑扫描版，你没法验证清洗规则（去页眉、合并断行）到底有没有用。

**两个文件放在一起跑，你才会相信：`pdf-parse` 对这两种文件的处理方式，差别不在报错，在"有没有字"。**

## 怎么造扫描件

1. 手机拍一张带文字的纸，传到电脑；
2. Word 新建，插入照片，拉满一页；
3. "另存为" → PDF；
4. 用 Edge 打开，试着选中文字——选不中，就对了。

**不要用客户真实合同。** 拍一页说明书、一张打印的通知都行。

## 为什么要留 `pdf-before.txt`

因为清洗规则会越改越复杂，你需要一个对照物。

```text
pdf-before.txt   原始输出，页眉、页码、断行都在
pdf-after.txt    清洗后，页眉没了、句子接上了
```

**没有 before，你就没法证明 after 更好。** 而且下次改规则改坏了，你能退回去看。

## 怎么建（一步步）

1. 复制上一节的 `doc-parser`；
2. `npm install pdf-parse`；
3. 下载一个公开 PDF，再做一个扫描件；
4. 写 `pdf-raw.js`，先看 `data.text` 长什么样；
5. 写 `read-pdf.js`，一节一节加：先按页，再去页眉，再合并，最后判定；
6. 每加一步，都跑一次，对照课件的输出；
7. 把 before / after 写进 `out`。

**不要一次把四个函数全写完再跑。** 一次加一个，出问题你能定位到是哪一步。

## 检验自己有没有真学会

做完后，试着不看课件回答：

- 为什么 `pdf-parse` 默认输出里没有空行？你的代码怎么补出段落边界？
- 页眉为什么不能按"每页第一行"删？你的判定依据是什么？
- 为什么不能把所有 `-` 删掉？举一个会被毁掉的字符串。
- 清洗顺序换一下，具体哪一步会出错？
- 扫描件为什么返回空字符串而不是抛异常？你怎么在入库前拦住它？
