# 环境手册 · 换任何一台电脑都照这个重来

> 这份文档的唯一标准：**拿到一台全新的电脑，只靠这一份文件，能恢复到「可以开始写代码」的状态。**
> 每一步都给验证方法。验证不过，别往下走。

---

## 第一部分 · 你要守住的四样东西

换电脑会废，不是因为代码没了，是因为**下面四样东西只存在那台机器上**。逐一处理：

| 东西 | 存在哪 | 换电脑会怎样 | 怎么保住 |
|---|---|---|---|
| 代码 + 笔记 | 本地磁盘 | 全没了 | 推到 GitHub，新电脑 `git clone` |
| Git 身份 | 本地 `~/.gitconfig` | 提交记录变成别人的名字 | 新电脑重设两行命令 |
| GitHub 登录 | 浏览器 Cookie | 要重新授权一次 | 用 Personal Access Token |
| 编辑器插件 | VS Code 内部 | 全没了 | 插件清单在本文末尾，照着装 |

**结论：只要代码推到 GitHub，换电脑就只是「装三个软件 + clone 一下」。** 半小时的事，不用怕。

## 第二部分 · 装环境（三件套）

只需要三个软件。别的都不要装。

### Windows

打开 PowerShell（`Win + R` → 输入 `powershell` → 回车），**逐行**粘贴执行：

```powershell
winget install --id OpenJS.NodeJS.LTS -e --accept-package-agreements --accept-source-agreements
winget install --id Git.Git -e --accept-package-agreements --accept-source-agreements
winget install --id Microsoft.VisualStudioCode -e --accept-package-agreements --accept-source-agreements
```

三条跑完，**关掉 PowerShell 重新打开一个**（关键，不重开环境变量不生效）。

### macOS

打开「终端」，先装 Homebrew（已装过会提示已存在，正常）：

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

然后：

```bash
brew install node git
brew install --cask visual-studio-code
```

### 验证（Windows 和 mac 都一样）

新开一个终端窗口，逐行执行：

```bash
node -v
npm -v
git --version
code --version
```

**四条都出版本号才算过。** 期望看到类似：

```
v22.22.2
10.9.7
git version 2.55.0.windows.3
1.xx.x
```

- 前三条任意一条报「不是内部或外部命令 / command not found」→ 终端没重开，关掉重开
- `code` 报错（Windows 常见）→ 不影响，可以手动在开始菜单打开 VS Code；想修就在 VS Code 里按 `Ctrl+Shift+P` 输入 `Shell Command: Install 'code' command in PATH` 回车
- Node 版本低于 18 → 太老，重装

## 第三部分 · 配 Git 身份（新电脑必做）

Git 靠两行配置认你是谁。不配的话，提交记录都是「unknown」，以后找回工作记录时一片模糊。

```bash
git config --global user.name "keal-24"
git config --global user.email "276084243+keal-24@users.noreply.github.com"
git config --global init.defaultBranch main
git config --global core.autocrlf true
```

验证：

```bash
git config --global --list
```

看到 `user.name=keal-24` 和 `user.email=...` 就对了。

> 邮箱必须和你 GitHub 账号的邮箱一致，否则 GitHub 不会把提交算到你头上，绿点不会亮。

## 第四部分 · 拿回你的代码（换电脑的核心动作）

### 情况 A：新电脑，第一次拉代码

**你的仓库地址（已经建好了，是空的）：**

```
https://github.com/keal-24/OPC-Distance_study.git
```

Windows：

```bash
cd /b
git clone https://github.com/keal-24/OPC-Distance_study.git
cd OPC-Distance_study
```

mac 或 Linux：

```bash
cd ~/Projects
git clone https://github.com/keal-24/OPC-Distance_study.git
cd OPC-Distance_study
```

> **仓库名和本地文件夹名故意保持一致**：`OPC-Distance_study`。
>
> 为什么不加自定义名字：因为两边不一致，你以后在文档、路径、命令里会反复搞混。**GitHub 上叫这个名字，本地也就叫这个，一眼对得上。**

**第一次会弹出登录窗口**，选 `Sign in with your browser` → 浏览器里点授权。成功后终端显示 `Clone succeeded`，本地就有全部代码和笔记了。

### 情况 B：这台电脑上已经有目录，只想接上 GitHub

就是把现有目录推上去（**你现在属于这种情况**）：

```bash
cd "B:/OPC-Distance_study"
git remote add origin https://github.com/keal-24/OPC-Distance_study.git
git branch -M main
git push -u origin main
```

三行分别是：记住远程地址、把当前分支改名成 `main`、推上去并建立跟踪。

第一次 push 会弹登录窗口：

1. 弹窗里选 **`Sign in with your browser`**（用浏览器登录）
2. 浏览器自动打开 GitHub 授权页，点绿色的 **`Authorize git-credential-manager`**
3. 回到终端，看到 `branch 'main' set up to track 'origin/main'` 就成功了

推完去 `https://github.com/keal-24/OPC-Distance_study` 刷新，能看到 `docs`、`w01-地基`、`final`、`README.md` 就对了。

**这一步没做，前面所有版本管理都只是在本地，等于没备份。** 这是整份文档里唯一一件「现在不做、以后一定后悔」的事。

> 你的仓库是**空仓库**（GitHub 上没勾 README 就直接建的那种），所以不用 `git pull`，直接 push 就行，不会冲突。反过来说：如果以后在 GitHub 网页上直接改过文件，本地 push 会被拒绝，那时要先 `git pull --rebase` 再推。

## 第五部分 · 装编辑器插件

打开 VS Code → 左侧竖排图标里点「扩展」（四个方块拼成的图标，或按 `Ctrl+Shift+X`）→ 搜索框输入名字 → 点 `Install`。

**必装（三个）**

| 插件名 | 作者 | 干什么 |
|---|---|---|
| `Live Server` | Ritwick Dey | 改完代码浏览器自动刷新。没有它，你每改一个字都得手动刷 |
| `Chinese (Simplified)` | Microsoft | 界面变中文。装完右下角弹窗点 `Change Language and Restart` |
| `Prettier - Code formatter` | Prettier | 一键把乱糟糟的代码排整齐，`Shift+Alt+F` |

**后面会用到，先记住名字**

`GitLens`（看每行代码谁改的）、`Thunder Client`（测接口，Week 3 起用）、`Error Lens`（把报错直接显示在代码行右边）。

## 第六部分 · Day 1 实操：让浏览器出现你的字

**今天只有一个目标：屏幕上出现一行你自己写的字。**

今天的工作目录：`B:\OPC-Distance_study\w01-地基\d01\`

### 先搞懂一件事（不用背）

网页就是一个文本文件，后缀 `.html`（超文本标记语言，就是「带格式的纯文本」）。

浏览器打开它，把它翻译成画面。里面用「标签」描述结构：

- `<h1>...</h1>` = 大标题（heading 1）
- `<p>...</p>` = 一段话（paragraph）
- `<button>...</button>` = 按钮

没有编译、没有安装、没有魔法。你现在看到的任何网页，本质都是这种文件。

### 步骤（一步只做一件事，别跳）

**1.** 打开资源管理器（`Win + E`），地址栏直接粘 `B:\OPC-Distance_study\w01-地基`，回车
**2.** 在空白处右键 → 新建 → 文件夹 → 命名 `d01` → 回车
**3.** 打开 VS Code → 左上角「文件」→「打开文件夹」→ 定位到 `B:\OPC-Distance_study\w01-地基\d01` → 点「选择文件夹」
   - 窗口标题栏应该显示 `d01`
   - 如果弹「是否信任此文件夹的作者」，点「是，我信任」
**4.** 鼠标移到左侧 `DAY01` 这行字上，出现一排小图标，点最左边那个「新建文件」图标（一张纸带加号）
**5.** 文件名输入 `index.html`，回车
   - 大小写都无所谓，但后缀必须是 `.html`
   - 如果失败后变成了 `index.html.txt`，是扩展名被隐藏了，看下面排错表
**6.** 在右边空白编辑区输入一个英文感叹号 `!`，然后按 `Tab` 键
   - 会「唰」地出现十几行代码。这叫 HTML 骨架，现在不用理解，只要知道它是空房子的框架
**7.** 找到这一行：`<title>Document</title>`，把 `Document` 改成 `我的第一个站`
**8.** 找到 `<body>` 和 `</body>`，在它们中间的空行里，输入：

```html
<h1>你好，我是凯旋</h1>
```

**9.** 按 `Ctrl + S` 保存
   - 判断有没有保存：看标签页名字 `index.html` 右边，有小圆点 = 没保存，没有圆点 = 已保存

**10.** 点左侧竖排图标里的「扩展」（四个方块），搜索 `Live Server`
**11.** 找到作者是 **Ritwick Dey** 的那个（几千万下载量那个），点 `Install`
**12.** 装完，看 VS Code 最下面那条蓝色状态栏，右下角出现 `Go Live` 四个字，点它

### 你会看到什么（自检）

- 浏览器自动打开，地址栏是 `http://127.0.0.1:5500/...`
  - `127.0.0.1` = 你自己这台电脑，`5500` = Live Server 开的端口。这个地址别人打不开，只对你自己有效
- 页面左上角一行大字：**你好，我是凯旋**
- 回 VS Code 把「凯旋」改成别的字，按 `Ctrl+S`，**浏览器自己就变了，你没点刷新**

最后这一下是今天真正学到的东西：**改文件 → 立刻看到结果**。以后 70 天全是这个循环，只是文件越来越复杂。

### 验收（三条都要打勾才能收工）

- [ ] 浏览器里能看到你自己的名字，是大字
- [ ] 改文件保存后浏览器自动更新，我没点过刷新
- [ ] 我能说出 `index.html` 这个文件在哪个盘、哪个文件夹里

第三条别跳过。说不出来，说明你是在「跟着点」，不是在做，明天就忘了。

### 可能出错

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 浏览器显示一堆代码，不是页面 | 文件名成了 `index.html.txt` | 资源管理器顶部「查看」→ 勾上「文件扩展名」，再看真实名字，改回 `.html` 并删掉 `.txt` |
| 右下角没有 `Go Live` | 插件没装完，或装错了插件 | 等它转完；还不行就 `Ctrl+Shift+P` → 输入 `reload` → 选 `Developer: Reload Window` |
| 点 `Go Live` 浏览器打不开 | 5500 端口被别的程序占了 | 右下角 `Go Live` 上右键 → `Open with Live Server` 换端口，或关掉占用的程序 |
| 改了没变化 | 没保存 | `Ctrl+S`，看标签页白点消没消 |
| 页面全白，什么都没有 | `<h1>` 写到了 `<body>` 外面 | 确认 `<h1>你好，我是凯旋</h1>` 夹在 `<body>` 和 `</body>` 之间，不在 `<head>` 里 |
| `!` 按 Tab 没反应 | 光标不在 html 文件里，或焦点在左侧文件树 | 用鼠标点一下右边编辑区空白处，再按 `!` |
| 中文显示成方块乱码 | 文件编码不是 UTF-8 | VS Code 右下角点 `UTF-8` 之类的字样 → 选 `Reopen with Encoding` → `UTF-8` |

### 收工三件事

**1. 提交代码。** 点左侧竖排第三个图标（圆圈带分叉线，叫「源代码管理」），在输入框里写：

```
day1: 第一个网页
```

然后点输入框上方的对勾 `✓`。第一次会问「要不要暂存所有更改」，点「是」。
第一次提交会要求登录 GitHub，弹窗里选 `Allow`，浏览器里授权一次，以后就不用了。

**2. 写笔记。** 在 `B:\OPC-Distance_study\w01-地基\d01\` 建 `NOTES.md`，只写三行：

```markdown
今天做了什么：做出第一个网页，Live Server 能自动刷新
卡在哪：
怎么解决的：
```

卡在那儿就照实写「文件名搞成了 index.html.txt」，别不好意思。这份笔记是给三个月后的你的，不是给别人看的。

**3. 推上去。** 如果第四部分「推上 GitHub」还没做，今天就做掉。做完之后，每天只需要在 VS Code 里点一个「同步」按钮（状态栏左下角的循环箭头图标）。

## 第七部分 · 老板视角（今天必须记住的一句）

> **「做个官网」不是一件事。**

接到这种需求，先用三个问题砍掉一半溢价：

1. **几个页面？**（1 个静态页 vs 8 个页面带后台，差 10 倍工作量）
2. **要不要后台管理？**（客户自己改内容 = 要做登录 + 数据库 + 编辑界面，工作量翻 3 倍）
3. **内容谁提供？**（客户给现成文案 vs 你帮他写，这是完全不同的两件事，前者是开发，后者是文案）

问完这三个，你才知道报价该报多少，也才知道对方说的「很简单」到底简单在哪。
