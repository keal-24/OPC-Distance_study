# Git 急救卡 · 只记四个命令

> 你说"对 git 这里还是不熟"。这不用专门去学，但**必须搞懂这四件事**，因为往后 69 天每天都要用。
> 不用背命令，理解"它在干什么"就够了。卡住了翻这张卡。

---

## 一、Git 到底在干什么（一句话）

**Git 是给你的代码文件夹"拍快照"的工具。** 每拍一张，就多一个可以退回去的时间点。

类比：打游戏存档。写代码就是打怪，`commit` 就是存档，`push` 就是把存档上传到云。

**为什么你必须会**：以后代码被改坏了，你可以退回任何一个存档。没存档，改坏了就真没了。

---

## 二、四个区，理解这个就全懂了

```
你的文件夹          暂存区            本地仓库            GitHub
（改代码的地方）  →（准备提交的）  →（快照存档）    →（云端备份）
              add              commit            push
```

| 区 | 在哪 | 里面是什么 |
|---|---|---|
| 工作区 | 你看到的文件夹 | 你现在写的东西 |
| 暂存区 | 看不见，Git 内部 | "我这次要存这几个文件"的清单 |
| 本地仓库 | `.git` 文件夹里 | 所有历史快照 |
| 远程仓库 | GitHub 网站上 | 云端的备份 |

**`git add` = 把文件放进清单，`git commit` = 按清单拍快照，`git push` = 把快照传到云端。**

在 VS Code 里：
- 点文件右边的 `+` = `git add`（放进清单）
- 输入信息点 `✓` = `git commit`（拍快照）
- 点同步按钮 = `git push`（传云端）

**图形界面已经帮你做好了，你只需要知道它对应哪一步。**

## 三、日常只用这三步（VS Code 里点，不用敲命令）

**每天收工：**

1. 点左侧第三个图标（源代码管理）

3. 点 `✓`
4. 点状态栏左下角的同步箭头（或左侧面板顶部的 `同步更改`）

**完了。** 就这四步。

## 四、出事时用的命令（这些才需要敲）

打开终端（`` Ctrl + ` ``）。

### 1. 看现在什么状态

```
git status
```

**什么时候用**：不确定自己改了什么、有没有提交成功。

**怎么读**：
- `nothing to commit, working tree clean` = 全提交了，干净
- 红色字 = 改了但没加进清单
- 绿色字 = 已加进清单但还没提交

### 2. 看历史（我提交过什么）

```
git log --oneline
```

**什么时候用**：想确认今天有没有提交、想找回某次改动。

输出长这样，每行一次提交：

```
532a777 chore: 删除冗余的 .gitignore
03bcb7d day1: 第一个网页
f604cf6 docs: day01 重写
```

**前面那串字母数字是快照的编号**，后面是你写的提交信息。想退回某次，就用这个编号。

### 3. 撤销还没提交的改动（改坏了想重来）

```
git restore .
```

**什么时候用**：你把文件改乱了，想恢复成上次提交的样子。

**⚠️ 危险**：这会**永久丢弃**你所有未提交的修改，没有反悔机会。用之前先用 `git status` 确认丢的是什么。

**只撤销某一个文件**：

```
git restore 文件名.html
```

### 4. 推上去被拒绝

```
git pull --rebase
git push
```

**什么时候用**：在 GitHub 网页上改过文件，本地推不上去，报 `Updates were rejected`。

**它在干什么**：先把 GitHub 上新的东西拉下来接到你本地后面，再推。

## 五、最容易搞混的一件事：提交 ≠ 备份

**这是你今天最可能理解错的地方。**

| 动作 | 做了什么 | 安全吗 |
|---|---|---|
| `Ctrl+S` 保存 | 写到硬盘上的文件 | ❌ 不算 |
| `commit` 提交 | 在**本地** `.git` 里拍快照 | ❌ 硬盘坏了还是没了 |
| `push` 推送 | 传到 **GitHub 云端** | ✅ 这才叫备份 |

**所以每天必须点那个"同步"按钮。** 只 commit 不 push，等于只在本地存了档，电脑一摔全没。

你今晚做的 `day1: 第一个网页` 已经推上去了（我在 GitHub 上看到了），所以是安全的。

## 六、常见报错怎么读

| 报错 | 它在说什么 | 怎么办 |
|---|---|---|
| `not a git repository` | 你不在仓库文件夹里 | `cd` 到 `B:\OPC-Distance_study` 再操作 |
| `nothing to commit` | 没有新改动，不用提交 | 正常，说明你已经提交过了 |
| `Please tell me who you are` | 没配名字邮箱 | 跑下面那两行 |
| `Authentication failed` | GitHub 登录失效了 | 重推一次，弹窗里重新授权 |
| `Updates were rejected` | 云端有你本地没有的改动 | `git pull --rebase` 再 push |
| `CONFLICT` | 同一个文件两边都改了 | **别自己乱改**，把报错原文发我 |

**配名字邮箱**（只需一次）：

```
git config --global user.name "keal-24"
git config --global user.email "276084243+keal-24@users.noreply.github.com"
```
