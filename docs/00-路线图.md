# 一人公司 AI 开发 · 252 天完整路线

起点 2026-11-15 · 终点 2027-07-24 · 36 周 · 每天 60–120 分钟

---

## 这份路线要解决什么

不是"学会写代码"。是**一个人把公司跑起来**。

会写代码的人很多，能把公司跑起来的人很少。差别不在聪明，在于**一串没人告诉你的东西**：

**技术层面**：怎么用 AI 写代码（元技能）、Git 分支、手写 SQL、表单防刷、后台管理、图片处理、实时通信、Docker、CI/CD、邮件送达率

**生意层面**：客户从哪来、怎么报价、合同怎么写、票怎么开、代码归谁、你出事时项目怎么办

这份路线把它们全排进去了。**252 天，36 周。**

---

## 排序的四个原则

**原则一：第一周先教"怎么用 AI 写代码"**

这是**元技能**。后面 35 周都在用 AI 写代码，但没人教过怎么用。用得好省一半时间，用不好你会在调试 AI 写的烂代码上花更多时间。

**原则二：每周必须有能看见的产出**

不能出现"这周学理论，下周才能做东西"。看不见进展的学习，三天就放弃。

**原则三：基础必须亲手写过一遍**

Git 分支、手写 SQL——这两个不能只让 AI 代劳。**你必须自己写过，才知道 AI 写的哪里不对。**

**原则四：抽象的东西往后放**

前端能看见、AI 能对话，这两块先做。测试、安全、财务这些看不见的，放在你已经有东西可测、可保护、可收钱之后。

## 这次新补的九个技术缺口（为什么必须有）

### 1. W1 AI 编程工具（元技能）

**这是最大的缺口。**

你从第一天就在用 AI 写代码，但没人教过你：

- 怎么给一个"能一次做对"的指令
- AI 写完怎么验收（不是"看起来对"）
- AI 改坏了怎么快速退回
- 什么时候**不该**用 AI（比如安全相关、钱相关）
- 多个文件改动时怎么让它不乱

**为什么放第一周**：因为后面 35 周都在用这个技能。**这一周学不好，后面每一周都在还债。**

### 2. W4 Git 分支

**你现在的 Git 水平只够"一条线往前走"。**

- 要同时试两个方案 → 只能复制文件夹
- 要紧急修线上 bug → 会把没做完的功能一起带上线
- 改坏了想退回三个版本前 → 不会

**这是你目前最明显的技术短板，而且是"不学会一直难受"的那种。**

### 3. W5 手写 SQL

**你到现在只会 SDK 的 `.insert()` 和 `.select()`。**

但真正需要 SQL 的时候：

- 备份恢复（导出、导入、按条件恢复某几行）
- 复杂查询（JOIN 两张表算统计）
- 修脏数据（批量更新、去重）
- 优化慢查询（看执行计划）

**这些 SDK 帮不了你。**

### 4. W8 表单防刷

**只要你有一个公开的表单，就一定有人刷。**

- 验证码被刷 → 短信费一夜几千
- 注册接口被刷 → 数据库被垃圾数据灌满
- 登录被撞库 → 用户账号被盗

**必须会**：限频、人机验证（滑块/点选）、蜜罐字段、IP 与设备指纹。

### 5. W9 后台管理

**这是客户提得最多的需求。**

列表分页、搜索筛选、增删改、批量操作、导入导出、操作日志、角色权限。

**没有后台，客户改一个字都要找你** → 你变成免费客服 → 永远只能做一个项目。

### 6. W10 文件与图片

**任何带上传的项目都会立刻遇到：**

- 客户传 10MB 手机照片，页面卡死 → 要压缩
- 客户传 100MB 视频，上传中断要重来 → 要分片续传
- 客户要看上传的 PDF → 要在线预览
- 列表里全是原图 → 要缩略图
- 图片被别人盗用 → 要水印

**这一周不起眼，但缺了会天天遇到。**

### 7. W17 实时通信

**AI 流式输出只是 SSE 的最简用法。**

还需要：

- 实时进度（批量任务跑到第几条）
- 消息推送（有新消息立刻显示）
- 多人协作（两个人同时编辑，冲突怎么办）
- 断线重连（网络断了自动恢复）

**不会这个，很多需求你只能做"刷新页面才能看到"。**

### 8. W23 通知与送达

**验证码进垃圾箱 = 产品坏了。**

- 邮件要配 SPF/DKIM/DMARC，否则被判垃圾邮件
- 短信模板要提前报备审核
- 发送失败要重试，要能查送达状态

**这一周的东西不起眼，但它是"用户能不能注册成功"的直接决定因素。**

### 9. W29 Docker + W30 CI/CD

**这两个是"工程基本功"，不该等到私有化部署才学。**

- **Docker**：「我本地能跑，服务器上不行」这个问题，90% 靠它解决
- **CI/CD**：你现在每次部署都 SSH 上去 `git pull` 再手动重启。一天三次就是三遍手工作业，每次都可能出错

**一人公司没有运维，能自动化的必须自动化。**

## 三条铁律

**一、每天 commit + push**

`commit` 是本地快照，`push` 才是备份。**只 commit 不 push 等于没备份。**

收工打 `git status`，看到 `ahead` 就是没推。

**二、`docs` 不要改**

它是刻度。

**三、`NOTES.md` 比代码重要**

代码 AI 三秒能重写，你踩过的坑只有你自己知道。

- 后台管理、文件图片处理、Excel、支付、多租户、小程序

**不会**：训练模型、微调、大规模分布式、复杂前端视觉设计、融资招人。
