# 一人公司 AI 开发 · 175 天完整路线

起点 2026-11-15 · 终点 2027-05-08 · 25 周 · 每天 60–120 分钟

---

## 这份路线要解决什么

不是"学会写代码"。是**一个人把一个项目从想法做到收到钱**。

会写代码的人很多，能把项目交付出去、还能收钱的人很少。差别不在技术难度，在于**一串没人告诉你的必备项**：数据从哪来、文档怎么解析、登录、支付、私有化、小程序、部署、安全、合同。

这份路线把它们全排进去了。**175 天，25 周，一个不落。**

---

## 排序的三个原则

**原则一：每周必须有能看见的产出**

不能出现"这周学理论，下周才能做东西"。看不见进展的学习，三天就放弃。

**原则二：依赖在前面，应用在后面**

不能先学支付再学数据库。每个技术只出现在它被需要的那一刻。

**原则三：抽象的东西往后放**

前端能看见、AI 能对话，这两块最先做。评测、工程化、安全这些看不见的，放在你已经有东西可测、可改、可保护之后。

## 九个阶段，读懂为什么这么分

### 阶段一：能看见（W1–W2，Day 1–14）

网页 → 后端 → 连起来 → 存数据库 → 接模型 → 上线

**为什么从这里开始**：你需要看到东西。写后端、写算法，跑完屏幕上一行字都没有，你不知道自己做对没有。

**结束时**：你有一个真的能对话的 AI 应用，别人点链接就能用。

### 阶段二：能用（W3–W5，Day 15–35）

提示词 → 结构化 → 成本 → 流式 → 登录

**为什么紧接着**：第一阶段的产物只是"能回话"。**能回话的东西任何人两天能做出来，不值钱。** 值钱的是"回得准、不烧钱、像产品、知道谁在用"。

### 阶段三：有数据（W6–W9，Day 36–63）**最关键，也最容易被忽略**

**抓数据** → **文档解析** → **检索** → **工具与 Agent**

**为什么单独给四周**：因为 AI 应用的瓶颈从来不是模型，是数据。

客户说"让 AI 懂我们的知识"，你问"知识在哪"，答案永远是这几种：

- "在我们的网站上" → 要爬
- "在这 300 个 PDF 里" → 要解析
- "在我们的数据库里" → 要对接
- "在老王的脑子里" → 没辙，得访谈整理

**你手上没有干净数据，后面再强的模型也白搭。**

这一阶段的顺序是死的：**先拿到数据（W6），再解析成文字（W7），再让它可被检索（W8），最后让 AI 用这些数据做事（W9）**。

### 阶段四：能测能扩（W10–W15，Day 64–105）

异步 → 评测 → 可靠 → 工程化 → 性能 → 多模态

**这六周是"从玩具到产品"的距离**：

- 不处理异步 → 长任务一跑就超时
- 不做评测 → 改一处坏三处，还发现不了
- 不做可靠 → 模型一挂，客户投诉
- 不分层 → 加第十个功能就崩
- 不做性能 → 数据一万条就卡
- 不支持图片语音 → 一半场景做不了

**这六周最没人愿意做，但它们决定了你的东西能不能活到客户上线。**

### 阶段五：能卖（W16–W19，Day 106–133）

多租户 → 文件/支付 → 平台集成 → 前端进阶

**为什么集中在这一段**：这四周的内容是**客户一定会问、但纯技术路线里没有的**。

"能加第二家客户吗""能导 Excel 吗""能收费吗""能在企业微信里用吗""手机上能用吗"

**这几个问题，任何一个答不上来，单子就谈不成，或者谈成了做不完。**

### 阶段六：能上线（W20–W22，Day 134–154）

服务器 → 域名/HTTPS/监控/备份 → 安全合规

**为什么放这里**：得先有东西可部署。空着服务器学 Nginx，配置改错了也不知道哪错了。

**但有一件事必须提前**：如果你的服务器在国内，**域名备案要 7–20 个工作日**。不能等 Day 141 才去想。见 `02-部署上线.md`。

### 阶段七：能进大客户（W23–W24，Day 155–168）

小程序/公众号 → 私有化部署

**这两周决定你的客单价上限。**

- **W23**：客户说"要在微信里用"是高频需求。但先判断清楚——90% 的情况 PWA 就够，成本差十倍。
- **W24**：国企、政府、医院、军工会明确要求"数据不能出内网"。**这类单单价最高，但门槛就在私有化。**

### 阶段八：能交付（W25，Day 169–175）

文档、验收、合同、报价、收款、完整演练

**为什么单独一周**：因为"会做"和"能收钱"之间隔着七天的活：写文档、定验收标准、谈付款节点、准备演示。

**这一周不产出代码，但它决定你前面 168 天能不能变现。**

## 每天固定五块

每一份 `TASK.md` 都有这五块，不增不减：

1. **学** —— 一句原理，看懂就行，不用背
2. **做** —— 编号步骤，每步写清点哪里、输什么、看什么，**并说明这一步的目的**
3. **你会看到什么** —— 自检，判断自己走对了没有
4. **可能出错** —— 表格：现象 / 原因 / 怎么办
5. **老板视角** —— 一句话讲清这个技术点对应的管理判断

2. **做** 在同一个文件夹里写代码
3. **写** `dNN/NOTES.md`：今天做了什么 / 卡在哪 / 怎么解决的
4. **交** VS Code 左侧第三个图标 → 写 `dNN: 主题` → 点 `✓` → **点同步**

## 三条铁律

**一、每天 commit + push**

`commit` 是本地快照，`push` 才是备份。**只 commit 不 push，等于没备份。**

收工打一句 `git status`，看到 `ahead` 就是没推。

**二、`docs` 不要改**

它是刻度。改了就没法对照自己有没有偏离。

**三、`NOTES.md` 比代码重要**

代码 AI 三秒能重写，你踩过的坑只有你自己知道。

## 175 天后你会什么、不会什么

**会**：

- 独立做出一个能上线的 AI 应用：有登录、有流式、有数据库、能识图
- **自己搞数据**：调 API、写爬虫、解析 PDF、清洗、增量更新
- 让 AI 懂客户的私有资料，能调工具、能自己完成多步任务
- 用数字证明改动是好是坏，知道该选哪个模型
- 数据量涨十倍也不卡
- 接支付、导 Excel、接飞书企微、做多租户
- 做小程序、接微信登录和支付
- **交付私有化部署**（数据不出客户内网）
- 部署到服务器，配域名、开 HTTPS、做备份和监控
- 通过基本的安全检查
- 把项目写成文档交给别人，还能验收回来
- 算出任何一个 AI 功能的单次成本，报出一个不亏的价

**不会**：

- 训练模型、微调、推理优化、算法研究
- 大规模分布式架构（几万台机器那种）
- 复杂前端动效和视觉设计

**这些你都不需要。你要的是"把数据搞到手，把模型用对地方，把项目交出去，把钱收回来"。**

**最后一句诚实话**：175 天给你的是"能独立完成一个真实商业项目的完整闭环"。真正的成熟来自第一个真实客户、第一次翻车、第一次自己判断对了。**所以 Day 175 之后别停，立刻接一个真活。**
