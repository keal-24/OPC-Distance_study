# 基础设施手册 · 域名 / 服务器 / 电脑 / 部署

> 这份手册解决一件事：**你的代码在你自己电脑上跑通了，怎么让全世界的人都能用。**
>
> 这个跨越里有六个环节，每一个都能单独卡你三天。**先看懂全貌，再逐个动手。**

# 第一部分 · 先看清全貌：一个网址是怎么变成页面的

你在浏览器输入 `https://你的域名.com`，按下回车，中间发生了什么：

```
浏览器
  ↓ ① DNS 查询：这个域名对应哪台电脑？
DNS 服务器（把域名翻译成 IP 地址）
  ↓ ② 得到 IP，比如 47.98.xx.xx
  ↓ ③ 建立 TCP 连接 + TLS 握手（HTTPS 的加密协商）
云服务器（一台一直在运行的电脑）
  ↓ ④ Nginx 收到请求，按规则转发
你的 Node.js 程序（后端）
  ↓ ⑤ 处理、查数据库、调模型
  ↓ ⑥ 返回结果
浏览器渲染成页面
```

**六步，六个可能出错的地方。** 用户看到的永远只有一句"打不开"——**你要能判断是哪一步断了。**

| 步骤 | 出错时的现象 | 谁负责 |
|---|---|---|
| ① DNS 解析 | 浏览器说"找不到服务器" / `DNS_PROBE_FINISHED_NXDOMAIN` | 域名商 / 解析配置 |
| ② 拿到 IP | 同上 | 同上 |
| ③ 建立连接 | "连接超时" / `ERR_CONNECTION_TIMED_OUT` | 防火墙 / 安全组 |
| ④ Nginx 转发 | 404 / 502 / 504 | Nginx 配置 |
| ⑤ 程序处理 | 500 / 页面转圈 | 你的代码 |
| ⑥ 返回 | 页面错乱 / CORS 报错 | 你的代码 |

> **这张表比这份手册后面的所有内容都重要。**
>
> 以后客户说"网站打不开"，你不是靠猜，是**按这六步从上往下查**。每查一步，范围就缩小一层。

# 第二部分 · 域名

## 域名是什么

**大白话：你网站的门牌号。**

`api.qiancan.cc` 这个域名，拆开看：

```
api . qiancan . cc
 │      │        └── 顶级域名（.cc / .com / .cn）
 │      └─────────── 二级域名（你自己起的名字）
 └────────────────── 三级域名（子域名，可无限加）
```

**`qiancan.cc` 是你买的，`api.qiancan.cc` 是你在它下面自己加的一个子域名，不用另外花钱。**

## 域名的三层结构，决定了成本

| 层级 | 例子 | 要不要备案 | 大概价格 |
|---|---|---|---|
| **顶级域名（.com）** | `example.com` | 用国内服务器必须备案 | 60-100 元/年 |
| **.cn 域名** | `example.cn` | 必须备案 | 30-50 元/年 |
| **.cc / .io / .ai** | `example.cc` | 用国内服务器必须备案 | 100-500 元/年 |

> **`.cc` 是你现在用的。** 它属于"国别域名"（其实是科科斯群岛的），但在国内可以正常注册使用。**价格比 `.com` 贵一些，好处是短、好记。**

## 在哪买

| 平台 | 特点 | 适合 |
|---|---|---|
| **腾讯云 / 阿里云** | 国内最大，和服务器同平台，解析方便 | **推荐。你现在用的腾讯云生态** |
| **Cloudflare** | 全球最便宜，但国内访问慢 | 纯海外业务 |
| **Namesilo / Porkbun** | 便宜，但要外币支付 | 有外币卡的人 |

**建议：域名和服务器在同一家买。** 解析配置、备案、续费都在一起，省事。

## DNS 解析：域名怎么指向服务器

**买了域名只是"拥有这个名字"，还得告诉全世界"这个名字对应哪台电脑"。这一步叫解析。**

在域名管理后台，加一条 **A 记录**：

| 类型 | 主机记录 | 记录值 | 含义 |
|---|---|---|---|
| A | `@` | `47.98.xx.xx` | `你的域名.com` 本身 |
| A | `www` | `47.98.xx.xx` | `www.你的域名.com` |
| A | `api` | `47.98.xx.xx` | `api.你的域名.com` |

> **`@` 是"根域名"的意思**，就是不带任何前缀的那个。
>
> **记录值填服务器的公网 IP。** 填错一个数字，域名就指向别人家去了。

**常用的几种记录类型：**

| 类型 | 填什么 | 干什么用 |
|---|---|---|
| **A** | IPv4 地址 | 最常用，指向服务器 |
| **AAAA** | IPv6 地址 | 指向 IPv6 |
| **CNAME** | 另一个域名 | 别名，比如把 `www` 指向 `xxx.vercel.app` |
| **TXT** | 一段文本 | **验证域名所有权**（申请证书、接入第三方服务时用） |
| **MX** | 邮件服务器地址 | 收邮件（`@你的域名.com` 邮箱） |

> **TXT 记录你一定会用到。** 申请免费 SSL 证书、把域名接入 Vercel / Cloudflare、验证 Google 搜索控制台，**都是加一条 TXT 记录**。它的作用就是证明"这个域名真是你的"。

**解析生效要多久：**

- 通常 10 分钟到 2 小时
- **最长 48 小时**（老域名的旧记录缓存时间可能很长）
- 检查方法：`ping 你的域名.com`，看返回的 IP 对不对

> **这里有个坑**：改了 DNS 之后，你本地可能还是访问到旧地址，因为**你电脑和运营商有 DNS 缓存**。
>
> 清缓存：Windows 里跑 `ipconfig /flushdns`；或者直接用手机 4G 测（不走同一缓存）。

## 备案：这一条是硬门槛

**服务器在中国大陆境内，域名必须备案。没有例外。**

| 情况 | 要不要备案 |
|---|---|
| 服务器在**中国大陆**（阿里云/腾讯云/华为云的国内机房） | **必须备案** |
| 服务器在**香港** | 不需要（但访问速度稍慢） |
| 服务器在**海外**（新加坡/美国/日本） | 不需要（但国内访问慢） |
| 只是本地开发（`localhost`） | 不需要 |

**备案要什么：**

- 身份证、手机号
- **一个已经实名认证的域名**
- 服务器（备案需要服务器的"备案服务码"，买服务器时给）
- 网站名称、内容说明
- 时间：**7 到 20 个工作日**

> **为什么我强调这一条**：因为很多人买了服务器，代码也写好了，最后卡在备案上，白白等两周。
>
> **备案期间网站不能对外访问。** 所以你要么提前办，要么先用香港/海外服务器过渡。

**最省事的路径**（如果你的目标客户在国内）：

```
1. 买域名（腾讯云）
2. 买国内轻量应用服务器（2核2G 起）
3. 立刻提交备案（用服务器给的备案码）
4. 备案期间用 localhost + 香港服务器做开发测试
5. 备案下来后指向国内服务器
```

> **你已经有 `api.qiancan.cc`，说明域名和服务器这套你已经走通过一次。** 那份经验比你想象的值钱——很多人第一次接活，客户问"要不要备案"，他答不上来。

## 子域名可以随便加

**你买了一个域名，能无限加子域名，不另外花钱：**

```
qiancan.cc              主站
api.qiancan.cc          你的中转服务
admin.qiancan.cc        后台管理
demo.qiancan.cc         给客户看的演示
client-a.qiancan.cc     A 客户的项目
client-b.qiancan.cc     B 客户的项目
```

**这是个很实用的技巧**：给小客户交付时，用 `客户名.你的域名.com` 就能上，不用每个都买域名。

> **但要注意**：备案是**按域名备的**，子域名不用单独备。所以你的主域名备过案，所有子域名都能用。

# 第三部分 · 服务器

## 服务器是什么

**大白话：一台永远开着、有公网 IP 的电脑，放在机房里。**

没有显示器、没有键盘，你只能通过网络远程操作它。

## 你电脑 vs 服务器，差别在哪

| | 你的电脑 | 服务器 |
|---|---|---|
| 关机 | 随时可以 | **不能关**（关了网站就打不开） |
| IP | 动态，每次重连都变 | **固定公网 IP** |
| 操作系统 | Windows | **几乎都是 Linux** |
| 操作方式 | 鼠标点 | **只能打命令（SSH）** |
| 谁在用 | 你一个人 | 可能几千人同时 |

> **"只能打命令"这一条是最大的门槛。** 但别怕——你前面十天在 Git Bash 里敲的 `cd`、`ls`、`pwd`、`node`，**在服务器上一模一样能用**。
>
> 你已经在练了，只是没意识到。

## 买什么配置

| 用途 | 配置 | 大概价格 |
|---|---|---|
| **学习 / 小项目 / 个人用** | 2 核 2G，40G 硬盘 | **60-100 元/月**（或年付 300-600） |
| 小客户项目（几十人用） | 2 核 4G，60G | 100-200 元/月 |
| 中等流量 | 4 核 8G | 300-500 元/月 |

> **起步就用最低配。** 你的 AI 应用主要开销不在服务器（AI 是调 API，不是本地跑模型），**2 核 2G 足够撑几十个用户。**
>
> **钱要花在模型调用上，不是服务器上。** 这个判断很重要——很多人一上来就买 8 核 16G，结果钱全浪费了。

**买哪种产品：**

| 类型 | 特点 | 建议 |
|---|---|---|
| **轻量应用服务器** | 便宜、配置简单、带宽包月 | **推荐起步用这个** |
| 云服务器 CVM/ECS | 灵活、可扩展、按量计费 | 业务稳定后再换 |
| 虚拟主机 | 只能放静态网页，不能跑 Node | ❌ 不能用于你的项目 |

> **虚拟主机不行。** 你的项目要跑 Node.js 常驻进程，虚拟主机只支持 PHP 或静态文件。**买之前确认支持 Node。**

## Linux 基础：只需要 10 个命令

**不要被"Linux"吓到。你在服务器上要做的事，10 个命令全覆盖。**

| 命令 | 干什么 | 例子 |
|---|---|---|
| `pwd` | 我在哪个目录 | `pwd` |
| `ls` | 这个目录有什么 | `ls -la` |
| `cd` | 进某个目录 | `cd /root/app` |
| `mkdir` | 建目录 | `mkdir app` |
| `nano` | 编辑文件（最简单的编辑器） | `nano server.js` |
| `cat` | 看文件内容 | `cat package.json` |
| `rm` | 删文件 | `rm 文件名` |
| `ps aux` | 看有哪些程序在跑 | `ps aux \| grep node` |
| `kill` | 停掉某个程序 | `kill 12345`（12345 是 PID） |
| `df -h` | 看硬盘还剩多少 | `df -h` |

> **`nano` 的用法**：打开后直接打字，`Ctrl + O` 保存，`Enter` 确认文件名，`Ctrl + X` 退出。
>
> **这五个键你要记住。** 因为服务器上没有 VS Code，你只能用它改配置文件。

## SSH：怎么连上服务器

**SSH = 远程登录。一条命令就进去了。**

```
ssh root@47.98.xx.xx
```

- `root` 是用户名（服务器默认最高权限账号）
- `@` 后面是服务器 IP
- 第一次连接会问 `yes/no`，输 `yes`
- 然后输密码（**输入时屏幕不显示任何东西，这是正常的，不是卡住了**）

> **"输入密码屏幕没反应"是新手第一个困惑。** Linux 就是这样设计的（防止别人看到你输了几位）。**盲打完回车就行。**

**更安全的做法：用密钥登录（免密码）**

```
# 在你本地电脑上生成密钥对
ssh-keygen -t rsa

# 把公钥传到服务器
ssh-copy-id root@47.98.xx.xx
```

> **密码登录的风险**：服务器暴露在公网上，**每天有几百次暴力破解尝试**。用密钥登录能挡掉 99%。
>
> **你以后要长期运营服务器，这一步必须做。** 否则某天你会发现服务器被人登进去装了挖矿程序。

## 防火墙 / 安全组：最容易卡住的地方

**云服务器默认把所有端口都关掉，只留 22（SSH）。**

**所以你把程序跑起来了，外面还是访问不到。**

要在云控制台的"安全组"或"防火墙"里开端口：

| 端口 | 用途 | 要不要开 |
|---|---|---|
| 22 | SSH | 必开（通常默认开） |
| 80 | HTTP | **必开** |
| 443 | HTTPS | **必开** |
| 3000 | 你的 Node 服务 | ❌ **不要开给公网** |
| 3306 / 5432 | 数据库 | ❌ **绝对不要开** |

> **为什么 3000 不要开**：应该让 Nginx 在 80/443 接收请求，再转发到本地的 3000。**直接暴露 3000 意味着别人能绕过 Nginx 的攻击防护直连你的程序。**
>
> **数据库端口绝对不要开。** 这是被入侵的头号原因——开放 3306 的服务器，通常几小时内就会被扫到并暴力破解。

**症状对照：**

| 现象 | 原因 |
|---|---|
| `ssh` 连不上，超时 | 22 端口没开 / IP 填错 |
| SSH 能连，但浏览器打不开网站 | 80/443 没开 |
| 浏览器能打开但显示"拒绝连接" | 端口开了，但程序没跑 / 跑在别的端口 |

# 第四部分 · 部署：让代码在服务器上跑起来

## 部署的本质

**大白话：把你的代码传到服务器上，让它一直在跑。**

三件事：

1. **传上去**（Git clone 或 scp）
2. **装依赖**（`npm install`）
3. **让它常驻**（不能关了 SSH 就停）

## 第一步：传代码

**最推荐：用 Git**

```bash
# 在服务器上
git clone https://github.com/keal-24/你的仓库.git
cd 你的仓库
```

> **为什么用 Git 而不是直接上传文件**：因为以后更新只需 `git pull`，不用重新传一遍。**而且能回滚到任何版本。**
>
> **注意**：`.env` 不在 Git 里（正确），所以服务器上要**手动建一个** `.env`。这是安全的代价，必须接受。

**另一种：scp（直接传文件）**

```bash
# 在你本地电脑上跑
scp -r ./你的项目 root@47.98.xx.xx:/root/
```

> **`scp` = secure copy，通过 SSH 传文件。** 适合传小文件、配置文件。**不适合传整个项目**（`node_modules` 几百 MB，传一次几十分钟）。

## 第二步：装依赖

```bash
cd /root/你的项目
npm install
```

> **服务器上也可能慢。** 换源：
>
> ```bash
> npm config set registry https://registry.npmmirror.com
> ```

## 第三步：让它常驻（关键）

**问题：你在 SSH 里跑 `node server.js`，一关窗口，服务就停了。**

**因为 SSH 会话结束，它启动的所有进程都会被终止。**

**解法一：pm2（推荐，简单）**

```bash
npm install -g pm2
pm2 start server.js --name my-app
pm2 save
pm2 startup
```

| 命令 | 干什么 |
|---|---|
| `pm2 start server.js --name my-app` | 启动，起个名字 |
| `pm2 list` | 看所有在跑的应用 |
| `pm2 logs my-app` | 看日志 |
| `pm2 restart my-app` | 重启 |
| `pm2 stop my-app` | 停止 |
| `pm2 save` | **保存当前状态** |
| `pm2 startup` | **设置开机自启** |

> **`pm2 save` + `pm2 startup` 这两条必须都做。**
>
> - `save` 记住"现在跑着哪些"
> - `startup` 让服务器重启后自动恢复
>
> **只做 `save` 不做 `startup`**，服务器重启（比如云厂商维护）后网站就挂了，而且你可能几小时后才发现。

**解法二：Docker（更规范，但学习成本高）**

```bash
docker build -t my-app .
docker run -d -p 3000:3000 --name my-app my-app
```

> **Docker 的好处**：环境完全一致，"我本地能跑"的问题彻底消失。
> **坏处**：要学 Dockerfile、镜像、卷挂载。**Week 9 再考虑，现在用 pm2 就够。**

## 第四步：Nginx 反向代理（让 80 端口指向你的 3000）

**为什么需要**：你的程序跑在 3000，但用户访问的是 `http://你的域名`（80 端口）。

**Nginx 就是那个"接线员"**：接收 80 端口的请求，转给本地的 3000。

**安装：**

```bash
apt update
apt install nginx -y
```

**配置**（`/etc/nginx/sites-available/default`）：

```nginx
server {
    listen 80;
    server_name 你的域名.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

**然后：**

```bash
nginx -t          # 检查配置对不对
systemctl reload nginx   # 重载配置
```

> **`nginx -t` 必须跑。** 配置写错了 `reload` 会失败，而且失败时 Nginx 会继续用旧配置跑——**你以为改了，其实没生效。**

**`proxy_pass http://127.0.0.1:3000`** 的意思是"转给本机的 3000 端口"。**用 `127.0.0.1` 不是 `localhost`，也不是公网 IP** —— 因为我们只让本机能访问，不给外面开。

## 第五步：HTTPS（必须做，不能省）

**没有 HTTPS 的后果：**

- 浏览器地址栏显示"不安全"，客户看了就慌
- **用户输入的任何东西都是明文传输**，中间任何一跳都能看到
- 很多 API（包括模型接口）**强制要求 HTTPS**
- 微信小程序、PWA 都要求 HTTPS

**免费方案：Let's Encrypt**

```bash
apt install certbot python3-certbot-nginx -y
certbot --nginx -d 你的域名.com
```

**它会自动做三件事**：申请证书、改 Nginx 配置、设置自动续期（90 天）。

> **`certbot --nginx` 是最省事的做法。** 不用手动下载证书、不用手动改配置。**跑完就有 HTTPS 了。**

**验证：** 浏览器打开 `https://你的域名.com`，地址栏有锁图标就成功。

> **证书 90 天过期，但 certbot 装了自动续期任务。** 检查方法：
>
> ```bash
> certbot renew --dry-run
> ```
>
> 这条会模拟续期一次，不真改。**没有报错，说明自动续期正常。**

# 第五部分 · 你的开发电脑

## 需要什么配置

| 用途 | 最低 | 舒服 |
|---|---|---|
| 学前端 + Node | 8G 内存，4 核 | 16G 内存 |
| 同时开 VS Code + 浏览器 + 两个服务 + Docker | 16G | **32G** |
| 跑本地大模型 | 32G + 独显 | 不推荐（成本高、效果差） |

> **你现在这台是 31G 内存**（我之前查过），**完全够用，不用升级。**
>
> **不要为了"学 AI"去买显卡。** 你调的是云端 API，本地不需要 GPU。**这是最常见的浪费。**

**硬盘**：至少留 50G 空闲。`node_modules` 一个项目就几百 MB，几十个项目加起来很可观。

## Windows 上的三个选择

| 方案 | 优点 | 缺点 |
|---|---|---|
| **原生 Windows** | 和客户环境一致，你熟悉 | 命令行是 PowerShell，和 Linux 有差异 |
| **WSL2** | 真 Linux，命令和服务器完全一致 | 要额外学一点 |
| **虚拟机** | 隔离干净 | 慢，吃内存 |

> **你现在用原生 Windows + Git Bash，够用。**
>
> **什么时候该上 WSL2**：当你开始部署、需要频繁改 Nginx 配置、或者某个包只支持 Linux 时。
>
> **判断标准**：如果你发现"本地能跑、服务器上不行"反复出现，就该上 WSL2 了。**那样本地环境和服务器就是同一个系统。**

## Mac 为什么常见

**做开发的人爱用 Mac，原因很实际：**

1. **底层就是 Unix**，命令和 Linux 服务器几乎一样
2. **不用装 Git Bash / WSL**，终端直接能用
3. **Docker 原生支持**（不用虚拟机）
4. 生态好，大部分工具优先支持

> **但这不是必须的。** Windows 现在完全够用（WSL2 补上了最后一块）。
>
> **如果你要买新电脑，做开发确实 Mac 更省事。** 但**别为了"学编程"专门买**——你现在这台完全能做完这 70 天。

# 第六部分 · 其他会用到的基础设施

## 对象存储：图片和文件放哪

**问题**：用户上传的图片、PDF、音频，**不能放在服务器硬盘上**。

**为什么不能：**

- 服务器硬盘有限（40G），几十个用户就满了
- 服务器挂了，文件全丢
- 用户下载要走你的服务器带宽，**带宽很贵**

**正确做法：对象存储**

| 服务 | 厂商 | 价格 |
|---|---|---|
| COS | 腾讯云 | 几毛钱/GB/月 |
| OSS | 阿里云 | 同上 |
| R2 | Cloudflare | 便宜，且**下载不收流量费** |
| Supabase Storage | Supabase | **你已经有了，100MB 免费** |

> **你现在用 Supabase，Storage 直接就能用**，不用另开服务。**做第一个带图片的功能时用它。**

**流程是**：用户上传 → 你的后端把文件传到对象存储 → 存储返回一个 URL → 数据库存这个 URL → 前端用 URL 显示图片。

> **为什么不直接把图片存成 base64 塞进数据库**：因为数据库会暴涨、查询变慢、备份变笨重。**文件归文件存储，数据归数据库。这条要分开。**

## CDN：让全国访问都快

**问题**：你的服务器在深圳，东北的用户访问要绕一圈，慢。

**CDN = 内容分发网络。** 把静态文件（图片、CSS、JS）复制到全国几十个节点，用户就近下载。

| 服务 | 价格 |
|---|---|
| 腾讯云 CDN / 阿里云 CDN | 按流量，约 0.2 元/GB |
| Cloudflare | **免费版够用** |

> **什么时候需要 CDN**：用户分布在多地、并且有大量静态资源时。
>
> **什么时候不需要**：几十个用户、没有大图片。**不要过早优化。**

> **注意**：Cloudflare 免费版在中国大陆访问较慢（节点在境外）。**如果客户在国内，用腾讯云/阿里云 CDN。**

## 监控和告警：挂了要知道

**这一条最容易被忽略，但最要命。**

**你不可能 24 小时盯着网站。** 服务器挂了、证书过期了、程序崩了——**你得被动收到通知，而不是等客户打电话骂你。**

| 工具 | 干什么 | 成本 |
|---|---|---|
| **UptimeRobot** | 每 5 分钟访问一次你的网站，挂了发邮件/短信 | **免费版够用** |
| 腾讯云监控 / 阿里云监控 | 服务器 CPU、内存、磁盘告警 | 随服务器附送 |
| Sentry | 代码报错自动上报（带堆栈） | 免费额度够小项目 |

> **最少要配一个 UptimeRobot。** 免费版能监控 50 个站点，5 分钟一次。
>
> **这是"专业"和"业余"的分界**：业余的等客户发现问题，专业的在客户之前就知道。

## 备份：数据丢了怎么办

**三条原则：**

1. **自动，不要靠手动**（手动的都会忘）
2. **异地**（备份和原件不在同一台机器）
3. **定期测试恢复**（没测过的备份等于没备份）

**Supabase 免费版**：可能没有自动备份，**去 `Project Settings` → `Database` 确认**。

**如果没备份，两条路：**

- 升级到付费版（有每日备份）
- **自己写个定时任务导出**（免费方案）：

```javascript
// 每天凌晨跑一次，导出数据到本地文件
const { data } = await supabase.from("messages").select("*")
require("fs").writeFileSync(
  `backup-${new Date().toISOString().slice(0,10)}.json`,
  JSON.stringify(data)
)
```

> **这个脚本你今天就能写。** 二十分钟的事，但**能救你的命**。

# 第七部分 · 成本怎么算（接活必用）

**客户问"一年要花多少钱"，你要能当场报出来。**

以一个"AI 聊天应用，50 个用户，每天 200 次对话"为例：

| 项目 | 单价 | 用量 | 月成本 |
|---|---|---|---|
| 服务器（2核2G） | 80 元/月 | 1 台 | **80 元** |
| 域名 | 80 元/年 | 1 个 | ~7 元 |
| SSL 证书 | 免费（Let's Encrypt） | — | 0 |
| 数据库（Supabase 免费版） | 0 | — | 0（超了 $25/月） |
| 模型调用 | 按 token | 200 次/天 × 30 天 × ~1000 token | **看模型** |
| 对象存储 | 0.1 元/GB | 几 GB | ~1 元 |
| **合计（不含模型）** | | | **约 90 元/月** |

**模型费用是变量，要单独算：**

```
月成本 = 每天次数 × 30 × 每次平均 token × 单价
```

**举例**（假设某个模型输入 1 元/百万 token，输出 3 元/百万 token）：

```
每天 200 次
每次输入 800 token、输出 300 token
每月输入 = 200 × 30 × 800 = 4,800,000 token = 4.8 百万
每月输出 = 200 × 30 × 300 = 1,800,000 token = 1.8 百万
月成本 = 4.8 × 1 + 1.8 × 3 = 4.8 + 5.4 = 10.2 元
```

> **这个例子里模型费用很便宜**（10 块一个月）。**但要注意**：如果每次对话带 20 条历史，输入 token 会翻 5-10 倍。
>
> **真实的成本大头永远是模型，不是服务器。** 你报服务器 80 块，客户觉得合理；你不提模型费，最后自己吃。

**报价的三个必须写清的：**

1. **开发费**（一次性的）
2. **服务器/域名**（每月固定，客户自己付还是你代付）
3. **模型费**（按量，谁付？**这是最容易扯皮的**）

# 附 · 遇到"网站打不开"怎么查（八步）

**照着顺序走，不要跳。**

| 步 | 查什么 | 命令 / 操作 | 说明 |
|---|---|---|---|
| 1 | DNS 解析对不对 | `ping 你的域名.com` | 返回的 IP 是不是你的服务器？不是就是解析没生效或填错 |
| 2 | 服务器活着吗 | `ping 服务器IP` | 不通 → 服务器关了 / IP 变了 |
| 3 | SSH 能进吗 | `ssh root@IP` | 进不去 → 22 端口 / 防火墙 / 密码错 |
| 4 | 程序在跑吗 | `pm2 list` 或 `ps aux \| grep node` | 没在跑 → `pm2 start` |
| 5 | 程序能本地访问吗 | 在服务器上 `curl localhost:3000` | 不通 → 程序本身有问题 |
| 6 | Nginx 活着吗 | `systemctl status nginx` | 挂了 → `systemctl start nginx` |
| 7 | Nginx 配置对吗 | `nginx -t` | 报错 → 按提示改 |
| 8 | Nginx 转发对吗 | `curl -I http://localhost` | 502 → 转发地址错；404 → `server_name` 不匹配 |

> **这八步的顺序是有道理的：从外往里。**
>
> 大多数人反过来——一上来就看代码。**结果查了两小时代码，发现是域名解析填错了一个数字。**
>
> **先确认"请求有没有到达你的程序"。这一步不通，后面的代码一行都不用看。**
