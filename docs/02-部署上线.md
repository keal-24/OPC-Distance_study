# 部署上线 · 让全世界都能用

> 代码在你自己电脑上跑通了，怎么让别人也能打开。
>
> **这个跨越里有六个环节，每一个都能单独卡你三天。先看懂全貌，再逐个动手。**

## 一、一个网址是怎么变成页面的

你在浏览器输入 `https://你的域名.com` 按回车，中间发生六件事：

```
浏览器
  ↓ ① DNS 查询：这个域名对应哪台电脑？
DNS 服务器（把域名翻译成 IP）
  ↓ ② 拿到 IP，比如 47.98.xx.xx
  ↓ ③ 建立连接 + HTTPS 加密协商
云服务器（一台一直在运行的电脑）
  ↓ ④ Nginx 收到请求，按规则转发
你的 Node.js 程序
  ↓ ⑤ 处理、查数据库、调模型
  ↓ ⑥ 返回结果
浏览器渲染成页面
```

**六步，六个可能出错的地方。用户看到的永远只有一句"打不开"。你要能判断是哪一步断了。**

| 步骤 | 出错时的现象 | 谁负责 |
|---|---|---|
| ① DNS 解析 | "找不到服务器" / `DNS_PROBE_FINISHED_NXDOMAIN` | 域名商 / 解析配置 |
| ② 拿到 IP | 同上 | 同上 |
| ③ 建立连接 | "连接超时" / `ERR_CONNECTION_TIMED_OUT` | 防火墙 / 安全组 |
| ④ Nginx 转发 | 404 / 502 / 504 | Nginx 配置 |
| ⑤ 程序处理 | 500 / 页面转圈 | 你的代码 |
| ⑥ 返回 | 页面错乱 / CORS 报错 | 你的代码 |

> **这张表比后面所有内容都重要。**
>
> 客户说"网站打不开"，你不是靠猜，是**按这六步从上往下查**。每查一步，范围就缩小一层。

## 二、域名

### 域名是什么

**大白话：你网站的门牌号。**

`api.qiancan.cc` 拆开看：

```
api . qiancan . cc
 │      │        └── 顶级域名（.cc / .com / .cn）
 │      └─────────── 二级域名（你自己起的名字）
 └────────────────── 三级域名（子域名，可无限加）
```

**`qiancan.cc` 是你买的。`api.qiancan.cc` 是你在它下面自己加的子域名，不另外花钱。**

### 三种域名的成本

| 类型 | 例子 | 用国内服务器要备案吗 | 价格 |
|---|---|---|---|
| .com | `example.com` | 要 | 60–100 元/年 |
| .cn | `example.cn` | 要 | 30–50 元/年 |
| .cc / .io / .ai | `example.cc` | 要 | 100–500 元/年 |

### 在哪买

**域名和服务器在同一家买。** 解析、备案、续费都在一起，省事。

腾讯云 / 阿里云都行。**Cloudflare 便宜但国内访问慢**，不适合给国内客户。

### DNS 解析：域名怎么指向服务器

买了域名只是"拥有这个名字"，还得告诉全世界"这个名字对应哪台电脑"。这一步叫解析。

在域名管理后台加 **A 记录**：

| 类型 | 主机记录 | 记录值 | 含义 |
|---|---|---|---|
| A | `@` | `47.98.xx.xx` | `你的域名.com` 本身 |
| A | `www` | `47.98.xx.xx` | `www.你的域名.com` |
| A | `api` | `47.98.xx.xx` | `api.你的域名.com` |

> **`@` 是"根域名"，就是不带任何前缀的那个。** 记录值填服务器的公网 IP，填错一个数字就指向别人家去了。

**五种记录类型，各干什么：**

| 类型 | 填什么 | 什么时候用 |
|---|---|---|
| **A** | IPv4 地址 | **最常用**，指向服务器 |
| **AAAA** | IPv6 地址 | 指向 IPv6 |
| **CNAME** | 另一个域名 | 别名，把 `www` 指向 `xxx.vercel.app` |
| **TXT** | 一段文本 | **验证域名所有权**（申请证书、接入第三方） |
| **MX** | 邮件服务器 | 收邮件 |

> **TXT 你一定会用到。** 申请免费 SSL 证书、把域名接入 Vercel/Cloudflare、验证 Google 搜索控制台，**全是加一条 TXT 记录**。它的作用就是证明"这个域名真是你的"。

**生效时间**：通常 10 分钟到 2 小时，**最长 48 小时**。

检查方法：`ping 你的域名.com`，看返回的 IP 对不对。

> **有个坑**：改了 DNS 之后你本地可能还是旧地址，因为**你电脑和运营商有 DNS 缓存**。清缓存跑 `ipconfig /flushdns`，或者用手机 4G 测（不走同一缓存）。

### 备案：这条是硬门槛

**服务器在中国大陆境内，域名必须备案。没有例外。**

| 情况 | 要备案吗 |
|---|---|
| 服务器在**中国大陆** | **必须** |
| 服务器在**香港** | 不用（但访问稍慢） |
| 服务器在**海外** | 不用（国内访问慢） |
| 只是本地开发 | 不用 |

**备案要什么**：身份证、手机号、已实名认证的域名、服务器的备案服务码、网站名称和内容说明。

**时间：7 到 20 个工作日。**

> **为什么强调这条**：很多人买了服务器、代码也写好了，最后卡在备案上，白等两周。**备案期间网站不能对外访问。**
>
> **最省事的路径**（客户在国内）：
>
> 1. 买域名
> 2. 买国内轻量应用服务器（2核2G 起）
> 3. **立刻提交备案**（用服务器给的备案码）
> 4. 备案期间用 localhost + 香港服务器做开发
> 5. 备案下来后指向国内服务器

### 子域名不另外花钱

买一个域名能无限加子域名：

```
qiancan.cc              主站
api.qiancan.cc          你的中转服务
admin.qiancan.cc        后台管理
demo.qiancan.cc         给客户看的演示
client-a.qiancan.cc     A 客户的项目
```

**实用技巧**：给小客户交付时用 `客户名.你的域名.com`，不用每个客户买域名。

> **备案是按主域名备的，子域名不用单独备。** 主域名备过，所有子域名都能用。

## 三、服务器

### 服务器是什么

**大白话：一台永远开着、有公网 IP 的电脑，放在机房里。**

没有显示器、没有键盘，你只能通过网络远程操作。

### 和你电脑的差别

| | 你的电脑 | 服务器 |
|---|---|---|
| 关机 | 随时可以 | **不能关**（关了网站打不开） |
| IP | 动态，每次重连都变 | **固定公网 IP** |
| 系统 | Windows | **几乎都是 Linux** |
| 操作 | 鼠标点 | **只能打命令（SSH）** |
| 谁在用 | 你一个 | 可能几千人同时 |

> **"只能打命令"是最大门槛，但别怕。** 你在终端里学的 `pwd`、`ls`、`cd`、`node`，**在服务器上一模一样能用**。
>
> 你已经在练了，只是没意识到。

### 买什么配置

| 用途 | 配置 | 价格 |
|---|---|---|
| **学习 / 小项目 / 个人用** | 2 核 2G，40G 硬盘 | **60–100 元/月** |
| 小客户项目（几十人） | 2 核 4G，60G | 100–200 元/月 |
| 中等流量 | 4 核 8G | 300–500 元/月 |

> **起步就买最低配。** AI 应用的开销不在服务器（你是调 API，不是本地跑模型），**2 核 2G 够撑几十个用户**。
>
> **钱要花在模型调用上，不是服务器上。** 很多人一上来买 8 核 16G，钱全浪费了。

**买哪种**：

| 类型 | 特点 | 建议 |
|---|---|---|
| **轻量应用服务器** | 便宜、配置简单、带宽包月 | **起步用这个** |
| 云服务器 CVM/ECS | 灵活、可扩展 | 业务稳定后再换 |
| 虚拟主机 | 只能放静态网页 | ❌ **不能跑 Node，别买** |

### Linux 十个命令

| 命令 | 干什么 |
|---|---|
| `pwd` | 我在哪个目录 |
| `ls -la` | 这目录有什么 |
| `cd /root/app` | 进某个目录 |
| `mkdir app` | 建目录 |
| `nano server.js` | 编辑文件（最简单的编辑器） |
| `cat package.json` | 看文件内容 |
| `rm 文件名` | 删文件 |
| `ps aux \| grep node` | 看 node 进程 |
| `kill 12345` | 停掉某个进程（12345 是 PID） |
| `df -h` | 看硬盘还剩多少 |

> **`nano` 的五个键记牢**：直接打字，`Ctrl + O` 保存，`Enter` 确认文件名，`Ctrl + X` 退出。
>
> 服务器上没有 VS Code，你只能用它改配置。

### SSH：怎么连上去

```
ssh root@47.98.xx.xx
```

- `root` 是用户名（默认最高权限账号）
- `@` 后面是 IP
- 第一次会问 `yes/no`，输 `yes`
- 然后输密码，**输入时屏幕不显示任何东西，这是正常的**

> **"输密码屏幕没反应"是新手第一个困惑。** Linux 就这么设计（防止别人看到你输了几位）。**盲打完回车就行。**

**更安全：用密钥登录（免密码）**

```
ssh-keygen -t rsa
```
```
ssh-copy-id root@47.98.xx.xx
```

> **密码登录的风险**：服务器暴露在公网，**每天有几百次暴力破解**。用密钥能挡掉 99%。
>
> **长期运营服务器这一步必须做。** 否则某天你会发现被人登进去装了挖矿程序。

### 防火墙 / 安全组：最容易卡住的地方

**云服务器默认只开 22（SSH），其他端口全关。**

**所以你把程序跑起来了，外面还是访问不到。**

在云控制台的"安全组"或"防火墙"里开端口：

| 端口 | 用途 | 开不开 |
|---|---|---|
| 22 | SSH | 必开 |
| 80 | HTTP | **必开** |
| 443 | HTTPS | **必开** |
| 3000 | 你的 Node 服务 | ❌ **不要开给公网** |
| 3306 / 5432 | 数据库 | ❌ **绝对不要开** |

> **为什么 3000 不要开**：应该让 Nginx 在 80/443 接收请求，再转发到本地的 3000。直接暴露 3000 意味着别人能绕过 Nginx 的防护直连你的程序。
>
> **数据库端口绝对不能开。** 这是被入侵的头号原因——开放 3306 的服务器通常几小时内就被扫到并暴力破解。

**症状对照**：

| 现象 | 原因 |
|---|---|
| `ssh` 连不上，超时 | 22 端口没开 / IP 填错 |
| SSH 能连，浏览器打不开 | 80/443 没开 |
| 浏览器显示"拒绝连接" | 端口开了，但程序没跑 / 跑在别的端口 |

## 四、部署五步

### 第一步：传代码

```bash
git clone https://github.com/keal-24/你的仓库.git
cd 你的仓库
```

> **为什么用 Git 而不是直接上传**：以后更新只需 `git pull`，还能回滚到任何版本。
>
> **`.env` 不在 Git 里（正确），所以服务器上要手动建一个。** 这是安全的代价，必须接受。

**传单个文件用 scp**：

```bash
scp -r ./项目 root@47.98.xx.xx:/root/
```

**不适合传整个项目**（`node_modules` 几百 MB，传一次几十分钟）。

### 第二步：装依赖

```bash
cd /root/你的项目
npm install
```

服务器上也可能慢，换源：

```bash
npm config set registry https://registry.npmmirror.com
```

### 第三步：让它常驻（关键）

**问题**：你在 SSH 里跑 `node server.js`，一关窗口服务就停。**因为 SSH 会话结束，它启动的所有进程都会被终止。**

**解法：pm2**

```bash
npm install -g pm2
```
```bash
pm2 start server.js --name my-app
```
```bash
pm2 save
```
```bash
pm2 startup
```

| 命令 | 干什么 |
|---|---|
| `pm2 start server.js --name my-app` | 启动，起个名字 |
| `pm2 list` | 看所有在跑的应用 |
| `pm2 logs my-app` | 看日志 |
| `pm2 restart my-app` | 重启 |
| `pm2 stop my-app` | 停止 |
| `pm2 save` | **保存当前状态** |
| `pm2 startup` | **设置开机自启** |

> **`save` 和 `startup` 必须都做。**
>
> - `save` 记住"现在跑着哪些"
> - `startup` 让服务器重启后自动恢复
>
> **只做 `save` 不做 `startup`**，服务器重启（比如云厂商维护）后网站就挂了，而且你可能几小时后才发现。

### 第四步：Nginx 反向代理

**为什么需要**：你的程序跑在 3000，用户访问的是 80 端口。**Nginx 就是那个"接线员"。**

```bash
apt update
apt install nginx -y
```

配置 `/etc/nginx/sites-available/default`：

```nginx
server {
    listen 80;
    server_name 你的域名.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

```bash
nginx -t
```
```bash
systemctl reload nginx
```

> **`nginx -t` 必须跑。** 配置写错了 `reload` 会失败，而且失败时 Nginx 继续用旧配置跑——**你以为改了，其实没生效。**

> **`proxy_pass http://127.0.0.1:3000` 用 `127.0.0.1` 不是公网 IP** —— 因为只让本机能访问，不给外面开。

### 第五步：HTTPS（必须做）

**没有 HTTPS 的后果**：地址栏显示"不安全"，客户看了就慌；用户输入的一切都是明文传输；很多 API 强制要求 HTTPS。

```bash
apt install certbot python3-certbot-nginx -y
```
```bash
certbot --nginx -d 你的域名.com
```

它会自动做三件事：申请证书、改 Nginx 配置、设置自动续期（90 天）。

验证：浏览器打开 `https://你的域名.com`，地址栏有锁图标就成功。

检查自动续期：

```bash
certbot renew --dry-run
```

**没报错说明自动续期正常。**

## 五、备份与监控（别省）

### 备份三原则

1. **自动，不要靠手动**（手动的都会忘）
2. **异地**（备份和原件不在同一台机器）
3. **定期测试恢复**（没测过的备份等于没备份）

**Supabase 免费版可能没有自动备份**，去 `Project Settings` → `Database` 确认。

**如果没备份，自己写个定时任务导出**：

```javascript
const { data } = await supabase.from("messages").select("*")
require("fs").writeFileSync(
  `backup-${new Date().toISOString().slice(0, 10)}.json`,
  JSON.stringify(data)
)
```

**二十分钟的事，但能救你的命。**

### 监控：挂了要知道

**你不可能 24 小时盯着网站。程序崩了、证书过期了，你得被动收到通知，而不是等客户打电话骂你。**

| 工具 | 干什么 | 成本 |
|---|---|---|
| **UptimeRobot** | 每 5 分钟访问一次你的网站，挂了发邮件 | **免费版够用** |
| 腾讯云/阿里云监控 | CPU、内存、磁盘告警 | 随服务器附送 |
| Sentry | 代码报错自动上报（带堆栈） | 免费额度够小项目 |

> **最少配一个 UptimeRobot。** 免费版能监控 50 个站点，5 分钟一次。
>
> **这是"专业"和"业余"的分界**：业余的等客户发现问题，专业的在客户之前就知道。

## 六、成本怎么算（接活必用）

**客户问"一年要花多少钱"，你要能当场报出来。**

以"AI 聊天应用，50 用户，每天 200 次对话"为例：

| 项目 | 单价 | 用量 | 月成本 |
|---|---|---|---|
| 服务器（2核2G） | 80 元/月 | 1 台 | **80 元** |
| 域名 | 80 元/年 | 1 个 | ~7 元 |
| SSL 证书 | 免费 | — | 0 |
| 数据库（Supabase 免费版） | 0 | — | 0（超了 $25/月） |
| **模型调用** | 按 token | 见下 | **看模型** |
| **合计（不含模型）** | | | **约 90 元/月** |

**模型费用单独算：**

```
月成本 = 每天次数 × 30 × 每次平均 token × 单价
```

**举例**（假设某模型输入 1 元/百万 token，输出 3 元/百万）：

```
每天 200 次，每次输入 800、输出 300
每月输入 = 200 × 30 × 800 = 4.8 百万
每月输出 = 200 × 30 × 300 = 1.8 百万
月成本 = 4.8 × 1 + 1.8 × 3 = 10.2 元
```

> **这个例子里模型费很便宜（10 块）。但要提醒**：如果每次带 20 条历史，输入 token 会翻 5–10 倍。
>
> **真实的成本大头永远是模型，不是服务器。** 你报服务器 80 块客户觉得合理；你不提模型费，最后自己吃。

**报价必须分开写三笔**：开发费（一次性）、服务器域名（每月固定）、模型费（按量，谁付）。**第三条最容易扯皮。**

## 七、网站打不开，八步排查

**照着顺序走，不要跳。**

| 步 | 查什么 | 命令 | 说明 |
|---|---|---|---|
| 1 | DNS 解析对不对 | `ping 你的域名.com` | 返回的 IP 是你的服务器吗？不是就解析没生效或填错 |
| 2 | 服务器活着吗 | `ping 服务器IP` | 不通 → 服务器关了 / IP 变了 |
| 3 | SSH 能进吗 | `ssh root@IP` | 进不去 → 22 端口 / 防火墙 / 密码错 |
| 4 | 程序在跑吗 | `pm2 list` | 没在跑 → `pm2 start` |
| 5 | 程序能本地访问吗 | 服务器上 `curl localhost:3000` | 不通 → 程序本身有问题 |
| 6 | Nginx 活着吗 | `systemctl status nginx` | 挂了 → `systemctl start nginx` |
| 7 | Nginx 配置对吗 | `nginx -t` | 报错 → 按提示改 |
| 8 | 转发对吗 | `curl -I http://localhost` | 502 → 转发地址错；404 → `server_name` 不匹配 |

> **顺序是从外往里。**
>
> 大多数人反过来——一上来就看代码。**结果查了两小时代码，发现是域名解析填错了一个数字。**
>
> **先确认"请求有没有到达你的程序"。这一步不通，后面的代码一行都不用看。**

## 一句话总结

> **域名是门牌号，DNS 是黄页，服务器是房子，Nginx 是门卫，HTTPS 是门锁，备份是保险。**
>
> **六样东西，每样缺了都能让网站打不开，但排查永远从外往里。**
