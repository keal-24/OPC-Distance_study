# 开篇先导课：先把这件事想明白，再开始学习

这是正式课程前的**唯一一节先导课**。

它不是技术课，不要求你安装软件，也不要求你马上写代码。它只做一件事：把现在的时代、人工智能的基本概念、就业和接项目方向、学完能做什么、为什么课程要学这么多，以及接下来应该怎么学，一次讲清楚。

看完后，你要能回答：

> 我为什么要花时间学习人工智能开发？学完以后，我准备拿它做什么？

如果暂时答不上来，先别急着进入技术课。方向没想明白，学习很容易半途而废。

---

## 一、现在到底发生了什么变化

人工智能不只是一个会聊天的搜索框。它正在降低“把想法做成工具”的门槛。

以前做一个企业内部小工具，通常是：

```text
提出需求 → 找开发人员 → 报价 → 等待开发 → 测试 → 修改
```

现在可以变成：

```text
你把需求说明白 → 人工智能帮你写第一版 → 你运行和检查 → 继续修改 → 做成能用的工具
```

变化不是“人工智能会写代码，所以大家不用学了”，而是：

- 做出第一版的速度变快了；
- 个人也能尝试以前需要团队才能做的工具；
- 小企业更容易负担定制工具；
- 会提需求、会检查、会部署和会维护的人更重要了。

但人工智能写的东西也可能：

- 能运行，却没有处理错误情况；
- 看起来对，却有权限和安全问题；
- 演示时能用，数据一多就变慢；
- 只有写它的人看得懂；
- 出问题后找不到原因。

所以真正有价值的能力不是“让人工智能吐出一段代码”，而是：

> **听懂需求、做出工具、检查结果、稳定运行，并对交付结果负责。**

## 二、先认识四个常见概念

### 1. 人工智能

人工智能是总称，指让电脑完成一些原本需要人理解、判断或生成的工作。

WorkBuddy、Codex 等工具，都是帮助你使用人工智能能力的工具。

### 2. 大语言模型（LLM）

LLM 是“大语言模型”的英文缩写。先把它理解成：

> **负责理解文字并生成文字、代码或回答的核心大脑。**

你问它一个问题，它根据已经学到的内容和你提供的上下文，生成一个最可能的回答。

它很有用，但不等于永远正确。它不知道你的全部业务，也不会替你承担错误后果。

### 3. 智能体（Agent）

智能体不是只回答一句话，而是接到一个目标后，自己分成几步完成任务。

例如你说：

```text
读取这个文件，找出所有金额，计算总数，再生成一份报告。
```

普通聊天可能告诉你怎么做；智能体可能按顺序读取文件、提取金额、计算总数、生成报告。

智能体能做更多事情，也更需要限制范围。删除文件、修改数据库、发消息、花钱和上线，都不能让它不经确认就执行。

### 4. MCP

MCP 是一种让人工智能连接外部工具的统一方式。

可以这样理解：

```text
大语言模型 = 会思考的助手
MCP = 统一的插座和插头
外部工具 = 文件、浏览器、数据库、GitHub 等
```

人工智能本身不能凭空看到你的电脑文件，也不能凭空访问你的数据库。连接了对应工具后，才可能读取或操作它们。

最重要的规则是：

> **能连接，不等于能随便操作。涉及删除、金钱、客户资料和上线，必须先看清楚并确认。**

四个概念放在一起：

```text
人工智能：总称
大语言模型：理解和生成内容的核心能力
智能体：围绕目标分步骤完成任务
MCP：让人工智能连接外部工具的方式
```

本套课程会围绕 WorkBuddy、Codex 和真实开发流程来学，不会只讲抽象概念。

## 三、WorkBuddy 和 Codex 分别怎么用

### WorkBuddy 适合什么

WorkBuddy 更像一个国内使用方便的人工智能工作台，适合：

- 解释一个新概念；
- 把复杂内容讲简单；
- 帮你设计学习步骤；
- 阅读你提供的文件；
- 生成和修改文字、代码；
- 通过已连接的工具完成一些工作。

你可以把它当成“会讲解、会分析、会协助工作的老师和助手”。

### Codex 适合什么

Codex 更像一个能进入代码项目工作的编程助手，适合：

- 查看项目文件；
- 根据要求创建代码文件；
- 修改已有代码；
- 解释报错；
- 检查多个文件之间的关系；
- 在你允许后运行命令、测试代码。

你可以把它当成“坐在项目旁边帮你写代码的助手”。

### 两者怎么配合

```text
WorkBuddy：先讲清楚概念、拆任务、制定步骤
Codex：进入代码项目，创建文件、修改代码、运行检查
你：决定需求、确认权限、检查结果、承担最终责任
```

后面的课程会直接告诉你：什么时候用 WorkBuddy，什么时候用 Codex，输入什么，应该看到什么，出错怎么办。不再只说“使用人工智能工具”这种空话。

## 四、学完这套课程可以做什么

### 方向一：找工作

可以了解和尝试这些方向：

- 人工智能应用开发；
- 自动化流程开发；
- 企业内部工具开发；
- 数据处理和文档处理；
- 网站和后台开发；
- 人工智能产品实施和交付。

岗位名称不一定叫“人工智能工程师”。企业有时更需要能把工具接进业务、让员工真正用起来的人。

### 方向二：接小项目

可以从范围清楚、结果容易验收的小项目开始：

- 企业内部问答工具；
- 文件整理和资料查询工具；
- 表格自动处理工具；
- 网站、表单和后台；
- 数据采集、清洗和汇总工具；
- 文档解析和报告生成工具；
- 飞书、企业微信或公众号里的业务工具。

刚开始不要急着接大型项目。先做出能演示、能说明、能交接的小作品。

### 方向三：做自己的产品

例如：

- 某个行业的资料助手；
- 帮一类人处理重复工作的工具；
- 文件解析和报告生成服务；
- 小型网络应用；
- 自己业务使用的客户管理工具。

产品做出来不等于自动赚钱，还要找用户、听反馈、控制成本、处理售后。

### 方向四：提升原来的工作

如果你已经有行业经验，优势往往是“行业经验 + 开发能力”：

- 做销售：客户资料整理和跟进工具；
- 做财务：表格处理和报告辅助工具；
- 做运营：内容整理和数据分析工具；
- 做教育：资料问答和作业辅助工具；
- 做电商：商品资料处理和客服辅助工具。

## 五、为什么不能只学会聊天

会聊天只是起点。真实项目通常要经过：

```text
了解需求
→ 设计方案
→ 写代码
→ 管理代码版本
→ 处理数据和文件
→ 测试和修问题
→ 部署到服务器
→ 绑定域名
→ 保护账号和数据
→ 交给别人使用
→ 维护、收费和交接
```

因此课程会逐步讲：

- 人工智能工具和提问方法；
- 网页、前端和后端；
- 数据库和文件；
- 数据采集、文档解析和检索；
- 智能体和工具连接；
- 测试、性能和安全；
- 服务器、域名、部署和备份；
- 平台集成、支付和小程序；
- 获客、报价、合同、财务和交付。

不是要求你马上成为每个领域的专家，而是让你知道每一环做什么，并能把小项目完整走通。

## 六、就业和赚钱要实事求是

不要相信“学完一定月入多少”“不会代码马上接单”这种保证。

真实情况是：

- 会使用工具，不等于能解决客户问题；
- 学完课程，不等于自动获得客户；
- 做出演示，不等于能稳定运行；
- 会写代码，不等于懂报价、合同和售后；
- 收入取决于能力、作品、沟通、市场需求和持续行动。

这套课程能给你的，是一条完整路线和一批真实作品。你需要用作品证明自己，而不是只说“我学过人工智能”。

## 七、你将按照什么方式学习

每一节课都按这个顺序：

```text
先讲这节课要解决什么问题
→ 解释本节课出现的新词
→ 说明为什么要做
→ 手把手操作
→ 说清做完应该看到什么
→ 故意测试错误情况
→ 记录卡点和解决方法
→ 提交本节课成果
```

以后遇到不懂的词，不要假装懂，也不要连续跳过去。把词记下来，直接问：

```text
请用完全不懂编程的人能听懂的话解释这个词。
先说它解决什么问题，再举一个生活例子。
不要使用新的专业词。
```

每节课都要留下一个能检查的结果：代码、网页、接口、数据表、测试记录、部署记录、项目说明或业务模板。

## 八、正式开始前，你要做的准备

你现在不用安装一大堆软件，只做三件事：

1. 确认能打开 WorkBuddy；
2. 确认电脑上已经有学习仓库：

```text
B:\OPC-Distance_study
```

3. 在仓库里找到正式课程入口（注意 `01-任务` 这一层不能少）：

```text
每周课程\01-元技能与基础\第01周-AI工具\第01节课\01-任务\TASK.md
```

**进正式课程之前，还有两份东西要看：**

```text
参考手册\00-完整路线图.md     252 天怎么排的、36 周各干什么、时间不够怎么砍
参考手册\01-环境搭建.md       装 Node / Git / VS Code，四条验证全过才算完
```

**顺序是：先读路线图（知道自己要去哪）→ 装环境（把车修好）→ 再进第 1 节课。**

正式第一节课会手把手教你：如何向人工智能提出清楚的要求，如何让 WorkBuddy 或 Codex 帮你生成一个小程序，以及如何检查结果。
