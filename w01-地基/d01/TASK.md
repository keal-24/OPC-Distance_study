# 第 1 步 · 认清 VS Code（10 分钟）

## 这一步在干什么

认识你未来 147 天要天天面对的软件。**这一步只看，不动手。**

**为什么必须先做**：后面每一步都会说"点左侧第三个图标""看最下面状态栏"。不知道这些词指什么，光找按钮就能耗半小时。

## 1. 打开它

开始菜单 → 直接敲键盘 `code` → 蓝色图标的 **Visual Studio Code** → 回车。

> **为什么输 `code` 而不是翻目录**：开始菜单支持直接搜索，比一层层点文件夹快十倍。以后每次都这么开。

## 2. 第一次打开会看到什么

```
┌──┬─────────────────────────────────────┐
│  │                                     │
│图│                                     │
│标│        （中间一大片空白）            │
│栏│                                     │

│  蓝色状态栏（最下面一条）               │
```

三块区域，记住位置：

- **左边一竖排小图标** = 功能入口
- **中间一大片空白** = 写代码的地方
- **最下面一条蓝线** = 状态栏，明天的 `Go Live` 就在这里

## 4. 汉化（把它变成中文）

**点左侧第五个图标（四个小方块）** → 搜索框输入 `Chinese` → 找作者是 **`Microsoft`** 的那个（几千万下载）→ 点 `Install`。

装完右下角弹窗，点 **`Change Language and Restart`**。

> **为什么必须认作者是 Microsoft**：搜 `Chinese` 出来几十个结果，大量第三方"汉化包"，有的一装界面就乱码。**只装官方那个。**

> **为什么必须点那个按钮**：只是"装上"不够，得告诉软件"以后用中文显示"。**不点它，装了也还是英文。**

> **汉化失败别死磕。** 英文界面照样能写代码。**超过 30 分钟没过就跳过**，用英文界面继续。

# 第 2 步 · 把仓库推上 GitHub（20 分钟）

## 这一步在干什么

把本地这个文件夹里的东西，复制一份到 GitHub 的服务器上。

**为什么今天必须做**：你电脑上的一切**只存在这块硬盘上**。硬盘坏了、电脑丢了，一样都不剩。

做完这一件，以后换任何电脑都是两条命令的事。

## 先搞懂：登录是在干什么

Git 要把代码送到 GitHub，得先证明「你是你」。

**用浏览器授权**：弹个窗，点一下，浏览器点一下确认。之后电脑记住这个凭证。

> **GitHub 早就不让用密码推代码了。** 输了会报 `Authentication failed`。

## 步骤

**1.** 点菜单 `终端` → `新建终端`（或按 `` Ctrl + ` ``）

**2.** 下方弹出终端，左边显示 `powershell`，右边光标在闪

   **这就是终端**：用打字代替点击的界面。点鼠标能做到的（进文件夹、复制文件），这里敲一行字也行，而且更快、可重复。

   **两个必须注意**：只能输**英文符号**；每行按**回车**才执行。

**3.** 输入，回车：

```
cd "B:\OPC-Distance_study"
```

   > **`cd` = change directory，切换目录。** 相当于在资源管理器里双击进去。
   >
   > **为什么必须先进去**：Git 只认"当前所在文件夹"里的仓库。你现在终端大概在 `C:\Users\Admin`，那里没有仓库，直接跑 Git 命令会报 `not a git repository`。
   >
   > **引号不能省**：路径里有中文，不加引号可能被截断。

   **回车后什么都没发生，这是正常的。** 终端里没消息就是好消息。

**4.** 输入，回车：

```
git remote add origin https://github.com/keal-24/OPC-Distance_study.git
```

   > **这行在干什么**：告诉 Git「以后我说推，你就推到那个地址」。`origin` 是给这个地址起的外号（约定俗成）。
   >
   > **为什么起外号**：地址长、容易打错。有了 `origin`，以后一句 `git push` 就够了。

   **同样没有提示。**

**5.** 输入，回车：

```
git push -u origin main
```

   > **`push` = 推。`-u` = 记住这次的关系**，以后再推只打 `git push`。
   >
   > **这行会有反应。**

**6.** 弹出 `Connect to GitHub` 窗口，点 **`Sign in with your browser`**

   > **为什么选第一个**：最省事。第二个（输入 8 位代码）是没浏览器时的替代；第三个（访问令牌）是给自动化脚本用的。

**7.** 浏览器自动打开授权页，点绿色 **`Authorize git-credential-manager`**

   > **这一步在干什么**：GitHub 在问「这个软件想访问你的仓库，你同意吗」。这是安全检查。
   >
   > **不点授权的后果**：终端会一直卡着等服务响应，最后超时报 `Authentication failed`。

**8.** 浏览器显示绿勾，关掉它

**9.** 回终端，看到最后一行是：

```
branch 'main' set up to track 'origin/main'.
```

   就成功了。

**10.** 浏览器打开 `https://github.com/keal-24/OPC-Distance_study`，刷新

## 你会看到什么（自检）

GitHub 页面上列着：`docs`、`w01-地基`、`w02-对话`…`w21-交付`、`final`、`README.md`。

**看到这些，第 2 步完成。** 从这一刻起，你的东西在这块硬盘之外有了一份。

## 可能出错

| 报错原文 | 意思 | 怎么办 |
|---|---|---|
| `fatal: not a git repository` | 第 3 步 `cd` 没成功 | 重跑第 3 步，路径带英文引号 |
| `remote origin already exists` | 之前加过这个地址 | `git remote remove origin` 再重跑第 4 步 |
| `Authentication failed` | 第 6、7 步授权没走完 | 重跑第 5 步，弹窗出来把浏览器那步做到底 |
| `error: src refspec main does not match any` | 当前分支不叫 `main` | `git branch -M main` 再重跑第 5 步 |
| `Repository not found` | 地址打错了 | 核对用户名和仓库名有没有打错字母 |

> **卡在这步超过 40 分钟就停。** 记下报错原文，明天再弄。**GitHub 备份重要，但别为它耽误学写代码。**

# 第 3 步 · 写出第一个网页（30 分钟）

## 这一步在干什么

做一个真正能在浏览器里看到的东西。

**为什么先做网页而不是别的**：因为你需要**看得见的反馈**。写后端、写算法，跑完屏幕上一行字都没有，你根本不知道自己做对没有。

## 先搞懂一件事（5 分钟，不用背）

网页就是一个**文本文件**，后缀 `.html`。

`.html` = HyperText Markup Language（超文本标记语言），说白了就是**"带标签的纯文本"**——用尖括号包起来的词，告诉浏览器"这块是标题""那块是段落"。

三个最常用的标签：

- `<h1>...</h1>` —— 大标题（h = heading，1 表示最大）
- `<p>...</p>` —— 一段话（p = paragraph）
- `<button>...</button>` —— 按钮

**没有编译、没有安装、没有魔法。** 你现在看的任何网页，本质都是这种文件被浏览器读出来画在屏幕上。

> **为什么这点重要**：很多人以为做网页需要特殊软件、需要"发布"。不需要。一个文本文件，用浏览器打开，就是网页。**理解这一点，后面听到"部署""上线"就不会觉得神秘** —— 那只是把这个文件放到别人能访问的电脑上而已。

## 做

**1.** 打开 VS Code → `文件` → `打开文件夹` → 定位到 `B:\OPC-Distance_study\w01-地基\d01` → 点「选择文件夹」

   > **这步在干什么**：让 VS Code"以这个文件夹为工作区"。之后左侧文件列表、搜索、提交，全都基于这个文件夹。**这是核心习惯：先打开文件夹，再在里面干活。**

   如果弹「是否信任此文件夹的作者」，点「是，我信任」。

**2.** 鼠标移到左侧 `D01` 这行字上，出现一排小图标，点**第一个**（纸带加号，「新建文件」）

**3.** 输入 `index.html`，回车

   > **为什么必须叫 `index.html`**：这是网页的**约定**。服务器默认会找这个名字当首页。今天随便叫 `a.html` 也能开，但以后部署到服务器，别人访问你的域名时找不到首页。
   >
   > **从第一天就用对名字，省得以后改。**

**4.** 在编辑区输入一个**英文感叹号** `!`，然后按 `Tab`

   会"唰"地出现十几行代码：

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document</title>
</head>
<body>
    
</body>
</html>
```

   > **这一步在干什么**：VS Code 的代码片段功能。打一个 `!` 按 Tab，自动生成整个骨架。
   >
   > **为什么不用手打**：这十几行是每个网页都必须有的固定结构，手打要两分钟且容易漏。**这就是"用工具"的第一个体现**——重复的活交给工具。
   >
   > **骨架各部分是什么**（不用背，看个印象）：
   > - `<!DOCTYPE html>` = 声明"这是 HTML 文档"
   > - `<head>` = 给浏览器看的说明，不显示在页面上
   > - `<meta charset="UTF-8">` = 声明编码，保证中文不乱码
   > - `<title>` = 浏览器标签页上显示的字
   > - `<body>` = **页面上真正显示的东西都写这里**

**5.** 找到 `<title>Document</title>`，把 `Document` 改成 `我的第一个站`

   > **这步在干什么**：改浏览器标签页的文字。**和页面内容无关**，是给用户在多个标签之间切换时认页面用的。

**6.** 找到 `<body>` 和 `</body>`，在两者**中间**的空行里输入：

```html
<h1>你好，我是闫凯旋</h1>
```

   改完是这样：

```html
<body>
    <h1>你好，我是闫凯旋</h1>
</body>
```

   > **为什么必须写在 `<body>` 里面**：`<head>` 是说明文字，浏览器不画出来；`<body>` 才是画布。**写在 `<head>` 里页面就是一片空白** —— 这是新手最常见的错误之一。
   >
   > **`<h1>` 和 `</h1>` 为什么要成对**：`<h1>` 是"开始当标题"，`</h1>` 是"标题结束"。少了后面那个，浏览器不知道该在哪停，可能把后面所有内容都变成大标题。

**7.** 按 `Ctrl + S` 保存

   > **为什么专门按保存**：VS Code 不会自动保存。**没保存 = 磁盘上的文件还是旧的 = 浏览器看到的还是旧的。** 这一条是新手 80% "改了没反应"的原因。

   判断标准：看上方标签页 `index.html` 右边，**有白点 = 没保存，没白点 = 已保存**。

**8.** 点左侧第五个图标（四个小方块「扩展」）→ 搜索 `Live Server`

**9.** 找作者是 **`Ritwick Dey`** 的那个（紫红色小方块带信号波）→ 点 `安装`

**10.** 装完看**最下面状态栏右下角**，出现 `Go Live`，点它

   > **Live Server 到底干了什么**（这个必须懂）：
   >
   > 它在你电脑上开了一个**小服务器**（5500 端口），然后自动打开浏览器访问它。
   >
   > **为什么不能直接双击 `index.html` 打开**？两个原因：
   > 1. 双击打开时地址栏是 `file:///B:/...`，浏览器把它当本地文件，很多功能（比如以后要调的接口）会被安全策略拦住
   > 2. 双击打开**不会自动刷新**，你每改一个字都得手动按 F5
   >
   > **Live Server 解决这两件事**：给你一个像真实网站的地址（`http://127.0.0.1:5500`），而且你保存文件它就自动刷新。
   >
   > **这是今天最该理解的概念**：网页不是"文件"，是"从某个地址取回来的东西"。这个理解方式，到 Week 1 第 6 天学后端时你会用上。

## 你会看到什么（自检）

- 浏览器自动打开新标签页
- 地址栏是 `http://127.0.0.1:5500/index.html`
  - `127.0.0.1` = 你自己这台电脑，`5500` = Live Server 占的端口
  - **这个地址别人打不开，只对你自己有效**
- 标签页上写着 `我的第一个站`
- 页面左上角一行大字：**你好，我是闫凯旋**

## 现在做最关键的一个动作

**1.** 回 VS Code，把「闫凯旋」改成别的字
**2.** 按 `Ctrl + S`
**3.** **不要碰浏览器，不要按刷新，就看着它**

页面上的字自己变了。

> **这一下是今天全部的价值：改文件 → 立刻看到结果。**
>
> 往后 147 天全是这个循环，只是文件越来越复杂。**你今天要建立的是这个循环的肌肉记忆** —— 改、存、看。等它变成本能，你才有多余的注意力去思考"这个代码在干什么"。

## 验收（四条全打勾才算过）

- [ ] GitHub 网页上能看到我的文件夹和文件
- [ ] 浏览器里能看到我自己的名字，是大字
- [ ] 改文件保存后浏览器自动更新，我没点过刷新
- [ ] 我能说出 `index.html` 这个文件在哪个盘、哪个文件夹

> **第四条为什么必须打勾**：能说出文件在哪，说明你真的知道自己在操作什么。说不出来，说明你在"照着点"而不是"在做"，明天换个场景就懵。**这个区别，就是"会"和"跟过"的区别。**

## 可能出错

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 浏览器显示一堆代码，不是页面 | 文件名成了 `index.html.txt` | 资源管理器「查看」→「显示」→ 勾上「文件扩展名」，改成 `.html` |
| 右下角没有 `Go Live` | 插件没装完或装错 | `Ctrl+Shift+P` → 输入 `reload` → 「重新加载窗口」 |
| 点 `Go Live` 打不开 | 5500 端口被占 | 右下角 `Go Live` 上右键 → 换端口 |
| 改了没变化 | 没保存 | `Ctrl+S`，看标签页白点消没消 |
| 页面全白 | `<h1>` 写到了 `<body>` 外面 | 确认它夹在 `<body>` 和 `</body>` 之间 |
| 按 `!` 再按 Tab 没反应 | 光标不在 html 文件里 | 鼠标点一下编辑区空白处再试 |
| 中文变方块乱码 | 文件编码不是 UTF-8 | 右下角点编码 → `Reopen with Encoding` → 选 `UTF-8` |

# 第 4 步 · 收工（10 分钟）

## 1. 提交

点左侧第三个图标（圆圈带分叉线「源代码管理」）→ 输入框写：

```
d01: 第一个网页
```

→ 点输入框上方的对勾 `✓`。

> **这一步在干什么**：给这次改动起个名字，然后"拍张照"存进 Git 的历史。
>
> **为什么每天必须做**：Git 记下每次快照，以后代码被改坏了可以退回任何一个。**没提交过，改坏了就真没了。**
>
> **提交信息为什么带 `d01:` 前缀**：让你以后翻历史时一眼看出是第几天。三个月后你会感谢自己。

## 2. 写笔记

在同文件夹 `d01\` 里建 `NOTES.md`：

```markdown
今天做了什么：装好了环境，第一个网页出来了，Live Server 能自动刷新
卡在哪：
怎么解决的：
```

> **为什么笔记比代码重要**：代码 AI 三秒能重写，你踩过的坑只有你自己知道。**三个月后遇到同样问题，翻笔记三秒解决，不翻要再耗半小时。**
>
> **"卡在哪"空着也行**，空着说明今天顺利。但一旦卡过，一定要写。

## 3. 推上去

点**最下面状态栏最左边**的循环箭头（`同步更改`）。

推完去 `https://github.com/keal-24/OPC-Distance_study` 刷新，看到 `w01-地基/d01/` 里多了文件就正式收工。

> **为什么还要推一次**：刚才的提交只是存到本地硬盘。**"提交"和"推送"是两件事** —— 提交是本地的快照，推送才是备份到云端。这一步做完，今天的成果才真的安全。

# 老板视角

> **「做个官网」不是一件事。**

接到这种需求，先用三个问题砍掉一半溢价：

1. **几个页面？** —— 1 个静态页 vs 8 个页面带后台，工作量差 10 倍
2. **要不要后台管理？** —— 客户能自己改内容，就要做登录 + 数据库 + 编辑界面，工作量翻 3 倍
3. **内容谁提供？** —— 客户给现成文案 vs 你帮他写，这是两件不同的事

**问完这三个，你才知道该报多少，也才知道对方说的「很简单」到底简单在哪。**

# 今天必须能讲出来的一句话

**网页就是文件，放到服务器上别人就能看。**
