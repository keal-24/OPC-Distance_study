今天不写页面，不装环境。**今天只练一件事：怎么跟 AI 说话。**

# 第 1 步 · AI 能干什么、不能干什么（10 分钟）

## 这一步在干什么

搞清它的能力边界。**这一步只看，不用动手。**

**为什么必须先懂**：不懂边界，你会两种错都犯——**要么什么都自己写（慢十倍），要么什么都交给它（出大事）**。

## 它不是"自动写代码"

**它是"一个非常快、非常自信、但不会负责的初级程序员"。**

三个特点：

| 特点 | 后果 |
|---|---|
| **极快** | 你写两小时的，它 20 秒。所以你会想什么都交给它 |
| **极自信** | 它错了也用同样肯定的语气说"这样就可以了" |
| **不负责** | 它不知道你的业务、不知道你的数据、不知道上线会出什么事 |

> **核心认知：它负责"写出来"，你负责"对不对"。**
>
> **这个分工不能反。** 反了就是"AI 写完，你上线，然后出事"。

## 它擅长什么

| 擅长 | 为什么 |
|---|---|
| 写样板代码（表单、列表、增删改查） | 这类代码有固定套路，它见过几百万遍 |
| 解释报错 | 报错信息是标准化的，它认得 |
| 转换格式（JSON 转类型定义） | 纯机械转换，不会错 |
| 写正则、SQL | 有明确语法规则 |
| 补全重复代码 | 复制粘贴加改名，它比人快 |
| 生成测试用例 | 按"输入→期望输出"罗列，它很擅长 |

## 它不擅长什么

| 不擅长 | 为什么 |
|---|---|
| **判断业务逻辑对不对** | 它不知道你的客户要什么 |
| **处理并发和边界** | 它默认写"一切正常"的那条路 |
| **安全性**（鉴权、注入、越权） | 它写的鉴权常常看起来对但有漏洞 |
| **知道你的真实数据结构** | 它只能猜，猜错了你还得改 |
| **跨文件的整体设计** | 它只看得到你贴给它的那几个文件 |
| **性能问题** | 它写的循环里常常藏着 N+1 查询 |

> **规律：越是"有标准答案"的事，它越强。越是"要判断"的事，它越弱。**
>
> **所以：让它写代码，你判断逻辑。**

## 五件事绝对不要让它代劳

| 场景 | 为什么 |
|---|---|
| **密钥、鉴权逻辑** | 它可能写出看起来对但有漏洞的鉴权，**这类漏洞你看不出来** |
| **金额计算** | 它可能用浮点数算钱，**这个错要一个月后对账才发现** |
| **数据库删除、批量更新** | 它可能漏 `WHERE` 条件，**一条 SQL 删掉全表** |
| **上线部署脚本** | 它不知道你的服务器状态，可能把线上搞崩 |
| **合同、报价** | 这是你的生意判断，它没这个信息 |

> **共同点：错了的后果不可逆，或者很久才发现。**
>
> **这类代码你必须自己写，或者自己逐行验。**

# 第 2 步 · 五要素指令（20 分钟）

## 这一步在干什么

学会一种"能让 AI 一次写对"的提问结构。

**为什么这是今天最重要的**：同样一个需求，指令写得好它一次就对，写得差你要返工三次。**这个差别每天都会累加。**

## 先看一个坏指令

```
帮我做一个用户列表功能
```

**为什么坏**：它不知道：

- 你有几张表、字段是什么
- 用什么框架
- 要不要分页
- 要不要权限
- 返回什么格式

**结果**：它猜着写一套，你花两小时改成自己要的样子。**比自己写还慢。**

## 好指令的五个要素

```
【背景】这是一个 Node.js + express + Supabase 的项目，
        现有 users 表：id, phone, name, role, created_at

【任务】加一个"用户列表"接口

【要求】
- 分页，每页 20 条，参数是 page
- 支持按 name 模糊搜索
- 只能管理员（role='admin'）访问
- 返回 { list: [...], total: 数字 }

【约束】
- 放在 routes/users.js
- 不要改现有的其他文件
- 用现有的 authMiddleware 做鉴权

【验收】
- 普通用户请求返回 403
- 不带 page 参数默认第 1 页
```

**五个要素，一个不能少：**

| 要素 | 回答什么问题 | 缺了会怎样 |
|---|---|---|
| **背景** | 我在什么项目里、已有什么 | 它按通用情况猜，和你的项目不匹配 |
| **任务** | 要做什么 | 它不知道要做什么 |
| **要求** | 具体到什么程度 | 它做最小实现，缺功能 |
| **约束** | 不能动什么 | 它顺手改一堆别的文件 |
| **验收** | 怎么算做对 | 你不知道该测什么 |

> **写这五行花两分钟，能省二十分钟返工。这是最划算的投入。**
>
> **记住这句话：写指令的两分钟，永远比返工的二十分钟便宜。**

## 三个必须避免的指令

### ❌ "优化一下这段代码"

**为什么坏**：它不知道你要优化什么（速度？可读性？体积？），也不知道哪些不能动。

**改法**：「这段代码查 1000 条数据要 8 秒。瓶颈可能在 N+1（每次循环都查一次数据库）。请改成一次批量查询，保持返回结构不变。」

### ❌ "这个报错怎么解决"

**为什么坏**：它没看到你的代码，只能给通用答案。

**改法**：「完整报错：`Cannot read properties of undefined (reading 'map')`。相关代码：……（贴代码）。我预期是拿到数组，实际拿到的是 undefined。」

### ❌ "按最佳实践改一下"

**为什么坏**："最佳实践"是空的。它会按自己偏好大改一通，把你风格全打乱。

**改法**：「统一改成 async/await，不要用 .then()。其他不动。」

# 第 3 步 · 亲手试一次（20 分钟）

## 这一步在干什么

用五要素结构，让 AI 写一个你能自己验证对错的函数。

**为什么选"日期格式化"这种小题**：因为它**足够小、你能一眼看出对错**。用它练指令结构，不掺杂项目复杂度。

## 做

**1.** 打开你平时用的 AI 对话工具（WorkBuddy / Codex / Claude / 任何）

**2.** **先写一个坏指令**，看它给什么：

```
写一个日期格式化的函数
```

**记下它的回答。**

> **为什么要先写坏的**：让你亲眼看到"指令模糊 → 结果不可控"。**有了对比，你才会认真写好的那个。**

**3.** 现在写五要素版本，**整段复制，把方括号里的内容按你的想法改**：

```
【背景】
Node.js 项目，前端是原生 JS，没有用任何日期库。

【任务】
写一个函数 formatTime(isoString)，把 ISO 时间转成中文显示。

【要求】
- 输入：'2026-11-16T04:30:00.000Z' 这种 ISO 字符串
- 输出规则：
  - 今天 → "今天 12:30"
  - 昨天 → "昨天 12:30"
  - 今年内 → "11月16日 12:30"
  - 更早 → "2025年11月16日"
- 按浏览器本地时区显示，不是 UTC

【约束】
- 纯函数，不依赖任何库
- 不改任何其他代码
- 加上中文注释

【验收】
- 传入今天的时间，输出以"今天"开头
- 传入昨天的时间，输出以"昨天"开头
- 传入去年的同一天，输出带年份
```

**4.** 看它的输出，**和刚才那个坏指令的结果对比**。

> **你要观察的差别**：坏指令给的常常是一个通用格式化函数，不处理"今天/昨天"；好指令给的会精确按你的规则来。
>
> **这个差别就是五要素的价值。**

## 你会看到什么（自检）

- 坏指令的版本：**功能少**（大概率没处理"今天/昨天"），或者用了额外的库
- 好指令的版本：**四个分支都有**，有中文注释，纯函数
- 你能说清"为什么第二个更符合我要的"

# 第 4 步 · 验收五步（20 分钟）

## 这一步在干什么

**检查 AI 写的东西到底对不对。**

**为什么这步最重要**：`"看起来对"`是最危险的。**AI 写的代码最大的特点是：能跑，看起来对，但有坑。**

## 一个真实例子

```javascript
// AI 写的"获取用户列表"
const list = await db.select("*").from("users")
res.json(list)
```

**看起来完全正常。但**：

- **没有分页** → 用户涨到 1 万条，一次返回 1 万条，接口 8 秒
- **没有权限检查** → 任何登录用户都能拿到全部用户
- **没过滤软删除** → 已删除的用户也在里面

**这些都不会报错。** 只有客户真用了才暴露。

## 五步，每步都要真做

### 第一步：读一遍，逐行说出它在干什么

**不是"大致看懂了"，是"能用话讲出每一行"。**

**拿刚才那个 `formatTime` 练**：逐行读，讲给自己听。

> **讲不出来的那几行，就是你不懂的地方 —— 也是将来出事的地方。**
>
> **这一条最重要，也最容易被跳过。** 你觉得"AI 写的我就直接用吧"，那这个代码对你就是个黑盒。**黑盒在出问题的时候会要你的命。**

### 第二步：问它三个问题

**在对话框里直接问**：

1. **"这段代码可能的边界情况有哪些？"**
2. **"如果时间跨年、跨月、闰年、或者用户在不同时区，会出问题吗？"**
3. **"这段代码有安全隐患吗？"**

> **为什么问这三个**：AI 默认只写"正常路径"。你问了，它才会补边界。
>
> **注意：它答的不一定对，但答出来的东西一般是它没写在代码里的真问题。**

### 第三步：故意输入坏数据（关键一步）

**在 Node 里跑一下，或者让 AI 帮你跑：**

```javascript
console.log(formatTime("2026-11-16T04:30:00.000Z"))  // 正常
console.log(formatTime(""))                           // 空字符串
console.log(formatTime("abc"))                        // 垃圾数据
console.log(formatTime(null))                         // null
console.log(formatTime(undefined))                    // undefined
console.log(formatTime("2026-13-45T99:99:99Z"))       // 非法日期
```

> **这一条是五步里最有效的。**
>
> **大部分问题在这一步就暴露了。** 而且你不需要自己写代码，让 AI 跑就行。

**你会看到什么（自检）**：

- 正常时间 → 正确格式
- 垃圾数据 → **报错，或者返回 "Invalid Date"，或者返回一串奇怪的东西**
- 如果它崩了 → **这不算 AI 写错，这算你没在要求里写"非法输入怎么处理"**

> **关键认知：它崩了不是它的错，是你没在"要求"里说清。**
>
> **这正好印证了五要素的必要性。** 补一句「非法输入返回 "未知时间"」，再试一次。

### 第四步：看它改了几个文件

**今天只让它写一个函数，所以只该有一个文件变动。**

**但在真实项目里，这一步很重要**：

- 只改了你说的那一个 → 好，风险低
- 改了五六个文件 → **停下来，逐个看**

> **AI 有时候会"顺手"改别的文件**（改个变量名、调整格式、甚至重构）。**这些附带改动可能是你不想动的。**
>
> **判断标准：超出范围的改动，一律先回退，再单独提需求。**

### 第五步：跑一遍完整流程

**不是"这个函数返回对了"，是"整个功能从点到尾都能用"。**

今天只有一个函数，所以：**把四种时间情况都试一遍**（今天/昨天/今年/更早）。

## 验收（六条全打勾才算过）

- [ ] 我能说清 AI 擅长什么、不擅长什么
- [ ] 我写过一个"坏指令"，并看到它的结果不够好
- [ ] 我写过一个"五要素指令"，结果明显更准确
- [ ] 我逐行读懂了 AI 写的函数（每一行都能讲出来）
- [ ] 我用六种坏数据测过它，知道它会怎么崩
- [ ] 我知道"它崩了不是它的错，是我要求没写清"

> **最后一条是今天的核心。**
>
> **把"AI 写得不好"重新理解成"我没说清"，这个转变是你从"抱怨工具"到"用好工具"的分水岭。**

## 可能出错

| 现象 | 原因 | 怎么办 |
|---|---|---|
| AI 给的结果很笼统 | 指令只写了"任务"，没有要求/约束/验收 | 补上另外四要素 |
| 它用了额外的库 | 没写"不依赖任何库" | 在约束里加 |
| 它改了别的文件 | 没写"不改其他代码" | 在约束里加 |
| 它在中文和英文之间混 | 没写"中文注释" | 在要求里加 |
| 它给的代码我看不懂 | 你跳过了第一步"逐行读" | **回去读，别往下走** |
| 它一直说"这样就可以了" | 它就是这样，不代表对 | 靠你的验收，不靠它的保证 |

# 老板视角

> **"你用 AI 写代码，那我为什么付钱给你？"**

这是客户会问、也是你自己要能答的问题。

**差的回答**：「我效率高。」

**好的回答**：

> 「AI 能把代码写出来，但它不知道你的业务、不知道你的数据结构、不保证安全，也不保证三个月后还能维护。
>
> 我做的事是：把需求拆成它能做对的粒度、验收它写的每一处、处理它处理不了的边界和权限、最后保证这东西上线不出事。」

**这个回答的价值在于**：它承认了 AI，但也说清了**你不可替代的那部分**。

**而今天学的五要素指令和验收五步，正是那部分的具体内容。**
