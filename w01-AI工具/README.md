# w01-AI工具 · Day 1-7

## 怎么让 AI 替你写代码，又不被它带进坑

---

## 这一周的目标

把 Codex、Claude Code、Cursor、WorkBuddy 这类工具真正用起来：

- **怎么下指令**（五要素：背景/任务/要求/约束/验收）
- **怎么验收**（五步：逐行读、问边界、喂坏数据、看改了哪些文件、跑完整流程）
- **命名和规范**（让项目三个月后你还敢改，让 AI 能接上）
- **改坏了怎么退回**（`git restore`、存档点习惯）
- **什么时候不该用它**（密钥、钱、删数据、部署、合同）

## 为什么排在第一周

这是整条路线里唯一的**元技能**。

后面 35 周你都在用 AI 写代码，但没人教过你怎么用。**用得好省一半时间，用不好你会花更多时间在调试它写的烂代码上。**

> **而且这不是"以后再说"的事。你已经在用了。**
>
> 前面十几天遇到的问题——占位符直接复制、站错目录、文件里混进重复代码——全都是"不会用 AI"，不是"不会写代码"。

## 这一周的最终产出

**不是代码，是一个文件：`CONTEXT.md`。**

周末你手上应该有：

1. 一份 `CONTEXT.md`，写清你的技术栈、目录结构、命名规则、十条硬规则、不要做的事
2. 一个习惯：**让 AI 大改之前先 commit**
3. 一个动作：**AI 写完的代码走验收五步**

## 周末的验收

不要急着进下一周。先确认这四条：

- [ ] 这一周每天都有 commit（打开 GitHub 看绿点，一天都不能缺）
- [ ] `d01/` 到 `d07/` 里都有 `NOTES.md`，而且「卡在哪」写了内容
- [ ] 我有一个能用的 `CONTEXT.md`，里面写了命名规则和硬规则
- [ ] 我能用一句话说清"AI 写的代码，我该怎么验收"

> **第三条和第四条才是真标准。**
>
> `CONTEXT.md` 是这个星期的核心产出。**没有它，你后面 35 周每次和 AI 对话都在重复解释同一件事。**
>
> **一周七天，落一天没关系，落三天就等于重来。**
